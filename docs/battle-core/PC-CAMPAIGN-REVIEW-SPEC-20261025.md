# PC 맵 확장·캠페인 통합 설계 검토 스펙

작성: 2026-10-25. 현재 위치: **워크플로우 2단계 스펙 초안 / 독립 검토 대기**.

이 문서는 이후 설계 검토 산출물을 판정할 채점표다. 게임 기능을 구현하거나 기존 제안을 사용자 확정으로 바꾸는 문서가 아니다. 작성자의 자체검사는 외부 검증 5-b가 아니다.

## 3. 사실·가설·결정·미지수

### 3.1 자료에서 확인한 사실

- S5는 표준 난이도, 고정 10Hz, ×1, 동일 시드 20824~20826, 단일 공격 정책으로 5조건×3판을 측정했다. 종료 중앙값은 baseline 1:31, slow_only 2:27, large_only 3:31, large_slow 8:50, terrain 5:41이다. 모두 게임 시뮬레이션 시간이다.
- S5에서 large_slow의 8~12분 포함은 2/3판이고 terrain은 3판 모두 패배했다. 원래 배치를 비례 확대한 실험이며 사람 플레이를 검증하지 않았다. 지형이 패배 원인이라는 결론도 없다.
- S5의 같은 시드 재실행 지문 일치와 명령 로그 재생 지문 일치는 서로 다른 검사다. 어느 쪽도 작전 중 저장·불러오기 완료 증거가 아니다.
- S5의 명령 로그 재생 검증 범위는 baseline/large_slow/terrain의 시드 20824 각 1판이다. 실제 게임 호스트 smoke의 종료 자원 잔존 경고도 남았다. 첫 발사 후 10초 발사 수는 baseline 8·8·9, large_slow 10·10·10, terrain 4·4·4이므로 감속이 초기 집중사격을 줄인다고 결론 내릴 수 없다.
- 효과 구역 10개 비교 기능과 물리 장애물·경로 탐색·레이저 차단·강습 전용 구역을 구분한다. 후자는 S5~S7에서 미구현으로 명시돼 있다.
- 현행 보급·사기·승패 기반 설명은 S1 §2와 S2 §4의 코드 검토 기록을 근거로 한다. 특히 적벽 전용 인물·군 사기·1200초 종료 규칙의 재사용 위험이 보고돼 있다. 이 문서 작성 자체가 최신 코드 재검증을 수행했다는 뜻은 아니다.

### 3.2 검증할 가설

- 임무를 가진 적, A/B 항로, 점령 후 보급과 유한 증원이 일제 접근보다 선택을 늘린다.
- 단일 성계 연속 작전과 전체 20분 전후 예산이 적절하다. 20분은 제안이며 사용자 확정 플레이 시간·실제 시간 기준이 아니다.
- 확대·감속 프리셋, 물리 장애물 최소 조합, 통신소 지연, 전력 보존 철수가 첫 샘플에 적합하다. 재미·난이도·완주 가능성은 아직 미검증이다.

### 3.3 확인된 결정과 이번 절차상 제한

- 사용자 요구는 함대 이동·조우·교전·행성 점령 후 보급·지연 시 적 증원과 전략게임 레퍼런스의 통합 제안이다. 은영전은 참고를 허용한 것이며 원작 전체 재현 명령이 아니다.
- 사용자는 S0를 따르도록 지시했고 이번 2단계 진행을 승인했다. 그 승인은 S1·S2의 모든 수치·구조 승인 또는 구현 착수 승인이 아니다.
- 이번 단계는 설계 검토 채점표만 작성한다. 범위를 바꾸지 않는 미지수는 open으로 기록하고, 범위나 검증 가능성을 바꾸는 미지수는 해당 후속 단계의 중단 조건으로 올린다.

## 6. 5-a와 5-b 운영 기준

### 6.1 5-a 기계·완결성 게이트

- [ ] G01: 산출물은 지정 스펙 파일 하나이며 게임 코드·브랜치·커밋·푸시를 변경하지 않았다. 동시 작업이 있으면 저장소 전체 변경을 작업자 소유 변경과 구분한다.
- [ ] G02: R01~R18은 중복·누락 없이 각각 1행이며 근거, 합격 조건, 검증 방법이 모두 있다. W01~W12가 적어도 한 ID에 연결된다.
- [ ] G03: S0~S7 파일 경로와 인용 구간이 존재한다. 원출처 확인이 필요한 주장은 추론·미확인으로 표시한다.
- [ ] G04: S5의 5개 중앙값·조건·시드 수가 원문과 일치하고, S2 §4.1 예산 2+3+3+3+2+5+2=20분을 재계산한다. 시간 단위·표본 한계를 빠뜨리지 않는다.
- [ ] G05: 목표/비목표/사실/가설/결정/미지수, 현재/미래 검증, open의 차단 범위, K=3, 5-b 반려 복귀와 체크포인트가 있다.
- [ ] G06: O01~O08의 상태는 open이고, 20분·6800×4600·30·45초/15초·증원 시점 등 후보를 사용자 확정이나 구현 완료로 표현하지 않는다.
- [ ] G07: 근거가 충돌하거나 누락되면 해당 ID를 실패/open으로 남긴다. 경로 존재·문구 검색만으로 내용의 정확성을 최종 승인하지 않는다.
- [ ] G08: R17에 Q67의 범위 대조 판정·적용 시 차이 목록 B항 등재/1000시드 재측정·범위 밖 판단 시 근거/제외 이유가 모두 있고, O08이 기존 확정 게이트를 미정으로 바꾸지 않는다.

게이트 실행자는 명령/검사 입력·결과·실패 ID·시도 횟수를 인계 기록에 남긴다. 작성자는 기계적 자체검사만 보고할 수 있다. 5-a 통과는 외부 검토로 넘길 필요조건이다.

### 6.2 독립 5-b 판정 기준

작성·수정에 참여하지 않은 검토 에이전트가 S0~S7 원문과 위 요구를 대조한다. 최소한 다음 반대 검토를 수행한다.

- [ ] X01: 범위·단위·승인 상태가 사용자 의도와 일치하는가. 기존 제안의 ‘채택/고정’ 문구를 사용자 결정으로 오인하지 않았는가.
- [ ] X02: 3판 실험·구편성·미구현 지형·적벽 특화 사기/승패·재생과 저장 차이의 한계가 유지되는가.
- [ ] X03: 넓고 느린 전장만으로 대기 증가, 강한 수비로 우회 필수화, 보급 거점으로 무한 회복, 사기 정책으로 첫 조우 종료, 증원으로 부당 패배가 생길 반례를 검토할 수 있는가.
- [ ] X04: 요구별 근거가 실제 주장을 지지하는가. 수치와 인과가 과장되지 않고 구현·사람 플레이 결과를 선행 주장하지 않는가.
- [ ] X05: open은 현재 완료/미래 착수 차단을 구분하며, 실험 전 확정할 수용 기준과 사용자 판단 항목이 드러나는가.
- [ ] X06: 다음 작성자가 이 문서만으로 범위와 자료를 찾아 검토를 시작하고 요구별 PASS/FAIL/OPEN을 기록할 수 있는가.

검토자는 발견 사항마다 요구 ID, 심각도, 원문 근거, 반례, 수정 또는 결정 필요사항을 낸다. 판정은 수용/조건부 수용/반려이며 조건부 수용은 미해결 조건과 진행 가능한 범위를 명시한다. 독립 검토 후 사용자에게 판정과 남은 선택을 제시한다. 에이전트 간 수용만으로 사용자 판단을 대체하지 않는다.

5-b 반려 시 **2단계로 복귀하여 기준·범위·근거를 수정**한 뒤 새 검토를 받는다. 표현만 다듬어 통과시키지 않는다. K를 소진하거나 해결 불가한 충돌이 있으면 중단·보고하며 자동으로 범위를 늘리지 않는다.

## 7. 완료 정의와 체크포인트

이번 **2단계 체크포인트**는 요구 ID별 채점표·근거·검증 방법·open 차단 범위가 작성되고 자체검사 결과를 독립 검토자에게 인계한 상태다. 이는 전체 설계 검토 완료도 3단계/구현 착수 승인도 아니다.

후속 **설계 검토 전체 완료**에는 R01~R18 판정 근거, 독립 5-b 결과와 사용자 판단, open의 처리/보류 범위, 의존성 있는 후속 조각과 성공 판정이 필요하다. 코드 실행·플레이 측정이 필요한 가설은 검증 계획과 미확정 상태를 명시해 남긴다.

되먹임은 이 파일의 변경/판정 기록을 먼저 남기고, 후속 단계 승인 시 S2·S3 등 0번 맥락 자산에 승인된 기준·반려 이유·남은 가정을 반영하는 작업으로 분해한다. 이번 단계에서는 다른 파일을 수정하지 않는다.
