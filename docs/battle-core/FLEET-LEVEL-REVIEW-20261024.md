# 편성된 함대의 레벨 시스템 도입 검토

작성: 2026-10-24. 추가 검토: 2026-10-25. 상태: **검토 제안, 미확정·미구현**. 아래 수치는 밸런스 검증 전 후보값이다. §6은 초기안의 제한과 우선 적용할 수정 권고다.

## 1. 판단

도입 가치는 있다. 한번 편성한 함대에 전투 이력과 숙련이 남으면, 플레이어가 함대를 보존하고 후퇴·보급·재편성을 고민할 이유가 생긴다. 제독 개인의 능력과 구별되는 **함대 조직의 숙련도**로 정의하는 편이 적합하다.

다만 현재 적벽은 독립 전투이며 캠페인 영속 상태가 없다. 전투를 반복할수록 기본 난이도가 쉬워지는 계정 누적 성장까지 바로 넣으면 기존 재플레이·밸런스 구조가 바뀐다. 우선 영속 함대의 규칙을 설계하고, 현재 적벽에서는 고정 숙련도 비교 실험으로 효과부터 검증하는 것을 권고한다. 새 캠페인이나 다른 시나리오 구현은 이번 검토 범위가 아니다.

## 2. 현재 구조와의 관계

- `core/battle/fleet_state.gd`: POC용 `lv`, `xp`가 남아 있다. 별도 `level`은 지휘관 레벨이므로 함대 숙련도로 재사용하면 안 된다.
- `core/battle/battle_sim.gd`의 `apply_dmg`: POC는 가한 피해를 경험치로 환산해 전투 중 레벨을 올린다. 정식 사격은 별도 `SalvoCombat` 경로를 사용한다. 기존 필드가 있다는 이유만으로 정식 함대 성장이 이미 연결돼 있다고 볼 수 없다.
- `docs/battle-core/PROPOSAL-realtime-battle-core.md` §7.1: POC의 레벨당 화력 +7%를 삭제하고 장수 성장을 캠페인에 맡긴다고 명시한다. 함대 숙련도는 이 설계와 별도로 검토·결정해야 한다.
- `core/battle/organization.gd`: 장수·함종·척수·특기 슬롯을 편성하고 전투 프로필에 반영한다. 현재 편성 계약에는 영속 함대의 숙련 이력이 없다.
- `scripts/world/battle_outcome.gd`, `docs/battle-core/WORLD-MAP-LINK.md`: 결과를 지도·후일담에 전달하며 캠페인 상태로 저장하지 않는다. 전투 간 성장에는 별도 저장·결산 계약이 필요하다.

## 3. 권고 규칙

### 성장의 귀속

함대에 영속 ID를 부여하고 경험을 귀속한다. 이름·화면 순번·제독 ID는 식별자로 쓰지 않는다. 제독을 교체해도 같은 조직이면 숙련을 유지한다. 장수 능력, 장수 특기, 함선 성능, 함대 숙련은 각각 다른 역할을 갖는다.

### 레벨과 효과

초기 후보는 5단계다. 전투 중에는 출전 당시 레벨을 고정하고, 종료 후 결산에서 경험을 반영한다.

| 레벨 | 표시 | 진형 전환 시간 | 일반 피격에 따른 사기 감소 |
|---|---|---:|---:|
| 1 | 신설 | 기준값 | 기준값 |
| 2 | 적응 | −2% | −1% |
| 3 | 숙련 | −4% | −2% |
| 4 | 정예 | −6% | −3% |
| 5 | 역전 | −8% | −4% |

화력·사거리·함선 수·특기 슬롯·제독 통솔에는 보너스를 주지 않는 초기안을 권고한다. 사기 감소 보정은 일반 피격에만 적용하고, 기함 상실·지휘관 사고·화공·결정 카드 등 사건의 고정 사기 변화는 그대로 둔다. 이 구분은 승패와 화공의 의미를 보존하기 위해 필요하다.

기존 진형 전환 시간 결정 및 장수 특기와의 중첩은 별도 확인 대상이다. 정수 bp로 보정을 합성하고 최종 하한을 정해야 한다. 위 수치가 실제 플레이에서 체감되는지는 아직 확인하지 않았다.

### 경험 획득

- 전투 종료 시 실제 기여에 따라 지급한다. 격침 막타에 집중시키지 않는다.
- 공격은 유효 선체 피해, 지원은 아군의 실제 부족분을 채운 보급·수리를 기준으로 삼는다. 공격과 지원은 각 역할의 기준량으로 정규화하고 함대별 전투당 상한을 둔다.
- 안전한 대기 시간·단순 출전·반복 클릭에는 경험을 주지 않는다. 피해를 일부러 받고 복구하는 반복으로 상한을 넘길 수 없게 한다.
- 패배했어도 생환한 함대는 기여 경험을 받는다. 승리 보너스는 작게 두어 승리 측 성장의 가속을 억제한다.
- 전투당 최대 100 XP, 누적 레벨 경계 0/100/300/600/1000 XP를 실험 시작값으로 둘 수 있다. 이는 성장 속도 확정안이 아니다.

### 보충·재편성·상실

| 상황 | 권고 처리 |
|---|---|
| 이름 변경·제독 교체·대기·출전 해제 | 같은 함대 ID와 숙련 유지 |
| 기존 함선 수리 | 숙련 유지 |
| 신병·신조함 보충 | 보충 비용 비중만큼 평균 숙련 경험 희석 |
| 함종 교체 | 일반 조직 숙련은 유지하되, 대량 신규 인원 유입은 보충 규칙 적용 |
| 분할·합병 | 1차 구현에서는 제외. 지원한다면 경험을 비용 가중 평균으로 이전하며 복제 금지 |
| 해산 | 함대 ID 종료. 같은 이름으로 다시 만들어도 신설 함대 |
| 전멸 | 경험 승계 없음. 전적만 보관 |

함대 XP를 **평균 숙련 경험**으로 정의하고 보충 시 `새 XP = floor(기존 XP × 잔존 전력 비용 / 보충 후 전력 비용)`로 계산하는 안이다. 예를 들어 600 XP 함대가 전력 비용 절반을 잃고 신병으로 원상 복구하면 300 XP가 된다. 레벨 하락은 전투 후 보충 확정 시 한 번만 반영하고 UI에서 미리 알려 준다. 비용은 함종별 기존 편성 비용을 사용하며, 손상·비활성 상태를 신규 인원 손실로 오인하지 않아야 한다.

이 방식은 개별 함선·승조원 이력이 없는 현재 구조에 맞춘 근사다. 함선 이동을 지원하게 되면 이동한 전력에 경험을 동반시켜야 하며, 새 ID 생성만으로 숙련이 복제되는 경로를 막아야 한다.

## 4. UI와 구현 범위

- 편성 화면: 함대명 옆 `숙련 Lv.3`, 효과 요약, 다음 단계 경험 표시. 제독 레벨·통솔 등급과 명칭을 구분한다.
- 재편성 확인: 보충 전후 숙련과 레벨 변화 예고. 자동 편성이 기존 함대를 새 조직으로 재생성하지 않게 한다.
- 전투 HUD: 선택한 아군 함대 상세에 숙련 효과 표시. 적 숙련 정보는 기존 탐지 공개 정책을 따른다.
- 결과 화면: 함대별 공격/지원 기여, 획득 XP, 승급 표시. 전투 중 승급 알림은 없다.
- 데이터: 영속 함대 ID, 경험, 규칙 버전, 전적을 저장한다. 레벨은 경험과 규칙에서 계산한다.
- 재생: 초기 함대 경험과 규칙 버전을 입력에 포함한다. 재생·불러오기·자동 해결 재시도로 결산이 중복 지급되지 않도록 완료 식별자를 저장한다.

## 5. 검증 후 도입 순서

1. 현행 무보정 기준과 전 함대 Lv.1/3/5 고정 실험을 같은 편성·시드로 비교한다. 아군만 고레벨인 조건과 적만 고레벨인 조건도 포함한다. 먼저 실제 체감과 난이도 이동 폭을 확인한다.
2. 승률·전투 시간·사기 이탈률·화공 성공률을 비교한다. 표준 난이도 승률 변화 ±5%p 이내를 초기 검토 경계로 제안하되, 현재 확정 밸런스 목표를 대체하지 않는다.
3. 효과를 수용할 수 있을 때 영속 ID·저장·결산·보충 희석을 구현한다. 직렬화 왕복, 동일 입력 결정론, 중복 결산, 제독 교체, 해산·재창설, 보충 경계가 필수 검증 항목이다.
4. 기존 적벽 독립 전투는 동일 초기 숙련에서 시작한다. 전투 간 누적 성장을 실제 제공하려면 별도 연속 운용 모드의 범위와 초기화 정책을 먼저 결정한다.

**최종 권고:** 함대 보존과 조직 정체성을 강화하는 낮은 폭의 숙련도 시스템을 채택 후보로 삼는다. 현재 적벽에 반복 플레이 누적 레벨을 곧바로 적용하는 것은 보류하고, 고정 레벨 비교 실험을 첫 단계로 둔다.

## 6. 추가 검토 (2026-10-25)

### 6.1 현재 제품에서 성장 보상을 받을 시점

현재 독립 전투에서 레벨을 종료 후에만 올리면 그 레벨로 다시 싸울 기회가 없다. 따라서 고정 레벨 실험은 전투 보정의 검증이지 성장 시스템의 완성이 아니다. 사용자에게 성장 기능을 제공하려면 다음 중 어느 경험을 제공할지 결정해야 한다.

- 독립 전투 안에서 성장: 전투 중 습득·승급을 허용하고 다음 판은 초기화한다. 효과를 바로 체감하지만 초반 우세가 후반 성장을 가속하는 위험이 있다. 기존 종료 후 반영안과 다른 대안이다.
- 같은 적벽을 같은 함대로 재도전하는 별도 운용 기록: 전투 간 경험을 유지한다. 추가 시나리오는 필요 없지만 재도전·복원·난이도 변경 시의 규칙이 필요하며, 기존 동일 조건의 독립 전투와 구별해야 한다.

두 방식을 자동으로 확정하지 않는다. 현 단계 권고는 고정 레벨 실험까지이며, 영속 저장 구현은 이 선택 뒤에 둔다. UI의 '함대 편성 저장'과 실제 병력·손실을 유지하는 '함대 운용 기록'은 별도 개념이다.

### 6.2 보충 희석은 유효하지만 손실 뒤 재기의 부담을 키운다

패배하면 함선과 경험을 동시에 잃어 다음 승리가 더 어려워진다. 600→300 XP 예시는 계산 예일 뿐 적절한 벌점이라는 근거가 아니다. 영속 성장 방식과 XP 계약을 정한 뒤 첫 보충 실험에서 희석 없음/비례 희석 두 조건을 비교하고, 재기 가능성과 함대 애착을 함께 평가한다. 현재 고정 레벨 효과 실험에는 보충 실험을 포함하지 않는다. 영구 경험과 일시 결속도를 추가로 분리하는 안은 상태·UI가 늘어나므로 첫 단계에서는 제외한다.

함종 비용은 승조원 수나 조직 지식을 뜻하지 않는다. 값비싼 함종으로 교체할 때 더 크게 숙련이 희석되는 것도 근사 모델의 한계다. 보충 방식 채택 전에 이를 수용할지 결정해야 한다.

미래 보충 결산 순서는 **회수 가능한 잔존 전력 확정 → 생환 함대 기여 XP 부여 → 보충 희석 → 레벨 산출**로 제안한다. 현재 전투의 `dead`·`lost_ships`만 보고 경험을 지우면 안 된다. `escaped`는 생환이고 `surrender`는 전멸과 다르며, 대파는 격침과 다르다. 대파 회수·항복 후 조직 처리 정책은 현재 전투 결과만으로 확정할 수 없어 영속 기능의 선행 결정으로 둔다.

특히 `victory.gd` 결산의 `captured_in_retreat`는 `out==""`이어도 패배측 퇴각 실패로 포로가 된 함대의 ID를 담는다. `fleets[].out`·`ships_left`만으로 생환을 판정하지 않는다. 이 목록까지 반영하여 함대별 생환/포로/상실 및 회수 가능 전력을 먼저 정규화하고 나서 XP 지급 대상을 판정해야 한다.

§3 희석 식은 기존 숙련 전력과 XP 0 신규 전력의 혼합에만 적용한다. 기존 함대 간 이동은 `혼합 XP = floor(각 전력 비용 × 각 XP의 합 / 총 전력 비용)`로 정의해야 한다. 내부 계산에는 경험 총량과 나눗셈 잔여를 보존하여 분할·재합병·반복 확정의 반올림 손실을 막는다. 자동 편성 미리보기·취소는 확정된 경험을 변경하지 않는다.

### 6.3 경험 지급 규칙은 아직 구현 가능한 수준이 아니다

전투당 100 XP 상한은 무한 축적을 제한할 뿐, 고의 소모·복구로 상한까지 올리는 문제를 해결하지 않는다. 지원과 공격 점수를 그대로 합산하면 공격과 지원이 가능한 혼합 함대가 유리할 수도 있다.

초기 검증은 보정 효과만 대상으로 하고 XP 지급을 연결하지 않는다. 성장 실험을 시작할 때는 다음 계약을 먼저 정의한다.

- 공격: 실제 적용된 적 선체 피해를 사용한다. 초과 피해·아군 피해를 제외하고, 같은 피해를 화공·강습·무장 피해로 중복 계상하지 않는다. 격침·연쇄 폭발의 기여 귀속을 따로 정한다.
- 지원: 공급한 함대에만 실제 전달량을 귀속한다. 기지 보급·자연 회복·자기 보급은 함대 지원 XP에서 제외한다. 수리와 함께 완료된 보급을 어떤 단위로 평가할지 명시한다.
- 소모 후 보충 반복: 경험 지급용 지원 예산을 수혜 함대별로 제한하고 동일 부족분에 한 번만 지급한다. 예산 산식·교전 필요 조건은 성장 실험 전에 확정한다. 적 공격을 의도적으로 유도한 손실까지 자동 판별할 수 있다고 가정하지 않는다.
- 함대 규모·역할: 출전 시 편성에서 고정한 기준량으로 정규화한다. 전투 종료 때 남은 함선 수로 나누면 피해를 크게 입은 함대가 유리해질 수 있다. 혼합 역할에는 공격·지원별 예산과 총상한을 적용한다.

### 6.4 전투 수식에 적용할 정확한 경계

`core/battle/morale.gd`에서 일반 피격은 `hit()`이고, `lose()`는 피격·함선 이탈 등 여러 원인이 공유한다. 숙련 보정은 `hit()`의 기존 거리·방향·연환·보급함 보정을 계산한 뒤, `lose()`를 호출하기 전에 한 번 적용하는 후보로 한정한다. `lose()` 전체에 적용하면 §3에서 제외한 사건까지 영향을 받을 수 있다. 기존 결집·특기 배율과 정수 절삭 순서를 고정해야 한다.

진형 전환 단축은 전환을 시작할 때 필요한 틱 수를 한 번 계산한다. 진행 중 레벨이나 다른 상태 변화로 남은 시간을 반복 재계산하지 않는다. 제안한 최대 8% 단축이 실제 틱으로 환산해 체감 가능한지 확인한다. 고정된 전환 시간에 대한 기존 결정을 변경하는 사안이므로, 제안서를 추가했다고 기존 규칙이 변경된 것으로 취급하지 않는다.

`salvo.gd`의 `formation_mul()`은 전환 중 화력을 낮추고, `assault.gd`의 `is_open()`은 전환 중인 적을 강습에 열린 상태로 판단한다. 따라서 전환 단축은 간접적인 화력·생존 보너스다. §3의 '화력 보너스 없음'은 직접 피해 계수를 추가하지 않는다는 뜻이며, 실제 전투력 영향이 없다는 뜻이 아니다. 전환 취약 구간을 노린 강습 입력도 검증에 포함한다. 기존 `transition_mul_bp=0` 즉시 전환은 그대로 보존하고, 임의의 최소 시간으로 기존 특기를 약화시키지 않는다.

### 6.5 검증과 상태 저장의 보완

- ±5%p는 허용 범위를 확정한 값이 아니다. 같은 시드의 승패 차이를 쌍으로 비교하고 표본 수·불확실성·난이도별 결과를 함께 보고한다. 결과가 경계에 걸리면 표본을 늘린다.
- 진형을 바꾸지 않는 AI끼리 싸우면 전환 단축 효과를 측정할 수 없다. 동일한 시점에 진형을 바꾸는 재현 입력을 별도로 사용하고, 사람이 조작할 때의 체감도 확인한다.
- 사기 상태 임계점 때문에 작은 감소 보정도 퇴각·항복 시점을 크게 바꿀 수 있다. 평균 승률 외에 첫 강제 퇴각 시점과 한쪽만 고레벨일 때의 불리함을 본다.
- §5의 레벨별 비교에 앞서 최대 후보 보정에서 기준/사기 감소 보정만/전환 단축만/두 보정 동시의 2×2 실험으로 원인과 상호작용을 구분한다. 수용할 효과를 고른 뒤 Lv.1/3/5별 차이를 비교한다. 일반 피격 사기 손실 누계, 실제 전환 틱·전환 중 사격 횟수, 강습 개방 시간·시도·성공을 함께 기록한다.
- 고정 레벨 실험도 재현 입력 계약이 필요하다. 별도 `proficiency_level`과 실험 조건 ID를 입력·재생 헤더·결과에 기록하고 아군·적군·증원 모두에 동일 정책을 적용한다. 기존 POC `lv`나 지휘관 `level`은 재사용하지 않는다. 현재 저장값 또는 화면 선택에서 암묵적으로 주입하지 않는다. 영속 성장 여부와 별개로 필요한 실험용 입력이다.
- 저장에는 규칙 버전뿐 아니라 함대 소유 세력, 출전 시작 상태, 영속 운용 기록 ID와 전투 ID를 포함한다. 재생은 기록된 시작값을 사용하고 현재 저장값을 다시 참조하지 않는다.
- 경험·전력 변경과 '결산 완료' 표시는 하나의 원자적 저장으로 반영한다. 완료 ID만 별도로 저장하면 중간 종료 후 누락·중복 지급이 발생할 수 있다. 자동 해결·관전·재생은 원래 전투 결산을 추가로 실행하지 않는다.

추가 검토 결론: 방향은 유지하되 **효과 실험 → 성장 방식 결정 → XP·보충 계약 확정 → 영속 구현** 순서로 좁힌다. 현재 문서는 구현 승인 사양이 아니다.
