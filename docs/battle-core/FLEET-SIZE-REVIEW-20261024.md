## 판단과 권고

1. 총량은 현 비용 목표에 적합하다. 적/연합 비용비는 1.470/1.590/2.139/2.139로 목표와 일치한다. 단, 비용비는 실제 승률이나 체감 난이도를 보장하지 않는다.
2. 일반 함대의 59~68척 규모는 아군 66~74척과 비슷해 개별 교전 단위로 무리가 없다. 당장 전군의 척 수를 일괄 증감할 근거는 없다.
3. 상급·극한 14번 함대는 22척, 비용 226으로 지휘 한도 600의 37.7%만 사용한다. 일반 함대와 같은 단위로 보이기에는 작다. 총비용을 유지하면서 후군 여러 함대에 감액을 분산하거나 14번을 소규모 지원대로 명시하는 편을 권한다. 전자는 편성 규칙 변경 및 재검증이 필요하다.
4. 모든 세력에 같은 MIX를 적용하여 대부분 전열4·포격2·요격2·보급1·강습모함1·전자전1의 유사 편성이 된다. 규모는 맞지만 선봉·고속대·후군의 역할 차이가 약하다. 전체 증감보다 역할별 함종 비율 조정이 우선이다.
5. 표준의 AI 출발 대기는 0초 132척, 180초 198척, 360초 301척이다. 시작부터 631척이 함께 진격하는 설정이 아니다. 가까운 적을 만나면 대기 중에도 교전할 수 있으므로 실제 접적 시점은 플레이로 확인해야 한다. 웨이브 간격은 총량과 별도 평가가 필요하다.
6. 유비군 208척, 손권군 203척으로 비용도 1972:2050에 그친다. 시나리오 설명의 손권:유비 3:2 방향과 현재 자동 편성 결과는 차이가 있다. 수동 지휘 비중을 의도한 결과인지 점검할 항목이다.
7. 표시 밀도는 낮음/보통/높음 35%/60%/85%다. 화면 선체를 직접 세어 실제 척 수로 해석하면 안 된다.

## 검증 범위와 근거

Organization.auto_fill의 장수 선발·MIX 탐욕 채움·정찰정 예약·마지막 함대 채움률을 Python으로 재현했다. 비용 합은 기존 Godot 실측 문서 REVIEW-P10b.md의 연합 4022, 적 5912/6395/8604/8604와 모두 일치한다. 합계와 함대별 지휘 한도도 검산했다. 이번 Godot 직접 실행은 프로젝트 경로 오류로 실행되지 않았으며 현재 빌드의 전투 승률·FPS는 새로 측정하지 않았다. 게임 소스는 수정하지 않았다.

소스: scripts/FleetBattle3D.gd, core/battle/organization.gd, core/battle/scenario_profile.gd, data/scenarios/red_cliffs_208_realtime.json, data/profiles/combat_m3.json, core/battle/ai/commander_ai.gd, view/fleet_render/fleet_renderer.gd, docs/battle-core/REVIEW-P10b.md.

모든 함대의 함종별 수량은 [편성 데이터](evidence/fleet-size-20261024/fleet-audit.json)에 포함한다.

## 실제 게임 반영

사용자 요청(2026-10-24)에 따라 마지막 적 함대에 몰린 감액을 출전 후군의 지휘 한도에 비례해 분산했다. `cao_last_fill_bp`는 총예산 산정값으로 유지하며, 누적 정수 배분으로 전체 예산을 보존한다. 아군 편성, 적 함대 수, 배치 위치, 투입 대기, 사기, AI 난이도는 유지한다. 함종 정수 채움 잔여 때문에 실제 소비 비용은 변경 전보다 1~4점 차이가 난다.

적 02번 선봉은 전열·강습모함, 03번 별군은 포격, 06번 고속대는 요격·강습모함, 07~14번 후군은 포격·보급 비중을 높인다. 역할은 자동 재배정되는 제독 이름 대신 전대 ID로 지정한다. 고속대의 이동 속도를 직접 올리는 변경은 아니다. 정책은 생성기의 `AUTO_ORGANIZATION`에서 관리하고 시나리오 JSON으로 생성한다.

### 검증

- `tests/fleet_size_review.gd`: 네 난이도의 편성 유효성·결정론, 총예산, 비용비, 후군 최소 규모, 역할별 함종 차이, 아군 편성 보존 통과. 새 정책을 제거했을 때 최초 집계의 함대별 척 수도 Godot 코어로 재현했다.
- `tests/roster.gd`, `tests/smoke.gd`, `tests/battle_flow.gd`: 통과.
- `tests/organization_rules.gd`: 편성·수리·승계·재생과 시드 3개 전투 종료 확인 통과. [검증 기록](evidence/fleet-size-20261024/validation.md).
- `tests/data_rules.gd`: 기존 `core/battle/battle_sim.gd:1019`의 `170.0` 규칙 리터럴 때문에 초기 정적 검사 실패. 동일 줄이 변경 전 HEAD에도 있어 이번 편성 수정의 회귀와 구분한다. 네 난이도 비용비는 새 전용 검사로 별도 확인했다.
- 로스터·씬 테스트에는 기존 trace 로그 접근 경고와 종료 시 ObjectDB/리소스 잔류 메시지가 있으며, 성공 마커와 종료 코드 0을 확인했다.
