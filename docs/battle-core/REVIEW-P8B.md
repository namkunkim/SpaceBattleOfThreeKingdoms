# REVIEW-P8B — 편성 화면 장수 특기 슬롯 교체 (5-b)

대상: `claude/exciting-perlman-9d57ef` 3a423eb (기준 main 42e42f1). 리뷰어는 코드를 고치지 않았다.
실행: `tests/boundary.gd`, `tests/organization_ui.gd`(헤드리스, 순차). 작업 트리 변경 없음.

## 판정
**조건부 수용.** 높음 없음. 결정 일치(슬롯 3, 직책 순 기본값, 유비군만 편집, Q92 중복 금지, 전투 중 교체 없음)와 결정론(기준선 지문 불변)은 확인됐다. 중간 2건(코어 단위 테스트 부재, 선택 목록이 열릴 때 함종 영역이 밀림)은 병합 전후 처리 권고.

## 확인한 것 (문제 없음)
- 결정론: `default_slots(fl,p) == refill_slots(fl,p,[])`. 새 함수는 빈 슬롯 배열로 시작해 후보를 같은 순서·같은 중복 건너뛰기로 채운다. 이전 구현(길이 < slots, 중복 skip, 남으면 "")과 결과가 같다. `default_org`·`auto_fill`·`load_auto`·`toggle`은 모두 `default_slots` 경로라 기준선 지문(O3b, 42e42f1 측정)에 영향 없음. 코어 변경은 `organization.gd` 한 함수뿐이고 apply/validate 쪽은 그대로다.
- AI 세력 편성 불변: `_put/_reslot/choose_skill`은 UI 전용이며 유비군 카드에서만 호출된다(`sel`은 `mine()`으로 제한). 재생 헤더는 `skill_slots`를 그대로 직렬화하는 기존 경로(special_skills.gd "재생 헤더 슬롯" 단언)이고 이번 변경으로 안 바뀐다.
- 경계 사례(코드 추적): 장수가 풀로 빠짐(빠진 장수 특기만 칸이 비고 후보로 재채움, 남은 장수가 같은 기술을 가지면 유지), 부제독 없음(`fl.vice==""`은 `_people`에서 제외), 특기 없는 장수(후보에서 건너뜀, 칸은 "" 유지), 출전 끄기(admiral/vice/staff 비운 뒤 default → 전부 ""), 맞바꿈(두 칸을 바꾼 뒤 각 함대 1회 재채움, 같은 함대 안 맞바꿈은 사람이 같아 불변), 제독 교체(기함 함대는 잠금), keep 안의 중복 손상값(두 번째를 비움). 모두 정상.
- boundary: 실패 3줄뿐 — `battle_source.gd:177`, `org_screen.gd:137-138`(줄 번호만 +6 이동, 허용된 기존 `ProfileLoader`·`ScenarioProfile` 두 줄). 새 core 직접 참조 없음(`Organization`은 기존 허용 클래스).
- `organization_ui` PASS(실행 확인). 캡처 2종 확인: 슬롯 3칸·카드 특기 한 줄·막힌 항목 사유 표시·48dp 이상 버튼.

## 발견

### F-1 (중간) `refill_slots` 단위 테스트가 없다
- `tests/` 어디에도 `refill_slots` 직접 단언이 없다(`grep` 0건). 결정론의 근거(`keep=[]`이면 `default_slots`와 동일)와 경계 사례(keep 안 중복, 길이 불일치, 빈 keep, 특기 없는 장수만 남음)가 UI 테스트 한 갈래에만 의존한다.
- 시나리오: 후속 PR이 `default_slots` 후보 순서를 바꾸면 `default_org`·AI 자동 편성이 조용히 바뀌어도 `refill_slots` 쪽 회귀는 잡히지 않는다.
- 권고: `tests/organization_rules.gd`에 3~4줄 추가(`refill_slots(fl,p,[]) == default_slots`, keep 일부 유지·빠진 장수 칸만 재채움, keep 중복 → 두 번째 비움, keep 길이가 짧아도 slots 길이 유지).

### F-2 (중간) 선택 목록이 열리면 함종 편성 영역이 아래로 밀린다
- `org_screen.gd:365-376`: 칸을 누르면 장수 최대 5줄(각 약 56단위)이 가운데 열 안에 삽입된다. 1920×1200 캡처에서 함종 줄이 이미 2줄만 보이고 나머지는 스크롤이다. 1600×900 같은 16:9 낮은 화면에서는 목록 열린 상태에서 함종 ± 버튼이 첫 화면 밖으로 밀린다(스크롤은 되므로 기능 결함은 아님).
- 권고: 로컬에서 1600×900으로 확인하고, 필요하면 장수 목록을 2열 그리드로 하거나 가운데 열 위쪽(특기 칸 바로 옆)에 고정 높이로 두기.

### F-3 (낮음) 테스트 단언 실효성
- `tests/organization_ui.gd` "officer out" 단언: `A and B or C`(우선순위상 `(A and B) or C`). `C = fleet_skills.has(gone_k)`가 참이면 슬롯 유지 여부와 무관하게 통과한다. 의도는 "고른 칸 0 유지 + 빠진 기술 제거"이므로 괄호를 명시하고 A·B를 독립 단언으로 분리하는 편이 낫다.
- 맞바꿈 단언은 제독↔부제독(같은 함대)만 있다. 서로 다른 두 함대 사이, 함대↔풀 맞바꿈에서 양쪽이 모두 재채움되는 경로(`press`의 `for f in [picked.fleet, i]`)가 테스트에 없다. 출전 끄기→슬롯 전부 ""와 부제독 없음 경계도 없다.
- 권고: 유비 본대↔관우 함대 부제독 맞바꿈 후 양쪽 슬롯이 `refill` 결과와 일치하는지 한 줄 추가.

### F-4 (낮음) 칸을 비울 방법이 없다
- 목록에 "비우기" 항목이 없고 `refill_slots`는 빈칸을 후보로 다시 채우므로, 사용자는 특기를 비워 쓸 수 없다. 결정문에 비우기 요구는 없어 결함은 아니다. 필요 시 §U에 사용자 결정 항목으로 올릴 것(아래).

### F-5 (낮음) 현재 칸의 선택 표시가 없다
- 목록에서 이미 그 칸에 있는 특기(예: 칸 1 격려의 "유비 — 격려")가 다른 항목과 같은 모양이다. 눌러도 무변화(`skill_block`이 같은 칸이면 통과해 `choose_skill`이 `skill_pick=-1`로 목록을 닫음). 현재 선택에 `PrimaryButton` 표시를 하면 이해하기 쉽다.

### F-6 (낮음) 형식·유지보수
- `org_screen.gd`가 `Organization._people`(밑줄 비공개)를 직접 부른다(`_fill_skills`). 공개 `people` 별칭이나 `fleet_officers` 접근자를 코어에 두는 편이 좋다.
- 카드 한 줄 `" · ".join(fl.skill_slots.map(skill_name))`는 빈칸을 "비어 있음"으로 찍는다. 출전 끈 함대 카드에 "장수 특기 비어 있음 · 비어 있음 · 비어 있음"이 나온다(투명도 0.55로 흐림). 빈칸이 모두 비면 줄을 생략하는 편이 깔끔.
- `tests/organization_ui.gd` 단언 중 `_label_text`가 개행을 문자열 리터럴 줄바꿈으로 넣는다(포맷 문제 없음).

## 사용자 결정 필요
1. 특기 칸을 **빈칸으로 비울 수 있게** 할지(현재는 불가, 후보 있으면 자동 재채움). 비움 상태를 쓰려면 `refill_slots`가 "사용자가 비운 칸"을 구분해야 해서 `skill_slots`에 표지가 필요하다.
2. 장수를 맞바꿀 때 **직접 고른 칸을 새 장수 특기로 덮어쓸지**(현재는 남은 장수 기준 유지, 빠진 칸만 기본값 — P8A-NOTES의 6866507 "매번 덮어씀"과 다른 동작이므로 의도 확인).
