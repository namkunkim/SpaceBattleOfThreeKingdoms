# PC 맵·캠페인 설계 검토 작업 분해

2026-10-25 / 워크플로우 **3단계 계획 초안·독립 계획검토 대기**.

기준: [워크플로우 플레이북](../../워크플로우-플레이북.md), [2단계 검토 스펙](PC-CAMPAIGN-REVIEW-SPEC-20261025.md). 스펙 마지막 기록의 독립 조건 재검토 수용과 사용자의 ‘다음 단계 진행해’를 이번 단계의 입력으로 삼는다. 스펙 머리말의 과거 ‘검토 대기’ 문구를 근거로 승인 상태를 되돌리거나 게임 구현 승인으로 확대하지 않는다.

## 1. 승인 경계와 이번 완료 정의

이번 승인 범위는 **설계 검토를 수행할 계획 문서 하나**다. 아래 D01~D10은 앞으로 승인받아 실행할 설계·조사·검토 조각이며 이번에 실행한 작업이 아니다. 워크플로우 4단계에서 이 조각을 실행하더라도 산출물은 설계 문서다. 게임 코드 구현, 테스트·1000시드·사람 플레이 실행, 브랜치 변경·병합, 커밋·푸시, 다른 사용자 채팅으로의 메시지 전송은 포함하지 않는다.

이번 완료 조건은 10개 조각의 책임·입력·출력·의존성·합격 조건·실패 반환처, R01~R18 커버리지, O01~O08의 책임과 차단 조건, 병렬 실행·파일 충돌 방지 규칙을 명시하고 독립 계획검토에 인계하는 것이다. 최종 설계 승인과 실제 구현 완료는 별도다. 기존 20분·A/B·좌표·시간·재고·편성 제안은 가설로 유지한다.

## 2. 모든 조각에 적용할 자족적 실행 계약

조율자는 아래 **공통 계약 전문 + 해당 D 카드 전문 + 스펙의 관련 R/O 전문 + 선행 산출물 전문**을 위임 프롬프트에 넣는다. 단순히 ‘앞 대화 참고’로 위임하지 않는다. S0~S7은 스펙 §2의 정확한 파일 경로를 뜻하며, 스펙 전체와 해당 원문 구간도 입력으로 제공한다. 누락되거나 서로 충돌한 입력은 가정으로 메우지 않고 차단 사항으로 반환한다.

> 역할: 지정 D의 설계 문서 실행자다. 사용자 의도는 함대 이동·조우·교전·점령 후 보급·시간 경과 증원이 있는 전략 작전 제안과 PC 맵 확장의 통합 검토다. 코드 구현을 수행하지 않는다. 지정 출력 파일 하나만 쓴다. 사실/가설/결정/open을 분리하고 모든 사실에는 원문 경로·구간·기준 시점이 있어야 한다. 관련 R의 합격 조건별 근거와 반례를 작성한다. 관련 O는 대안·장단점·추천 이유·사람 판단 시점·미해결 시 차단 범위를 기록하며 임의로 확정하지 않는다. 선행 문서의 정책을 변경하지 말고 충돌 ID로 보고한다. 출력은 범위, 근거, 상태/대안표, 반례, 관련 R/O 판정, 차단·인계 사항으로 제한한다. 결과를 바꾸는 미지수가 있으면 실행 중 새 질문을 만들지 말고 조율자에게 결정 패킷을 반환한다. 승인된 후보 범위에서 가능한 조사만 이어간다.

공통 운영 조건:

- **허용:** 원문·현재 코드·로컬 브랜치 차이의 읽기, 수치의 문서상 재계산, 지정 문서 작성. 코드 조회와 실행 결과를 구분한다. 외부 사례의 새 사실은 공식 원출처를 직접 확인하고 버전을 표시한다.
- **금지:** 코드·데이터·기존 정본 문서 수정, 테스트/게임 실행, 체크아웃·fetch·병합·커밋·푸시, 미승인 후보 확정, 다른 조각 파일 편집. 지정 파일 외 임시 산출물도 만들지 않는다.
- **출력 경로:** 아래 표의 `Dxx-….md`는 모두 `C:/WorkSpace/SpaceBattleOfThreeKingdoms/docs/battle-core/pc-campaign-design/` 아래를 뜻한다. 이 경로는 후속 문서 작업 때만 생성한다. 이번 산출물은 본 파일 하나다.
- **기계 5-a:** 관련 R/O ID 누락·중복 검사, 원문 경로/구간 존재, 단위·수치 대조, 미구현/미실행/후보 표시, 허용 파일 검사. 각 카드의 추가 검사도 수행한다. 문서 작업 재시도 **K=3**을 조각별 누적 기록하고 초과하면 멈춰 보고한다.
- **외부 5-b:** 해당 문서 작성·수정에 참여하지 않은 리뷰어가 원문과 반례를 대조한다. 리뷰어는 `REVIEW-Dxx.md`에만 쓰고 원문을 고치지 않는다. 독립 리뷰의 수용/조건부 수용은 사람 판단을 대체하지 않는다. 사람이 미확정 정책을 채택해야 해당 정책을 전제한 후속 설계를 확정할 수 있다.
- **성공:** 각 카드의 필수 항목과 근거가 있으며 관련 R의 문서 합격 조건을 만족하고 독립 검토가 수용한 상태. open이 남으면 진행 가능한 조사와 확정 불가 항목을 명시한 조건부 인계만 허용한다. open 방치나 미래 게임 검증 통과 주장은 실패다.
- **반려:** 5-a는 해당 D만 재시도(K=3). 5-b는 **2단계 스펙으로 복귀**하여 범위·기준·근거 문제를 재검토하고 영향을 받은 D를 재분해한다. 단순 수정으로 우회하지 않는다. 의도 자체의 불확실성은 1단계 사용자 판단으로 올린다. 선행 정책 변경 시 후손 문서를 무효 표시하고 재검토한다.

### D01 — 근거·현재 기반

**입력:** 공통 계약, 스펙 R01/R16/R17·O06, S1 §2, S2 §2, S3 지형/PC 항목, S4 Q67·Q82 최신 보충, S5~S7. 필요 코드·PC 로컬 작업 트리 diff는 읽기만 한다.

**구체 위임:** 현재 기준 커밋·로컬 PC 실험 기준·미커밋 변경의 소유 미확인 상태를 구분한다. 편성 변경 전 측정·3판 단일 정책·직접 플레이 미실시·재실행/재생/저장 차이·잔존 경고를 표로 만든다. 가져올 기능/미구현 기능/통합 위험 목록과 Q67 적용 범위 판정 패킷을 작성한다. 원문 없는 사실은 확인 불가로 둔다. 브랜치 통합 자체는 하지 않는다.

**5-a 추가:** 5개 실험 중앙값과 표본·시간 단위 대조; Q67 원문과 영향 항목의 존재 확인. **5-b/성공:** 실험을 최신 밸런스로 오인하지 않고 변경 범위별 Q67 판단 근거가 있다. **중단/반환:** 최신 기반을 읽을 수 없으면 O06 open으로 통합 가능성 판단을 중단하고 조율자에게 반환한다. 일반 대안 검토는 진행 가능하다.

### D02 — 작전 범위·레퍼런스 대안

**입력:** 공통 계약, R01/R02/R15·O02, S1 §3~6, S2 §1·5, S4 시나리오/캠페인 범위, S7의 출처·버전 한계.

**구체 위임:** 단일 연속 성계와 독립 전투 연결안의 장단점·상태 인계 비용·첫 샘플 범위를 비교한다. A/B·강하 보급로는 후보로 두고 제미나이 제안의 채택/수정/보류/제외 근거와 은영전 등 레퍼런스의 우리 게임 재해석을 정리한다. 새 사례를 늘리기보다 기존 8유형 중 첫 실험의 이유와 반대 사례를 작성한다.

**5-a 추가:** 사용자 요구 5요소(이동·조우/교전·점령·보급·증원) 누락 없음; 원작/게임 버전/독자 규칙 구분. **5-b/성공:** O02를 판단할 비교표가 있고 ‘권고’를 사용자 결정으로 쓰지 않는다. **중단/반환:** O02 미선택 시 이후 조각은 후보별 차이 분석까지만 허용하고 하나의 확정 규칙으로 합치지 않는다. 범위 채택은 아래 H0에서 사용자 판단을 받는다.

### D03 — 지도·시계·지형 계약

**입력:** 공통 계약, D01/D02 수용본, R03~R05/R17·O01/O03, S2 §4.1~4.3, S6 전체, S7 §4~5.

**구체 위임:** E/J/A/B/C/D/R의 유형·연결·역할을 구분한 추상 그래프, 진형 논리 외곽과 서비스/탈출 접근의 측정 계획, 효과 구역/본체/특수 병기 구역의 판정표를 작성한다. 게임 시계와 실제 시간 3종·배속 체류, 병행 활동과 조기 성공, 20분 후보 예산을 분리한다. 치수·속도는 측정 전 확정하지 않는다. Q67 적용 판정을 D01 근거와 제안 범위로 구체화한다.

**5-a 추가:** 예산 합계·시간 단위·노드 수/유형 대조; 두 T ID 체계 혼용 없음. **5-b/성공:** 통로·보급·퇴로가 막힐 반례와 검사 계획이 있고 단일 10분 교전을 전체 20분에 합산하지 않는다. **중단/반환:** O03 측정이 필요하면 해당 치수 확정을 중단한다. Q67이 적용되면 신규 지형 활성화 전 **차이 목록 B항 등재+1000시드 재측정**을 유지하고, 별도 작전이라 적용 범위 밖이라고 판단하면 근거·제외 이유를 기록한다. 자동 적용·면제는 금지한다.

### D04 — 조기 상태 계약

**입력:** 공통 계약, D01/D02 수용본, R13/R14·O07, S1 §2·6, S2 §4.6, S5 재실행/재생 기록.

**구체 위임:** 함대 손실·탄약·사기, 거점 소유/진행/재고, 임무·접촉, 예약 사건·결산 ID의 소유자·수명·직렬화 필요 여부를 후보 상태표로 만든다. 연속 상태 유지/저장 왕복/재실행/명령 재생/결산 1회성의 입력·비교 대상·다른 실패를 정의한다. 아직 정해지지 않은 D06~D08 필드는 확장 자리와 확정 책임만 두고 값을 지어내지 않는다. 버전 호환 대안을 낸다.

**5-a 추가:** 5검증 종류 구분 및 각 데이터 소유자 존재. **5-b/성공:** 이후 기능 설계자가 읽을 초기 계약이 있고 저장을 마지막에 미루지 않는다. **중단/반환:** O07 미결이면 스키마·호환의 확정을 중단한다. 후속 카드가 필요한 필드를 반환하면 D10에서 충돌을 식별하고 D04 후속 수정 승인을 요청한다. 다른 작성자가 이 파일을 고치지 않는다.

### D05 — 적 임무·정보

**입력:** 공통 계약, D03/D04 수용본, R06/R07, S1 §6.6, S2 §4.5, S6 탐지·AI 규칙.

**구체 위임:** 순찰/수비/호송/구원/재점령마다 목표·유지/추격 한계·미접촉 일정·보고·재계획의 상태표를 만든다. 확인/추정/상실, 공유 탐지와 사격선 분리, 알려진 정보만 쓰는 임무 판단을 정의한다. 미끼·양쪽 분견대·접촉 상실·차폐 뒤 표적을 문서상 반례로 점검한다. 사거리 등 새 수치를 정하지 않는다.

## 4. 의존성·병렬 실행·사람 판단

의존성의 ‘수용본’은 독립 리뷰와 사람 판단의 범위가 기록된 버전이다. 조건부 수용본으로 수행하는 후속 조각은 승인된 공통 부분의 조사 또는 대안 분기만 가능하다. 미선택 후보를 확정 정책처럼 쓰지 않는다.

정상 실행 파이프라인(조율자 제외 최대 **3개 슬롯**, 리뷰어도 슬롯 사용):

1. D01 ∥ D02. 각 완료 뒤 작성에 참여하지 않은 리뷰어에게 인계하고 H0를 거친다.
2. D03 ∥ D04. 리뷰 중인 조각과 그 후손은 동시에 수정하지 않는다.
3. D05 ∥ D06. 완료 뒤 D07 → D08을 수행한다. D08은 보급·재점령·호송의 자원 계약까지 필요하므로 D05/D06/D07 수용 전 시작하지 않는다.
4. D09 → D10 → 최종 독립 검토 → H2. 검토·수정 대기 시 빈 슬롯을 채우려고 의존성 게이트를 건너뛰지 않는다.

리뷰는 결과별로 순차 슬롯을 배정한다. 두 실행자+독립 리뷰어 또는 실행자 한 명+리뷰어 한 명까지만 운영해 총3을 넘지 않는다. 리뷰어가 다른 조각을 쓴 적 있으면 자기 문서와 그 문서를 실질적으로 통합 작성한 문서를 최종 판정하지 못한다. 최종 D10 리뷰어는 D01~D10 어떤 작성에도 참여하지 않은 새 역할로 배정한다.

논리 임계 경로는 기간 추정 없이 **D01/D02 → D03/D04 → D06 → D07 → D08 → D09 → D10**이다. D03·D04와 D05·D06의 늦게 수용된 쪽이 다음 합류를 제한한다. D08은 D07의 재고 계약도 기다린다. 리뷰/사람 판단 대기 역시 경로의 게이트다.

| 사람 판단 | 시점·패킷 | 미결이면 허용/중단 |
|---|---|---|
| H0 범위 | D01/D02 검토 후: O02 단일/다중·첫 샘플, O06 기반 제약 | 범위별 조사 가능. 하나의 선택을 전제한 확정 설계는 중단 |
| H1 정책 | D03/D04 후 O01/O03/O07, D06~D08 후 O04/O05를 묶어 대안·근거·권고·차단 항목 제시 | 계약·대안 문서 작성은 가능. 치수·회복·종료·사건·저장 구현 스펙 확정은 해당 미결별 중단. 측정 필요는 후속 실험 승인으로 분리 |
| H2 통합 | D09/D10 외부 검토 후 O08 측정 기준·나머지 open·최종 권고 판단 | open이 영향 없는 검토 결과만 조건부 수용 가능. 게임 코드 구현/테스트 실행은 별도 승인 전 시작하지 않음 |

파일 충돌 방지: D01~D10 실행자는 자기 출력만, 리뷰어는 자기 `REVIEW-Dxx.md`만 단독 소유한다. 공통 스펙·S1/S2/S3/S4는 읽기 전용이다. 수정 필요는 ID·이유·영향 후손 목록으로 반환하고 소유 실행자에게 순차 재배정한다. D04 계약과 D06 목표/사기, D08 사건 사이의 정책 충돌을 상대 파일 직접 수정으로 해소하지 않는다. 조율자는 파일 편집을 대신하지 않는다.
