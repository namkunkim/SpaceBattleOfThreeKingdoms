# REVIEW-P8C — 전투 화면 장수 특기 UI (5-b 리뷰)

대상: `claude/awesome-mendeleev-61e825` 00893aa (기준 main 42e42f1). 리뷰어 Sonnet(구현 Opus). 코드는 고치지 않았다. 실행한 것은 `tests/boundary.gd` 하나뿐(기존 3줄만 실패, 새 위반 없음). 나머지 테스트 결과는 구현 측 `out/p8c-tests.txt`를 그대로 신뢰했다. 스크린샷 2장(skills, select)은 읽었다.

## 판정: 조건부 수용

정보 경계·결정론은 깨끗하다. 막을 것은 F-1(실패한 특기 누름이 위임을 해제), F-2(1회용 비가역 발동이 탭 한 번)다. 둘 다 코드 몇 줄이거나 사용자 결정 하나로 닫힌다.

## 검증한 것(문제 없음)

- 투영 경계: `battle_projection.gd:32` `if sim.skills and f.side == side`에서만 `skills`를 붙인다. 추가 키(kind·type·text·active_s)도 같은 `view()` 안이라 적 접촉에는 안 나간다. `tests/special_skills.gd:154`가 적 진영 투영에 skills 없음을 이미 검증한다.
- 사건: 적 `skill`·`skill_end`는 `drain_events_for`가 시전 진영 기준으로 버린다(`battle_sim.gd:423`). 안개가 없으면(`detect==null`) 걸러지지 않지만, UI가 `f.side == 0`으로 한 번 더 막고 `vm.fleet(e.sq)`가 숨은 적에게 null이다. 토스트의 "→ 대상 함대"는 `_confirmed` 대상만이라 새는 정보 없음. `SFX_OF`에 skill이 없어 소리도 안 샌다.
- Q97: foe 효과는 `src` 없이 이름·남은 초만. `received()`가 `foe or src != self`로 거른다.
- 결정론: `view`/`_active_s`는 읽기 전용(RNG·상태 변경 없음), 지문은 `fingerprint()` 경로 그대로. `do_skill`은 일반 `skill` 명령으로 `command_log`에 남아 재생이 된다.
- 문구: REJECT에 `block()`이 내는 코드(skill_used·no_slot·commander_down·requires_* 7키)와 `use`의 skill_no_target, assault_blocked·chain_* 가 있다. 테스트 4가 데이터의 requires 키 전부를 순회한다.
- 성능: 갱신은 `_process`의 0.1초 틱 안(`command_deck.gd:324`)과 `skill` 사건 때만. `view()`는 아군 함대×슬롯 3 + fx 순회라 가볍다.
- boundary: `skill_bar.gd`는 core 클래스를 참조하지 않는다.

## 발견

### F-1 [중간] 거부된 특기 누름도 위임을 직접 지휘로 바꾼다
- `core/battle/battle_sim.gd:154-159` `_mark_direct`는 `apply` 전에 `control = "direct"`로 바꾼다. `skill`이 DIRECT_KINDS에 있어서, 막힌 버튼(③)을 눌러 코어가 거부해도 위임이 풀린다.
- 시나리오: 위임 함대의 "사용함"/"조건 미충족" 버튼을 오조작으로 누르면 토스트는 "이미 썼습니다"인데 조용히 직접 지휘가 된다. 툴팁 문구는 "발동하면"이라 실제 동작과 다르다.
- 권고: 둘 중 하나. (a) UI에서 `block != ""` 또는 `uses_left == 0`이면 위임 함대에는 명령을 안 보내고 토스트만(코어 무변경, 가장 작음). (b) `_mark_direct`를 skill일 때 사용 성공 뒤로 미룸(코어 변경이라 지문·재생 영향 확인 필요). (a)를 권한다. 정책은 사용자 결정 D-2.

### F-2 [중간] 1회용 비가역 발동이 탭 한 번으로 실행된다
- `skill_bar.gd:70` `pressed` → 즉시 `do_skill`. (함대,기술)당 1회라 오탭 한 번이 그 전투의 그 기술을 소진시킨다. 대상도 고르지 않는다(②).
- EXPERIENCE-DESIGN §6 U3(되돌릴 수 없거나 비용이 큰 명령은 길게 눌러 확정)와 어긋난다. 터치(태블릿)에서 버튼이 6px 간격으로 붙어 있어 위험이 크다.
- 권고: 슬롯 버튼도 길게 눌러 확정(기존 `confirm` 명령 버튼 방식 재사용), 짧게 누르면 툴팁·사유만. 사용자 결정 D-1.

### F-3 [낮음] 대상 지정 없음(②)의 부작용 표시
- 교란은 가장 가까운 확인 적, 일신시담은 선체 비율 최저 아군으로 고정된다. 버튼 상태 문구는 "준비 · 적 함대"뿐이라 누르기 전에 누가 대상인지 안 보인다. 발동 알림에 대상 이름이 나오지만 이미 소진된 뒤다.
- 권고: 최소한 툴팁에 "대상: 가장 가까운 확인 적" 같은 `target_pick` 설명(데이터 text에 이미 있으면 그걸 노출). 지정 UI는 P8c 이후로 미뤄도 된다(1차 결정 D-3).

### F-4 [낮음] `block()`에 대상 유무가 없어 "준비"로 보이다가 거부
- `skill_no_target`은 `use()`에서만 나온다. enemy_fleet 기술이 requires 없이 반경 안 확인 적이 없을 때 "준비 · 적 함대"로 보이고, 눌러야 거부된다. 코어 `view`에 `target_ok`를 추가하는 방법이 있으나 지금은 ③ 판단(코어 거부를 토스트로)과 일관된다. 수용 가능.

### F-5 [낮음] 가독성·터치
- 버튼 132×56은 48dp 이상이다(touch_targets 통과). 다만 상태 문구·칩이 11px, 위임 안내가 10px라 태블릿에서 작다. 칩에 "받은 효과" 같은 머리글이 없어 "교란 33초"가 무엇인지 처음엔 모호하다(스크린샷 skills). 슬롯 버튼 사이 간격 6px은 오탭 가능성이 있다(F-2와 겹침).
- `SlotButton.custom_minimum_size`가 132×56으로 하드코딩이라 UI 배율을 바꾸면 따라가지 않는다. 낮음.

### F-6 [낮음] 테스트 실효성
- 좋은 점: 사유 문구를 데이터 requires 키 전체로 순회하고, 적 투영에 skills 키 없음을 확인하며, foe 칩에 src 없음을 단언한다.
- 빈 곳: (i) 위임 함대가 "거부"될 때의 동작(F-1)을 검증하지 않는다. 테스트 7은 성공 경로만. (ii) 안개 없는 규칙에서 적 `skill` 사건이 UI로 들어와도 토스트가 안 나는지 단언이 없다. (iii) 1600×900 같은 다른 해상도 레이아웃 단언이 없다(캡처는 1920×1200 하나).

### F-7 [참고] 레이아웃
- 정보 패널은 중앙 640폭 고정이고, 늘어난 64px는 `_info_h()`로 되돌리기·퀵 알림·보급 메뉴에 반영되어 있다(`command_deck.gd:224-226, 1133`). 펼침(L2) + 특기 줄 = 346px 높이, 1600×900에서도 하단 중앙에서 왼쪽 레이더·오른쪽 명령 패널(364px)과 가로로 겹치지 않는다. 세로로는 상단 작전 목표·토스트(top 130)와 겹치지 않는 계산이다. 다만 직접 확인한 것은 아니므로 아래 체크리스트에 넣었다. 결정 포착 카드 표시 중에는 `info.visible = false`라 특기 줄도 같이 숨는다(`command_deck.gd:155-156`) — 카드 중에는 특기를 못 쓴다는 뜻인데 의도인지 확인 필요(D-4).

## 사용자 결정 필요

- D-4: 결정 카드가 떠 있는 동안 특기 줄이 숨는 것이 의도인지(F-7).
