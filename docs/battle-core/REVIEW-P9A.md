## 2. 공개 경계

- **`detail()`이 적에게 빈 사전을 주는 근거:** `battle_source.gd:289`에서 `v.side != 0 or v.contact != ""`이면 `{}`를 돌려준다. 적은 side 1이고, 접촉은 contact가 비어 있지 않다. 그래서 `_info_detail`(:722)이 바로 반환한다. 지휘관·편성·속도·사거리·진형·탄약 줄은 적에게 그려지지 않는다. 다중 선택은 `battle.my_sel()`(아군만)을 쓴다.
- **사거리:** 투영 `ranges`는 아군에게만 들어간다(P2). 접촉 FleetView의 `ranges`는 빈 사전이다(테스트가 확인한다).
- **진형:** `form_name`은 접촉이면 `""`이다. 메타 줄은 적일 때 `"적 · 확인/추정/상실"`로 덮어쓴다(:658). 적 FleetView에는 `defense`·`charge_t`·`fire_t`·`is_flag`가 설정되지 않는다(`_apply_contact`가 쓰지 않는다). 그래서 상태 칩도 나오지 않는다.
- **척 수:** 적은 `contact_strength_text`만 나온다. 추정·상실이면 `band=0`이 되어 "전력 ?"가 나오고 막대는 비어 있다.
- **미탐지:** 투영에 없어 FleetView가 생기지 않는다. 사라진 접촉은 `dead`로 바뀌고, `_draw_info`가 `inspect.dead`를 걸러 낸다.
- **추정·상실 접촉의 이름·초상(제안서 :480):** 코어 투영(`battle_projection.gd:94-108`)은 추정·상실에 이름·역할·초상을 **보내지 않는다.** 화면 모델(`battle_view_model.gd:272-276`)은 마지막 확인 때의 `fname/role/portrait`를 지우지 않고 유지한다. 그래서 패널과 지도 이름표에 "문빙"(캡처로 확인)이 계속 보인다. :480의 "추정·상실 접촉은 마지막 본 위치, 오차 반경, 신뢰도뿐"을 **글자 그대로 읽으면 위반**이다. 다만 이 동작은 P9a 이전부터 있었고 P9a가 새로 만든 경로가 아니다. 또 플레이어가 이미 본 정보를 기억하는 것이라 게임 설계상 자연스럽다. → **사용자 결정 필요(F-6).** "마지막 확인 신원 유지"로 제안서를 고칠지, `_apply_contact`에서 비확인 전환 때 "미확인 함대"·기본 초상으로 되돌릴지 정한다. 구현자의 "요구 밖이라 그대로"는 이 PR 범위로는 수용한다.
- **새는 정보는 아니지만 오해를 부르는 것(F-4):** 적 펼침 패널에 `표시 편성  전열 · 화력 · 전자전`(:685)이 나온다. 적 접촉은 `counts`가 없다. 그래서 렌더러가 id 시드 난수(`fleet_renderer._assign_class`)로 정한 **가짜 함종**을 보여 준다. 진짜 편성이 새는 것은 아니다. 하지만 "함종 비공개"인데 함종처럼 읽힌다.

## 3. 정확성

- **현재 속도:** `tpos.distance_to(ppos) * vm.hz`. 실제 게임 루프(`FleetBattle3D._process`)는 한 프레임에 틱이 여러 개 돌면 마지막 틱 직전에 `_sync()`를 한다. 그래서 `ppos`는 항상 1틱 전 위치이고, 값은 배속(×1/×2/AUTO ×4/SKIP ×8)·선택 감속(×0.2)과 관계없이 **게임 초당 이동량**이다. 단위는 사거리와 같은 전장 단위라 "사거리 260, 속도 113/341"처럼 비교할 수 있다. 맞다.
  - 헤드리스 `update_sim(dt)`는 사이에 `_sync`를 하지 않아 n틱 이동량 × hz가 된다. 테스트에서만 생기는 일이라 게임 화면에는 영향이 없다.
  - 틱마다 흔들림: 선회 중(`cos` 감속), 도착 직전(lerp 정착), 평행 이동, 지형 감속, 지휘 혼선 때 값이 틱마다 바뀐다. 패널을 다시 그릴 때마다 숫자가 출렁일 수 있다(낮음, F-7).
- **F-2 일시정지 판정이 죽은 코드다:** `_cur_speed`(:638)는 `battle.G.get("hold", false)`를 본다. 그런데 `G`에는 `hold` 키가 없다(`FleetBattle3D.gd:165`, 쓰는 곳도 없다). 일시정지는 `G.state == "pause"`이고, 전투 종료 뒤에는 틱이 멈춘다. 이때 `ppos/tpos`가 굳어 **마지막 틱 속도가 계속 보인다**. 주석("일시정지 중에는 0")과 다르다. 수정: `src.state() != "play" or battle.sim.st.over`이면 0.
- **최대 속도 출처:** `d.speed = FleetState.speed` = `salvo._speed()` = 가장 느린 함종의 `speed_per_turn / turn_div × (1 + 진형 mobility_bp)`. 코어 이동(`battle_sim.gd:874`)이 쓰는 기준값과 같다. 다만 **돌격 중에는 `charge_speed_mul`이 곱해져 현재 속도가 "최대"를 넘는다**(F-5, 낮음). "기준" 같은 이름표나 돌격 중 최대값 보정을 권고한다.
- **다중 평균 사기:** `Σ morale_bp/100 ÷ n`, 반올림. 전대 단순 평균이라 척 수 가중이 아니다(설계 선택, 수용). 단일 패널은 `int(morale_bp)/100`(버림, :735)이라 같은 전대가 74%/75%로 다르게 보일 수 있다(낮음).
- **척 수 합:** `_info_multi`의 `tot/mx`는 기존 코드이고 맞다.
- **"전력 ?" 정정의 일관성(F-3):** 패널은 추정·상실에서 막대를 비운다. 그러나 `FleetView.ships`는 마지막 확인 구간 값으로 남는다. 그래서 지도 이름표 막대(`tactical_overlay.gd:254`, `:277` 원거리 기호)는 **여전히 마지막 전력 구간을 그린다.** 캡처 est에서 우상단 "문빙" 이름표 막대로 확인했다. 같은 접촉을 패널은 "모름", 지도는 "3/4"로 보여 준다. 수정: 판정을 한 곳에 둔다(예: `BattleSource.strength_frac(f)`. `max_band == 0`인 접촉이면 0). 패널과 오버레이가 모두 이 판정을 쓰게 한다.

## 4. 요구 충족도

요구는 "선택된 함대 정보(HP/CP 등과 같거나 함대 이동 속도 등)"다.

- **CP 제외는 맞다.** Q21이 CP를 폐지했다(미사일 = 탄약, 함재기 = 탑재 수, 광선 = 열). 선체(HP)·사기·탄약·에너지·열은 이미 표시된다.
- 이미 있던 것: 함대(그룹)·부지휘관·참모·능력치·손상 단계·진형(전환 남은 시간 포함).
- P9a가 더한 것: 지휘관, 속도 현재/최대, 범주별 사거리, 다중 평균 사기, 적 접촉 상태.
- **지휘관 줄은 중복이다(낮음):** 패널 제목이 이미 지휘관 이름(`f.fname`)이다. 그래서 `지휘관 관우`가 제목을 되풀이한다. 테스트 `d.commander == ally.fname`도 같은 값을 비교하는 동어반복이다.
- **빠진 것(F-8, 중간):** CHECKLIST §8 후보의 **특수기술**이 없다. 데이터에 있다: 시나리오 `commander/vice_commander/staff.traits`(예: 인덕·신기묘산·만인지적), 코어 `FleetState.traits`. 매력(charm) 능력치도 데이터에 있으나 빠졌다(쓰임이 없으면 생략해도 된다).
- **다중 선택에 이동 속도가 없다(낮음):** 그룹 이동은 가장 느린 전대 속도로 맞춘다(`battle_sim.gd:615-618`). 그래서 "그룹 속도 = min(speed)"가 다중 선택에서 가장 쓸모 있는 수치다. 지금 다중 L2는 초상 줄 아래가 비어 있다(캡처 multi).

## 5. 터치·레이아웃

이 세션이 p9a에 p12-followups를 미커밋으로 병합한 작업본에서 창 모드로 캡처했다. 1280×800과 1920×1080, 장면은 아군 단일 L2·다중·적 확인·적 추정이다. p12의 긴 탄약 이름("미사일(포격)·광선(전열)")까지 넣어 확인했다.

- 6줄이 모두 패널 안에 들어간다. "탄약 … 에너지 … 열 …" 줄이 가장 길지만 640px 안이다. 1280×800에서 패널은 대사 상자(좌)·명령 덱(우) 사이 틈에 들어가고 미니맵·명패 줄(우측 전대 스트립)을 가리지 않는다. 1920×1080도 같다.
- 상태 칩이 3줄로 감기면(칩 5개 이상) 마지막 줄이 282를 넘는다. salvo 규칙의 아군 칩은 많아야 4개라 지금은 일어나지 않는다.
- **적·다중 L2는 대부분 비어 있다(낮음).** 적은 "표시 편성" 한 줄뿐인데 282px 높이로 펼쳐져 전장을 가린다. 적이거나 `detail()`이 비면 L1 높이(또는 내용 높이)로 줄이기를 권고한다.
- 1920×1080 캡처에서 사거리 고리 이름표("미사일(포격) 260")가 패널 제목 줄 근처에 겹쳐 비친다. 패널 배경이 반투명이기 때문이다. 낮음, 로컬 확인 항목.
- 태블릿 실기(UI 배율·안전 영역)는 확인하지 못했다. 아래 체크리스트에 넣었다.

## 8. 사용자 로컬 확인 체크리스트

1. 아군 전대 하나 선택 → 패널 펼침 → 6줄(편성 / 능력·사기·선체 / 손상 / 탄약·에너지·열 / 속도·진형 / 사거리)이 패널 안에 다 보이는가.
2. 이동 명령 중 "속도 현재 / 최대"가 움직이고, 도착하면 0이 되는가. 숫자가 지나치게 출렁이지 않는가(F-7).
3. ESC 일시정지·결과 화면에서 속도가 0인가(F-2 수정 후).
4. 돌격 중 현재 속도가 최대를 넘는 것이 이상해 보이는가(F-5).
5. 사거리 줄 수치가 지도 고리 이름표 수치와 같은가.
6. 2개 이상 선택 → "평균 사기 N%"와 척 수 합이 보이는가.
7. 적 확인 접촉 점검 → "적 · 확인", "전력 n/4"만 보이고 세부 6줄·사거리 고리가 없는가.
8. 적이 탐지에서 벗어남(추정·상실) → 패널 "적 · 추정/상실"·"전력 ?"·빈 막대. **지도 이름표 막대도 비는가**(F-3, 지금은 안 빈다).
9. 추정·상실 적 이름·초상이 계속 보이는 것을 원하는가(F-6 결정).
10. 태블릿(안드로이드, 1920×1200급·UI 배율)에서 펼친 패널이 미니맵·대사 상자·명령 덱·전대 스트립을 가리지 않는가. 패널 탭(접기·펼치기)이 48dp로 잡히는가.
11. 1920×1080에서 지도 고리 이름표가 패널 위로 비쳐 읽기 방해가 되는가.
