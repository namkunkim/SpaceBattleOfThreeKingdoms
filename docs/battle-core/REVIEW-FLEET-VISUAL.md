## 2. 현재 구현 (코어인가 뷰인가)

- **함선 개체 위치는 전부 뷰가 만든다.** 코어/POC는 전대 단위 `pos`·`heading`·`ships`·`formation`만 준다(`BattleSource._sq`). 함선 위치는 `FleetRenderer._build_slots`가 `formation_points` + 난수 지터로 **한 번** 만들고, 전대 `Node3D`의 위치·회전에 **그대로 붙여** 움직인다.
- 함선 수는 `정원 × 표시 배율(0.35/0.6/0.85)`, 손실은 같은 배율로 줄어든다(C-1). 코어 `ships`로 `alive_n`만 맞춘다.
- 진형 투영 키(`formation_id`, `form_to`, `form_left_s`, `route`, `strafe`)는 렌더러가 아직 읽지 않는다.

## 4. 목표 동작 규칙 (결정)

모두 **뷰 전용**이다. 코어 입력은 지금 그대로(전대 `pos`·`heading`·`formation`·`ships`)이고, 새 투영 키는 필요 없다.

**G1 슬롯 추종.** 함선마다 `home`(진형 슬롯, 전대 로컬)과 `pos`(현재 월드 위치)를 둔다. 목표 `T = 전대 위치 + 회전(heading) × home (+ 흔들림)`. 갱신: `pos += (T - pos) × (1 - e^(-dt/τ))`. 프레임률에 무관하고 오버슈트가 없다.
- τ는 함선마다 0.25~0.95초(전대 id 시드). 앞줄을 더 빠르게 하고 싶으면 `rank`로 가중하되 첫 구현은 시드 값만 쓴다.
- 선회하면 바깥 슬롯의 `T`가 더 빨리 움직여 안쪽과 속도 차이가 생기고, 지연이 부채꼴 전개로 보인다(P2 해소). 별도 선회 코드는 두지 않는다.

**G2 방향.** 속도가 0.3 단위/초 이상이면 속도 방향, 아니면 전대 방향으로 yaw를 `1 - e^(-dt/0.35)`로 돌린다(P5). 전대 방향 모델 yaw는 `-heading - π`(현재 `node.rotation.y` 유도로 확인).

**G3 진형 전환.** `sq.formation`이 바뀌면 새 슬롯 집합을 만들어 앞줄 순서로 기존 함선에 다시 배정하고(함종 구성 유지) G1이 알아서 흘려 보낸다. 전환 시간은 코어 `form_left_s`(30초/60초/팔진 절반)를 **쓰지 않고** τ로 수렴시킨다. 슬롯이 멀리 떨어진 함선이 3~4초 안에 새 자리로 가는 정도면 충분하고, 코어 전환 중 피해 ×0.8(M5)과 화면의 시간 일치는 후속 PR에서 `form_left_s`로 τ를 늘리는 방식(전환 중 τ ×N)으로 맞춘다. 

**G4 흔들림.** 이동 중에만 목표에 반경 0.22 단위의 느린 사인 오차(위상은 함선별 시드)를 더한다. 정지하면 0으로 수렴한다.

**G5 갱신 예산(태블릿 Q57 기준).** 개체 갱신은 30Hz로 하고, 전대가 정지해 있고 모든 함선이 목표에 닿으면(오차² < 0.0004가 3회 연속) 갱신을 건너뛴다. 전투 장면에서 항상 움직이는 전대는 절반 이하일 것으로 보지만 **실기기 측정이 먼저**다(§8). 기준: 표시 함선 약 760척(높음 밀도 기준 상한), 태블릿에서 프레임 시간 증가 2ms 이내. 넘으면 (a) 갱신을 20Hz로, (b) 줌 아웃 LOD에서는 함선별 갱신을 끄고 전대 중심 점 하나로 그린다.

**G6 격침.** 사라질 함선은 피격이 집중된 전열(`rank` 작은 쪽)에서 우선 고르고, 뒤 함선이 G1로 빈자리를 메운다. 자리를 메우려면 G3와 같은 재배정이 필요하므로 별도 PR(PR3)로 둔다.

**G7 크기·밀도 정책.** 영상(R1)은 "작고 많음"을 택했다. 우리 모델은 줌 인에서 읽혀야 하므로(적벽 함선은 모델이 정체성) 크기를 줄이지 않는다. 대신 **밀도 기본값을 태블릿에서 정하는 것을 Q59로 사용자에게 묻는다**(§9).

**G9 윤곽 (P10).** 영상 확대(0:19)에서 함선은 **가늘고 긴 어두운 선체 + 한쪽 가장자리의 밝은 테두리 + 양 끝의 작은 하이라이트**다. 길이:폭 약 8:1. 몸체 면적이 아니라 **밝은 가장자리선**이 형태를 읽게 한다. 규칙:
- 외곽선 패스: 함종·세력별 재질에 `next_pass`로 뒤집힌 선체(`cull_mode = front`, `grow = true`, `grow_amount ≈ 0.03`, 무조명, 세력색 밝은 톤: 아군 청백 `(0.62, 0.9, 1.0)`, 적 주황 `(1.0, 0.72, 0.5)`)를 건다. LOD2(480 삼각형)는 두 번 그려도 예산에 영향이 작다. LOD1 줌 아웃에서는 끈다.
- 림 라이트 강화: `rim 0.35 → 0.9`, `rim_tint 0.6 → 0.0`(흰 림).
- 비율: `HULL_STRETCH` 폭·높이를 0.7배(길이 유지)로 줄여 날씬하게. 가독성이 떨어지면 되돌릴 수 있게 상수 하나로 둔다.
- 줌 아웃에서 점으로 사라지는 문제(§6)는 같은 외곽선 색을 쓰는 **최소 화면 크기 보장**(선체 길이가 화면 3px 미만이면 3px 선분으로)으로 푼다. 이 부분은 PR4.
- 결정론: 재질만 바꾸므로 코어와 무관하다. 검증은 §8 캡처 비교(줌 인·기본 줌) + 기존 12종 테스트.

**G8 목적지 고리(R5).** `route`·`move_to`가 이미 있다. 선택한 전대의 도착 예상 위치에 진형 슬롯 모양의 고리를 그리는 것은 `tactical_overlay.gd` 쪽 UI 작업이라 이 문서 범위 밖이다. 구현 세션이 PR4로 검토한다.

## 5. 코어 결정론과 충돌하는가

없다.
- 입력은 투영/POC의 읽기 전용 값뿐이다. 렌더러는 이미 `BattleSource`로만 읽고 쓰지 않는다(파일 머리 주석). 함선 위치·속도·yaw는 렌더러 안에서만 산다.
- 난수: 전역 `randf()`를 쓰지 않는다. 함선별 τ·위상은 전대 id 시드의 `RandomNumberGenerator`(기존 `jr`)로 생성 시점에 한 번만 뽑는다. 연출 난수 `rng`(`seed=20261003`)는 이미 전투 난수와 분리돼 있다. 추종 갱신에는 난수가 없다(결정적).
- 시간: 갱신 `dt`는 표현 계층이 넘기는 게임 dt를 쓴다(일시정지 0, 배속 ×N). 배속에서 대형이 같은 모양으로 움직이게 하려면 dt를 그대로 쓴다. 갱신 주기를 프레임 수가 아니라 누적 dt로 잡아 프레임률 의존을 없앤다.
- 결과: 같은 시드의 전투 로그·지문은 화면 연출과 무관하다. 화면 캡처는 프레임 시점에 따라 달라지므로 캡처 비교는 정지 장면에서만 한다(§8).
- 주의: 코어가 `heading`을 0.1초 틱으로 갱신하므로 뷰가 틱 사이를 보간하지 않으면 계단이 보일 수 있다. G1의 지수 추종이 이를 흡수하지만, 실제 투영(M10)에서 `heading`이 틱 값으로 올 때 한 번 확인한다.
