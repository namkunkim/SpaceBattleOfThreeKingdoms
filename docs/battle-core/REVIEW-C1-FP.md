## 코드 검토 (결과 불변 논거)
- 거리 상한(`_range_cap`): 사거리는 `qualifying`에서 플랫폼 사거리 × 지형 배율뿐이다. 진형·기술·지휘 보정은 이 판정에 들어가지 않는다. 지형 배율은 구역별 배율을 ID 순으로 곱한 값이고 상한은 `max(1, 배율)`을 같은 순서로 곱한 값이라 부동소수 곱의 단조성으로 항상 이상이다. 최대 사거리는 손상과 무관한 편성 기준(`f.stages`, `f.equip`)이라 `platforms()`보다 넓다. 경계 `dist == cap`은 통과(`>`로 자름).
- 강습·화공·기함·요격·뇌격은 `qualifying`을 거치지 않는다(호출처는 `_pick_target` 두 곳뿐). 별도 사거리 경로가 영향받지 않는다.
- `_any_qualifies`: `platforms()`의 조건(스테이지 보유, 유효 척 수 > 0, 사거리, 사격각)을 같은 식으로 옮겼고 순서 무관한 불리언이라 동일. 최종 결과 배열은 여전히 `platforms()` 루프로 만든다.
- `_pick_target`/`sight_foe` 접촉 기록 한 번 조회: `sees`(생존·confirmed/estimated)와 `_aim`/`known_pos`(confirmed는 실제 위치, estimated는 기록 위치)와 같다. `d >= bd`, truce, 순회 순서(`fleets` 배열 순)가 그대로라 RNG·동률 처리 불변. 이 경로는 RNG를 쓰지 않는다.
- `by_id`: `fleets`는 `_spawn`(battle_sim.gd:225)에서만 추가되고 제거·재할당이 코어에 없다. 크기가 바뀌면 재구축하므로 증원·대기(deploy_delay) 함대도 반영. 죽은 함대는 배열에 남는다. 같은 ID는 앞의 것(선형 탐색과 같음).
- 보급 정렬 캐시: 한 번의 `step()` 안 지역 변수라 틱 간 무효화 문제가 없다. 정렬 중 탄약·ID·정지 시각이 바뀌지 않는다. `_prior`(P7 "이 함대 먼저") 비교가 먼저 유지되어 P7 의도 불변. 7d588e8 대비 supply.gd 차이는 비율 캐시 몇 줄뿐이다.
