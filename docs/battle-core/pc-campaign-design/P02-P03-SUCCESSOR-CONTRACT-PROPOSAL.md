# P02·P03 후속 작전 승계와 전환 권한 제안

이 문서는 미승인 제안이다. 기준 제품은 적벽 v1을 명시적으로 다시 시작하면 새 작전 ID와 C0를 생성한다. 제품 정산 원장은 정산 ID, 유형, 사유, 논리 시각, seed, mode, difficulty를 저장하며 동일한 정산의 재게시를 한 번으로 처리한다. 제품 저장은 결산된 작전 ID의 재개를 거부한다. [작전 로컬 검증](../../../tests/first_operation_handoff_preparation.gd)

## 권한과 전환 시점

플레이어가 캠페인 프로필에서 후속 출격을 명시적으로 확인한다. 제안하는 캠페인 서비스는 현재 프로필의 승인된 세션에서 요청자를 확인하고 전환 원장의 단독 작성자가 된다. 지도 화면은 확인 의사를 전달한다. 전투 소유자는 정산을 게시하며 외부 저장과 리플레이는 정산·전환 승인 경로에서 제외한다.

서비스는 캠페인 원장에 고정한 eligible_parent ID로 제품 정산 원장의 consumed 레코드를 조회한다. 표시용 latest는 화면 표시에만 사용한다. 전환 정책은 승인된 버전·정산 자격과 대상 정의를 묶고, 대상 매니페스트는 정의/버전·편성·지도/경로·전투/이동 규칙의 지문, capability, mode, difficulty와 고정 seed를 묶는다. 실승인 정책의 자격 집합과 대상 매니페스트는 현재 비어 있다. 적벽 v1 재시작은 별도 기존 경로다.

부모 Cn은 terminal tick 처리 및 정산 원장 게시가 완료된 뒤 캠페인 서비스가 지정한 시점이다. 후속 C0의 실행 권한은 전환 CAS가 성공한 뒤 생긴다. 서비스는 후속 준비 후보를 내부에서 만들 수 있고, 게시가 완료된 기록에서 동일 ID와 입력으로 C0를 재구성한다.

## 승계 및 초기화

| 필드 | 제안 규칙과 권위 |
| --- | --- |
| 부모 정산 id, kind, reason, clock_ms, seed, mode, difficulty | consumed의 정확한 일곱 필드를 전환 기록의 parent에 복제한다. clock_ms 단위는 정수 밀리초다. 부모 값은 전환 근거이며 새 전투 초기 입력은 대상 매니페스트에서 얻는다. |
| 부모 operation_id, parent_digest | 정산 ID 끝의 /settlement를 제거해 부모 ID를 얻는다. 일곱 필드의 정규화 표현에 SHA-256을 적용해 부모 내용에 결속한다. |
| 캠페인 ID, 확인 요청 ID, actor, policy_digest, target_digest, transition_id, 전환 세대 | 전환 원장이 보유한다. 새 실행은 전환 ID로 원장을 참조한다. 전환 세대는 CAS 세대이며 작전 tick과 독립이다. |
| capability, definition_id/version, roster_id, route_id, seed, difficulty, mode | 승인된 대상 매니페스트에서 해석한다. 부모와 우연히 값이 같더라도 대상 값으로 기록한다. |
| 새 operation_id, rules_digest, source_digest, effective_digest, state_digest, meta | 승인된 대상 준비자에서 생성한다. 새 ID는 전환 레코드에 저장한다. 런타임 지문·초기 프레임은 그 대상과 ID에서 생성한다. |
| tick, clock_ms, phase, hz, projection, events, settlement | tick=0, clock_ms=0, phase=brief, settlement는 빈 값으로 시작한다. hz·투영·초기 이벤트는 대상 C0에서 산출한다. |
| commands, pending, event_cursor, proposal_serial | 명령 이력과 대기열은 빈 배열이다. 이벤트 커서와 정책 제안 순번은 새 소유자의 초기 값이며 커서는 C0 이벤트 배출 뒤 새로 증가할 수 있다. 새 명령을 적용할 때 operation_id로 소유자를 검증하고 현재 로컬 tick·배치 순서를 쓴다. 캠페인 전역 명령 번호를 두지 않는다. |
| 함선·함대·사기·보급·지휘·거점·철수 상태, 투사체, 효과 ID 및 owner_epoch | 부모 전투에 귀속된다. 활성 객체와 대기 효과를 이전하면 안 된다. 후속 값은 대상 데이터가 정한 C0에서 얻는다. 전투 밖의 재고·보상·지속 함대 효과를 추가하려면 별도 승인 입력과 효과 키가 필요하다. |

## 게시·재시도

1. 확인 요청은 캠페인 ID, 확인 요청 ID, 관측한 캠페인 세대, 부모 정산 ID·내용 지문, 정책·대상 지문을 담는다. 요청 ID는 소문자·숫자·하이픈 1~64자다. 캠페인 서비스는 actor를 세션에서 확인한다.
2. 재시도 키는 (캠페인 ID, 부모 정산 ID, 확인 요청 ID)다. 같은 키의 정규화 요청 지문이 같으면 이미 기록한 응답을 반환한다. 지문이 다르면 intent_conflict를 반환한다. 응답은 접근 권한 확인 뒤에 반환한다.
3. 새 요청은 캠페인 세대, 지정 부모 ID와 내용 지문, 정책 및 대상 지문, 부모 미전환을 한 원자적 판정에서 비교한다. 전환 ID는 SHA-256으로 스키마 태그, 캠페인 ID, 부모 내용 지문, 정책 지문을 결속한다. 부모 정산 ID는 부모 내용에 들어 있다. 지문은 키 순서가 정렬된 공백 없는 UTF-8 JSON으로 계산한다. 해시 입력은 해당 스키마에서 정한 문자열·정수·불리언·목록·객체를 사용한다.
4. 성공 시 서비스는 동일 트랜잭션으로 전환 기록·응답·새 작전 ID·권한 상태·세대를 기록한다. 전환은 캠페인과 부모 ID당 한 번이다. 정책 버전이 바뀌어도 이미 전환된 부모는 다시 사용하지 않는다. 다른 요청이 같은 이전 세대를 제시하면 stale_generation, 세대를 다시 읽은 새 요청은 parent_already_transitioned를 받는다.
5. 게시 전 실패는 새 세대와 실행 권한을 남기지 않는다. 게시 뒤 응답 전 실패는 같은 요청 키로 기존 응답과 새 작전 ID를 회수한다. 승인된 대상 데이터를 열 수 없다면 기존 전환은 보존하고 해당 ID에서 실행 재시도를 대기한다. 둘 이상의 실행 호스트가 붙는 경우 같은 ID를 한 활성 소유자만 잡도록 실제 저장소에서 검증해야 한다.

## 헤드리스 범위

[검증 스크립트](../../../tests/first_operation_successor_contract.py)는 기존 격리 실행의 적벽 v1 철수 실패 정산 원장만 읽고, 파일과 body의 SHA-256 및 정산 내용을 확인한다. 정산 파일은 커밋에 포함하지 않는다. 승인이 없는 경로와 같은 정의로의 재진입을 거부한다. 성공 분기의 대상은 실행할 데이터가 없는 시험 전용 참조이며 해당 분기의 failure 허용 또한 시험용이다. 단일 프로세스에서 값으로 표현한 CAS의 호출 순서를 바꿔 재시도·충돌을 재현한다. 운영 원자적 저장소, 동시 프로세스, 후속 전투 C0 실행, A05/A06 통합 검증은 실제 정책·대상·원장·호스트가 준비된 뒤 수행한다.

```powershell
python tests/first_operation_successor_contract.py <isolated-run-3-settlement-ledger>
```
