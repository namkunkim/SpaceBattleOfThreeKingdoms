# D04 상태 소유·인계 기초 계약

2026-10-25 / 초기 설계 초안 / **독립 5-b 및 H1 정책 판단 대기**.

계약은 [작업 분해 D04](../PC-CAMPAIGN-WORK-BREAKDOWN-20261025.md), [스펙 R13/R14·O07](../PC-CAMPAIGN-REVIEW-SPEC-20261025.md), [D01](D01-BASELINE.md), [D02 최신 §9](D02-SCOPE.md), [H0 단일 결정 기록](H0-DECISION.md)이다. H0 기록을 받은 뒤 작성했다. H0는 단일 성계 연속작전·보급로 개방·정면/우회·시간 증원과 호송 차단/통신소 지연/재점령의 **설계 포함 범위**를 확정했다. 제작 순서 분리는 상태에서 확장 기능을 빼라는 뜻이 아니다.

H0는 아래 필드명·저장 형식·호환·동일 틱 우선순위·회복/점령/철수 수치의 승인이 아니다. `OperationState` 등 이름은 설계용 후보이며 현재 클래스 구현 주장이 아니다. **O07은 OPEN**이고 확정 전 상태 계약을 쓰는 게임 구현 착수는 차단한다. 읽기 기반 설계·반례 정의는 가능하다. 이번 산출물은 이 파일 하나이며 코드·테스트·브랜치·공통 문서를 변경하지 않았다.

## 1. 현재 사실과 후보 계약의 경계

아래 코드 경로는 프로젝트 루트 기준이며 정적 열람 근거다. 현재 기반 시점·미커밋 제약은 D01 §1/O06을 따른다. 최신 통합 가능성을 재판정하거나 게임을 실행하지 않았다.

| 현재 관측 | 직접 근거 | 기초 계약에 대한 판단 |
|---|---|---|

## 2. 상태 권위·ID·단일 시계의 초기 제안

**권고 가설:** 하나의 작전 권위 상태와 커밋 경계를 두고, 전술 코어·임무·점령·보급·일정은 각자 소유 필드만 변경한다. UI·미니맵·알림·예상 ETA는 읽기 투영이며 소유권·자원·사건 실행을 독자 갱신하지 않는다. 구체 클래스 분리와 직렬화 표현은 O07/H1 미정이다.

| 식별자·권위 후보 | 수명·참조 규칙 | 아직 결정하지 않는 것 |
|---|---|---|
| `operation_definition_id` / `operation_instance_id` | 정의와 실제 시도 식별을 분리. seed가 같아도 새 시도는 별개. 로드 재개는 같은 인스턴스 | ID 문자열/번호 형식·생성 방법 |
| `fleet_id`, 정의상 `roster_id`, 현재 런타임 ID 매핑 | 작전 내 전투·점령·보급·증원·결산에서 같은 함대를 가리킴. 상실·철수 후 ID를 다른 함대에 재사용하지 않음. 참조 해소표 보존 | 현 `id`/`sq_id`를 어느 층에서 정본으로 삼을지, 증원 ID 배정 방식 |
| `node_id` / `edge_id` / `control_point_id` / `facility_id` | 공간 노드·항로와 점령 대상·시설을 구별. 행성 한 곳의 표식·통제·재고를 동일 ID 하나로 혼동하지 않음 | 노드 수·좌표·범위와 최종 그래프. D03 소유 |
| `mission_id`, `convoy_id`, `scheduled_event_id` | 임무·물류 묶음·사건 정의의 ID. 호송을 구성하는 함대 ID 목록과 별개 | 임무별 단계와 연결 필드 상세. D05/D08 |
| `command_id`, `transition_id`, `transaction_id`, `settlement_id` | 명령·상태 전이·자원 효과·결산의 중복 방지 범위 구별. 한 사건의 여러 효과에는 별도 효과 키 또는 원자적 묶음 식별 | 현 난수용 `next_event_id`와 작전 의미 사건 ID의 매핑·정렬 형식 |
| 논리 시계 / 저장 커서 | 작전 전체에서 한 시간 원천 사용. 정지·배속은 실행 속도만 바꾸고 호송/증원/점령의 독립 벽시계를 만들지 않음 | tick·하위걸음·clock_ms의 정확한 정본/파생 관계·반올림·종료 중간 경계. D03와 대조 후 H1 |

**중복 권위 금지의 검토 기준:** 실제 잔존척수는 손상단계와 연관된 정본에서 계산하거나 명시한 동기화 규칙을 가진다. 지도 색을 바꾸는 UI 값과 SupplyCore 소유권이 따로 진실이 될 수 없다. 도착예정 ETA는 사건 실제 완료 상태와 구별한다. 통신소 지연도 일정 필드와 UI 대사를 별도 수정하지 않는다.

실제 경과·정지 포함 경과·배속별 체류는 평가 로그 후보이며 게임 효과를 구동하는 두 번째 작전 시계로 쓰지 않는다. 로그를 저장할지·다시 불러올 때 세션별로 잇는 방법은 평가/UX 계약과 구분해 인계한다. D03 작성자가 전달한 fixed_dt/규칙·기하/통행/병기태그 버전·논리 진형 외곽/경로 재계산 기준·출입점 역할·유효경로 버전·last_seen·사건별 시각/지연 적용상태는 **D03→D04 후보 요청**으로 접수했다. ST01/02/06/12/14/16 슬롯에서 추적하며, 전달 자체가 확정 정책은 아니다. 경로 캐시의 저장/재계산 선택은 O07에서 근거와 비교 검증 후 판단한다.

## 4. 커밋·동일 틱 중재·멱등성의 후보 계약

**권고 가설:** 저장은 명시한 일관된 커밋 경계에서만 잡는다. 경계 도중 저장 요청은 완료 경계까지 대기하거나, 전체 중간 단계 상태를 보존하는 별도 형식이 필요하다. 첫 후보는 전자를 권고하지만 H1 확정 전 구현 규칙으로 사용하지 않는다. `issue()`가 틱 사이 즉시 적용되는 현행 경로를 고려해 ‘tick 번호만 저장’으로는 적용 커서를 충분히 표현하지 못할 수 있다.

| 항목 | 기초 불변식 후보 | 최종 결정 책임·open |
|---|---|---|
| 명령 | 접수·적용 순서와 유효성 판단 시점을 구분. snapshot에 반영된 명령을 로그 재생으로 다시 적용하지 않음 | 적용커서+대기열 저장 vs 입력 경계 제한, D04/O07 |
| 자원 거래 | 검사→자원/진행/소유 변화→완료 키를 같은 원자적 상태 갱신으로 간주. 실패 시 전체 미반영 | 전역 트랜잭션 vs 기능별 원장, D04/D07/O07 |
| 점령·시설 | 한 소유 전이 버전에 공급원/목표/표시 투영을 연결. 같은 커밋에서 두 세력이 동일 재고를 사용하지 않음 | 전이/가동·경합·재상실 정책 D06/O04 |
| 증원·호송 | 전이/효과 키와 생성/배송 ID를 결합. `처리됨`만 먼저 저장하거나 효과만 적용하고 키를 누락하지 않음 | 출발/진입/도착 각 전이와 취소 D08/O05 |
| 종료·결산 | 결과 결정은 한번, 이후 저장/게시/지급은 같은 결산 ID로 중복 검사를 거침. 알림 다시 보기와 자원 재지급을 구분 | 종료 우선순위 D06, 이벤트 중단 D08, 원장 O07 |
| 복원 | 규칙·참조·해시·단위 검증→객체 재구성→ID참조 해소→파생상태 검증→원자적 교체→표시 | 불일치 파일을 새 작전 기본값과 섞지 않음. 실패 시 기존 활성 상태 보존/로드 중단 후보 |

**동일 틱 중재는 슬롯만 지정한다.** `(논리시각, 단계, 안정 ID/명령순서)` 같은 정렬 키와 규칙 버전을 기록하는 대안을 둔다. 단계의 우선순위는 다음 사건쌍을 D06/D08에서 비교해 선택한다. 사전 정의 없는 배열 순서·UI 프레임/벽시계로 결정하지 않는다는 기준만 초기 계약이다.

- 통신소 점령 완료와 증원 출발이 같은 틱: 지연 성립/불성립, 평가 기준 시각 모두 O05.
- 최종 목표 완료·지휘 상실·시한·철수 완료가 같은 틱: 승패·우선순위·결산 조건 O05.
- 거점 재상실·시설 가동·보급 주기 완료·호송 배송이 같은 틱: 자원 귀속·진행 중단/완료 O04/O05.
- 증원 진입·새 함대의 사기 비용 집계·전역 사기 평가가 같은 틱: 모집단과 평가 시점 O04/O05.

H0의 ‘시간 경과 증원 포함’은 특정 출발/도착시각이나 위 순서 승인이 아니다. 기존 캠페인 제안의 ‘목표 먼저·지휘 상실 실패 먼저’는 대안으로 추적하며 확정하지 않는다.

## 6. 검증 5종의 입력·비교·반례 — 모두 미래 검사

이번 문서는 검증 기준만 정의한다. 아래 게임 실행·저장 시험은 **미실행·미통과**이며 스펙 §5의 미래 구현 검증에 해당한다. 비교는 논리 상태의 정규화 비교+부문 지문+후속 진행의 결과를 사용하고, 전체 해시 하나만으로 완전성을 주장하지 않는다.

| 검증 ID | 검사 종류·입력 | 비교 상태·성공 기준 | 드러내야 할 실패 |
|---|---|---|---|
| T01 | **연속 상태 유지**: 같은 작전에서 조우→점령→보급→다음 교전 | 같은 함대/작전 ID, 실제 손상단계·무기자원·사기·명령/임무·전역 시간의 연속성. 변화는 소유 규칙의 효과와 일치 | 목표 완료/화면 열기만으로 회복·탄약 리셋, ID재배정, 이벤트 시계 초기화 |

## 7. 후속 필드 요청·D10 정합화 — R14

| 요청 주체 | D04에 반환할 필드 계약 | 소유 충돌을 피할 경계 |
|---|---|---|
| D03 공간/시간 | clock/tick/하위단계 관계·저장 허용 경계, node/edge/지형/경로 버전·좌표단위 | D04는 저장 참조만 제안. D03의 치수·시간 정책을 대신 선택하지 않음 |
| D05 임무/접촉 | 임무 상태·보고/기억·AI 타이머·추격/재계획 커서·공개 투영 | 실제 적과 접촉 기억의 권위를 섞지 않음 |
| D06 목표/사기 | 전이·경합/가동·재상실·종료 우선순위·군 사기 모집단·철수 결과조건 | D04가 보존 틀을 소유하고 정책 의미/값은 D06이 제안 |
| D07 물자 | 재고 단위·소유 이전·주기 지출/노획·유입·대기열과 중복키 | 점령 소유와 재고 작업이 이중 갱신되지 않게 같은 전이 버전 참조 |
| D08 일정 | 사건 상태·같은 틱 중재·일정 변경 이력·spawn/배송/취소/종료 원장 | 출발/진입/목표도착 및 통신소 지연·재점령을 구별 |
| D10 통합 | ST별 최종 책임·필드 누락/중복·버전/순서 충돌 색인 | 새 필드를 임의 추가해 합의된 것처럼 만들지 않고 D04 소유자에게 수정 요청 |

모든 요청에는 `요청ID / 관련 R·O / 필드·단위 / 정본·파생 / 유일 작성자 / 전이·시간 / 복원·재생·지문 필요 / 기본값의 의미 / 충돌 상대`를 적는다. D05~D08은 자기 문서에 요청을 남기고 이 파일을 수정하지 않는다. D10이 조정 필요사항을 모아 D04 후속 수정 승인을 요청한다. 이 과정은 의존성 피드백이며 D04 초기 계약을 기다리며 D05~D08을 거꾸로 선행시키는 DAG 순환이 아니다.

기존 적벽의 승패·사기·Q84를 전역 변경하지 않는다. Q67의 적용 여부는 D03 범위 대조에 맡기며, 적용되면 B항 등재+1000시드 게이트 유지, 비적용이면 근거·제외 이유 기록이라는 조건을 저장/프로필 버전에도 추적한다. ‘신규 작전’이나 새 저장 버전만으로 지형 게이트를 면제하지 않는다.

## 8. 자체 5-a·미결·독립 인계

| 추적 | 초기 계약의 근거·반례·잔여 조건 | 자체 완결성 점검 |
|---|---|---|
| R13 | §2~3의 상태 소유·ID·직렬화 후보, §4의 커밋·원자성, §5버전, §6의 검증5종 | 필요한 데이터와 비교대상 정의. 실제 저장/재생/멱등성 통과 주장은 없음 |
| R14 | §7 초기계약→분야요청→D10 정합화, 단일 파일 소유·정책 책임 | 상태 설계를 마지막에 미루지 않음. 후속 필드 미정은 명시적 요청 슬롯 |
| O07 | §5 V01~V05 대안·권고 이유·비용, H1 판단·게임 구현 차단 | **OPEN**. 초기 저장 계약 제안만 인계 가능, 스키마·호환 확정 불가 |
| 연계 O01/O03~O05/O06 | 시계/치수·점령/회복·동시틱/생환·현재 통합 가능성 | H0로 해소된 범위와 미결 정책을 구분. 호송/통신소/재점령을 미선택으로 되돌리지 않음 |

자체 5-a 검사 입력은 본 파일·H0·스펙/계획·위 원문 경로다. ST01~ST18 소유자/수명/보존·미결, T01~T05 입력/비교/실패, V01~V05 대안/H1 차단, 관련 R13/R14/O07과 H0 포함 범위를 검사한다. **문서 K=3**, 자체검사 실패는 해당 문서만 재시도하고 초과 시 중단 보고한다. 독립 5-b 반려는 2단계 스펙으로 복귀하여 기준/범위/근거를 재검토한다.

현재는 실행자의 자체 문서 완결성 점검이며 독립 5-b 승인이 아니다. 별도 검토자는 원문과 저장 누락·중복효과·동일틱·정보 누출 반례를 대조해 `REVIEW-D04.md`에만 판정한다. 사용자 H1 선택과 미래 게임 검증을 대체하지 않는다.

자체검사 기록: 1차 문서 점검에서 ST18개·검증5종·대안5개·R13/R14/O07·H0 참조·독립 검토 대기·게임 검증 미실행 구성을 검사했다. 원문 경로와 스키마 후보/기존 사실의 구분을 대조하며, 기계적 개수·링크·공백 검사는 내용 정확성의 최종 판정이 아니다.

**현재 위치: D04 초기 상태 계약 초안·자체 5-a 인계. 독립 검토 및 O07/H1 대기. 게임 구현·테스트 미실행.**
