# I01 입력·인수 계약과 사전등록 구체화

2026-10-26 / **준비 문서 초안·독립 검토 대기 / 코드·검사·측정 실행 미승인** / 문서 K=3.

## 1. 범위·결정 원천

입력은 [구현 스펙 I01/A01~06](IMPLEMENTATION-SPEC-20261026.md), [측정 계획 PR01~06](MEASUREMENT-PLAN-20261026.md), [준비 독립 검토](REVIEW-IMPLEMENTATION-PREP-20261026.md), [H2](H2-DECISION.md), [D03](D03-SPACE-TIME.md), [D04](D04-STATE.md), [D09](D09-UX-EVALUATION.md), [D10](D10-INTEGRATED-REVIEW.md)이다. 이번 승인은 이 문서 한 개의 작성과 읽기 기반 O06 감사·계약 준비이며 게임 코드·데이터·검사/측정 실행·브랜치/커밋 승인이 아니다.

I01은 opt-in 작전 프로필/실효 설정뿐 아니라 공간 접근과 지속 상태 경계를 포함한다. 이를 문자열 선택기만으로 축소하지 않는다. 아래는 **구현 전 권고 계약**이며 승인된 게임 정책을 바꾸지 않는 타입·검증·오류 처리 선택을 구체화한다. 실제 런타임의 공간/상태 생성은 O03/O06/O07의 관련 미결 해소 전 차단한다. 물량·시간·회복·일정·승계 등 후속 정책을 이 문서에서 새로 확정하지 않는다.

## 3. I01 입력 사전 — 필드명은 신규 계약 후보

범용 숫자는 bool을 제외한 유한 JSON 숫자다. 정수 의미 필드는 소수부 없는 값만 허용하며 강제 절삭하지 않는다. ID는 비어 있지 않은 문자열이며 같은 종류 내 고유하다. 화면 이름과 내부 ID를 구분하고 알 수 없는 필수 enum·중복 ID·미해결 참조는 거부한다. 모든 오류는 입력 경로·이유를 갖는다.

|---|---|---|
| F01 | `mode: legacy|operation`, `definition_id`, `definition_version:int` | opt-in은 명시 operation. 선택 없음은 기존 legacy. operation인데 정의/버전 없음은 실패, legacy 추정 금지 |
| F02 | `schema_version/rules_version`, `profile_id`, 원천별 내용 해시 | 지원 목록은 실행 전 고정. 같은 이름의 내용 변경은 해시로 검출; 불일치·미지원은 거부. 저장 버전 확정으로 확대하지 않음 |

## 4. 변환·소유·실패 계약

순서는 **선택 분기→파일 읽기/깊은 복제→형식/버전·참조검증→난이도/편성 확정→원본 bounds 검증→좌표 변환→기동 튜닝1회→상태 참조/모듈 readiness 검증→실효 manifest 게시**다. 신규 정의는 유효성 검증 전 BattleSim을 만들지 않는다. 오류 결과는 `ok=false/errors[{path,code}]`와 `effective=null` 권고이며 활성 전장/기존 프로필은 불변이다.

source 좌표는 x에 `target_w/source_w`, y에 `target_h/source_h`를 한 번 곱한다. 노드·함대 배치·효과 rect·기지/탈출/진입 중심·서비스 형상은 같은 변환표에 등록한다. 원형 반경을 비등방 확대할 때는 원→타원 또는 원유지/금지 중 형상 정책을 고정해야 하므로, I01 첫 fixture/비교는 **등방 확대만** 권고한다. 비등방 후보를 쓰려면 F12 형상 계약을 먼저 해소하며 자동 평균반경 금지. 속도·사거리·탐지/지휘 반경은 좌표 확대와 별개 단위이고 임의로 함께 배율하지 않는다. 서비스 반경이 원천좌표/실효규칙 중 어느 쪽인지 필드별 표시한다.

변환은 원본의 새 사본에서만 수행하고 재시작도 원본으로 재구축한다. 입력/출력 배열 순서가 편성·난수 ID에 의미가 있으면 보존하고 해시 편의를 위해 정렬하지 않는다. Dictionary 키의 canonical 직렬화만 명세해 사용한다. 초기 roster 순서·상태 ID 매핑·변환 버전을 manifest에 보존한다.

공유 변경 후보는 `ProfileLoader/ScenarioProfile/RuleSet`, 호스트 초기화/투영 경계이며 정확 허용파일은 O06 승인 목록 후 고정한다. 신규 전용 정의·검증 모듈 경로는 미작성이다. 기존 적벽·POC는 원래 선택/튜닝/오류 대체를 보존하고 공통 옵션이 없는 실행의 결과를 바꾸지 않는다. `combat_m3.json` 생성물만 손으로 고치거나 전체 생성기를 이번 준비에서 실행하지 않는다.

## 6. A01~06 fixture·oracle — 인라인 자료, 미작성/미실행

모든 fixture 이름은 검사용이며 product 밸런스가 아니다. **FX-G**는 source `[0,0,1000,600]`, target `[2000,1200]`, seed20824/hz10, move=2/turn=3인 산술 fixture다. 노드 E(50,300),J(200,300),A(400,180),B(400,420),C(800,300),D(650,420),R(950,300); 항로 E-J,J-A,A-C,J-B,B-D,D-C,A-B,R-C,R-D(검사 fixture는 모두 bidirectional=true). 논리 반경20/여유5, 서비스 A/B·출입 E/R의 source 반경60. 효과 rect `[300,50,100,50]`. 원천 함종속도10·선회9·회피속도계수8을 별도 가짜 자료로 주입한다. 실제 전투 원천값으로 쓰지 않는다.

## 8. 착수 판정·기준 감사 인계 자리

O03: FX-G는 검사 oracle만 구체화했다. product 최대진형/전환·서비스/퇴로/진입의 실제 치수/좌표·F12가 없으면 I01공간구현 착수는 여전히 차단한다. O07: F13~16/ST범위·커서권고는 제시했지만 전체필드/커밋/복원/호환검사 확정은 상태담당·독립검토 게이트다. 후속P2/P3의물량·회복·일정(O04/O05)을 여기서 정하지 않는다.

[O06 기준 감사](I01-BASELINE-AUDIT-20261026.md) §1~4를 직접 대조했다. 관측 시각은 2026-10-26T14:47:33.1659388+09:00이며, 그 이후 공유 변경은 실행 직전 다시 확인해야 한다. 감사의 관측은 다음과 같다: main HEAD와 로컬 origin 추적은 93e60e6, tracked dirty15파일391추가/44삭제·stage없음이다. 원격 최신성을 확인한 것은 아니다. I01 직접 후보인 profile_loader/scenario_profile/FleetBattle3D/battle_sim/terrain/detection/camera/tactical/state/fingerprint 및 data/profiles/scenarios에는 당시 status 항목이 없었다. 그러나 간접 의존인 bundle_layout.gd와 관련 검사가 dirty이고 project.godot 아이콘2줄 변경의 소유도 미확인이다. 따라서 직접 파일이 깨끗하다는 사실만으로 공간·편성 기준을 clean으로 간주하지 않는다. 기존 변경은 보존하고 사용자 소유·통합 방법 확인 전 가져오거나 되돌리지 않는다.
