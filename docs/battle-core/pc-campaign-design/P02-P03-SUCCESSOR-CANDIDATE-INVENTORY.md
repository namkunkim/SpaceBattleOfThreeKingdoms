## 별도 프로세스에서 검증한 범위

[SQLite 검증기](../../../tests/first_operation_successor_persistence.py)는 격리된 기존 Godot 정산의 바이트를 읽어 임시 데이터베이스에 적재한다. 테스트 모델은 이전 제안의 판정 함수를 호출한다. 각 작업 프로세스가 새 SQLite 연결을 열고 `BEGIN IMMEDIATE`에서 권한, 세대, 부모 정산과 정책을 읽는다. 단일 트랜잭션에서 세대를 비교·갱신하고 부모당 하나의 응답을 삽입한다. 재시도 조회는 요청이 지정한 부모 ID를 사용한다.

동시 시작한 별도 PID의 동일 요청은 같은 응답을 받고 저장 행은 하나다. 다른 요청의 경합에서는 하나가 커밋되고 다른 하나는 이전 세대로 거부된다. 두 단계의 강제 프로세스 종료는 커밋 직전의 롤백과 커밋 직후 응답 유실을 재현한다. 새 PID로 재개했을 때 원래 응답이 복원되고 캠페인의 지정 부모가 나중에 바뀌어도 이전 요청으로 같은 응답을 조회한다. 변경된 요청, 다른 actor, 오래된 세대, 철회된 정책은 거부된다. 격리 정산 원본은 바이트가 같다.

```powershell
python -B tests/first_operation_successor_persistence.py <isolated-settlement-ledger> <local-temporary-parent>
```

이 실험은 한 Windows 머신의 F: 고정 exFAT 볼륨, 로컬 SQLite, 독립 프로세스 및 연결을 사용했다. 강제 프로세스 종료를 검증했으며 실제 전원 차단, 서버 중단, 네트워크 연결 단절, 원격 파일 잠금, 운영 인증 및 다중 머신 활성 소유자 검증은 다음 단계에 속한다.

## 독립 Windows 머신 인수의 선행 조건

- 서로 다른 두 Windows 머신과 각각 격리된 프로필·고정 빌드·대상 매니페스트가 필요하다. 기존 체크리스트의 두 번째 호스트 무게시 복귀·원장/슬롯 보존 시험은 준비된 독립 호스트가 필요하며 기존 차단 시험을 재실행하지 않았다.
- 두 호스트는 승인된 동일 시험 캠페인에 인증된 서비스 API로 연결한다. 제안하는 서비스가 전환 DB와 세대·커밋 권한을 단독 소유하며 DB는 서비스 머신의 지원되는 로컬 볼륨에 둔다. 각 호스트에 파일 저장을 복제하면 동일 권위의 CAS를 검증할 수 없다. 연결 주소와 자격 증명은 제공 주체가 별도로 설정하고 실행 증거는 비밀값을 제외한다.
- 승인 후 실제 대상 정책·매니페스트와 서비스 트랜잭션, 동일 작전 ID의 활성 소유자 임대 및 펜싱을 고정한다. 동시 동일/상이 요청, 커밋 전 장애, 커밋 뒤 응답 단절, 재접속 후 동일 응답, 오래된 세대·펜싱 거부, 단일 효과와 후속 C0, 보호 원장·슬롯 바이트 및 두 호스트별 증거를 검증한다.
