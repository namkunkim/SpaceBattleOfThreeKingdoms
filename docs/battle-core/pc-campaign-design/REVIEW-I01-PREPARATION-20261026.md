# I01 기준 감사·인수/사전등록 구체화 독립 검토

2026-10-26 / final_independent_review / **준비 문서로 수용·실제 I01 착수는 계속 차단**.

대상은 [O06 기준 감사](I01-BASELINE-AUDIT-20261026.md)와 [I01 인수/사전등록](I01-ACCEPTANCE-PREREG-20261026.md)다. 검토자는 두 산출물의 작성·수정에 참여하지 않았다. 작성자의 최종 자체 5-a 인계를 받은 뒤 전체 문서를 [선행 구현 스펙](IMPLEMENTATION-SPEC-20261026.md), [측정 계획](MEASUREMENT-PLAN-20261026.md), [직전 독립 검토](REVIEW-IMPLEMENTATION-PREP-20261026.md), [H2](H2-DECISION.md), 플레이북과 관련 정적 코드에 대조했다.

## 1. 최종 판정

실질적인 전달 오류·입력 계약 누락·후보의 무단 확정·사용자 승인 확대는 발견하지 못했다. 두 문서를 **다음 인수 계약 정합화·사전등록 준비의 근거로 수용**한다. O06 전체가 해소되거나 코드/검사/측정을 지금 실행할 수 있다는 수용은 아니다. 최종 감사 링크와 실제 관측 경계까지 대조한 후 판정했다.

## 2. 독립 확인 범위

정적 대조는 ScenarioProfile의 확대/튜닝, BattleRules의10Hz/0.05초 참조폭, BattleSim의 tick/하위걸음·clock, BattleRng의 무상태 키, BattleState의 ID/사건 카운터 및 선행 검토의 코드 근거를 사용했다. O06 감사의 관측은 그 기록과 계약 §8 사이의 시점·수치·범위 일치를 대조했으며, 승인 대기를 재시도하거나 원격·PC 상태를 재조회하지 않았다.

문서 완결성 보조 검사에서는 감사 링크5개·계약 링크9개의 누락0/행말공백0, F16/A6/PR6행과 산술60/24를 확인했다. 이것은 문서·산술 확인이며 A검사나 게임 실행이 아니다. 실제 A01~06·게임·저장·성능·1000시드·사람 플레이 시험은 모두 미실행이다. 이 리뷰 기록만 작성했고 대상 본문·코드·브랜치는 수정하지 않았다.

## 3. 현재 해소·남은 것·다음 행동

**이번에 구체화한 것:** O06의 시점부 로컬 기준/직접·간접 영향/권한 미확인 경계, I01 입력16항·변환·실패·상태 계약 후보, A6의 fixture/oracle, PR6의 실행 전 고정 항목이다. 준비 산출물의 수용은 가능하다.

**여전히 남는 것:** 실제 코드 변경 경로·공유 hunk·소유/허용 작업트리·통합 방식, 최신성 재확인, product 공간/진형/서비스/퇴로의 입력·측정, 상태 전체 필드/원자 커밋/지원 버전 판정, 검사 fixture의 최종freeze와 기기·표본/판정·실행 범위다. 옛 PC 실험 전체 병합은 opt-in 계약 준비의 필수 선행 조건이 아니나 실제 재사용·통합은 검증되지 않았다.

**즉시 추가 사람 질문이 반드시 필요한가:** 이 두 준비 문서를 수용하고 타입·필드·변환/오류 계약과 기존 근거를 더 정합화하는 데는 새 질문이 필수는 아니다. 실제 코드/측정 착수 전에 변경 소유·허용 경계/작업트리와 필요한 공간 기준 선택, 경험·지원 범위에 영향을 주는 정책 및 실행 범위를 정해야 한다. 소유를 증명하지 못한 외부 변경을 가져오거나 되돌리는 결정을 기술 기본값으로 대신하지 않는다. 단순 로그 필드나 불변식마다 새 승인 질문을 만들라는 뜻은 아니다.

불일치가 발견되면 해당 스펙·근거 책임으로 반환하고, 외부 5-b 반려는 플레이북2단계로 복귀한다. 문서 재시도 상한 K=3과 작성자/최종 심판 분리를 유지한다.
