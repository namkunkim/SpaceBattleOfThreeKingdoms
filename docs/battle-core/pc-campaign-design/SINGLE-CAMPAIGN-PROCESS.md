# 단일 캠페인 제작·적용 프로세스

캠페인 기본 환경이 준비된 뒤 신규 캠페인 한 편을 완성하거나 기존 캠페인에 새 작전·이벤트를 추가할 때 사용한다. 새 작업은 새 Codex 채팅에서 시작하고, 같은 작업의 검증·재심은 해당 채팅에서 이어간다. 적용 상태와 남은 작업은 [캠페인 적용 통합 체크리스트](CAMPAIGN-APPLICATION-CHECKLIST.md)에서 관리하고, 검증 증거는 작업 결과 문서에 남긴다.

## 1. 범위와 시작 조건 확인

캠페인·작전·이벤트 ID, 변경 범위, 기준 리비전 또는 빌드, 담당자, 독립 리뷰 담당과 인수 조건을 기록한다. P02·P03을 최우선으로 두고 통합 체크리스트에서 이번 작업이 의존하는 기본 환경의 판정 근거를 확인한다. 지도 진입, 전투, 결산 및 지도 복귀, 저장·이어하기 등 이번 범위에 필요한 기능을 실제 제품 경로에 매핑한다. 의존 기능이 막혔다면 필요한 조치·담당·재개 기준을 기록하고 시나리오 작성 등 독립적인 작업은 진행한다.

## 2. 시나리오 작성과 설계 검토

- 캠페인 전체에는 배경, 플레이어 세력, 시작 상태, 작전 순서, 분기와 결말을 정한다. 이벤트 추가에는 기존 작전의 삽입 지점과 앞뒤 이벤트·작전의 영향을 기록한다.
- 작전마다 지도 위치, 세력별로 보이는 정보, 함대·함선·장수 배치, 브리핑, 목표, 성공·실패·철수, 보상, 다음 작전으로 넘길 상태를 정의한다.
- 이벤트마다 ID, 발생 조건과 시점, 표시 내용과 선택지, 결과, 적용 순서, 반복 여부, 저장·복원 후 동작을 정의한다. 기존 저장에 신규 필드가 없다면 읽을 기본값과 기본값 적용 조건도 정한다.
- 인수 사례를 「초기 상태와 입력 → 플레이어가 보는 결과 → 기록되거나 승계되는 상태」로 작성한다. 정상 진행, 실패 또는 미충족, 적용 후 재진입을 포함하고, 동시 조건·리플레이가 영향을 받으면 해당 사례를 추가한다.

설계 검토에서 도달할 수 없는 분기, 기존 규칙과 충돌하는 조건, 필요한 데이터·에셋 누락을 확인한다. 구현에 필요한 항목이 설명되고 합의된 기대 결과를 재현할 수 있으면 구현으로 넘어간다.

## 3. 데이터와 제품 경로 구현

기존 작전·이벤트 데이터 구조와 API를 재사용하고, 실제 진입점에서 등록·로드되는지 확인한다. 변경 규모가 크면 대표 작전 또는 이벤트 하나를 진입부터 결산까지 먼저 연결한 뒤 나머지 콘텐츠를 적용한다. 시나리오의 ID와 인수 사례를 구현·검증 항목에 연결한다. 영향 범위에 따라 지도·브리핑·편성·전투·결산·복귀, 현지화·에셋, 저장·이어하기·리플레이 및 후속 작전 승계를 연결한다. 여러 이벤트가 함께 충족되거나 같은 이벤트가 다시 로드되는 경우 판정 순서와 보상·상태의 중복 적용 여부를 확인한다.

## 4. 구현 검증과 플레이테스트

- 자동 검증에서 데이터 참조와 조건 판정, 성공·실패 분기, 상태 승계 및 영향받는 기존 작전을 확인한다. 변경 범위에 맞춰 `tests/data_rules.gd`, `tests/battle_flow.gd`, `tests/world_link.gd`, `tests/localization_coverage.gd` 등 실제 적용 가능한 테스트를 선택한다.
- 대상 빌드의 정상 메뉴에서 진입해 대표 성공 경로와 변경된 실패·분기를 플레이한다. 저장에 영향이 있으면 이벤트 전후 저장·이어하기, 기존 저장 로드, 중복 지급 여부를 확인한다. 리플레이가 영향을 받으면 원본 결산과 비교한다.
- 변경된 화면·연출·오디오는 해당 장치에서 확인하고, 난이도가 달라지면 대표 전략과 실패 사례로 목표의 가독성, 난이도, 보상을 검토한다.
- 결과 문서에 빌드·실행 환경, 테스트 명령 또는 조작 순서, 입력 저장이나 시드(해당 시), 예상·실제 결과, 로그·캡처 경로를 남긴다. 자동 검증과 실제 플레이 결과는 각각 기록한다.

## 5. 독립 리뷰와 마감

구현 담당과 다른 리뷰 담당이 시나리오와 변경 사항을 대조하고 대표 사례를 같은 기준 빌드에서 재현한다. 코드·데이터 검토와 플레이 검토 결과에 각각 재현 조건, 영향, 수정 담당, 재검증 기준을 남긴다. 마감을 막는 지적은 수정하고 해당 사례와 영향받는 회귀 사례를 재실행한 뒤 리뷰 담당이 재심한다. 예를 들어 진행 불가, 저장 손상, 보상 중복, 다음 작전 승계 오류는 마감 전에 해결한다.

범위 내 인수 사례가 통과하고 차단 지적의 재심이 끝나면 결과 문서에 변경 범위, 최종 빌드, 검증 증거, 리뷰 판정 및 후속 항목을 남긴다. 통합 체크리스트에 판정과 남은 조건을 반영하고 담당 채팅의 제목을 `(DONE)`으로 갱신한다. 필수 검증이나 독립 리뷰가 남으면 `(ING)`을 유지하고 차단 조건·담당·재개 기준을 기록한다.
