# I01a/I01b 분리 선택 기록

2026-10-26 / **아래 §1~3은 분리안 채택 당시 기록이며, 최신 실행 승인·진행 상태는 §4~5를 따른다**.

입력은 조율자가 전달한 사용자 답변 **‘I01a부터 구현하는 분리안 채택’**이다. [플레이북](../../../워크플로우-플레이북.md), [readiness 분리 제안 §7](I01-READINESS-DECISION-20261026.md), [독립 검토](REVIEW-I01-READINESS-20261026.md)의 사용자 판단과 실행 범위 구분을 따른다. 본 파일이 이번 선택의 단일 기록 원본이며 기존 문서는 수정하지 않는다.

## 1. 받은 답변의 범위

- **채택:** 신규 순수 설정 구축·검증/fixture 조각 **I01a**를 먼저 진행하는 I01a/I01b 분리안.
- **유지:** 원래 전체 I01과 I01b의 실제 공간·지속 상태·운영 snapshot 요구는 남는다. 원 A04/A05/A06을 삭제하거나 I01a의 a01~a06으로 대체하지 않는다.
- I01a는 순수 Dictionary 설정·복제·변환/manifest와 가짜 FX-G fixture 범위다. 실제 BattleSim/OperationState 생성·host 활성화·운영 저장/suffix 실행·게임 통행을 제공하는 조각이 아니다.
- 첫 답변만으로 아래 두 번째 질문의 구체 코드·검사·작업경로를 승인했다고 추론하지 않는다. 시간 경과나 권고안 사전 선택도 승인으로 보지 않는다.

## 2. 아직 응답을 받지 않은 실행 범위

두 번째 질문은 **로컬 `93e60e6a957ffdb002a1cb06bc796c4c46496736` 기준 새 관리 작업트리 + 신규4파일 코드 + headless검사2종**이다. 현재는 응답 대기이며 다음은 허용 완료 목록이 아닌 **후보**다.

| 구분 | 대기 중 후보 |
|---|---|
| 코드4파일 | `core/battle/operation_profile.gd`, `tests/i01_operation_config.gd`, `tests/fixtures/i01/valid_definition.json`, `tests/fixtures/i01/invalid_definitions.json` |
| 검사2종 | 승인 작업트리에서 Godot headless로 `tests/i01_operation_config.gd`, 기존 `tests/data_rules.gd` 실행 |
| 작업경로 | 로컬 고정 ref의 새 관리 작업트리. 최신 원격 보장이 아니며 실제 생성·경로 확정은 아직 하지 않음 |

**현재 상태는 `CODE_AUTHORIZATION_PENDING`**이다. 두 번째 응답 전에는 이 파일 기록 외 코드·검사 실행·새 작업트리·git 변경을 하지 않는다. 원래 checkout의 15개 dirty와 소유 미확인 변경, PC 실험 checkout을 보존하며 PC 권한 조회도 재시도하지 않는다. 커밋·병합·푸시가 자동 포함되는 것도 아니다.

## 3. 기록 자체 5-a·인계

문서 K=3. 사용자 첫 답변/두 번째 미응답을 분리하고 입력3링크·원 I01/A04~06 유지·미실행 경계를 확인한다. 자체 검사는 독립 승인이나 실제 게임 시험이 아니다. 두 번째 답변이 도착하면 조율자가 실행 범위를 별도 기록·대조한다. 그 전에는 추가 독립 준비 조사로 범위를 넓히지 않는다.
## 4. 최신 실행 범위 승인 — 2026-10-26

입력은 조율자가 전달한 사용자의 후속 typed 지시 **‘이어서해’**다. 대기 중이던 새 관리 작업트리·신규4파일 코드·headless검사2종의 실제 진행 지시로 확인했다. 조율자가 그 범위를 사용자에게 설명하고 `i01a-operation-config` 작업트리 생성 절차를 시작했다. 앞선 `CODE_AUTHORIZATION_PENDING`과 미실행 문구는 그 지시 전 이력이며 시간 경과를 승인으로 간주한 것이 아니다.

**최신 상태: `I01A_EXECUTION_AUTHORIZED / WORKTREE_READY`.** 다음 범위만 승인됐다.

| 구분 | 승인 범위·경계 |
|---|---|
| 기준·작업경로 | 조율자가 도구 결과로 생성 완료를 전달했다. 경로 `C:/Users/nk782/.codex/worktrees/i01a-operation-config/SpaceBattleOfThreeKingdoms`, 로컬 base `93e60e6a957ffdb002a1cb06bc796c4c46496736`, detached 관리 작업트리. 이는 최신 원격 확인 또는 코드/검사 완료를 의미하지 않음 |
| 신규 코드/자료4파일 | `core/battle/operation_profile.gd`, `tests/i01_operation_config.gd`, `tests/fixtures/i01/valid_definition.json`, `tests/fixtures/i01/invalid_definitions.json` |
| 실행 검사2종 | 해당 작업트리의 Godot headless `tests/i01_operation_config.gd` 및 기존 `tests/data_rules.gd`. 아직 결과를 기록하지 않았으며 실행·통과를 추정하지 않음 |
| 실행자·독립 심판 | 코드 실행자는 `implementation_spec`, 작성 비참여 코드 검토자는 `final_independent_review`. 기록자는 승인·범위 문서만 갱신 |
| 불허·보존 | legacy/host 연결·BattleSim/OperationState 생성·운영 저장/suffix 실행·product 통행·전체 게임 구현은 미포함. 원 checkout의 dirty·PC 실험은 보존하고 PC 권한 조회를 재시도하지 않음. 기존 파일 변경·커밋·병합·푸시 없음 |

I01a는 명시적으로 분리된 순수 설정/fixture 조각이다. 원 전체 I01과 I01b, 원 A04/A05/A06의 실제 공간·논리시계·지속 상태/운영 snapshot 게이트는 그대로 남는다. a01~a06이나 설정 비교 결과로 원 검사의 전체 PASS를 선언하지 않는다. 허용4파일 또는 검사2종을 넘는 필요가 생기면 조율자에게 범위를 반환한다.

이번 갱신은 **구현 결과가 아닌 승인·실행 맥락 기록**이다. 작업트리 생성/경로는 조율자의 완료 결과를 연결했으며, 코드 작성·검사 결과·독립 검토 판정은 이후 실제 증거로 기록한다. 기록 실행자는 게임 코드·검사·브랜치 작업을 수행하지 않았다.

## 5. 자율 진행 지시·실행 부분 결과 — 2026-10-27

조율자가 전달한 사용자 최신 지시 **“내 컨펌 없어도 계속 진행”**에 따라, 합의된 I01a 범위의 구현·검증·수정은 단계별 추가 확인 대기 없이 진행한다. 이 지시는 기존 공유 코드 수정, host/runtime/save 연결, 커밋·병합·푸시를 자동 허용하는 범위 확대가 아니다. 앞선 대기/미실행 문구는 당시 이력이다.

신규 4파일은 승인된 작업트리에 배치 완료했다. 실제 Godot headless I01a runner는 exit 0, 설정 구축 60·명명 거부 24·추가 반례 17·326체크 및 a01~a06 PASS다. 기존 data_rules는 exit 1로 기존 battle_sim.gd:1019의 170.0 리터럴을 지목했다. 해당 파일은 수정하지 않았고 별도 baseline 실행은 없으므로 전후 실행 실패 일치를 주장하지 않는다. 두 검사 전체 PASS 상태는 아니다. [독립 5-b 검토](REVIEW-I01A-IMPLEMENTATION-20261027.md)는 신규 4파일의 잔여 반려 없이 조건부 수용했다. 기존 170.0 실패는 target/HEAD 코드·검사 blob 동일성으로 확인됐지만 baseline 실행 결과는 아니며, data_rules의 후속 검사는 미실행이다.

현재 상태는 **I01A_IMPLEMENTED / I01A_RUNNER_PASS / DATA_RULES_FAIL / INDEPENDENT_CONDITIONAL_ACCEPT**이다. 정확 4파일 해시·실제 로그·생성 metadata 백업·최종 변경 감사·미검증 경계는 [구현 결과](I01A-IMPLEMENTATION-RESULT-20261027.md)에 기록했다. 원 I01/I01b와 원 A04/A05/A06 NOT_READY는 유지한다.
