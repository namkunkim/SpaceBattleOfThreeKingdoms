## 1. 승인과 후보 계약

사용자는 `p05-layout-disks-v1`을 첫 작전의 논리 외곽으로 채택했다. 적용 대상은 LIU01 39척과 LIU02 21척의 FRM-01↔03 양방향 전환 및 동시 운용, C 수비 CAO04 45척 FRM-04, R 증원 CAO05 30척 FRM-03이다. 원형 반경은 배정 독립 상계 **75.457852 / 50.059254 / 87.179651 / 47.927882** 전술 단위다. 새로 산정한 편차·안전 예산, 회랑과 영역 반경, 정지 좌표와 속도는 아래 검증 후보에서 사용했다. [승인 모델 산정](P05-PC-FORMATION-ENVELOPE-EVIDENCE-20261109.md) · [지도와 노드](P05-PC-MAP-INPUT-EVIDENCE-20261109.md).

정상 구간에서 계획과 실제 중심을 같은 시각의 두 끝점 사이에서 각각 직선으로 잇는 후보라면, 양끝 오차의 볼록 결합도 2 이하라서 연속 구간 전체를 덮는다. 구간 접합은 도착과 선회/정지를 명시적으로 나눈다. 팽창 반경은 각 외곽과 편차를 이미 포함한다. 별도의 중심 벽 제한 40은 외곽 여유에 더하는 대신 두 조건을 각각 검사한다. 오프라인 스크립트는 이 기하 계약과 가드 예시를 검사하며, 실제 코어에 가드가 있다는 증거는 아니다. [중심 제한](../../../core/battle/battle_sim.gd#L1163) · [양자화](../../../core/battle/rules.gd#L38).

## 2. 기존 추종의 한계

코어는 함대 중심을 heading·이동 속도에 따라 전진시키거나 접적/평행 이동 분기로 보낸다. 경유점 도착은 기존 반경 `arrive_r=10` 안에서 다음 점으로 넘어가는 방식이다. 10Hz에서 논리 틱 0.10초를 보통 0.05초 하위 걸음으로 나누고 틱 끝에서 좌표를 양자화한다. legacy PC가 이동·선회에 150/15를 적용한 뒤 이동 선회율은 기준 9°/초의 15배인 135°/초, 도착 제자리 선회율은 36°/초다. 속도는 교전·스킬·비용·돌격 등으로 달라진다. 이 경로에는 계획 기준점과의 거리 2를 매 걸음 검사하는 장치가 확인되지 않았다. 예를 들어 경유점까지 9 남은 위치에서도 legacy 도착 조건을 만족할 수 있지만, 후보의 경유점 정지 오차 2는 그 상태를 허용하지 않는다. [경유점·이동](../../../core/battle/battle_sim.gd#L1023) · [하위 걸음](../../../core/battle/battle_sim.gd#L936) · [도착 반경](../../../data/profiles/poc_corridor.json#L60) · [선회 변환](../../../core/battle/scenario_profile.gd#L128) · [기준 선회율](../../../data/profiles/combat_m3.json#L600).

렌더러는 최초 슬롯 생성 시 목표 슬롯으로 스냅한다. 이후 실제 표시 위치를 따로 보관하고, 샘플 `h=min(acc,0.25)`에 대해 `α=h/(τ+h)`, `τ=0.3초`로 목표를 추종한다. 샘플 중심을 `c_n`, 회전·전환된 명목 슬롯을 `q_n`, 표시 위치를 `s_n`, 오차를 `e_n=s_n−c_n−q_n`으로 쓰면, 연속 갱신 구간의 속도 예측 `(c_n−c_prev)/h` 때문에 중심 이동 항은 소거된다.

```text
e_n = τ/(τ+h) × (e_prev + q_prev − q_n)
||q_n−q_prev|| ≤ K × elapsed, elapsed ≤ ρh
⇒ ||e_n|| ≤ max(||e_0||, τρK)    [갱신 직후, 가정 충족 구간]
```

예시로 heading 속도 ≤135°/초, LIU01의 최대 슬롯 반경 59.075757, 5초 선형 전환, `ρ=1`이면 `K≤59.075757×(135π/180+2/5)`로 잡아 슬롯 표시 중심의 조건부 상계 **48.847283**을 얻는다. 5초는 legacy 일반 값의 예일 뿐 숙련·특기·즉시 전환이 가능하다. `acc>0.25`일 때 `ρ=1`이 깨질 수 있고, 갱신 건너뜀·불연속 pose 변경·샘플 사이 화면 오차는 위 예시가 보장하지 않는다. 정확한 180° 반전과 슬롯 점대칭이 동시에 적용되면 명목 세계 슬롯은 유지되지만, 일반적인 즉시 전환까지 덮지는 않는다. 화면상 조건부 상계를 제품의 논리 편차 2나 안전 여유 1에 합산하지 않는다. 아군 두 경로 모두 그룹 중점 기준 반경 **145.457852**로 캡슐 안에 든다. 각 선분을 감싸는 캡슐과 월드 사각형은 볼록하므로 선분의 양끝 및 반경 대조가 연속 구간을 보장한다. 접합점에는 회랑의 끝원 전체가 들어 있고 고정 중심에서 heading만 바꾸므로 정지·재출발·반대 방향 회전도 같은 외곽 안이다. 정면 전진 heading은 −51.546291°, −33.690068°, 43.264295°이고 우회는 −51.546291°, 66.175739°, −1.548158°, −40.872408°다. 역방향은 각 구간을 180° 바꿔 역순으로 진행한다. P07의 C 점령, E 철수 완료, R 시간 증원과 아군 동시 교전은 이 정적 접근 검사와 별도다.

**음성 1 · 실제 폭 부족.** J→A의 전진 축 거리 205.346955–245.346955에 옆으로 새지 못하는 횡단 목을 두고 그 구간의 물리적 반폭만 60으로 줄인다. 같은 edge와 시작·종료는 유지한다. 연속적으로 J에서 A로 가려면 중간 횡단면을 통과해야 하며, LIU01의 **채택 외곽만 적용해도** 반폭이 15.457852 부족하다. 경계에 원을 옆으로 붙이거나 heading을 바꿔도 채택 원이 그 단면에 들어갈 수 없다. 대체 경로의 우회 양성은 유지한다. 이 결과는 횡단 목을 강제한 검증 회랑의 기하 실패다.

**음성 2 · 가동 서비스 접근 불가.** 별도 지도 사본에서 A 가동 상태·정면 경로를 유지하고 서비스 영역만 (0,240), 반경 20으로 바꾼다. 도착 가능한 서비스 중심의 x는 최대 20이며, 전장 안 합법 중심은 x≥40이다. 전체 지도에서 20 간극으로 교집합이 없어 A 서비스만 실패한다. 정면 항로의 기하 양성과 B 서비스 양성은 유지된다.

## 4. 재현·인계

[P05 접근 검증 스크립트](p05_map_access_validation_20261109.py)를 Python 3으로 실행하면 이전 외곽 스크립트의 반올림 전 값을 받아 각 경로의 좌표·heading·양성 여유, 두 음성 이유, 중심 오차 2의 경계 예를 JSON으로 출력한다. 입력 파일을 읽고 표준 출력만 사용한다. 원본 HEAD `0be09755b703`에서 확인했다. 스크립트 SHA-256은 `990e945af8ae09305de98d04720c30f15b16dbb2f1691af51dd0fa757e08765e`, 불러오는 [외곽 스크립트](p05_formation_envelope_probe_20261109.py) SHA-256은 `f106c2b51a02037bd70967ef5d69b41b029ba7e218833217b79d6eb40e371f40`이다. 기존 지도/외곽 산정과 공유 파일, P02/P03 제품 파일에는 쓰지 않았다. 엔진·UI는 실행하지 않았다.

다음 구현에서 P05는 이 후보의 회랑/영역/안전 수치를 승인 입력으로 동결하고, 전투 이동 담당은 중심·swept 가드와 실패 원자성을 연결한다. P02는 실제 시작·명령·결과에서 동일 manifest를 확인하고, P03은 진형과 이동의 소유 경계를 확인하며, P07은 가동 보급·시간 증원·목표/철수 사유를 연결한다. PC 제품에서 같은 정·부 사례를 재현할 때까지 제품 A04는 **NOT_READY**다.
