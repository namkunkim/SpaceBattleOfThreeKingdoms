# H0 — PC 맵·캠페인 작전 범위 사용자 결정

2026-10-25 / **사용자 범위 선택 기록 완료·세부 정책/독립 검토 상태 별도**.

기록 실행자: D02 소유 실행자. 입력: 조율자가 전달한 사용자의 H0 명시 선택. 근거 절차: [플레이북](../../../워크플로우-플레이북.md) 0·5·6단계, [작업 분해](../PC-CAMPAIGN-WORK-BREAKDOWN-20261025.md) §4 H0/수용본 계약. 계획에 H0 결정 전용 파일 경로가 없어 이 파일을 **H0 범위 선택의 단일 기록 원본**으로 사용한다. [D02 §9](D02-SCOPE.md)는 이 기록의 요약이며 이전 대안 비교·O02 OPEN 표시는 선택 전 이력이다.

## 1. 사용자 선택과 채택 범위

| 결정 ID | 사용자가 선택한 내용 | 의미와 경계 |
|---|---|---|
| H0-01 | **A안: 단일 성계 연속작전** | 한 작전 공간에서 이동·조우·교전·점령 후 보급이 이어지는 범위. 다중 국지전 화면 연결 또는 적벽 확장을 이번 기준으로 선택한 것이 아님 |
| H0-02 | 첫 유형은 **보급로 개방** | 주제는 점령한 보급 기반을 이용해 다음 목표를 수행하는 작전. 가칭 ‘강하’ 명칭·기존 제안 전체를 승인한 것은 아님 |
| H0-03 | **정면/우회 선택** 포함 | 두 항로의 선택을 설계한다. 정확한 노드 수·좌표·거리·수비력·재고 배분은 미정 |
| H0-04 | **기본 시간 경과 증원** 포함 | 지연하면 적 증원이 접근하는 압박을 설계한다. 20분 도착·16분 출발·편성·지연량 등 예시 수치는 미채택 |
| H0-05 | **호송 차단·통신소 지연·재점령까지 설계** | 세 요소는 이번 설계의 포함 범위다. 이후 따로 승인할지 미정인 기능으로 되돌리지 않는다. 실제 일정·효과·상태 전이는 후속 정책 검토 |
| H0-06 | **제작 순서는 분리** | 기본 작전과 확장 기능을 순차 제작할 수 있게 분해한다. 설계에서 확장 요소를 누락하거나 코드 제작을 즉시 시작한다는 뜻이 아님 |

이번 결정으로 **O02의 H0 범위 항목만 해소**됐다. 설계 실행자는 이후 A/B/C 미선택 상태를 이유로 범위 논의를 다시 멈추지 않는다. B안·C안은 D02의 대안·반대근거 이력으로 유지한다.

## 2. 채택하지 않은 수치·정책과 기존 게이트

| 항목 | 현재 상태·소유 |
|---|---|
| O01 | **OPEN**. 20분 목표와 게임/실제 시간 기준·최종 페이싱은 D03/D09·H1/H2 |
| O03 | **OPEN**. 좌표·지도 크기·속도·진형 외곽·통로 폭·서비스 반경은 D03 및 승인된 측정 |
| O04 | **OPEN**. 점령 진행/가동·경합/재상실·유한 재고/유입·사기 회복/비용·증원 후 사기 모집단은 D06/D07·H1 |
| O05 | **OPEN**. 사건 일정·편성·이동시간·통신소 지연량·같은 틱 순서·철수 분모/증원 포함·동시 종료 우선순위는 D06/D08·H1 |
| O06 | **OPEN·시점부 기반 제약 유지**. 최신 브랜치 차이/미커밋 소유/실제 통합 가능성은 D01 및 미래 구현 직전 확인. H0가 병합 안전성을 승인하지 않음. PLAN D01 카드가 허용한 일반 대안 조사와 읽기 기반 D03/D04 설계는 계속할 수 있으나 코드 통합 가능성 확정·실제 통합은 차단 |
| O07 | **OPEN**. 저장 스키마·호환/재생 범위는 D04·H1. 확정 전 상태 계약을 쓰는 게임 구현 착수 불가 |
| O08 | **OPEN**. 신규 사람 플레이/성능 표본과 수용 기준은 D09·H2 |

Q67 적용 범위는 D01/D03이 실제 변경 범위로 판단한다. 적용 시 차이 목록 B항 등재·1000시드 재측정 게이트를 유지한다. ‘신규 성계’ 선택만으로 적용 또는 면제를 확정하지 않는다. 기존 적벽의 승패·사기·Q84 철수 규칙을 전역에서 바꾸는 승인도 아니다.

**명시 비승인:** 게임 코드·데이터 구현, 게임/테스트/1000시드/사람 플레이 실행, 브랜치 변경·병합, 커밋·푸시. 기존 S1/S2 수치·시설 규칙·노드 배치·이름·모든 권고도 포괄 승인하지 않았다.

## 3. D03/D04에 전달할 입력

공통 전달: 이 파일 전체 + [D02-SCOPE.md](D02-SCOPE.md)의 범위 비교/반례/§9 최신 결정 + [D01-BASELINE.md](D01-BASELINE.md) 기반 제약 + [검토 스펙](../PC-CAMPAIGN-REVIEW-SPEC-20261025.md) + [작업 분해](../PC-CAMPAIGN-WORK-BREAKDOWN-20261025.md)의 공통 계약·해당 카드. 선행 독립 검토 기록은 존재/판정 확인 후 첨부한다.

- **D03 공간·시간:** 단일 성계의 정면/우회·보급/최종 목표와 호송·통신소·재점령·시간 증원의 공간/시계 요구를 모두 수용한다. 20분·7노드·6800×4600·속도30은 미확정 예시다. 필수 경로·보급 접근·퇴로와 동시 활동을 검토하되 폭/좌표를 측정 사실로 만들지 않는다.
- **D04 상태:** 한 작전 안에서 같은 함대 ID와 손실·탄약·사기·위치/명령을 유지하는 기본 후보 계약에 더해, 호송·통신소 지연·재점령·예약 증원의 상태 확장 자리·소유자·중복 방지를 포함한다. D06~D08 미정 정책의 값을 지어내지 않는다. 기능 제작 순서가 뒤여도 초기 상태 계약에서 빠뜨리지 않는다.

**게이트 상태:** 사용자 범위 선택은 기록됐다. evidence_audit의 [D01 독립 검토](REVIEW-D01.md)·[D02 독립 검토](REVIEW-D02.md)는 모두 **문서 수용**이며 파일 원문에서 확인했다. 최초 수용 당시의 O02 미선택은 이번 H0 선택 기록으로 갱신된다. D02 작성자가 독립 수용을 추론하거나 새로 판정한 것이 아니다. 후속 인계 시 이 리뷰 기록과 적용 범위를 함께 제공한다. O06의 PC 작업 트리 청결·통합 가능성 미확인은 읽기 기반 D03/D04 설계검토 자체를 막지 않으며, 실제 코드 통합과 최신 통합 가능성 확정은 계속 차단한다. 독립 검토 반려가 발생하면 2단계 스펙으로 반환하고 사용자 선택 자체를 임의 삭제하지 않는다.

## 4. 기록·자체 5-a

허용 변경: 이 파일 신설, D02 §9 추가, CHECKLIST-OPEN의 PC 맵·캠페인 새작업 블록만 갱신. BATTLE_DECISIONS의 기존 Q는 수정하지 않았다. 게임·테스트·브랜치 작업은 수행하지 않았다.

기록 검사 1회(K=3): 선택 6개, O02 범위 해소와 O01/O03~O08 미정, 확장 3요소 포함/제작순서 분리, 비승인 경계, D03/D04 인계 항목·원문 링크 존재를 대조한다. 이는 결정 전달의 자체 완결성 검사이며 독립 5-b 판정이 아니다.
