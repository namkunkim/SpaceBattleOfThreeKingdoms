## 2. 물자·서비스 권위와 자원 경계 — R09

**권고:** 거점 소유·가동은 D06, 실제 재고·예약·소모/이전 원장은 D07, 호송/증원 도착 사실과 시각은 D08이 소유한다. 임무·UI가 직접 물자를 지급하지 않는다. 자기 재고는 정확한 장부로, 적 재고/화물은 D05의 허용 정보로만 표시한다. IP1은 미채택 권고 상태를 유지한다.

**시설 가동과 재고는 별도다.** 빈 창고는 현재 서비스 가능한 물자가 없다는 뜻이며 시설 소유/가동 완료를 자동 취소하는 조건으로 추가하지 않는다. 선택된 주목표는 현재 통제·가동을 요구한다. ‘최소 재고 보유’나 ‘보급작업1회 완료’를 새 승리조건으로 몰래 추가하지 않는다. 확보 이력과 현재 상태도 별도로 D06 결과 계약에 전달한다.

**유입·고립 권고:** 아군 진입점/공급망과 연결되면 명시한 재적재 유입을 받을 수 있다. 단순 지도선 연결과 안전/통제 연결 판정은 D03/D06 입력으로 구별한다. 연결이 끊기면 **새 유입만 중단**하고 현지 잔여재고·휴대한 보급함 재고는 사용할 수 있다. 재고 삭제·이미 완료한 수리 취소·전역 즉시 공급불가로 바꾸지 않는다. 연결은 UI에 이유와 마지막 갱신을 표시한다.

유한성을 유지하기 위해 연결 유입은 **정의된 작전 외부 보급예산/예약 물량→시설**의 자원이전으로 표현하는 안을 권고한다. 유입률·시설용량·작전별 총 유입 예산을 표시하고, 끊겼다 이어져도 미사용 예산을 새로 생성하지 않는다. 무제한 유입을 허용하는 대안은 적 화력을 정비로 무효화할 위험이 있어 비교 검증 없이는 기본안으로 채택하지 않는다. 실제 수송을 모두 물리 호송으로 만들 필요는 없다. 호송 화물과 추상 유입이 같은 원물량이면 이중으로 예산/재고를 더하지 않는다. 숫자·재충전 일정은 O04/D08 실험 후보다.

## 3. 서비스 상태·대기열·거래 후보

H1의 **점령** 중단량 보존은 보급/정비 주기 보존까지 승인한 것이 아니다. 보급은 현행 이동 시 진행0을 우선 비교 기준으로, 사기정비의 정지/환불은 아래 후보로 둔다. 순간이동·강제 자동진형 변경으로 서비스 접근을 해결하지 않는다.

| 상태 ID | 진입·진행 | 완료·정지·취소·재개 후보 |
|---|---|---|
| S01 요청/대기 | 자기 진영·동맹허용·정상 공급원, 반경/유효접근·정지·필요작업 검사 | 빈재고/자리없음은 대기 사유. 공급원/작업을 지정할 수 있게 하며 즉시 회복하지 않음 |
| S02 배정/예약 | 처리자리+작업에 필요한 가용재고를 같은 원자적 배정으로 예약 | 예약은 stock에서 차감된 소비가 아닌 사용권. 다른 손님은 reserved를 제외한 available만 사용 |
| S03 처리 | 주기 진행은 공급원 처리량·작업자 상태·단일 게임시계로 누적 | 일반 보급과 사기정비의 안전 조건을 분리. 공급원 손상으로 처리량/자리가 줄면 안정 순서로 재배정·취소 |
| S04 완료 | 소유epoch·대상·잔존플랫폼·필요량·예약유효성을 재검사 | 실제 제공분의 비용+효과+완료키를 한 거래로 적용. 남는 예약은 해제. 새 부족분이 예약을 넘으면 증액예약 가능분만 재검사하거나 다음 작업으로 넘김 |

| S06 경합/소유변경 | 경합 중 새 작업 배정 정지 권고. 소유변경이면 옛epoch 서비스 전부 무효화 | 진행중 경합 처리는 유효조건 미충족으로 중단 권고. 미사용예약은 같은 저장고로 해제하며 옛 소유군에 외부환불하지 않음. 재가동 후 새 소유/허용관계로 다시 배정 |
| S07 공급원손실/파괴/용량변경 | 보급함 손실·시설 물자손실은 실제 남은 재고/용량 계산 | 감소 후 예약을 다시 검증하여 음수재고 금지. 이미 파괴된 물자를 취소환불로 부활시키지 않음. 손실/폐기 기록은 거래 원장에 남김 |

**대기열 권고:** 현재의 진행중 손님 자리 유지·명시 우선→탄약비율→정지시각→안정 ID를 출발점으로 삼되, 사기정비·수리·재적재의 필요가 탄약비율 하나에 묻히지 않게 **작업유형/요청**을 구별한다. 사용자가 지정한 정비와 자동탄약 작업이 하나의 물자/자리를 중복 예약하지 않게 조정한다. 주기 완료 후 다음 작업을 재배정하며 자동 정비가 모든 자리를 영구 독점하지 않게 검토한다. 최소 처리대기·우선순위 가중·슬롯 분할 수치는 실험 대상으로 두고 새 숫자마다 승인 질문을 만들지 않는다.

**원자성 권고:** 작업별 비용/효과를 구별해 예약하고, 한 완료 거래 안에서 검사→실제소모→회복/전달→완료키를 함께 커밋한다. 한 틱에 여러 손님이 같은 마지막 물자를 모두 쓰거나, 지원함A→B→A 순환으로 물자를 늘리지 못해야 한다. 일반탄약·횟수·수리·정비를 묶어야 한다면 합계 비용을 먼저 예약하고, 개별 작업이면 독립 거래ID/작업결과를 남긴다. 구체 배치 방식은 O07과 대조할 일상 설계 선택이며 별도의 사용자 플레이 정책 질문이 아니다.

**취소 대안:** 위 기본안은 미완료 효과/소비0으로 일관성이 쉽지만 반복 취소로 시설을 묶을 수 있다. 시작 시 일부물자 소모+부분 진행 보존 대안은 소모·취소 손실을 이해하기 어렵고 무료회복/재입력 악용 검증이 추가된다. 기존 주기 완료 차감과 가까운 **예약 후 완료소모·취소 시 미사용해제**를 권고하며, 완료분을 원상복구/무료재사용하지 않는다. 점령 중단량 보존 정책을 바꾸는 것이 아니다.

장부의 최소 일관성은 **기초재고+실입고−실출고−실소모−실손실=현재재고**, 예약은 실소모가 아니라 그 안의 묶인 가용량이다. 한 자원이 시설→보급함→함대 탄약으로 이전되면 각 이동의 출처·목적지·단위/변환을 기록한다. 소유가 바뀌어도 저장고 인스턴스는 그대로이며 재점령 횟수만큼 물자가 늘면 실패다. 실제 적 화물량은 플레이어/AI에게 무조건 공개하지 않는다.

**정비 안전 권고:** 마지막 피격/사격 후 안전대기·유효 정지·자기/공유 관측에 알려진 근접위협과 시설 통제/경합을 이용한다. 안개 너머 적 실제 좌표로 ‘회복불가’ 경고를 켜 정보누설하지 않는다. 위험이 다시 성립하면 다음 미완료 정비주기를 중단하며 완료된 회복은 유지한다. 안전대기·회복량/상한·물자소모·재투입 기준은 기존 사기 상태와 D06 정책을 따라 비교할 수치 후보이고 미측정이다.

정비는 결집 사용횟수·군사기 사건 latch를 재설정하지 않는다. 기존 결집의 사기증가/손실감소는 고유효과로 유지하고, 정비는 별도 물자작업으로 실제 증가분만 적용해 상한을 넘지 않는다. 중파→경파 수리·경파 자연회복·사기회복 각각 별도 원인/효과를 기록한다. **대파/격침/항복 함대의 재생, 신조함 보충, 연료 신규 의무화는 넣지 않는다.**

## 6. D08·D04/D10 인계와 잔여 판단

**D08 최소 입력 계약:** 공급원/화물/거래 ID, owner_epoch, 실제/예약/가용재고, 서비스 상태/취소 사유, 연결상태·유입원장, 완료/미배송 화물량, 정비/소유 전이 사실과 단일 논리시각을 전달한다. 예정/출발/진입/목표도착/배송이 별개라는 사건 계약을 유지한다. 같은틱 `재점령↔보급완료`, `호송도착↔소유/용량변경`, `연결상실↔유입`, `공급원피해↔예약/완료`, `작전종료↔지급`의 순서는 D08과 대조한다. 어느 순서를 택해도 동일 커밋의 소유권·유효성·장부를 공유하고 종료 뒤 새 게임효과를 생성하지 않는 일관성 원칙을 권고한다. H1의 목표/지휘 동시 실패우선 외 전역 순서는 미확정이다.

**D04 요청 D07-REQ:** R09/R10·O04 및 ST09~12/15/17/18에 `source/cargo/transaction_id`, `owner_epoch`, 단위별 `stock/reserved/capacity`, 작업/대기열·예약내역/시작·진행/완료/취소, 순입출고/손실/연결유입예산·누적나머지, 사기정비 적용량·원인·결집참조를 후보로 요청한다. 정본작성자는 재고/서비스 D07이며 소유/가동 D06·일정 D08의 참조를 읽는다. 기본값 없음은 완료/지급으로 간주하지 않는다. 값의 단위·전이시각·재구성/지문 필요를 정리해 D10에서 누락/중복을 색인화하고 D04 소유자에게 수정 요청한다. 스키마/커밋 O07은 선택하지 않았고 다른 문서를 수정하지 않는다.

**잔여 판단:** 사용자 선택된 현재가동/유한정비/지역복귀 방향을 다시 묻지 않는다. 예약후완료소모·고립잔여사용·잔여노획·유입예산·빈재고와가동분리는 그 방향을 구체화한 **권고 정책**이며 일관성/멱등성·정보제한 원칙과 함께 후속 정합화한다. O04에는 실제 재고/유입/회복량/비용·중단 세부를, O05에는 배송·소유/종료의 같은틱을, O07에는 저장/원자커밋을 남긴다. 새 핵심 플레이 방향을 바꿀 실질 선택이 드러날 때만 묶어서 사용자 판단으로 올리고 기술필드/수치마다 중단하지 않는다. 수용 후 D08의 사건 설계는 가능하나 잔여 정책이 확정된 게임 구현 인수 스펙으로 승격하지 않는다.

Q67의 변경범위 대조·적용 시 B항+1000시드/비적용 근거, O06 코드통합 재확인, O07 상태기반 구현게이트는 별도 유지한다. 이번 D07은 효과지형 단계에서도 성립하는 거래 계약이며 물리장애물이 이미 구현됐다고 전제하지 않는다.
