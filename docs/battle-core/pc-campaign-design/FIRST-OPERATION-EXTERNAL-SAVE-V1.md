# 첫 작전 외부 저장 v1

Windows E 개발 작전에서 진행 중인 전투 한 건을 사용자가 선택한 파일로 내보내고 다시 가져오는 계약이다. 같은 승인 규칙·입력·엔진 빌드에서 seed 208, standard 난이도, direct 모드, front 또는 flank를 지원한다. 이 범위의 외부 파일과 P04의 내부 로컬 슬롯은 서로 다른 포맷이다. 전체 캠페인, 종료 전투, 관람 기록, 배포 PCK 및 다른 플랫폼의 지원은 O07에 남는다.

## 파일과 API

- 확장자는 `.pcopsave`다. 명시적인 로컬 Windows 드라이브 절대 경로를 받는다. 내부 슬롯, 상대 경로, UNC·장치 경로, 상위 디렉터리 구성요소와 대체 스트림은 지원하지 않는다.
- `first_operation_external_save.gd`의 `write(packet, path)`는 라이브 owner의 `capture_checkpoint().packet`을 받아 새 파일을 만든다. 이미 존재하는 대상은 거부한다. 같은 디렉터리의 임시 파일에 기록·검증한 뒤 이름을 바꾼다. 경로 점검과 쓰기는 같은 게임 프로세스 안에서 직렬화한다.
- `read(path)`는 `{ok:true, payload}`를 반환하며 파일, 내부 슬롯, 활성 owner를 바꾸지 않는다. 호출자는 `FirstOperationDev.begin_restore(payload)`로 별도 후보를 검증한다. 검증 성공 후에만 게시한다. 실패·취소 시 후보를 폐기하고 현재 전투와 저장 파일을 보존한다.
- 오류는 `{ok:false, error, path}` 형식이다. 버전·크기·체크섬·입력·규칙 지문 불일치와 재생 검증 실패를 구분한다.

## 바이트 표현

UTF-8 JSON 한 개로 작성한다. BOM과 후행 줄바꿈은 없다. 외부 v1의 정규 표현은 정렬된 객체 키, 공백 없는 구분자, 검증된 정수 필드로 구성한 Godot `JSON.stringify(value, "", true, true)` 출력이다. 객체 키 중복, 정규화 전후 바이트가 다른 표현, 추가 필드는 거부한다. 바깥 객체와 body 각각의 중첩을 파싱 전에 8단계로 제한한다. 바깥 파일은 최대 1 MiB다.

| 바깥 필드 | 의미 |
| --- | --- |
| `format` | 정확히 `pc-first-operation-external` |
| `version` | 정수 `1` |
| `body` | 아래 필드로 이루어진 정규 JSON 객체를 담은 문자열 |
| `sha256` | 이스케이프를 해제한 body 문자열을 UTF-8로 인코딩한 SHA-256, 소문자 64자리 |

| body 필드 | 의미 |
| --- | --- |
| `request` | `capability`, `definition_id`, `definition_version`, `roster_id`, `seed`, `difficulty`, `mode`, `route_id`의 원 작전 요청. 개발 작전 정의 v1과 지원 선택 조합만 허용 |
| `operation_id` | 원 작전의 안정 ID. 재생 사건과 결산의 ID 네임스페이스를 유지 |
| `rules_digest`, `source_digest`, `effective_digest` | 현재 승인 코어·엔진과 원본·유효 입력의 지문. 외부 v1은 현재 규칙 지문을 요구하며 입력 지문은 복원 후보에서 다시 확인 |
| `tick`, `clock_ms` | 커밋 완료 논리 틱과 밀리초. 10 Hz에서 `clock_ms = tick × 100`. 최종 시한 틱과 재생 중 검출된 종료 상태는 거부 |
| `commands` | 적용된 명령 배치. 각 행은 `{tick, batch}`이며 틱은 적용 직전 시점, 오름차순·중복 없음 |
| `pending` | 저장 당시 대기 명령 순서. 적용 배치와 합해 최대 16,384개이며 각 배치는 최대 256개 |
| `event_cursor` | 게시된 side 0 사건의 소비 커서. 초기 화면 사건은 별도 인수되며 재생 중 과거 소비분을 다시 발행하지 않음 |
| `proposal_serial` | P07 정책 제안 번호의 저장 시점 상한. 폐기된 제안 번호 재사용을 방지 |
| `state_digest` | 재생한 전투 상태·경로·정책 원장·명령·미소비 사건의 일치 검증값 |

명령은 `{"kind":"move","goal":n}` 또는 `{"kind":"stop"}`, `{"kind":"withdraw"}`, `{"kind":"finalize_withdrawal"}`이다. `goal`은 선택 항로의 웨이포인트 인덱스다. 명령의 시점·선택·경로 적법성은 실제 재생에서 검증한다. 전투 객체, 리소스 경로, 코드, UI 투영을 파일에서 역직렬화하지 않는다. 네이티브 상태, RNG 입력과 카운터, P05 경로 진행, P07 원장 및 미소비 사건은 정본 입력과 명령으로 재구성한다.

## 호환과 이전

현재 로컬 슬롯의 외부 이전은 지원되는 로컬 저장을 정상 복원한 후 새 외부 파일을 명시적으로 내보내는 방식이다. 로컬 원본과 이전 세대를 유지한다. 이전 로컬 지문의 한정 호환은 내부 매니페스트에서만 적용한다. 외부 v1에는 현재 규칙 지문으로 캡처한 패킷을 기록한다. 버전 숫자, 지문 또는 파일 확장자를 바꾸는 방식의 자동 마이그레이션은 지원하지 않는다.

SHA-256 체크섬과 재생 지문은 손상 및 불일치 검출 수단이다. 서명, 작성자 인증, 암호화, 플랫폼 간 실행 동등성은 제공하지 않는다. 현재 규격은 개발 실행의 코어 파일과 엔진 지문을 사용한다. 배포 빌드의 정본·마이그레이션 정책, 캠페인 전역 사건 커서와 결산 지급 확인은 O07에서 별도 결정한다.
