# 구현 인수 스펙·측정 계획 준비 독립 검토

2026-10-26 / final_independent_review / **조건부 준비 문서로 수용**.

대상은 [구현 스펙 준비](IMPLEMENTATION-SPEC-20261026.md)와 [측정 계획 준비](MEASUREMENT-PLAN-20261026.md)다. 검토자는 두 문서 및 D01~D10·H2 기록의 작성·수정에 참여하지 않았다. 작성자의 최종 자체 5-a 인계 후 두 문서 전체를 [H2 원본](H2-DECISION.md), [H2 독립 검토](REVIEW-H2.md), [D10](D10-INTEGRATED-REVIEW.md), [D09](D09-UX-EVALUATION.md), [R18/O8 스펙](../PC-CAMPAIGN-REVIEW-SPEC-20261025.md), 플레이북·기존 결정·현재 정적 코드와 대조했다.

## 1. 판정과 범위

실질적인 요구 누락·근거 오류·사용자 선택 변경·미정의 무단 확정은 발견하지 못했다. **다음 준비 작업의 입력으로 두 문서를 수용**한다. 첫 코드 조각을 즉시 시작할 수 있는 확정 스펙, 실행을 승인한 실험 계획, 게임 기능·밸런스·성능 검증 결과로 수용하는 것은 아니다.

| 독립 검토 축 | 판정·근거 |
|---|---|
| H2 및 선행 선택 | 조건부 설계 수용/문서 준비, 전체 상태+후속 명령·동일 규칙 버전 재개, 제한 정보·필수 일정 공지가 구현 문서 §1~2에 보존된다. 목표·철수·정비·사건 선택도 일치하며 후보 수치를 확정하지 않는다. |
| 첫 조각 I01 | opt-in 실효 설정·공간 입력의 목적, 현재 코드 변경 후보, 입력·출력·중단·A01~A06이 있다. 기존 적벽/POC 기본값 보존, 잘못된 신규 정의의 명시 실패, 반복 구축·중복 배율 방지, 단위/버전·공간 접근·시계·상태 계약이 판정 가능하게 제시된다. 후보 새 경로와 테스트 이름이 미작성임을 명시한다. |
| 착수 게이트의 적정성 | I01은 단순 문자열 선택기만이 아니라 공간 접근·프로필/지속 상태 경계를 포함하므로 O03/O06/O07의 관련 계약을 먼저 요구하는 것이 타당하다. A06은 실제 새 지속 상태를 만드는 경우로 한정한다. 이러한 게이트는 읽기·계약 준비까지 금지하는 뜻이 아니며 임의 기본값으로 우회하지 않는다. 순수 설정 변환만 별도로 구현하려면 조각 범위·검사를 다시 명시해야 한다. |
| 현재 기반·생성 책임 | ProfileLoader/ScenarioProfile, FleetBattle3D 초기화의 오류 대체·확대/튜닝, BattleSim의 사기/승패 결합을 정적으로 재대조했다. 생성기 설명과 combat 산출물의 관계·가까운 검사 파일 존재도 일치한다. 정적 열람을 최신 원격·미커밋 소유·통합 안전성 증거로 쓰지 않는다. 기존 정본/생성물 변경 목록을 먼저 정하며 전체 재생성을 자동 실행하도록 지시하지 않는다. |

## 2. 독립 완결성 확인과 실행 제한

문서 읽기와 정규식·상대 링크 존재 확인에서 구현 문서 R18/O8/A6, 측정 문서 PR6/M8/E9를 확인했다. 상대 Markdown 링크는 각각 12개/7개이며 누락0·행말 공백0이다. 이는 내용 대조의 보조 증거이며 실제 테스트 결과가 아니다.

정적 근거로 `scripts/FleetBattle3D.gd`, `core/battle/profile_loader.gd`, `core/battle/battle_sim.gd`, `scripts/battle_trace.gd`, `tools/scenario/make_combat_m3.py`, Q67 원문 및 가까운 tests 파일의 존재를 확인했다. 게임·AI·UI·저장·통행·성능·1000시드·사람 플레이 시험은 실행하지 않았다. 대상 본문·공통 스펙·코드·브랜치는 수정하지 않았고 이 독립 기록만 작성했다.

## 3. 다음에 가능한 준비와 남은 실제 차단

**바로 이어갈 수 있는 준비**는 I01 구현 전 인수 계약 묶음이다. 다음 조각을 작은 별도 산출물로 구체화할 수 있다.

1. O06: 당시 로컬 기준 커밋·작업 트리/PC 차이·미커밋 소유·허용 변경 파일을 읽기 확인하고, 확인 불가 부분과 통합 선택을 기록한다. 옛 D01 기록을 최신 사실로 대체하지 않는다.
2. O03/O07: I01이 실제 사용할 입력 필드·단위·ID/버전·정본/파생·실효 설정 변환·커서/커밋 경계를 좁힌다. 공간 치수와 ST/F 필드 정합은 후보·미정·책임을 표시하고 새 정책으로 덮지 않는다.
3. PR01~PR06: 첫 비교군의 가설·환경·표본·제외·판정·관찰 체크포인트를 사전 등록하는 문서를 준비한다. 측정 실행이나 합격값 수용은 별개다.

**사람 판단/외부 상태가 필요한 차단**은 허용 작업 트리·변경 소유/통합 선택, 게임 경험이나 지원 약속을 바꾸는 새 정책, 실제 측정 조건·정량 수용 기준, 범위가 확정된 코드/시험 실행 승인이다. 기술 로그 필드나 불변식마다 새 승인 질문을 만들라는 뜻은 아니다. O04/O05의 물량·회복·일정/비율·전체 동시 순서와 O07 세부 계약, O01/O08 정량 기준은 해당 구현·측정 이전에 확정해야 한다.

본 수용으로 새 코드 작업을 자동 착수하지 않는다. 범위를 좁힌 준비는 진행할 수 있지만 I01의 현재 착수 차단 상태는 유지된다. 독립 검토 반려가 발생하면 플레이북의 2단계 스펙으로 돌아가고 문서 재시도 상한 K=3을 지킨다.
