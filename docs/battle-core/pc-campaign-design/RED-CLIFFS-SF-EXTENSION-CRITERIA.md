# 적벽 SF 캠페인 후속 적용 기준

## 다음 작전과 운영 저장 · P02·P03·P06·A06

다음 일반 승계는 **〈퇴로의 등불〉 → 〈오림의 마지막 신호〉** 한 경로부터 적용한다. 현재 Windows 캠페인 프로필에서 수송선 한 척 이상을 구출해 성공 결산이 확정되면 천하 지도에서 한 번 출격할 수 있다. 실패와 포기는 출격 자격이 없다. 구출 수는 후일담에 반영한다.

승계에는 부모 작전과 결산 ID, 결산 결과와 구출 수, 검증용 결산 지문을 넘긴다. 새 작전은 표준·직접 지휘, 시드 20826, 고정 편성, 함선 수에 따른 정기 포격, 작전당 1회 정비로 0틱에서 시작한다. 새 작전의 명령 순번과 사건 커서는 초기화한다. 같은 작전을 이어할 때는 기존 작전 ID와 명령 순번·사건 커서·대기열을 복원한다.

현재 프로필의 Windows 캠페인 호스트가 단독으로 슬롯을 쓴다. 자격 검사와 부모 사용 기록, 새 작전 ID 및 초기 체크포인트를 한 번에 확정한다. 마지막 저장 시점은 모든 적용 명령과 사건이 확정된 틱 경계다. 체크포인트에는 입력·상태 지문, 시계, 적용 명령, 대기 명령, 사건 소비 커서와 결산을 담는다. 저장 실패는 이전 확정 슬롯을 보존한다. 응답 전에 프로세스가 종료됐더라도 같은 부모의 재요청은 기존 작전 ID와 확정 상태를 돌려준다. 완료한 부모의 재요청은 기존 결산을 연다.

인수에서는 같은 부모로 두 번 요청했을 때 출격 ID 한 개, 같은 작전 재개 시 적용 완료 명령 1·2의 재실행 0건과 대기 명령 3의 단일 실행을 확인한다. 사건 커서와 결산 지문을 무중단 실행과 대조하며, 슬롯 쓰기 실패와 재시도 전후 파일과 상태도 확인한다.

## 〈퇴로의 등불〉 외부 저장 · P04

Windows 공개 지도에서 **진행 중인 〈퇴로의 등불〉 v1 체크포인트** 한 건을 가져오고, 공개 호송 화면의 저장 버튼 옆에서 내보낸다. 확장자는 `.pclanternsave`, 형식은 `lantern-escort-checkpoint/1`로 정한다. 파일에 부모 결산 ID·지문, 후속 작전 ID, 규칙 지문, 체크포인트와 본문 SHA-256을 넣는다. 가져오기는 같은 캠페인 프로필에서 공개 호송 호스트를 열기 전에 진행하며, 동일 부모로 이미 배정된 활성 후속 ID와 파일이 일치해야 한다. 파일 틱과 사건 커서는 현재 확정 슬롯 이상이어야 한다. 같은 틱에서는 적용 이력과 기존 대기 명령이 같아야 한다. 새 틱에서는 현재 적용 이력을 보존하고 저장된 대기 명령이 저장 당시 틱의 다음 적용 배치에서 기존 순서로 한 번 처리되는지 재생으로 검증한다. 같은 체크포인트 재입력은 성공 응답만 반환한다.

내보내기는 새 파일 경로에 원자적으로 게시한다. 가져오기는 검증과 게시가 끝날 때까지 같은 Win32 리스를 유지한다. 게시 직전 최신 슬롯 세대와 SHA-256을 기준값과 대조한 뒤 활성 체크포인트만 원자적으로 교체한다. 결산·부모 자격·활성 작전 ID는 지역 원장에서 확인한다. 적벽 v1·v2의 외부 파일과 이 형식은 각자의 버전을 사용한다.

인수에서는 실제 파일 선택기 왕복, 같은 파일 재입력, 이전 틱·다른 부모·다른 작전 ID·변조 지문 거부, 동시 게시 시 한 파일만 게시되는 경우를 확인한다. 실패 시 활성 슬롯과 부모 결산 파일을 바이트로 대조하고 정상 파일로 재시도한다.

## 다중 진형 · P05

적벽 v2의 별도 확장 출격인 pc/first-operation/3, 규칙판 red-cliffs-multi-formation/1의 표준·직접 지휘에서 연합 `RC-LIU-SQ-01` 39척과 `RC-LIU-SQ-02` 21척 각각에 `FRM-01 ↔ FRM-03`을 적용한다. 한 명령에 한 전대만 지정하고 동시에 전환하는 전대는 하나로 제한한다. 완편·정지·고정 방향에서 시작하며, 논리 완료는 50틱이다. 두 편성의 양방향 네 경로를 각각 인증한다. 확장 출격은 전용 저장 슬롯과 리플레이 형식 1판을 사용한다. 기존 v2 저장과 리플레이는 기존 공개 메뉴에서 계속 열며 확장 출격은 서로 다른 형식을 접수할 때 버전 불일치를 표시한다.

선체는 함종별 승인 2D 외곽과 함선별 위치·방향을 쓴다. 시작·종료 자세와 틱 사이 이동 구간 모두에서 선체 내부 겹침 0건을 요구한다. 전환 중 정지는 현재 전환을 계속하고, 같은 목표 재지정은 남은 시간을 유지한다. 전환을 진행하는 동안 이동·선회·철수 진입과 다른 목표 지정은 접수 단계에서 거부한다. 손실로 인증 편성이 깨지면 마지막으로 확인된 자세에서 생존 함선의 위치와 방향을 고정하고 전환 타이머를 해제한다. 진형 전환 중단 사건을 한 건 기록하고 생존 편성에 후속 명령을 허용한다. 중단된 전환은 성공 수와 50틱·5.1초 완료 판정에서 제외한다. 손실 사건과 전환 완료가 같은 틱이면 손실을 먼저 반영한다.

인수에서는 네 경로의 논리 50틱, 연속 충돌 0건, 전환 전 대기 및 전환 중 저장·새 프로세스 재개, 손실과 경합 명령의 판정을 확인한다. Windows 1600×900에서는 전체 전대의 목표 자세 표시가 늦어도 5.1초에 안정되는지 별도로 측정한다.

## 〈오림의 마지막 신호〉 작전 규칙 · P07

노숙은 귀환한 수송선의 항법 기록에서 오림 통신소의 위치를 찾아낸다. 위군은 살아남은 선단의 위치를 파악하기 전에 중계소를 되찾으려 한다. 감녕은 신호를 끝까지 송신할 시간을 벌어야 한다.

- **통신소**는 중립에서 시작한다. 전투 가능한 정지 아군 전대가 범위 안에 있고 전투 가능한 적이 없으면 10초 연속 점유로 확보한다. 확보한 상태에서 같은 조건을 15초 연속 유지하면 구조 좌표 송신을 마치고 작전에 성공한다.
- **재점령**은 송신 전 적 정지 전대만 범위 안에 있을 때 10초 연속 점유로 성립한다. 양측 경합과 빈 거점은 연속 점유·송신을 초기화한다. 진행을 시작한 전대가 이탈·이동·전멸하거나 다른 전대로 바뀌면 해당 연속 진행을 초기화하고 새 전대는 다음 틱부터 센다. 거점 소유는 상대편의 재점령이 확정될 때까지 유지한다. 재점령 확정 시 송신 진행을 초기화하며, 아군은 다시 점유부터 시작한다.
- **정비**는 통신소 범위 밖의 아군 정비 지점에서 전투 가능한 정지 아군 전대 하나가 적 경합 없이 15초 연속 대기했을 때 작전당 한 번 완료한다. 살아 있는 함선의 손상 체력을 각각 최대 체력의 20%만큼 회복하며 최대 체력에서 막는다. 소실 함선은 복원 대상에서 제외한다. 대기 전대의 이탈·이동·전멸·교체, 적 경합, 정비 지점이 빈 틱은 정비 진행을 초기화한다. 정비가 이미 완료됐으면 재점유해도 회복 효과를 다시 적용하지 않는다.
- **결산**은 120초 제한으로 한다. 틱의 피해·파괴 → 위치와 점유 상태 → 재점령과 정비 → 송신 → 결산 순으로 처리한다. 지휘 전대 전멸과 송신 완료가 동시에 발생하면 실패가 우선이다. 지휘 전대가 살아 있으면 시한과 같은 틱의 송신 완료도 성공으로 친다. 명시적 포기는 실패로 확정한다.

인수에서는 무경합 송신, 경합으로 초기화, 적 재점령 뒤 아군 탈환, 정비 완료의 1회 제한, 시한 틱 송신과 지휘 전대 전멸 동시 발생을 확인한다. 편성·좌표·거점 반경과 접근 경로는 [오림 동결 작전 정의](ORIM-LAST-SIGNAL-DEFINITION.md)를 사용한다. 위 시간·우선순위를 인수 기대값으로 사용한다. A05 인수는 동일 정의·편성·시드와 동일 논리 명령을 전투 호스트·헤드리스·내부 재생 경로에 공급한다. 송신 중인 틱에 정지와 저장을 수행하고 재개 뒤 동일한 틱·사건 순서·결산 ID와 결과를 대조한다. 같은 비교에서는 동결한 작전 ID를 사용한다.

## 운영 슬롯과 지급 · O07

대상은 같은 Windows 사용자 프로필의 `user://lantern-escort-v1.save`다. 호송 호스트와 운영 복구 도구는 같은 Win32 리스를 획득한 동안에만 슬롯을 쓸 수 있다. 첫 운영 반영은 동일 형식의 같은 프로필 슬롯에 적용한다. 리스를 유지한 상태에서 원본 슬롯과 이전 세대의 SHA-256을 기록하고, 후보 검증과 게시 직전 기준 SHA 확인을 마친 뒤 원자 교체한다.

교체 후보는 기존 완료 영수증과 부모 사용 기록을 전부 그대로 포함해야 한다. 현재 활성 작전이 있으면 동일한 부모 결산과 작전 ID의 체크포인트만 허용한다. 틱·사건 커서의 역행 및 확정 명령 이력 변경은 거부한다. 같은 틱의 후보는 확정 슬롯의 대기 명령을 순서 그대로 앞부분에 보존해야 한다. 틱이 진행된 후보는 기존 대기 명령이 저장 당시 틱의 다음 적용 배치에서 순서대로 한 번 처리됐음을 재생으로 검증한다. 운영 반영으로 새 출격이나 새 결산을 만들 수 없으며, 활성 작전이 비어 있는 경우 완료 기록이 동일한 슬롯만 허용한다. 새 프로세스에서 기존 작전 ID 또는 영수증과 슬롯 지문을 확인한다. 교체 실패 시 마지막 확정 슬롯을 보존한다.

캠페인 첫 적용의 보상은 **게임 내 구조 공적 1건**이다. 공적은 호송 슬롯의 성공 결산에서 결산 ID별로 한 번 계산해 표시한다. 결산 영수증이 공적의 기준이며 별도 잔액이나 지급 원장을 두지 않는다. 동일 결산을 재열었을 때 공적 수는 그대로이고, 서로 다른 성공 결산만 각각 한 건씩 집계한다. 외부 지급은 실제 수신 시스템과 시험 환경이 지정될 때 별도 인수한다.
