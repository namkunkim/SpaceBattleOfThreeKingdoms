# P08·P09 Windows 1600×900 전경 검증 사전 준비

체크리스트 21행의 대표 플레이·성능·오디오 종료·전체 TRACE 범위다. 이 문서는 실행 전 계획이다.

## 실행 파일과 격리

기준 커밋은 `7f138c2df7f1a55118bf9a5b7e251703049d5bb6`이다. 아래 두 파일을 함께 사용하고 실행 직전에 `Get-FileHash -Algorithm SHA256`로 대조한다. 복사본을 사용하면 같은 폴더에 두고 그 복사본의 해시를 대조한다.

| SpaceBattleOfThreeKingdoms.exe (원본 실행 폴더 자료) | `542eaa33c4a97a39b472d2d501f5b1783f2caac9f5d76475033ae65954689f2d` |
| o07_win32.dll (원본 실행 폴더 자료) | `a9e45eed91cbe8721469359160bbcb3716675a575537acf716a2da782a75b6e8` |

새 검증 폴더 아래 `profile/roaming`과 `profile/local`을 만들고 자식 실행 환경의 `APPDATA`와 `LOCALAPPDATA`로 지정한다. 첫 시작 전 빈 프로필을 확인한다. 일반 전경 실행에서 이 제품 창의 클라이언트 크기가 1600×900인지 확인한다. 실행별 UTC 시작·종료, EXE 경로, PID·대상 창, 클라이언트 크기, 디스플레이 주사율·배율, GPU·드라이버, 오디오 출력 장치·볼륨을 남긴다. 실행별 엔진 로그는 별도 파일로 보존하고 모든 클릭과 수집 구간을 UTC로 대조한다. 패키지 검증 (원본 실행 폴더 자료) · 같은 패키지의 헤드리스 기동 (원본 실행 폴더 자료)

## 전경 동선과 수집 지점

1. 타이틀의 설정을 열고 설정 페이지를 바꾸는 버튼을 눌러 실제 클릭음과 배경음악을 기록한다. **시작 화면으로 돌아가기** 직전·직후를 표시하고, 타이틀에서 들리는 소리도 따로 기록한다.
2. **천하 지도 → 적벽으로**에서 지도 전환음과 배경음악을 기록한다. **타이틀로**로 나가는 시점에 오디오를 계속 수집한다. 지도를 다시 열어 표준·직접 지휘 **첫 작전 · 정면 → Start operation**으로 진행한다. 단계별 화면과 실제 선택 문구를 남긴다.
3. 초기 전장과 교전 구간을 표시한다. 보존된 실제 동선대로 **Move to waypoint 2**로 A에 이동하고, A 활성화 후 **Move to waypoint 3**으로 C에 접근한다. 자연 종료의 C 소유권·승패·사유를 기록하고 **Return to map**에서 결산을 확인한다. 초기 전장·교전·지도 결산 구간의 성능 원본과 재생 중인 음악의 교체 및 지도 복귀 시점도 보존한다. [이전 배포본의 실제 입력·화면·결산](../I01/r5-dimensions-canonical-windows-ui-prep-01a1c838/run-67f9cb20-20261111-01/RESULTS.md)
4. 설정 및 지도 각각에서 효과음을 재현한 뒤 정상 화면 이탈을 기록한다. 제품 종료도 해당 화면에서 배경음악이 실제 재생되는 상태에서 별도 실행으로 관찰한다. 각 정상 창 닫기 전후의 오디오, 종료 코드, 대상 PID와 소유한 하위 프로세스 잔류 여부, 엔진 로그의 오디오·ObjectDB·리소스 종료 진단을 남긴다. 이후 화면의 새 재생과 이전 화면 재생의 잔류를 구별할 근거가 부족하면 미확인으로 기록한다. 설정·지도·BGM 소스 범위 (원본 실행 폴더 자료)
5. 각 실행의 엔진 로그와 정상 종료 진단을 보존하고 `[TRACE]` 표식 및 격리 프로필의 `Godot/app_userdata/SpaceBattleOfThreeKingdoms/battle_traces/`에 생성된 파일을 기록한다. `session_start`부터 자연 종료의 `battle_end`까지 이어지는 JSONL은 `scripts/FleetBattle3D.gd`가 기록기를 만드는 기존 전장 경로의 형식이다. 이 기준 커밋의 승인 첫 작전 `FirstOperationHost`·어댑터·런타임에서 해당 기록기 연결은 확인되지 않았다. 승인 동선의 전체 TRACE는 정확한 제품 경로에서 기록기 연결과 실제 원본이 확인될 때까지 열린 항목으로 둔다. 기존 전장 JSONL이 관측되면 원본·경로·해시·PID·구간을 보존하고 JSON 파싱과 연속 시퀀스를 대조한다. 승인 동선에서는 엔진 로그, 성능, 실제 오디오를 각각 수집할 수 있다. 기존 전장 TRACE 형식 (원본 실행 폴더 자료)

## 수집 가능 범위

- 이 호스트에서 WPR의 CPU·GPU·DesktopComposition·Audio 프로필과 `typeperf`, `logman`을 확인했다. 성능 수집 담당자는 시작 전에 사용할 프로필·내보내기 방법·PID 귀속을 정한다. WPR 성능 원본과 선택한 프로세스 카운터의 시계열을 남긴다. 표시 프레임 간격은 제품 PID에 귀속할 수 있는 프레젠트 이벤트와 추출 경로가 확인될 때 보고한다. PATH에서 PresentMon과 WPA는 확인되지 않았다. 이 계획에는 합격 수치가 없다.
- 설치된 FFmpeg에서 `gdigrab`과 DirectShow 입력을 확인했다. 화면 캡처는 UI·실제 입력의 보조 증거다. FFmpeg 장치 목록에서 네이티브 WASAPI 입력은 확인되지 않았다. WPR Audio는 글리치 진단용이다. 실제 출력의 전후를 기록할 루프백 또는 검증된 출력 장치 녹음 경로와 시간 동기화가 남아 있다. 출력 파형과 종료 로그는 관측된 재생·중단과 엔진 진단을 보여 준다. 릴리스 패키지 내부 오디오 객체의 참조 해제 여부는 그 증거만으로 확정하기 어렵다.
