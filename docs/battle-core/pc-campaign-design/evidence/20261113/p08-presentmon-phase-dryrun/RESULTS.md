# P08 PresentMon phase-analysis dry run

The P08 Windows 1600×900 card uses PresentMon 2.6.0 x64 with v2 metrics, raw QPC ticks and input tracking disabled. This dry run replayed the preserved upstream Gold case 2 ETL offline with the card's CSV switches and PID 1300. See args.json and process.json for arguments, input SHA-256 values, and exit 0. The Gold fixture contains dwm.exe samples. Its observed timings are fixture values.

The CSV has 21 columns and 56 ordered rows, all from PID 1300 and swapchain 0x296989CD030. The older offline run used extra tracking switches. Projecting its 26 columns onto the new 21 gave exact equality for every field and row. The new CSV SHA-256 is 44518bca57a92d1394ccb4df646fa28cf40f3cfae620cb165201bbdf290350a7.

For the actual acceptance run, select the observed game PID and swapchain and group by CPUStartQPC in half-open [start, end) intervals. Record boundary QPC ticks from the same host clock in timeline.jsonl. The dry run used two adjacent intervals with 4 and 3 rows. Synthetic controls added a foreign PID and swapchain exactly at the shared boundary and verified exclusion. A second control verified that DisplayedTime NA counted as not displayed, blank counted as unknown, and numeric durations alone contributed to the median. An empty interval returned no samples. CPUStartQPC places the start of CPU work within a phase. DisplayedTime is frame visibility duration in milliseconds. [PresentMon v2.6.0 CLI reference](https://github.com/GameTechDev/PresentMon/blob/v2.6.0/README-ConsoleApplication.md)

RESULT.json and verify.py preserve fixture QPC boundaries, statistics and checks. Run the verifier in a scratch copy with the prior 26-column Gold export as its first argument. The prior export and upstream ETL are external fixture inputs; their digests are recorded in RESULT.json and process.json. The live ETW session, game PID and swapchain identification, actual 1600×900 client dimensions and gameplay measurements still require the foreground run. The product was not launched.
