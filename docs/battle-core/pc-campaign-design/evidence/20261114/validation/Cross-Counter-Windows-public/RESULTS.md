# Cross Counter Windows 공개 경로 검증

Windows 한 대의 격리 사용자 프로필에서 공개 제품 1600×900 창으로 검증했다. 실행 후보 소스는 `da000b66ad756145995d5b854d9da4772c41ee27`이며 [제품 PR #86](https://github.com/namkunkim/SpaceBattleOfThreeKingdoms/pull/86)에 포함됐다. 두 프로필에는 검토된 적벽 v1 목표 성공 결산 원장 사본만 넣고 시작했다. [후보 해시·스냅숏 요약](snapshot-summary.json)

| 확인 항목 | 실제 관찰 |
| --- | --- |
| 공개 진입 및 자연 승리 | 소비된 적벽 목표 성공 결산에서 별도 출격 버튼을 열었다. 화면에 0틱이 표시됐고 시작 버튼으로 진행했다. 추가 명령 없이 128틱·12,800ms에 `objective_success / counter_salvos_completed`로 종료했다. |
| 결산 재열기 | 적벽 화면과 새 프로세스에서 결산을 다시 열었다. 재개·명령 버튼은 비활성화됐고 자식 슬롯 개정 3과 단일 영수증 및 파일 해시가 유지됐다. |
| 정상 창 닫기 및 재개 | 다른 격리 프로필에서 61틱에 이동 명령을 기록했다. 진행 중 창을 닫고 새 프로세스에서 같은 작전의 121틱·12,100ms에 정지한 상태로 복원했다. |
| 동일 프로필 소유권 | 복원된 첫 프로세스가 정지한 동안 두 번째 프로세스에 `Cross Counter · 사용 중` 버튼이 비활성 상태로 표시됐다. 세 시점의 자식 슬롯과 패킷 해시가 일치했다. |
| 시간 제한 | 두 번째 창만 정상 종료한 뒤 첫 창이 121틱에 머무른 것을 확인하고 재개했다. 650틱·65,000ms에 `failure / deadline`로 끝났고 같은 작전의 단일 영수증이 개정 4에 기록됐다. |

읽기 전용 디코더는 닫은 직후와 바이트가 같은 이전 세대 패킷에서 초기화 완료, 이동 명령 한 건, 대기 명령 없음, 사건 커서 5·방출 사건 5, 반격 단계 0과 양측 반격 포격 0을 확인했다. 이는 **저장된 패킷**의 값이다. 재개 직후의 프로세스 내부 커서를 직접 계측하지 않았다. 실제 복원 화면의 121틱과 같은 슬롯 해시, 동일 작전의 후속 결산으로 재개 경로를 확인했다. 적벽 v1 보호 파일과 원본 부모 원장의 해시는 모든 표본에서 유지됐다.

패키지 내장 지문 검증은 통과했다. `EntryBoot.tscn`과 `NewEntry.tscn`에서 잘못된 UID가 보고됐고, 엔진 로그는 각각 선언된 `res://scripts/entry/entry_boot.gd`, `res://scripts/entry/entry_screen.gd`로 대체 로드했다고 기록했다. 수집 스크립트의 `Finish`는 경고를 실패로 처리해 스냅숏을 남긴 뒤 비정상 종료 코드를 반환했다. 두 시험의 제품 창은 정상 종료했고 저장·복원 및 결산 결과가 기록됐다. 이 근거는 단일 Windows PC와 승인된 Cross Counter 경로에 한정한다.
