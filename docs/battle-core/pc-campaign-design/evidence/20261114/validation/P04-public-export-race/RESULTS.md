# P04 공개 적벽 v1 동일 파일 동시 내보내기

Windows 한 대에서 원격 main `6730ccb807d7d103d823a03ef545ff626c2279d5`와 동일한 커밋 트리의 Godot 4.7.2 디버그 소스를 시험했다. 각 프로세스의 APPDATA·LOCALAPPDATA와 Godot 저장 경로를 분리했다. 헤드리스에서 현재 공개 v1 파일 선택기 신호를 호출했으며 Windows 네이티브 파일 게시를 실행했다.

- PID 20228과 30040이 서로 다른 2틱·3틱 정상 패킷을 같은 미존재 경로로 내보냈다. 공통 실행 시각을 사용했고, 기록된 두 콜백 구간은 약 96ms 겹쳤다.
- 한 프로세스만 게시했다. 패자는 파일 존재 사전 검사 이후의 네이티브 게시 경로에서 `external_publish_failed / file`을 반환했다.
- 공유 파일은 승자의 기준 내보내기와 SHA-256 `64ba3a0f25f060d3fd95028cf315262ff2d3b6f6ecba254ca11e4ed1fd1ae978`로 일치했다. 패자는 별도 경로에 재시도했고 쓰인 파일은 자신의 기준 파일과 일치했다.
- 양쪽 활성 상태와 보호 파일 네 개씩을 보존했고 임시 게시 파일은 남지 않았다. A 41/41, B 37/37을 통과했고 두 프로세스의 종료 코드는 0이었다.

첫 실행은 시험 도우미 구문과 콘솔 래퍼의 PID 식별 문제로 경합 전에 중단됐다. 수정한 실행기는 Windows 엔진 EXE의 실제 PID로 검증했다. 별도 모델이 코드 경로, 로그, PID, 파일 해시 및 정리 상태를 독립 확인했다.
