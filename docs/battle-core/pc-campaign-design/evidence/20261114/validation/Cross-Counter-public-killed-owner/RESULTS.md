# Cross Counter 공개 저장 후 소유 프로세스 강제 종료·재개

Windows 한 대에서 `6730ccb807d7d103d823a03ef545ff626c2279d5`와 동일한 커밋 트리의 Godot 4.7.2 디버그 소스를 실행했다. 새 격리 프로필에 소비된 적벽 목표 달성 결산의 검토된 사본을 놓고 EntryBoot와 공개 지도에서 Cross Counter를 열었다. 공개 컨트롤 신호와 수동 틱을 사용한 헤드리스 시험이다.

- 16틱에 이동·정지를 대기열에 넣고 공개 저장으로 확정했다. 소유 프로세스가 네이티브 슬롯 임대를 보유한 상태에서 감독자가 PID 13712와 저장 지문을 확인하고 해당 프로세스를 강제 종료했다. 종료를 기다린 뒤 재개 전 슬롯 SHA-256을 다시 확인했다.
- PID 10712에서 같은 격리 프로필의 공개 진입으로 작전 ID, 전체 체크포인트, 사건 커서, 두 대기 명령을 복원했다. 두 명령은 17틱에 순서대로 한 번씩 적용됐고 18틱에는 재적용되지 않았다.
- 포기 결산 영수증 한 건, 지도 복귀, 결산 재열기를 확인했다. 저장 전후 단계 9/9와 새 프로세스 13/13을 통과했다. 복원 프로세스 종료 코드 0을 확인했다.
- 강제 종료 전과 재개 전 슬롯 SHA-256은 `a867ac3a9421a2457c415ee69a268edd0ebe8132375ce53b43bae3bb35fef185`로 동일했다. 부모 원장 원본과 격리 사본은 `adb0e006848ed1be5cdb0749d634701eb2a2d99802fa0fb58f0d2296b32be3bf`로 일치했다.

첫 실행은 잘못 전달한 실행 인자로 격리 가드에서 종료됐다. 인자를 바로잡아 새 프로필에서 통과했다. 별도 모델이 실행기, 원시 로그, 파일 SHA와 재개 조건을 독립 확인했다. 시험의 강제 종료 시점은 공개 저장 확정 직후다.
