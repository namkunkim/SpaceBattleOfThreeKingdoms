### 항목별 확인(사양·확정 대비)
- 사유 코드 한국어 문구: 코어 상수 12개 전부 `REASON`에 있다(누락 없음). 확정 잠금 문구는 테스트(제독 없음·0척·기함 함대 출전)로 확인.
- 출전 토글: 기함 함대는 비활성, `toggle`이 장수·함선을 비운다. 끈 함대 장수는 풀로 간다(테스트).
- 장수 맞바꿈: 칸↔풀, 칸↔칸, 빈 칸 처리가 맞다(코드·테스트). 다른 함대 칸끼리는 #3.
- ±: `+`는 한도(`cap_left`)까지만, `-`는 0에서 멈춘다. 한도 초과는 제독 교체로만 생기고 경고만 한다(테스트). `tier_of`는 `CommandCore.limit_tier`와 같은 식이다(`command.gd:36-43` 대조).
- 자동 편성: 버튼 = `Organization.auto_fill(org, 유비)`, 끈 함대는 그대로. 테스트가 같은 결과를 확인한다.
- 초기화: 유비군만 `default_org`로, 손권·조조는 자동 편성 유지, 4함대 모두 `under_text` 경고(난이도 4종 확인).
- 함대 수 증가: `mine()`이 유비군 함대만 거른다(조조 8~16함대는 목록에 안 나옴), 유비군 목록은 `ScrollContainer`.
- 결정론: 화면 첫 상태(`start_org`) = 건너뛰기 = 기본 경로(`load_auto`) 지문이 같다(`organization_ui` 시드 7 동일, 300틱). 확정 경로는 `org.duplicate(true)`를 `battle.org`에 넣고 `init_game`이 `load_profile` + `apply`로 만든다. 같은 `prof`·`scn`을 쓰는 `apply`라 화면이 검사한 사본이 그대로 전투에 들어간다(테스트 `battle uses applied org`).
- 빈 프로필 대체: `load_error` 문구가 브리핑에 나온다(테스트 `empty profile guarded`). 단 #1.
- REVIEW-O1b #2(apply 반환 확인), O2b #1(빈 프로필 방어), O5 #6(formations 가드): 반영 확인. O5 #3·#4는 `ui_wording` 보강.

## 5. 사람이 PC·태블릿에서 확인할 목록
1. PC: 브리핑 → 편성 → 확정 → 전투, "뒤로", "자동 편성으로 시작"이 전투를 바로 연다.
2. 정사 편성으로 초기화 직후 화면: 4함대 경고 두 줄이 카드와 가운데 열에서 읽히는지, 목록이 스크롤되는지.
3. 제독을 비우거나 함선을 0으로 만든 상태(확정 잠금, 사유 문구 길이), 통솔 낮은 제독으로 교체한 한도 초과 경고.
4. 함종 ±를 누르는 반응 속도(PC, 태블릿 연타). 풀 스크롤 위치가 유지되는지.
5. 태블릿: 칸·풀 장수·± 터치 크기, 함대 목록을 끌어 스크롤할 때 선택이 바뀌는지, 검색 입력 뒤 가상 키보드가 버튼을 가리는지, 안전 영역(노치).
6. 해상도: 진짜 1920×1200, 2560×1600(창 높이 1071 한계 밖)에서 레이아웃과 작은 글자.
7. 출전 끄기 → 켜기 흐름, 확정 뒤 재시작해도 편성 유지.
