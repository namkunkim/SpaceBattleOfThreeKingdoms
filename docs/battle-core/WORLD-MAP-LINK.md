# 천하 지도와 적벽 전장 연동 (설계 + 구현 메모)

갱신: 2026-10-05. 상태: **구현됨**. 1차 구현이며 태블릿 터치를 기준으로 했다. 화면 확인은 로컬에서 해야 한다.
범위는 적벽 하나다. 캠페인은 만들지 않는다(제안서 §7.5). 본편 턴제 코어는 고치지 않는다(Q16).

## 1. 결론

- 두 지도를 한 화면으로 합치지 않는다.
  - 천하 지도는 **연속 확대 연출**로 적벽까지 내려간다.
  - 전장과는 **계약 두 개**로만 주고받는다. 가는 길이 `BattleBrief`, 오는 길이 `BattleOutcome`이다.
- 성계 세분화(본편 지도 v3의 거주 행성계 펼침)는 **형주 태양계권(RGN-04) 구지 행성계 한 곳에만** 한다.
  - 나머지 18성계와 21곳의 거주 항성계는 점과 이름만 그린다.
  - 근거:
    - 범위가 적벽 하나다.
    - 본편도 모바일 UI 부담을 미결로 두었다(본편 `star-map.md` §7 #1·#11).
    - 축척이 맞지 않는다(§5).
- 천하 지도는 상태를 저장하지 않는다. 결과는 권역 색과 결말·후일담 연출로만 보여 준다.

## 3. 계약

```text
BattleBrief  (scripts/world/battle_brief.gd, 천하 → 전장)
  scenario_id, seed, difficulty, mode("direct"|"auto"), whatif_cards[]
  anchor: {system: "SYS-13", region: "RGN-04", body: "BODY-RGN-04-01"}   # 본편 ID 그대로
  edge_labels: {cao_exit: "장강 대항로", cao_side: "오림", alliance_exit: "강하", alliance_side: "적벽"}

BattleOutcome  (scripts/world/battle_outcome.gd, 전장 → 천하)
  kind(alliance_win | alliance_limited | cao_win), win, limited, reason, grade,
  cao_status, liu_status, t_s, loss_pct{alliance, foe}, ending(J-D), line(E번호),
  fingerprint, seed, mode, difficulty
```

- **장면 전환:** autoload `WorldLink`(`scripts/world_link.gd`)가 Brief를 들고 전장으로 가고, Outcome을 들고 돌아온다. 결과는 천하 지도가 한 번만 가져간다(`take_outcome`).
- **Brief의 규칙 영향:** `anchor`와 `edge_labels`는 표시용이다. 규칙에 영향을 주는 것은 `seed`, `difficulty`, `mode`뿐이다.
- **`whatif_cards`:** M9 전에는 `validate()`가 거부한다.
- **등급:** 군 사기 격차(bp ÷ 100) 기준이다(제안서 §6.3). 60 이상 결정적 승리, 30~59 우세, 10~29 근소 우세, 10 미만 무승부다.
- **결말 J-D:** `ending_of`가 종료 사유로 고른다.
  - 승리: 기함 격파 J-D2, 사기 붕괴 J-D3(결정적)·J-D4, 시계 J-D5, 제한적 승리 J-D6, 그 밖 J-D1
  - 패배: 사기 붕괴 J-D7, 유비 기함 J-D8, 시계·동시 성립 J-D10
- **후일담:** 정사 계열만 쓴다(E1·2·4·5·6·9·11). 조건이 맞는 것 가운데 시드로 하나를 고른다(NARRATIVE §6). 연의판(3·7·10)은 연의판 설정이 생길 때 넣는다.
- **POC 판:** 전장이 POC 프로필이라 결산(`st.result`)이 없다. 이때는 승패와 종료 사유만 쓰고, 손실·조조 상태는 "—"로 표시한다.

## 4. 이어지는 느낌을 만드는 규칙

1. **같은 원본을 쓴다.** 좌표·ID·이름은 본편 지도 v3를 그대로 쓴다. 세력 색은 UI 키트의 `Factions`(위 주황, 오 보라, 촉 청록)이고, 경합은 `WARN`이다.
2. **방위:** 본편 v3에서 구지 행성계는 태양이 서쪽, 형혹·목성이 동쪽이다. 그래서 오림(조조)을 구지 동쪽, 적벽(연합)을 서쪽에 두면 전장 방위(조조 동, 연합 서)와 회전 없이 맞는다. 앞서 걱정한 방위 충돌(조조의 실제 퇴로 화용도 → 강릉은 서쪽)은 후일담 문장에만 남긴다.
3. **정보 경계:** 출격 연출에서도 조조군은 "규모 추정"만 보여 준다. 난이도별 배치 전대 수는 화면에 나오지 않는다. 자동 해결 화면은 작업 스레드가 써 둔 시계와 군 사기만 읽고, 코어 상태를 직접 읽지 않는다.
4. **결과는 연출만:** 권역 소유 변화는 `world_208.json`의 `outcome_owners`가 정한다. 저장하지 않는다.
   - 연합 승리: 강릉권·태양계권 → 손권, 남부권 → 유비(후일담 6·9)
   - 제한적 승리: 남부권 → 유비
   - 조조 승리: 형주 전부 → 조조(J-D7)

## 5. 축척

- 본편 좌표에서 강릉권(RGN-02)과 태양계권(RGN-04)은 약 1,877단위 떨어져 있다. 적벽 전장은 가로 1,600이다(Q37).
- 구지 행성계 전체(태양~목성)는 약 280단위다. 거주 행성의 최소 표시 반지름은 5다.
- 따라서 본편 `map-ux-concept.md` §9.1의 "확대하면 같은 위치·같은 지형이 전장으로 드러난다"를 글자 그대로 따를 수 없다. 연속 확대는 행성계까지만 하고, 전장으로는 장면 전환으로 넘어간다.
- 본편과 합칠 때 "앵커 좌표 + 별도 축척" 같은 국지 전장 인스턴스 규칙을 본편이 정해야 한다(`UPSTREAM-ISSUES.md` §F).

## 8. 기존 테스트 영향

- 진입 장면이 바뀌었으므로, 전투 장면을 직접 띄우는 기존 테스트(`ui_flow` 등)는 장면을 직접 불러 쓴다. 전투 장면만 단독으로 띄우면 `WorldLink.brief`가 없어서 동작이 전과 같다(무작위 시드, 타이틀부터 시작).
- 2026-10-05 실행 결과 모두 통과: smoke, ui_flow, battle_flow, touch_targets, safe_area, touch_input, touch_hold, decision_flow, order_undo, pacing, rule_text, squadron_strip, ui_sound, roster, core_rules, boundary, salvo_rules, data_rules, victory_rules, formation_rules, detection_rules, commander_ai, supply_rules, world_link.
- 연결 클래스를 처음에 `core/world/`에 두었다가 `boundary`(코어에 스레드·화면 참조 금지)와 `data_rules`(코어에 규칙 수치 리터럴 금지)에 걸려 `scripts/world/`로 옮겼다.
