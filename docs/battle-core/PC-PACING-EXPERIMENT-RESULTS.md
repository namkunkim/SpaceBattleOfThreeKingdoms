# PC 전장 1차 실행 결과

2026-10-24 / main `254e056` 기반 `codex/pc-ten-minute-battle-review`

## 실행 범위

Godot 4.7.2 헤드리스에서 5개 프리셋 × 동일 시드 3개(20824~20826), 총 15판을 실행했다. 난이도 표준, 자동 편성, 고정 10Hz, 배속 ×1이다. 유비군은 직접 지휘로 공개된 전장 중심을 향해 이동한 뒤 5초마다 확인 가능한 적을 공격하는 정책, 손권군은 위임 AI를 사용했다. 미탐지 적의 실제 좌표는 정책에 사용하지 않았다.

실제 사람 플레이 시간이 아니라 시뮬레이션 게임 시간이다. 각 조건 표본이 3판뿐이고 단일 공격 정책이므로 10분 밸런스 달성·승률·최적 맵을 확정할 수 없다. 이번 구현은 확대·이동·효과 구역 비교용이며 물리적 장애물, 레이저 차단, 강습 전용 구역은 아직 구현하지 않았다.

## 결과

| 프리셋 | 전장 / 이동 배율 / 효과 구역 | 종료 중앙값 | 종료 범위 | 첫 발사 |
|---|---|---|---|---|
| baseline | 1700×1150 / 150 / 3 | 1분 31초 | 1분 24초~2분 12초 | 2.5~2.9초 |
| slow_only | 1700×1150 / 30 / 3 | 2분 27초 | 2분 11초~2분 41초 | 10.5~11.2초 |
| large_only | 6800×4600 / 150 / 3 | 3분 31초 | 3분 16초~3분 36초 | 12.1~12.2초 |
| large_slow | 6800×4600 / 30 / 3 | 8분 50초 | 7분 35초~9분 47초 | 58.0초 |
| terrain | 6800×4600 / 30 / 10 | 5분 41초 | 4분 57초~9분 28초 | 58.4초 |

`large_only`와 `large_slow`는 원래 시나리오의 배치를 비례 확대한 조건이며, 설계 문서의 초기 배치 재설계안은 아직 적용하지 않았다.

## 판단

맵 확대와 이동 감속을 결합한 `large_slow`는 이번 표본에서 10분 목표에 가장 가까웠다. 다만 8~12분 범위에 든 것은 3판 중 2판이고, 실제 사람 플레이 검증은 없다. 같은 조건에 지형 10개를 적용한 `terrain`은 목표 시간에 더 가까워지지 않았으며 3판 모두 패배했다. 지형 수 증가 자체를 개선의 증거로 보지 않는다.

첫 발사 후 10초의 발사 수는 baseline 8·8·9회, large_slow 10·10·10회, terrain 4·4·4회였다(양측 모든 범주 합). 초기 사격량은 줄어도 terrain의 종료 시간과 승패가 나빠졌으므로 이후 기함 노출·사거리/AI·항로별 교전을 추가 계측해야 한다. 이번 자료만으로 특정 지형이 조기 패배의 원인이라고 확정하지 않는다.

`large_slow` 종료 사유는 연합 사기 붕괴 2회·조조 탈출 1회이고, `terrain`은 유비 기함 상실 1회·연합 사기 붕괴 2회다. 승패 조건을 바꾸거나 강제로 10분을 채우는 처리는 적용하지 않았다.

- 2026-10-25 추가 검증: baseline·large_slow·terrain에서 시드 20824의 명령 로그를 실제 재생하여 세 프리셋 모두 원래 전투와 상태 지문이 일치했다. [명령 로그 재생 결과](pc-pacing-replay.json). 세 판의 종료 시간은 각각 131.95·586.95·296.95초로 최초 측정과도 일치했다.
- `tests/pc_battle_smoke.gd`: 실제 게임 호스트의 전장·속도·10개 지형 표시·자동 배속 해제·재시작 중복 배율 방지·기본 전장 복귀 검증 통과.
- `tests/terrain_display.gd`: 기존 3개 지형 표시 회귀 통과.
- `tests/pacing.gd`: 기존 자동/수동 배속 회귀 통과.

최초 15판 실행에서는 코어의 상호 참조에 따른 종료 시 ObjectDB/Resource 잔존 경고가 나왔다. 비교 스크립트가 소유한 코어 참조를 종료 시 해제한 뒤 단일 재실행은 이 경고 없이 끝났다. 실제 게임 호스트를 생성하는 smoke 및 기존 지형/배속 테스트에서는 종료 시 잔존 경고가 계속 관측됐다. 판정 실패나 스크립트 오류는 없었으나 해당 자원 수명 문제까지 해결했다고 보지 않는다.

## 직접 플레이

이 피처 브랜치의 작업 트리에서 다음을 실행한다:

```powershell
.\tools\run_pc_battle.ps1
# 지형 10개 비교판
.\tools\run_pc_battle.ps1 -Preset terrain
```

기본 실행 프리셋은 `large_slow`다. 게임 창에서 편성/출격을 진행하면 해당 프리셋으로 플레이할 수 있다. 이 실행에서 자동 ×4는 꺼지고 수동 배속은 사용할 수 있다. 일반 게임 실행은 기존 설정을 유지한다. PC 프리셋 이름은 전투 trace의 `session_start`에 함께 기록된다.

측정 재현과 명령 로그 재생 검증은 프로젝트 루트에서 다음과 같이 실행한다. 실행 파일 경로는 설치 환경에 맞게 바꾼다.

```powershell
& 'C:\Tools\Godot\Godot_v4.7.2-stable_win64_console.exe' --headless --path . --script tests/pc_battle_pacing.gd -- --runs 1 --presets baseline,large_slow,terrain --replay 1 --out res://docs/battle-core/pc-pacing-replay.json
```

이후 병기 제한 지형 실험은 [SF 지형 사례 리뷰](SF-SPACE-TERRAIN-REVIEW.md)의 T1~T4 비교군으로 추가한다. 기존 효과 구역의 표시만 바꾸어 항행/레이저/강습 제한이 구현됐다고 판단하지 않는다.
