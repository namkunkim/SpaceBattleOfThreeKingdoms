## 3. 구조

### 3.1 원칙 [정본 `DECISIONS.md` V-25·V-60·V-72, 세션 Q9]

- **코어가 유일한 권위다.** 위치, 피해, 사기, 탐지, 승패는 코어만 계산한다.
- **화면은 공개 투영만 읽는다.** 표현과 HUD는 코어가 내주는 "이 진영이 볼 수 있는 것"만 받는다.
- **입력은 명령만 만든다.**
- **고정 틱이다.** 프레임 시간에 의존하지 않는다.
- **결정론이다.** 같은 빌드에서 같은 초기 상태와 같은 명령 기록이면 결과와 상태 지문이 같다 [세션 Q40].
- **계산 단위는 전대와 함종별 카운터다.** 개별 함선은 시뮬레이션하지 않는다. 3D 함선은 카운터를 그린 표현이다 [세션 Q35]. 이 원칙 덕분에 자동 해결 수백 회 통계가 가능하다.

### 3.2 계층

| 계층 | 책임 | 금지 |
|---|---|---|
| `core/battle/` | 상태, 고정 틱, 규칙, 승패, 공개 투영, 명령 검증, 사건(event) 발행 | `Node`, `Input`, 전역 난수, `Time`, 타이머, 프레임 delta |
| `core/battle/ai/` | 방침·성향에 따른 명령 생성. 공개 투영만 입력 | 미탐지 정보 사용 [정본 `ai-design.md` §1.3] |
| `view/` | 투영을 3D에 반영, 틱 사이 보간, 효과. 연출 전용 난수 | 규칙 계산, 코어 상태 변경 |
| `hud/` | 투영 표시, 버튼 | 규칙 계산 |
| `input/` | 터치·마우스·키 → 명령. 선택·그룹·끌기 같은 UI 세션 상태 | 코어 상태 변경 |
| `data/` | 본편에서 가져온 수치와 실시간 전용 수치 | 코드에 수치 박기 |

`view/`는 코어 좌표(1600×900)를 장면 좌표로 **같은 비율로** 늘린다. 비율이 다르면 방향 판정 각도가 화면에서 왜곡된다. POC 장면(3400×2300)은 16:9 비율(예: 3400×1912.5)로 바꾼다 [제안값].

### 3.3 틱, 난수, 수치

- 틱: **10Hz** [세션 Q41]. 표현은 틱 사이를 보간한다.
- 속도: 실제 1초에 몇 틱을 돌리는가만 바꾼다(정지 0, ×0.2 2틱, ×1 10틱, ×2 20틱, 자동 빨리 감기 ×4 40틱 [세션 Q52]). 한 프레임에 돌리는 틱 수에 상한(8)을 둔다 [제안값].
- 빠른 물체(투사체, 고속정 돌입 경로): 한 틱 동안 지나간 선분과 표적 사이의 최근접 거리로 판정한다 [세션 Q41]. 본편 데모도 이동 경로 선분으로 교차와 기회 사격을 판정한다 [데이터].
- 난수: `sha256(profile_id|tick|event_id)` 앞 8자리 mod 10000 [데이터 `red-cliffs-combat-effects-rules.json`]. 사건 ID는 상태 안의 증가 카운터로 붙인다.
- 연출 난수는 `view/` 전용 생성기를 쓴다. 현재 POC는 사격선 연출이 규칙과 같은 전역 난수열을 써서, 그리는 프레임 수가 전투 결과를 바꾼다. 이것부터 분리한다.
- 수치 [세션 Q40]: 사기·선체·명중률·자원은 정수 bp다. 위치와 방향은 실수이고, 매 틱 끝에 0.001 격자로 반올림한다(half-up). Godot `Vector2`는 32비트이므로 지문에는 양자화한 값만 넣는다.

### 3.4 명령, 사건, 재생

- 명령: `(tick, side, squadron_ids, kind, target_id, point, args)`. 객체 참조 없이 ID만 쓴다.
- 코어가 명령을 검증한다. 거부하면 사유 코드가 담긴 사건을 낸다.
- 사건: `(tick, kind, squadron_id, other_id, pos, value)`. 표현과 로그는 사건을 받아 그린다.
- 자동 해결 = 플레이어 명령 없이 AI 명령만으로 끝까지 틱을 돌리는 것.
- 연출 = 초기 상태와 명령 기록을 다시 돌리며 표현 계층만 붙이는 것.
- 저장 = 초기 상태 + 명령 기록 + 현재 틱. 또는 스냅숏 + 이후 기록.

### 3.5 테스트

모든 테스트는 실패하면 종료 코드 1로 끝나고 멈추지 않는다(`tests/lib/check.gd`).

- **규칙 단위:** 거리대 판정, 명중률 식, 방향 구간과 경계값, 사기 감소, 진형 전환, 승패 경로 전부, 군 사기 즉시 결산
- **결정론:** 같은 시드로 두 번 → 지문 일치. 속도를 바꿔도 지문 일치
- **재생:** 명령 기록 재생 → 지문 일치
- **정보 경계:** 투영과 AI 입력에 미탐지 적 0건
- **정적 검사:** `core/`에 `Node`·`Input`·`randf`·`randomize`·`create_timer`·`Time.` 0건. `view/`·`hud/`에서 코어 상태 클래스 참조 0건
- **자동 해결 통계:** 같은 편성을 여러 시드로 돌려 승률, 길이, 종료 경로 분포를 낸다

### 4.2 거리, 거리대, 이동

- **전대 속도** [데이터]: `편성 안 가장 느린 함종의 속도 × (100 + 지휘 초과 기동%) / 100`. 실시간에서는 턴 값을 60으로 나눈다.
  - 조조 전대: 59/턴 ≈ 0.98/초
  - 유비 전대: 140/턴 ≈ 2.33/초
  - 초기 대치 거리 약 841이라, 접근에 3~8분이 걸린다.
- **거리**는 전대 중심 사이로 잰다 [제안값]. 전대 반경은 첫 버전에서 두지 않고, M3 측정으로 정한다.
- **거리대는 무기 범주의 사거리로 정의한다** [제안값]. 광초 축척(v0.1 P2)은 폐기한다 [세션 Q37].

| 거리대 | 조건 (사격 전대 기준, 지형 보정 뒤 사거리) | 사기 가중 |
|---|---|---|
| 접적 | 확인·추정 접촉이 있으나 어떤 무기 사거리에도 없음 | 0.8 |
| 포화 | 포격 사거리 안 (포격함 260, 공성함 150) | 1.2 |
| 교전 | 전열 사격 사거리 안 (강습모함 190, 전열함 180) | 2.0 |
| 강습 | 80 이내 [제안값] | 1.6 |
| 결착 | 퇴각 상태 전대가 관련된 사격, 결산의 추격 | 1.0 |

- 사기 가중 값은 정본 `combat.md` §1.3이다. 거리대 정의는 제안값이다.
- **화면의 국면 표시** [제안값]:
  - 양 진영 코스트의 과반이 들어간 거리대를 보여 준다.
  - 어떤 접촉도 없으면 "대치", 결산 중이면 "결착"으로 표시한다.
  - 국면이 바뀔 때 짧은 표시와 로그 한 줄을 낸다.
- **초기 방향**: setup에 방향이 없어 데모는 모두 0°(동쪽)로 시작한다. 그러면 조조가 연합에 등을 보인다. 실시간에서는 가장 가까운 적 전대의 중심을 향해 시작한다 [제안값].
- **선회와 평행 이동** [제안값, 정본에 수치 없음]: 제자리 선회는 180°에 20초, 평행 이동은 전진 속도의 60%.

### 4.3 사격과 피해

데모의 피해 계산을 기반으로 하고 [세션 Q33], 실시간 사격 규칙을 새로 둔다. 이 절의 사격 주기, 표적 선택, 피해 배율은 **데모에 없는 실시간 전용 규칙**이다.

**사격 주기** [세션 Q46]
- 전대는 무기 범주마다 60초에 한 번 일제사격한다. 범주는 포격, 전열 사격, 요격, 뇌격이다 [데이터].
- 주기의 시작 틱은 전대 ID에서 유도해 전대마다 엇갈리게 한다.
- 조건은 셋이다.
  - 표적이 사거리와 사격각 안에 있다.
  - 표적이 같은 진영의 **확인** 접촉이다(진영 공유).
  - 자원이 충분하다.
- 데모는 "사거리에 들어오는 순간만 쏘는 기회 사격"이라, 서로 사거리 안에 멈춰 있으면 쏘지 않는다. 실시간에서는 이 규칙을 쓰지 않는다.
- 진영 공유 탐지는 데모와 다르다. 데모의 전대 단위 탐지로는 제갈량 전대가 거리 0에서도 조조를 확인하지 못한다.
- **탐지 재조정 (2026-10-03):** 진영 공유 탐지를 켜면 규모를 줄인 조조 전대가 확인 등급을 받지 못해 추정 사격(신뢰도 5000 = 명중 ×0.5)이 전면에 걸리고, 표준 조조 승률이 뒤집혔다. **추정 접촉의 시작 신뢰도를 7500으로 올려** 해결한다(§4.9, `EXPERIENCE-DESIGN.md` §8).
- 무장 탭의 "일제사격" 버튼은 해당 범주의 다음 주기를 지금 당긴다. 다음 주기는 그 시점부터 60초다.
- 화면은 한 번의 일제사격을 여러 발의 빔과 미사일로 나눠 보여 준다. 코어 판정은 한 번이다.

**명중률** [데이터 `red-cliffs-combat-effects-rules.json`, `red_cliffs_combat_effects.gd`]

```
명중률 = clamp(범주 기본값 + (사격측 화력% − 표적 방어%) × 100, 1000, 9500)
       × 지휘 초과 명중 배율 (half-up)
       × 추정 사격이면 신뢰도
표적 방어% = 진형 방어% + 방향 방어% (정면 +10, 측면 0, 후면 −15)
```

- 범주 기본값: 요격 8000, 전열 사격 7000, 포격 6500, 뇌격 6000 (bp).
- 방향 구간: 정면 ≤60°, 후면 ≥120°, 그 사이 측면 [데이터, 세션 Q33]. POC는 `<60°`라 경계값이 다르다. M3에서 맞춘다.
- POC의 피해 배율(측면 ×1.3, 후면 ×1.6)은 쓰지 않는다.
- 판정 난수는 §3.3을 따른다.

**피해** [세션 Q45]

```
피해 = 범주 기본 피해 × 플랫폼 배율 × 함종 거리대 계수 × 지휘관 보정 × 사기 계수 × 진형 배율 × 지형 보정
```

| 항 | 값 | 근거 |
|---|---|---|
| 범주 기본 피해 | 요격 70, 전열 사격 100, 포격 140, 뇌격 180 | 데이터 |
| 플랫폼 배율 | **√(그 범주의 사격 가능 플랫폼 수)** | 세션 Q45 |
| 함종 거리대 계수 | 그 범주 플랫폼 함종의 현재 거리대 계수, 척 수 가중 평균 | 세션 Q12, 데이터 |
| 지휘관 보정 | 거리대별 능력치 ±. 접적·포화는 지력, 교전은 통솔, 강습은 무력, 결착은 통솔·무력 | 정본 `combat.md` §3.2. 폭은 제안값으로 ±20% |
| 사기 계수 | `0.6 + 사기bp / 25000` (0.6~1.0) | 정본 식의 bp 환산 |
| 진형 배율 | 상성 우위 ×1.2 (교전 거리대만), 장사진 ×0.9, 전환 중 ×0.8 | 정본 `ship-specs.md` §5 |
| 지형 보정 | 지형 구역의 효과 | 데이터 |

- **플랫폼 배율이 왜 √인가.**
  - 데모처럼 피해를 전대 단위 고정값으로 두면 31척 전대와 7척 전대의 한 발이 같다. 그러면 소수 대형 전대가 극단적으로 불리하다. 간이 시뮬레이션에서 조조는 선체 31%만 잃고 사기로 무너졌다.
  - 피해를 함선 수에 정비례시키면 승패가 뒤집힌다. 조조가 70% 승리하고, 종료 경로도 코스트 70%로 바뀐다.
  - √는 그 중간이고, 기본안으로 확정했다(Q45). M3에서 고정·정비례와 다시 비교한다.
- 사기와 지휘관은 정본처럼 전투력을 조금 깎고(사기 계수 폭 0.4), 붕괴는 사기 임계가 크게 당긴다.
- **지휘 범위 밖** 전대는 명중률 −10%p [제안값]. POC의 화력 −25%를 명중률 체계로 옮긴 것이다.
- **같은 틱의 피해**는 피해 전 스냅숏에서 계산해 표적별로 합산한다 [데이터, 데모의 처리 순서].

### 4.4 맞는 방향과 함종별 손실

- **선체** [데이터]: 함선 비용 1점당 10. 전대 최대 선체는 `Σ(척 수 × 비용 × 10)`이다.
- **손실 척 수** [데이터]: `floor(원래 척 수 × 누적 선체 손실 / 최대 선체)`. 단조 증가한다.
- **배분** [세션 Q5·Q6, 제안값]: 새로 생긴 손실을 맞은 방향의 노출 함종에 60%, 나머지에 40% 나눈다.
  - 각 묶음 안에서는 현재 척 수에 비례해 나눈다.
  - 나머지는 함종 ID 순으로 처리한다.
  - 노출 함종이 그 전대에 없으면 그 몫을 나머지 묶음으로 넘긴다.
  - 데모의 "누적 손실 전체를 ID 오름차순으로 배분"은 대체한다. 데모 방식이면 비싼 강습모함부터 사라져 코스트 70% 조건이 선체 약 51%에서 성립한다.

**진형별 노출 함종** [제안값]

| 진형 | 정면 | 측면 | 후면 |
|---|---|---|---|
| 어린진 | 전열함 | 요격함, 포격함, 고속정 | 보급함, 강습모함 |
| 학익진 | 전열함, 요격함 | 전열함, 고속정 | 포격함, 보급함 |
| 방원진 | 전열함 | 전열함 | 전열함, 요격함 |
| 안행진 | 포격함, 전열함 | 포격함, 고속정 | 보급함, 공성함 |
| 봉시진 | 강습모함, 전열함 | 요격함, 고속정 | 보급함, 포격함 |
| 장사진 | 전열함 | 포격함, 보급함, 강습모함 | 보급함 |
| 팔진 | 전열함 | 전열함, 요격함 | 전열함 |

- 장사진의 측면은 v0.1에서 "전 함종"이라 나머지 40%가 갈 곳이 없었다. 측면에 약한 함종 셋으로 고쳤다.
- M3는 기본 진형 하나(어린진)로 시작하고, M5에서 표 전체를 넣는다.

**함종 손실의 결과**
- 강습모함 0척: 함재기 발진 불가, 전열 사격 사거리가 190에서 180으로 준다.
- 보급함 0척: 보급 영역, 수리, 결착 사기 유지 효과 없음.
- 전자전함 0척: 탐지가 남은 함종 기준으로 떨어진다. 데모는 탐지를 원래 편성으로 계산하지만, 실시간에서는 현재 척 수를 쓴다 [제안값].
- 뇌격 고속정 0척: 연쇄 폭발 작전 불가.
- 정찰 고속정 0척: 정찰 탐지 보너스 없음.

### 4.5 손상 단계 [세션 Q35, 정본 `ship-specs.md` §3.7]

함종마다 다섯 칸 카운터를 둔다: 무손상, 경파, 중파, 대파, 격침.

| 단계 | 전투력 계수 | 전열 |
|---|---|---|
| 무손상 | 1.00 | 유지 |
| 경파 | 0.90 | 유지 |
| 중파 | 0.65 | 유지 |
| 대파 | 0.00 | 이탈 (표류, 전투 후 회수 대상) |
| 격침 | | 소멸 |

- **피해를 단계로 옮기는 규칙** [제안값]
  - §4.4의 손실 척 수만큼 그 함종의 함선이 **이탈**(대파 또는 격침)한다.
  - 이탈 가운데 대파 비중은 거리대 주 무장이 정한다 [정본]: 접적 0.80, 포화 0.50, 교전 0.60, 강습 0.75, 결착 0.55. 화공은 0.25다.
  - 이탈하지 않은 선체 손실의 나머지는 경파·중파로 쌓는다. 신규 중파는 경파 함선에서 먼저 나온다 [정본].
  - 전대 선체 비율이 7500bp 아래면 남은 함선의 25%, 4000bp 아래면 50%가 최소 중파 이상이 되도록 맞춘다.
- "유효 함선 수"(플랫폼 수, 함종 계수의 가중치)는 단계별 계수를 곱한 합이다.
- 데모의 전대 선체 구간(7500/4000/1/0)은 표시와 보급함 처리량 계산에 쓴다 [데이터].

### 4.6 사기

**전대 사기** [데이터, 세션 Q30]

| 상태 | 범위 (bp) | 효과 |
|---|---|---|
| 안정 | 6000 이상 | 없음. 돌격 사용 가능 |
| 동요 | 3000~5999 | 계략에 잘 걸림. 명령은 수행 |
| 퇴각 | 1~2999 | 공격과 임무 변경 불가. **탈출 지점으로 강제 이동** |
| 항복 | 0 | 종결 |

- 적벽 전대는 10000bp에서 시작한다 [데이터].
- 캠페인과 합칠 때는 `combat.md`의 초기 사기(게이지 45~125)를 ×100 하고 10000에서 자른다 [제안값]. 상한을 넘는 몫을 어떻게 쓸지는 캠페인 합류 때 정한다.
- 강제 퇴각 이동은 데모에 구현이 없다. 실시간에서 새로 구현한다.
- 판정은 확률이 아니라 고정 임계값이다. 현재 값과 다음 위험 단계를 화면에 보여 준다 [정본].

**감소** [데이터, 세션 Q43]

```
명중 1회 = max(300, ceil(피해 × 10000 / (최대 선체 × 5))) × 거리대 가중 × 방향 가중
함선 이탈 1척 = 200 (가중 없음)
연쇄 폭발 피격 = 3500 (전대)
```

- 거리대 가중은 §4.2 표를 쓴다.
- 방향 가중은 측면 ×1.25, 후면 ×1.5다 [세션 Q43].
- **회복은 사건으로만 한다** [실시간 전용, `EXPERIENCE-DESIGN.md` §4]. 시간에 따른 자연 회복은 없다(데모와 같음).
  - 적 전대가 퇴각·항복하면 아군 군 사기 +300, 기함 진입에 성공하면 +1000.
  - **유비 결집 (전투당 1회):** 유비 본대 반경 200 안의 아군 전대 사기 +1200, 30초 동안 감소 ×0.5. 크기는 유비의 매력에 비례한다. 손권군은 주유의 결집 1회를 같은 틀로 둔다 [제안값].
- 보급함 비율이 10% 이상이면 결착 거리대의 감소를 ×0.6으로 줄인다 [정본].
- 간이 시뮬레이션에서는 이탈 200bp와 명중 하한 300bp가 사기 감소를 지배했다. 다만 **사기 감소를 줄여도 전투는 길어지지 않는다.** 전대가 퇴각하기 전에 선체가 먼저 바닥나기 때문이다. 그래서 사기 수치는 본편 정본 그대로 두고, 길이는 투입 시차로 맞춘다(§4.12, Q54 보충).
- **연환·역병** (§4.7): 밀집 진형 조조 전대는 감소 ×0.8, 분산 진형 북방군은 역병.

**군 사기** [세션 Q23·Q29]

```
군 사기 = Σ(전대 사기 × 전대 코스트) / Σ(전대 코스트) − 사건 누적
```

- 진영 단위로 계산한다. **연합(유비 + 손권)은 하나의 군 사기**를 쓴다 [세션 Q47]. 승패가 연합 단위이기 때문이다(§4.12).
- 퇴각 상태 전대는 **현재 사기 그대로** 계산한다. 항복·파괴·탈출한 전대는 0으로 계산한다 [세션 Q47].
  - v0.1은 퇴각 전대도 0으로 셌다. 간이 시뮬레이션에서 그러면 붕괴가 계단식으로 번졌다(손권 전대 하나가 퇴각하면 연합 군 사기 상한이 약 4870으로 떨어진다).
- 사건 감소량 [제안값, `combat.md` E 표 ×100]:
  - 전대 퇴각·항복 500
  - 화공 피격 2500 (군 단위, 전대의 3500과 별개)
  - 위장 항복 피격 4000
  - 기함 진입 허용 4000
  - 일기토 패배(장수 사망·포로) 4000
  - 매복 피격 1500
- **군 사기가 3000bp 아래로 떨어지면 그 시점에 결산으로 들어간다** [세션 Q29].
  - 실시간 퇴각 이동과 패주 손실을 이중으로 계산하지 않는다.
  - 데모 편성의 조조군은 전대가 하나라 그 전대의 퇴각이 곧 결산이었다. 시나리오 편성은 조조군을 4~7개 전대로 나눠 이 문제가 없다(`SCENARIO-RED-CLIFFS-208.md`).
- **붕괴 위기 구간** [실시간 전용]: 군 사기가 4500 아래면 "붕괴 위기"를 표시하고 결정 카드를 띄운다(§5.5). 마지막 한 수를 둘 창이다. 3000 즉시 결산은 그대로다.

### 4.7 진형 [세션 Q10·Q24·Q34, 데이터 `red-cliffs-formation-rules.json`]

| ID | 진형 | 화력% | 방어% | 탐지% | 요구 통솔 | 밀집 |
|---|---|---|---|---|---|---|
| `FRM-01` | 어린진 | +10 | −5 | 0 | 60 | |
| `FRM-02` | 학익진 | +5 | +10 | +5 | 75 | 밀집 |
| `FRM-03` | 방원진 | −5 | +15 | 0 | 55 | 밀집 |
| `FRM-04` | 안행진 | +15 | −5 | +5 | 65 | 밀집 |
| `FRM-05` | 봉시진 | +10 | −10 | −5 | 70 | |
| `FRM-06` | 장사진 | −5 | −10 | −10 | 40 | |
| `FRM-07` | 팔진 | +10 | +10 | +10 | 90 + 전용 특성 | |

- 화력%와 방어%는 명중률 식(§4.3)에, 탐지%는 탐지 점수(§4.9)에 들어간다.
- 데이터의 기동%는 데모 코드에서 쓰이지 않는다. 실시간에서도 쓰지 않는다.
- `formations.json`의 국면 계수는 **코어에 곱하지 않는다** [세션 Q34]. 참고용이다.
- "밀집"은 연쇄 폭발의 표적 조건이다 [데이터].
- **진형 분류와 연환·역병** [실시간 전용, `EXPERIENCE-DESIGN.md` §3]
  - 분류는 데이터를 따른다: 밀집(학익·방원·안행), 분산(봉시·장사·팔진), 중립(어린진).
  - 밀집인 조조 전대는 **연환 보너스**: 사기 감소 ×0.8, 역병 없음.
  - 분산인 북방군 전대는 **역병**: 10초마다 사기 −40bp. 정사 무제기의 대역(大疫)에 근거한다.
  - 중립은 둘 다 없다.
  - 그래서 조조는 "묶어야 버티고, 묶으면 탄다"는 딜레마를 진다. 상급 AI도 무조건 분산하지 않는다.
- **상성** [정본]: 학익 → 어린 → 방원 → 봉시 → 안행 → 학익. 우위 진형은 교전 거리대 피해 ×1.2. 장사진은 피해 ×0.9. 팔진은 상성 판정 자체를 무효화한다.
- **팔진** [정본]: 통솔 90 이상이면서 "신기묘산" 특성 보유자만 쓴다.
- **지형 제한** [정본]: 기저 항로에서는 학익·안행 불가. 중회랑에서는 방원·봉시·장사만. 대회랑에서는 장사진 강제.

**전환** [세션 Q24]
- 횟수 제한 없이 바꿀 수 있고, 30초 걸린다.
- 전환 중 피해 ×0.8이고, 방어%는 이전 진형 값을 쓴다.
- 통솔이 요구치에 못 미치면 60초 걸린다.
- 지휘 한도 초과의 전환 불이익(단계당 −8%)은 전환 시간을 늘리는 쪽으로 적용한다(단계당 +8%) [제안값].
- 팔진 조건 충족자는 전환 시간이 절반이다 [제안값].
- 전환 중의 노출 배치는 이전 진형을 쓰고, 완료 시점에 바뀐다 [제안값].

### 4.8 자원: 탄약, 에너지, 열, 함재기 [세션 Q21, 데이터 `red-cliffs-combat-resource-rules.json`]

| 무기 범주 | 플랫폼 (사거리 / 사격각) | 플랫폼당 탄약 | 1회 비용 (탄·에너지·열) |
|---|---|---|---|
| 포격 | 포격함 260 / 90°, 공성함 150 / 80° | 6 | 1 · 5 · 25 |
| 전열 사격 | 강습모함 190 / 120°, 전열함 180 / 120° | 10 | 1 · 8 · 20 |
| 요격 | 요격함 210 / 180°, 요격 고속정 200 / 200° | 8 | 1 · 4 · 15 |
| 뇌격 | 뇌격 고속정 170 / 70° | 특수 2회 | 0 · 3 · 20 |

- 탄약은 **전대 풀**이다: 플랫폼 수 × 플랫폼당 탄약.
- 에너지 용량은 `80 + 12 × 척 수`, 열 용량은 `100 + 8 × 척 수`다.
- 회복은 60초마다 일어난다: 에너지 용량의 20%, 함재기 출격 25% (올림) [데이터]. 열 방출은 **30 + 척 수 × 2** [세션 Q49, 계수는 제안값]. 본편 데이터는 척 수와 무관하게 30이다.
  - 실시간에서는 틱마다 1/600씩 연속으로 적용한다 [제안값].
- 강습모함이 있는 전대는 전열 사격을 강습모함 플랫폼(190)으로 쏘고, 매 사격에 함재기 출격 1을 쓴다 [데이터]. 강습모함 1척당 출격 4회다.
- 자원이 모자라면 그 범주의 사격이 보류되고 사유를 표시한다: 탄약 부족, 에너지 부족, 과열, 함재기 미복귀, 특수 자원 부족.
- 간이 시뮬레이션에서 탄약은 떨어지지 않았고 **열이 실제 제약**이었다(손권 전대는 약 5~6분 뒤부터 과열). 본편처럼 냉각이 전대 크기와 무관하면 큰 전대가 유리해서 척 수에 비례시켰다 [세션 Q49].
- 정본의 "미사일 소진 시 포화 계수 절반"은 쓰지 않는다. 포격 탄약이 0이면 포격 범주가 쏘지 못하는 것으로 충분하다.
- **배분**: 무기 범주 비율 합계 10000bp. 프리셋은 균형, 장거리 집중, 요격망 우선, 근접 타격이다 [데이터].
  - 실시간 일제사격은 범주마다 따로 쏘므로, 배분 비율은 **어느 범주를 쏠지** 정한다. 비율이 0인 범주는 쏘지 않는다.
  - 열이 모자라면 비율이 높은 범주부터 쏜다.
- "공격 보류"는 비율 0이 아니라 별도 명령이다.

### 4.9 탐지와 전쟁 안개 [데이터 `red-cliffs-sensor-ew-rules.json`, `red-cliffs-fog-of-war-rules.json`]

```
점수 = round_half_up(함종 센서 합 × (100 + 진형 탐지%) / 100) + 지력 구간 보너스
     − 표적 전자전 − floor(거리 / 25) + 지형 보정
확인 ≥ 37, 추정 ≥ 15, 그 아래 미탐지
```

- 접촉 상태는 넷이다: 미탐지, 확인, 추정, 상실. 진영 단위로 합친다.
- 추정 접촉 [데이터를 60초 주기로 환산]:
  - 180초 동안 기억한다.
  - 신뢰도는 **7500**에서 60초마다 −1000(하한 1500)이다 [실시간 전용, 탐지 재조정]. 본편 데이터의 시작값은 5000이다. 진영 공유 탐지에서 규모가 작은 전대도 싸울 수 있게 올렸다.
  - 오차 반경은 30에서 60초마다 +25다.
- 추정 사격은 명중률에 신뢰도를 곱한다.
- **미탐지 적은 어디에도 나타나지 않는다.** 전장, 레이더, 태그, 로그 모두.
- 확인 접촉도 정확한 함종·척 수·선체·사기를 공개하지 않는다. 관측 구간만 보여 준다.
- AI도 같은 안개 속에서 싸운다 [정본, 데이터 `red-cliffs-ai-rules.json`].
- 탐지는 데모처럼 원래 편성이 아니라 현재 척 수로 계산한다 [제안값].

### 4.11 계략과 강습

**연쇄 폭발 작전** [정본 + 실시간 재설계, `EXPERIENCE-DESIGN.md` §2·§8]

정본의 "조건이 충족되면 확률 없이 확정 발동"은 유지한다. 발동까지 가는 과정과 발동 뒤 결과를 플레이 숙련이 정하게 바꾼다. 데모의 "폭발정 비소모, 효과 고정"과 확률 간파 타이머는 대체한다.

- **운용:** 유비(플레이어)가 운용하고, 자산은 **황개 화공대**(`RC-SUN-SQ-03`, 뇌격 고속정)다. 데모는 주유 중군이었으나 정사에 따라 옮겼다(Q44).
- **발동 조건:** 기류 창 안, 거리 240 이내, 표적이 밀집 진형, 표적이 확인 접촉. 운용 전대에서 표적이 +X 방향 ±60° 안.
- **기류 창:** 첫 명중 뒤 9~10분 사이에 시드로 시작하고 3분간 열린다. 1막에 예보한다.
- **위장 항복과 의심 게이지:**
  - 서신을 보내면 황개 화공대가 "투항 중"이 된다. 의심이 100 미만인 동안 서로 쏘지 않는다(황개도 공격하지 않는다).
  - 정욱의 **의심 게이지(0~100)를 화면에 보여 준다.** 초당 입문 0.4, 표준 0.8, 상급 1.5, 극한 2.0씩 오른다.
  - 빠른 접근, 호위 동반, 투항 중 연합의 공격은 상승을 빠르게 한다. 성운 안과 고육계(미리 피해를 입었으면 시작 −30)는 늦춘다 [제안값].
  - 100이 되면 간파: 표적이 분산 진형으로 바뀌고 황개에게 집중 사격, 연합 군 사기 −1500.
- **위력:** 거리 240에서 최대 선체의 25%, 120에서 40%, 60에서 50%(선형). 이탈 중 대파 비중은 0.25 [데이터].
- **불길 번짐:** 반경 150 안의 밀집 전대로 20초마다, 최대 2회, 번질 때마다 위력이 절반이다.
- **사기 충격:** 표적 전대 3500, 군 2500 [데이터]에 위력/0.4를 곱한 뒤 각각 ×0.5, ×0.25 [밸런스 RX].
- **결과 등급:** 번짐 0회 "흔들림"(전투 계속), 1회 "큰 타격", 2회 "연환 대화재"(사실상 승리).
- **폭발정 2회분, 쓸 때마다 소모.** 1회차가 간파되면 2회차는 위장 없이 돌입한다. 기류 창이 남아 있을 때만 쓸 수 있다.
- **조조의 차단:** 인접 전대 긴급 분산(30초, 연환 상실), 요격망으로 2차 폭발정 격추, 불붙은 전대를 끊어 내 번짐 정지(군 사기 −1000) [제안값].
- **센서 장애와 임시 위험 지대** [데이터]: 센서 −40% 120초, 160×160 위험 지대 120초(이동 비용 ×1.5, 관측 −15%, 은폐 +8, 사거리 ×0.85, 사격각 −10°).
- **황개 AI 기본 정책:** 기류 창 전에는 모든 적에게서 280 밖(포격 사거리 260 밖)에 대기하고, 창이 열리면 투항 상태로 가장 가까운 밀집 전대에 120까지 접근해 발동한다.
- **목표 성공률:** 상급 AI 대 AI 기준선은 정본 27.4%에 맞춘다(RX 28%). 숙련 플레이어는 50~60%를 노린다.
- 즉시 승리가 아니다. 효과를 적용한 뒤 일반 승패 조건으로 판정한다.
- 그 밖의 계략(교란, 매복, 유인)은 같은 틀(조건 → 예약 → 발동)로 차례로 더한다 [제안값]. 위장 항복은 화공의 일부로 첫 버전에 들어간다.

- 진입 수단은 이동 명령과 **돌격**(§4.15)이다.
- 적 진형 붕괴도가 임계를 넘으면 전면 강습, 못 넘으면 제한 강습이다.
  - "진형 붕괴도 임계 초과"의 실시간 정의 [제안값]: 표적 전대가 퇴각 상태, 진형 전환 중, 직전 30초 안에 측면·후면 명중을 3회 이상 받음 가운데 하나.
  - v0.1의 "동요 이하"는 너무 쉽다는 리뷰 지적에 따라 바꿨다.
- 무력형 인물이 있으면 붕괴도 판정이 빨라진다: 측후면 명중 횟수 요건을 강습형 1인이면 2회, 특급 무력이면 1회로 줄인다 [제안값, 정본의 +20~50%를 옮긴 것].
- 강행 돌입: 진형이 열리지 않아도 시도할 수 있다. 성공률은 통상의 1/3이고, 실패하면 강습 부대 대량 손실과 아군 전대 사기 −3000이다.
- 첫 버전은 **부대 강습**(성공 시 적 함선 나포, 표적 사기 −1500)과 **기함 진입**(호위 판정 뒤 무력 대결, 성공 시 표적 사기 −4000, 지휘관 보정 소멸)까지 넣는다. 에이스 단기와 일기토 연출은 후속이다 [제안값].
- 성향은 성공률이 아니라 계략 선택에 걸린다 [정본 `combat.md` §5.6].

### 4.12 승패 [데이터 `red-cliffs-victory-rules.json`, `red_cliffs_victory_resolver.gd`, 세션 Q3·Q19·Q29]

**시간** [세션 Q19]
- 전투 시계는 20분이다.
- 감속 중에는 시계도 느려지고, 정지 중에는 멈춘다. 10분 대기(§5.5) 중에도 멈춘다.

  | 대회전 (적벽) | 15~20분 | 4~6번 | 약 8~12분 |

  - 손권군 AI는 아군 전대에서 300 안에 들어온 적에게 접근한다.
  - 간이 시뮬레이션 결과: 표준 15~16분, 파도 3번, 결정 지점 5~6번. 한 판의 막 구성은 `EXPERIENCE-DESIGN.md` §1을 본다.

### 4.13 보급과 수리 [세션 Q25, 데이터 `red-cliffs-fast-craft-rules.json`]

데모에는 일반 전대의 탄약 재보급과 수리가 **없다.** 전량 재충전은 순수 고속정 전대만 받는다. 아래는 Q25에 따른 **실시간 전용 규칙**이며, 데모의 고속정 보급 계약을 일반 전대로 넓힌 것이다 [제안값].

- 정상 작동하는 보급함을 가진 전대가 보급 영역을 만든다.
  - 영역 반경은 140 [데이터의 보급함 반경]이다.
  - 처리량은 보급함 1척당 동시 1개 전대다. 보급함 전대의 선체 구간에 따라 100%, 50%, 25%로 준다 [데이터].
- 아군 기지 (유비 (120,780), 손권 (300,440), 조조 (1460,180))도 반경 180, 동시 4개 전대로 보급한다 [데이터].
- 영역 안에 60초 정지하면 탄약이 전량 보충된다. 중간에 벗어나면 완료되지 않는다.
- 보급함 재고 [데이터]: 1척당 탄약 12단위, 물자 4단위. 전대 하나를 보충할 때 물자 1을 쓴다. 보급함이 파괴되면 남은 비율만큼 재고를 잃는다.
- 처리 순서: 남은 탄약 비율이 낮은 전대, 먼저 들어온 전대, 전대 ID 순 [데이터의 연료 기준을 탄약으로 옮김].
- 수리: 영역 안에 60초 정지하면 물자 1을 써서 중파 1척을 경파로 올린다. 경파는 120초 동안 피격이 없으면 무손상으로 돌아간다. 대파와 격침은 전투 중 수리하지 않는다.
- 연합끼리는 서로 보급한다 [데이터].

### 4.14 지휘 승계 [세션 Q25, 정본]

- 함대 지휘관이 지휘 불능이 되면 부함장이 승계한다.
- 부함장이 없으면 소속 전대 지휘관 가운데 레벨이 가장 높은 인물이, 같으면 지휘 능력치가 높은 인물이 승계한다.
- 승계 뒤 **60초 명령 혼선**이 온다: 기동 −20%, 명중률 −10%p, 진형 전환 시간 +50% [제안값]. 무작위 명령 실패는 없다.
- 승계 즉시 지휘 한도를 다시 계산한다.
- 조조군은 전대가 하나라 승계 대상이 없다. 연합은 유비 함대(2개 전대) 안에서만 승계가 일어난다.
- 장수의 부상·전사·포로 조건은 본편 `G8-04`가 정해지면 따른다.

### 4.15 기동 명령 [세션 Q25·Q28·Q42]

| 명령 | 뜻 |
|---|---|
| 이동 | 목적지까지 가고 도착 방향을 지정한다. 경유점 1~5개 [데이터] |
| 제자리 선회 | 위치는 그대로, 방향만 바꾼다 |
| 평행 이동 | 방향을 유지한 채 옆이나 뒤로 움직인다 |
| 정지 | 위치와 방향 유지 |
| 공격 | 확인 접촉을 표적으로 지정하고 사거리까지 접근 |
| 추정 사격 | 추정 접촉의 마지막 확인 위치에 사격 |
| 공격 보류 / 사격 재개 | 사격만 멈춘다 |
| **돌격** | 표적 쪽으로 강습 거리대까지 접근하는 이동 모드를 켜고, 10초간 피해 ×1.35, 속도 ×1.4. 사용 즉시 열 용량의 40%를 쌓는다. 전대 사기가 안정(6000bp 이상)일 때만 사용 가능 |
| 후퇴 | 탈출 지점으로 이동 |
| 집결 | 기함 주위로 이동 |

- 돌격의 효과 수치는 POC 값을 출발점으로 쓴다 [세션 Q42, 수치는 제안값]. 쿨다운은 따로 두지 않는다. 열이 제한 역할을 한다.
- POC의 방어진형 버튼(화력 ×0.7, 받는 피해 ×0.6)은 **삭제**한다. 같은 역할은 방원진이 맡는다 [제안값].

## 5. 지휘 체계

### 5.1 한 체계, 세 가지 쓰임 [정본 `ai-design.md` §7.1, 세션 Q2·Q7·Q20]

직접 지휘, 위임, 자동 해결, 적 AI가 모두 같은 지휘관 AI를 쓴다. AI 명령은 수동 명령과 같은 해석기를 거친다 [데이터].

```
전대의 다음 행동 = 플레이어의 직접 명령이 있으면 그것
                 없으면 지휘관 AI가 (전투 방침, 성향, 특성, 공개 투영)으로 고른 것
```

### 5.2 전투 방침 [정본 `combat.md` §2.3]

| 방침 | 행동 |
|---|---|
| 적극 | 거리 압축, 돌파, 돌격, 추격 우선 |
| 균형 | 표준 |
| 신중 | 원거리 유지, 방어, 질서 퇴각 우선. 인터뷰 Q7의 "회피·거리 유지"는 이 방침에 흡수했다 |
| 계략 중시 | 화공, 매복, 교란 우선 |
| 인물 위임 (기본값) | 지휘관의 성향과 특성에 따라 자동 |

- 성향 대응 [정본 `dispositions.md` §7.1]: 절의는 신중, 명사는 균형, 실무는 균형(손실률 임계를 넘으면 퇴각), 야심은 적극, 무뢰는 적극(기함 직격).
- **전황 반응** [정본 `ai-design.md` §7.3, 임계는 제안값]
  - 아군 사기가 동요 구간(6000bp 미만)이면 방어·퇴각 가중 +0.3
  - 적 사기가 동요 구간으로 관측되면 공세·추격 가중 +0.3
  - 계략 조건을 충족하면 해당 계략 +0.4
  - 지휘관 특성 조건을 충족하면 해당 국면 +0.5
- **출발점 데이터** [데이터 `red-cliffs-ai-rules.json`]
  - 손권 `allied_defensive`: 방원진, 요격망 우선, 확인 표적과 거리 150 유지
  - 조조 `aggressive_pressure`: 안행진, 근접 타격, 거리 100 유지, 접촉이 없으면 순찰, 연쇄 폭발 위험에 대응
  - 손권의 추정 사격 신뢰도 요구치(6500)는 추정 접촉 신뢰도(5000)보다 높아 추정 사격이 불가능하다. 실시간에서는 4500으로 둔다 [제안값].

### 5.3 지휘관 AI가 정하는 것 [제안값]

- 목표 거리대, 표적 선택, 방향 관리(정면 유지, 선회, 평행 이동)
- 진형 선택과 전환 시점, 무기 배분 프리셋
- 돌격 시점 (적극 방침, 열 여유, 사기 안정일 때)
- 퇴각 판단: 신중·실무 성향은 전대 사기 4000bp 아래나 손실률 임계에서 스스로 탈출 지점으로 향한다. 조조 AI의 탈출 판단도 이 규칙을 쓴다.
- 계략 예약

### 5.4 직접 명령과 위임 [세션 Q20·Q27]

- 모든 전대는 기본이 위임이다. 유비군과 손권군 모두 같다.
- 플레이어가 명령하면 그 전대는 직접 지휘가 되고, AI는 이동과 표적을 바꾸지 않는다.
- "위임으로 돌리기"로 AI에게 다시 맡긴다.
- 직접 지휘 중에도 자동으로 유지되는 것 [제안값]: 사거리 안 확인 표적 사격(공격 보류가 아니면), 보급, 퇴각 임계의 강제 퇴각. 돌격은 자동으로 쓰지 않는다.
- "전 전대 수동" 설정을 켜면 모든 아군 전대가 직접 지휘로 시작한다.
- 조조군은 항상 AI다.

### 5.5 부재와 자동 해결 [세션 Q2, 정본 `combat.md` §2.2·§8.1]

| 규모 | 개입 | 길이 목표 |
|---|---|---|
| 소전투 | 0회, 결과만 통보 | 3~5분 |
| 중전투 | 0~1회 | 8~15분 |
| 대회전 | 1~2회, 수동 전환 시 더 많이 | 15~30분 |

- 알림 분기: 계략 기회 개방, 사기 붕괴 위험 진입, 일기토 가능, 추격 여부 결정, 예상 외 전개.
- 분기에서 **최대 10분** 응답을 기다린다. 기다리는 동안 전투는 일시정지하고 시계도 멈춘다 [제안값]. 응답이 없으면 위임으로 처리하고 재개한다.
- 적벽은 대회전이면서 직접 지휘하는 시나리오 모드다. 시나리오 모드에서는 10분 대기 대신 **결정 카드**를 쓴다 [실시간 전용, `EXPERIENCE-DESIGN.md` §5].
  - **예고(약 3초 전):** 자동 ×4를 끄고, 화면 가장자리 펄스와 짧은 진동.
  - **도착:** 결정 카드가 엄지 영역에서 올라온다. 전투 속도는 입문 정지, 표준 ×0.2, 상급 이상 ×1(설정에서 변경).
  - **응답 없음:** 게임 시계 30초가 지나면 지휘관 AI의 추천안을 적용하고 로그에 "위임 처리"로 남긴다.
  - 카드에는 참모 대사, 선택지 2~3개, 추천 배지(추천한 참모), "전장 보기"를 둔다.
  - 예상 결과는 세 층으로만 보여 준다: 규칙상 확정 효과는 숫자로, 관측으로 추정한 위험은 낮음·보통·높음과 근거 한 줄로. 결과 승률은 보여 주지 않는다.
  - 동시에 열린 분기는 줄을 세운다. 상단에 "결정 2/5"를 작게 표시한다.
- 단기판의 "부재"는 앱 안에서 다른 화면을 보고 있는 경우다 [정본 V-25].

## 6. 다섯 국면의 화면 흐름 [세션 Q4]

### 6.1 접촉: 배치 단계

- 시간이 흐르지 않는다. 바탕은 본편의 전투 준비 화면이다 [정본 `demo-rc-g2-01`].
- 정하는 것 [제안값]
  - 전대별 진형, 전투 방침, 무기 배분 프리셋
  - 고속정 임무장비 (전투 중 변경 불가 [데이터])
  - 허용 구역 안의 초기 위치와 방향
  - 함대 묶기, 세력 재고로 전대 추가
- 보이는 것: 탐지된 적만.
- 자동 해결에서는 이 단계를 AI가 즉시 처리한다.

### 6.2 포화, 교전, 강습: 실시간

- 거리에 따라 자연히 넘어가고, 상단에 현재 국면을 표시한다.
- 거리를 벌리면 되돌아갈 수 있다 [세션 Q27].
- 돌격 명령으로 강습 국면을 직접 만들 수 있다 [세션 Q28].

### 6.3 결산

- **들어가는 시점:** 종료 조건(§4.12) 성립. 군 사기 붕괴도 즉시 결산이다 [세션 Q29].
- **추격 선택** [정본]: 전면 추격, 제한 추격, 전열 재편, 질서 퇴각. 자동 해결과 위임에서는 지휘관 AI가 고른다.
- **패주 손실** [정본]: `붕괴 시점 잔존 함선 × (15% + 추격 계수)`. 제한 추격 +10%p, 전면 추격 +25%p.
  - 잔존 함선에 퇴각 이동 중인 전대는 넣고, 이미 탈출한 전대는 뺀다 [제안값].
  - 보급함 비율 10% 이상이면 패주 손실 계수를 ×0.6 한다(결착 사기 유지의 결산 적용) [제안값].
- **추출 순서** [정본]: 중파 → 경파 → 무손상. 카운터에서 뺀다 [세션 Q35].
- **대파 회수** [정본]: 결정적 승리와 우세는 자군 대파 전량 회수와 적 대파 나포, 근소 우세와 무승부는 절반 회수, 패주 측은 0.
- **승리 등급** [정본 기준, 제안값 적용]: 종료 시 군 사기 격차(bp ÷ 100)가 60 이상이면 결정적 승리, 30~59 우세, 10~29 근소 우세, 10 미만 무승부.
- **결과 화면** [정본 `demo-rc-requirements-interview.md` §15]: 승리 조건과 판정 우선순위, 양측 손실과 잔존 코스트, 장수 상태, 사용한 특수 전술, 유비군 결과와 연합 판정의 구분.
- 전투 기록 다시 보기를 제공한다. 다섯 국면을 장(章)으로 쓴다.
  - 장 나누기는 거리대 전환 사건을 쓴다.
  - 데모의 5단계 원장(사건 종류별 분류)은 기록 내부의 감사용으로 쓴다 [제안값].

**명령 패널의 탭** [제안값]

| 탭 | 내용 |
|---|---|
| 태세 | 전투 방침 5종, **돌격**(사용 불가면 사유: 과열, 사기), **결집**(1회), 정지, 후퇴, 집결, 위임으로 돌리기 |
| 진형 | 진형 7종. 못 쓰는 진형은 이유와 함께 비활성. 전환 중이면 남은 시간 |
| 무장 | 배분 프리셋 4종, 공격 보류 / 사격 재개, 범주별 일제사격(다음 주기 당기기), 위장 항복 서신, 연쇄 폭발 작전(조건 충족 시), 고속정 임무 |

- 이동, 공격, 선회, 평행 이동은 버튼이 아니라 전장의 끌기 동작이다.
- **전대 띠:** 그룹 탭 I~IV 자리를 넓혀 아군 전대 초상 띠로 쓴다. 탭하면 선택이고, 띠에서 끌어도 명령이 된다 [`EXPERIENCE-DESIGN.md` §6 U4].
- **정보 층** [`EXPERIENCE-DESIGN.md` §6]
  - L0 상시: 군 사기와 다음 임계, 국면, 시계, 배속. 태그에는 소유 글리프, 사기 모양(안정 ● / 동요 ◐ / 퇴각 ▽ / 항복 ×), 직접·위임, 가장 급한 경고 하나.
  - L1 선택: 손상 단계 막대, 사기, 진형·방침, 사격 보류 사유.
  - L2 펼침: 함종 8종 × 손상 단계 표, 자원, 무기 배분.
  - L3 끌기 중: 표적 위 유불리 화살표와 도착 시 사거리 원.
- 새로 필요한 화면 요소: 결정 카드, 정욱 의심 게이지, 기류 창 예보와 남은 시간, 붕괴 위기 표시. 자리 제안은 `REVIEW-UI-v2.md` §3에 있다.
- POC 레벨·경험치(레벨당 화력 +7%)는 삭제한다. 장수 성장은 캠페인이 맡는다 [제안값].
- 표현 규칙 [정본]: 색만으로 상태나 진영을 구분하지 않는다. 진영 구분은 소유 글리프 + 세력명, 문장 데칼, 도장 패턴, 색 순이다.

- **터치 목표 크기는 물리 크기로 정한다**: 약 9mm 또는 48dp 이상 [제안값]. DPI 스케일, 노치 안전 영역, 엄지 도달 범위를 반영한다.
  - v0.1의 "44px [정본]"은 출처가 없어 삭제했다. 현재 POC 명령 버튼은 폰 가로 화면에서 약 3.6mm다.
- POC 단축키는 PC 보조 입력으로 남기고 탭 구성에 맞춰 다시 배정한다.
- **실수 복구와 오조작 방지** [`EXPERIENCE-DESIGN.md` §6]
  - 명령 뒤 4초 동안 "되돌리기" 알림을 띄운다. 직전 상태로 돌아가는 새 명령으로 기록해 결정론을 지킨다.
  - 되돌릴 수 없거나 비용이 큰 명령(화공 발동, 돌격, 후퇴, 강행 돌입)은 0.6초 길게 눌러 확정한다.
  - 전대 태그를 끌기 손잡이로 쓴다(판정 영역 48dp 이상). 공격 끌기에는 적 자석을 단다. 미리보기는 손가락 위에 띄운다.
- **선택 사항:** 탭-탭 명령(전대 탭 → 목적지 탭), 왼손잡이 좌우 반전. 첫 판에서는 도착 방향 고리를 끈다.
- **조작 목표:** 두 엄지로는 모든 기능을 쓴다. 한 손으로는 방침, 결정 카드, 전대 띠만으로 완주한다.

### 7.3 시간 감속 [세션 Q7·Q31·Q36]

- 전대를 선택하거나 끌기를 시작하면 감속한다. 배율은 ×0.2다 [제안값].
- 선택을 풀거나 명령이 확정되면 원래 속도로 돌아간다.
- 설정에서 감속 방식을 고를 수 있다: 선택 시 감속(기본) / 끌기·패널 조작 중에만 / 정지 / 없음.
- **유휴 해제** [세션 Q55]: 선택한 채 5초 동안 입력이 없으면 ×1로 돌아가고, 선택 강조는 유지한다. 다시 만지거나 끌기를 시작하면 다시 감속한다. M11 실기기 검증에서 다시 본다 [세션 Q36].
- **자동 빨리 감기** [세션 Q52]
  - 어느 전대도 교전 거리대(포화 이하)에 없고 대기 중인 알림 분기도 없으면 자동으로 ×4가 된다.
  - 교전이 시작되거나 분기가 열리면 ×1로 돌아온다.
  - "다음 분기까지 건너뛰기" 버튼을 둔다. 멈춤 지점은 §5.5의 결정 분기와 국면 전환이다. 버튼에 다음 멈춤 사유와 예상 시간(예: "접적까지 약 40초")을 표시한다.
  - 배속이 바뀔 때 상단 배속 표시가 반짝인다.
  - 설정에서 자동 빨리 감기를 끌 수 있다.
- **중단 처리** [세션 Q53]
  - 앱이 백그라운드로 가면 즉시 일시정지하고 저장한다(초기 상태 + 명령 기록 + 틱).
  - 국면이 바뀔 때마다 체크포인트를 남긴다. 홈 화면의 "이어하기"와 결산의 "체크포인트에서 다시"가 이것을 쓴다.
- 감속, 정지, 빨리 감기는 모두 틱 빈도만 바꾼다. 결정론에 영향이 없다.

### 7.4 성능

- 적벽 편성은 91척(대형함 61, 고속정 30)으로, 본편 3D 증거창 목표 204척 안이다 [정본 `s5-02`].
- 현재 POC는 전대당 28척 고정 표시라 최대 420척이다. 표시 척 수를 카운터에 맞추면 줄어든다.
- 런타임 모델은 삼각형 2.5만~6만이고 LOD와 MultiMesh가 없다.
- 함선 텍스처는 2048×2048 무손실, VRAM 압축 꺼짐이다. 모바일 전에 압축(ETC2/ASTC)과 LOD를 넣는다.
- 고속정은 모델이 없어 절차적 글리프로 그린다 [데이터, 본편 매니페스트와 같음].
- 렌더러는 Compatibility다. 모바일 실기기 측정 전에는 표시 척 수를 늘리지 않는다.

### 9.1 M1 이전 단계

코드 리뷰 결과에 따른 순서다. 각 단계에서 게임이 실행되고 헤드리스 테스트가 붙는다.

0. **기준선 고정:** 현행 코드를 `seed(i)`, dt 0.05로 200회 돌린다. 플레이어 정책은 셋이다(무명령 / 5초마다 최근접 공격과 미사일·함재기 사용 / 30초에 돌격). 승률, 길이, 손실, 증원 시각을 `tests/fixtures/m1_baseline.json`에 저장한다. 그리기가 난수를 쓰므로 기준선은 헤드리스로만 잡는다.
1. **순수 규칙 추출:** `flank_mul`, `power`, `ang_diff`, `formation_offsets`를 `core/battle/rules.gd`로 옮긴다.
2. **사건 싱크:** `apply_dmg`, `kill`, `enemy_ai`, `spawn_reinf`, `update_sim` 안의 표현 호출(`boom`, `say`, `add_log`, `float_text`, `refresh_panel`, `root.visible`, 선택 해제)을 사건 발행으로 바꾼다. `Part`, `Floaty`, `marker` 갱신은 view로 옮긴다.
3. **난수 분리:** 규칙 난수를 `BattleRng`(사건 ID 기반)로 바꾼다. 연출 난수(`_draw_fx`, `boom`)는 view 전용 생성기를 쓴다. 이 단계에서 처음으로 결정론이 성립한다.
4. **상태와 노드 분리:** `FleetState`(코어)와 `FleetVisual`(view)로 나눈다. `target`, `fire_t`, 미사일·함재기의 참조를 ID로 바꾼다. view가 생성 사건을 받아 노드를 만든다.
5. **명령과 기록:** `do_cmd`, `order_*`, AI가 모두 명령 객체를 만든다. 검증과 자원 차감은 코어가 한다.
6. **고정 10Hz 틱과 누산기:** 초 단위 값을 틱으로 바꾼다. dt 보간식은 기준(20Hz) 결과와 같아지도록 `1 − (1 − k·0.05)^(dt/0.05)` 꼴로 바꾼다. 미사일은 선분 판정을 쓴다(10Hz에서 한 틱 이동 26~40이 판정 반경 22보다 크다). `create_timer`와 종료 지연은 틱 사건과 view로 옮긴다.
7. **수치 표현:** 척 수는 1/1000척 정수로, 경험치·CP는 bp 정수로 바꾼다. 위치·방향은 매 틱 0.001 격자로 반올림한다.
8. **투영 전용 화면과 파일 분할:** HUD, 라벨, 레이더, 3D, 히트 테스트가 투영만 읽는다. `view/`, `hud/`, `input/`으로 나눈다. 정적 검사 테스트를 붙인다.
9. **자동 해결 실행기:** `tests/autoresolve.gd -- --runs 200`이 통계 JSON을 낸다.

**M1에서 고치지 않고 목록으로만 남기는 규칙 결함**
- 방향 경계(`<60°`와 `≤60°`): M3에서 고친다.
- 후퇴 중 표적이 없을 때의 처리: M4에서 고친다.
- AI의 전지적 시야: M6에서 고친다.
- 진형 슬롯 좌표가 미사일 발사 위치를 정하는 것, 함재기 첫 점 위치가 피해 조건인 것: 동등성을 지키려고 M1에서는 코어에 두고, M3에서 정리한다.

### 9.2 M1 완료 기준

1. 현행 규칙의 헤드리스 단위 테스트가 통과한다: 방향, 지휘 범위, 화력식, CP 회복·비용, 쿨다운, 증원 950틱, 패배와 승리 경로.
2. 결정론: 같은 시드와 명령 기록이면 100·600·종료 틱의 지문이 일치한다. 속도를 바꿔도 같다.
3. 재생: 초기 상태와 명령 기록으로 다시 돌린 결과의 지문이 일치한다.
4. **통계 동등성**(화면 동일성 대신): 정책 3종 각각 200시드에서 다음을 만족한다.
   - 아군 승률 차이 |Δ| ≤ 5%p
   - 전투 길이와 양측 손실 분포의 2표본 KS 통계량 D < 0.136
5. 경계 정적 검사가 통과한다.
6. 화면 수동 점검표가 모두 동작한다: 선택, 그룹, 명령 8개, 토스트, 로그, 속도(×0.2·×1·×2·정지), 종료 화면, 재시작.
7. 모든 테스트가 실패하면 종료 코드 1로 끝난다.

**M1의 위험**
- 10Hz 전환으로 동역학이 달라질 수 있다(보간, 간격 밀어내기, 미사일 유도, 함재기 판정). 분포가 어긋나면 6단계 안에서 원인을 하나씩 분리한다. 규칙 수치는 고치지 않는다.
- sha256 비용: 자동 해결 200회 × 약 2000틱 × 수십 회 추첨. 느리면 사건별 sha256 시드에 카운터 기반 생성기를 붙인다.
- 누산기의 틱 폭주: 한 프레임 상한을 두고, 넘치는 시간은 버린다.
- 기존 테스트(`capture_3d_poc.gd`)가 내부 API에 기대므로 단계마다 같이 고친다.
- 선택 시 감속은 M1에서 메커니즘만 만들고 기본값은 끈다. 켜는 것은 M10이다.

- 시간 단축 과금은 없다. 감속·배속 기능이 과금과 엮이지 않아야 한다.
