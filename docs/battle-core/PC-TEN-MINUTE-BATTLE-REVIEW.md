# PC 전투를 약 10분으로 확장하는 설계 검토

- 검토일: 2026-10-24
- 기준: `main` / `254e056f133e50aff8773d0a8209c98b2a4c1d6c`
- 브랜치: `codex/pc-ten-minute-battle-review`
- 범위: 현재 코드와 저장된 플레이 로그 분석, PC 전용 설계안·검증 기준. 후속으로 별도 실행 인자를 사용하는 PC 실험 프리셋을 추가했으며, 일반 게임의 기본 밸런스는 유지한다. [후속 실험 결과](PC-PACING-EXPERIMENT-RESULTS.md)와 [병기 제한 지형 사례 리뷰](SF-SPACE-TERRAIN-REVIEW.md)를 참고한다.

## 결론

맵 확대와 지형 복잡화는 비교 실험으로 검증할 개선 가설이다. 맵만 키우면 이동 대기 후 같은 사기 붕괴가 반복될 수 있다. **전장 확대 + 이동 속도 조정 + 전선 분리 + 사기 감소 검증 + 단계별 목표**를 함께 다루는 PC 전용 프로필 시제품을 권고한다.

목표는 기본 설정에서 출격 후 결산까지 실제 8~12분, 중앙값 약 10분이다. 브리핑·편성·메뉴 정지는 제외하고 자동 배속은 포함한다. 숙련자의 빠른 승리와 명백한 지휘 실패의 조기 패배는 허용하며, 10분 이전 승패 판정을 막는 방식은 쓰지 않는다.

## 현재 상태와 확인된 증거

| 항목 | 현재 구현·관측 | 영향 |
|---|---|---|
| 플레이 전장 | `FleetBattle3D.FIELD_SIZE = CameraRig.WORLD * 0.5`, 1700×1150 | 사거리 대비 전장이 작다 |
| 이동 | `move_mul = 150`, `turn_mul = 15` | 로그의 아군 기본 속도 157.5~192.5 좌표/게임 초. 직선 1700 이동은 약 8.8~10.8초(선회·지형·접적 제외) |
| 지형 | 성운·잔해·행성 그림자 각 1구역 | 이동·탐지·사거리 효과는 있으나 다중 전선을 만드는 배치는 부족 |
| 지형 통과 | `BattleTerrain`은 사각형 효과 구역, 이동 비용 적용 | 통과 불가 장애물이나 자동 우회 경로 탐색은 현재 제공하지 않음 |
| 무기 | 기본 사격 주기 60 게임 초, 초기 발사 시각은 주기 안에서 분산 | 첫 60초 안에도 여러 전대가 사격할 수 있음 |
| 사기 | 명중·함선 이탈로 감소, 군 사기 3000bp 미만이면 패배 | 선체가 남아 있어도 조기에 끝날 수 있음 |
| 배속 | 조용한 구간 자동 ×4 기본 켜짐, 건너뛰기 ×8 | 게임 시계 10분과 실제 플레이 10분은 다름 |
| 제한 시간 | 1200 게임 초 | 이미 20분 제한. 제한 시간만 늘려도 조기 패배는 해결되지 않음 |
| 대기 병력 | 일부 전대에 180초·360초 AI 대기 지정. 초기부터 존재하며 가까운 적에 의해 대기가 조기 해제될 수 있음 | 확정 증원 시각이 아님. 사격·탐지도 대기와 동일하게 차단되지 않음 |

저장된 로컬 로그 19개를 확인했으며, 종료 시간이 양수인 정규전 두 건은 다음과 같다. 모의전은 별도 규칙이므로 정규전 분석에서 제외했다. 시작만 기록되거나 0초에 종료된 기록은 일반 플레이 시간 표본으로 사용하지 않았다.

| 로그 | 시드 | 전투 시계 | 실제 경과¹ | 종료 사유 |
|---|---:|---:|---:|---|
| `battle-2026-10-24T11-21-19-16260-21619117.jsonl` | 4018146443 | 46.95초 | 45.413초 | `alliance_morale_collapse` |
| `battle-2026-10-24T16-43-23-32244-16009433141.jsonl` | 2170418147 | 63.95초 | 62.470초 | `alliance_morale_collapse` |

¹ 첫 `ui_state.state == play`의 `mono_ms`부터 마지막 `battle_end`까지. 중간 정지는 별도 공제하지 않은 관측값이며, 신규 수용 시험에서는 정지 시간을 제외한다. 로그 위치는 Godot의 `user://battle_traces`이고 원본은 개인 로컬 진단 자료이므로 저장소에 복사하지 않는다.

두 로그 모두 전장 1700×1150·이동 배율 150을 기록했다. 두 번째 로그는 54.5초에 군 사기 위기, 63.95초에 붕괴가 발생했다. 정확한 30초 종료는 이번 표본에서 확인하지 못했으나, 1분 안팎의 조기 종료는 확인했다. 두 건만으로 평균 승률이나 특정 명령의 인과관계를 확정할 수는 없다. 특히 이동 속도와 지형은 조기 접적·집중사격을 유발할 가능성이 있으나 사기 붕괴의 원인별 기여도는 추가 계측이 필요하다.

## 권고하는 PC 첫 시제품

다음 수치는 실측으로 확정한 밸런스가 아니라 비교 실험의 출발점이다.

| 요소 | 첫 실험안 | 조정 의도 |
|---|---|---|
| 맵 | 6800×4600 | 현재 가로·세로 4배, 면적 16배 |
| 이동 배율 | 30, 비교군 25·40 | 관측 아군 기준 약 31.5~38.5 좌표/초. 1000좌표 기동 약 26~32초 |
| 선회 배율 | 우선 15 유지 | 속도와 선회를 동시에 크게 바꾸지 않고 도착·선회 이상 유무 확인 후 별도 조정 |
| 초기 배치 | 선봉 간 거리 1800~2400, 기함은 선봉 뒤 700~1000 | 첫 유효 교전 30~60초 목표. 전체 좌표를 단순 4배 확대하는 방식 대신 재배치 |
| 사거리 | 기존 150~260 수준 우선 유지 | 전장 확대의 의미를 살리고 원거리 집중사격을 줄임 |
| 지형 | 8~12개 효과 구역, 첫 배치 10개 | 북·중앙·남 3개 항로, 2개 이상의 횡단 연결로 |
| 자동 배속 | PC 새 프로필에서 기본 끄기, 수동 배속 제공 | 실제 플레이 시간을 기준으로 조정. 기존 저장 설정 이관 방식은 구현 때 명시 |
| 제한 시간 | 우선 기존 1200 게임 초 유지 | 10분 강제 종료 대신 정상적인 승패가 목표 시간에 나오도록 검증 |

6800을 31.5~38.5 속도로 직선 횡단하면 약 177~216초다. 이 수치는 전체 전투 시간이 아니다. 첫 접적을 맵 횡단 끝까지 미루지 말고, 짧은 선봉 교전과 후방 기함·보급선 기동을 분리한다.

### 지형 배치 초안

전장 좌표 원점 (0,0), 사각형 표기는 `[x, y, 폭, 높이]`. 기존 지형 종류와 효과 체계를 사용한다. 여기서 항로는 통과 불가 벽으로 둘러싸인 길이 아니라, 이동·탐지·사거리 비용 차이로 유도하는 경로다.

| 구역 | 종류 | 좌표 초안 | 전술 역할 |
|---|---|---|---|
| N1 | 성운 | [1700, 350, 900, 650] | 북측 접근 은폐 |
| N2 | 잔해 | [3000, 650, 750, 700] | 북측 진입의 속도 비용 |
| N3 | 행성 그림자 | [4400, 250, 900, 650] | 북측 측면 기동 |
| C1 | 잔해 | [2200, 1550, 800, 650] | 중앙 직진의 위험·사거리 감소 |
| C2 | 성운 | [3550, 2000, 850, 650] | 중앙 재배치·원거리 탐지 약화. 직접 가시 범위의 접촉 단절은 보장하지 않음 |
| C3 | 잔해 | [4700, 1500, 650, 650] | 적 후방 진입 비용 |
| S1 | 행성 그림자 | [1400, 3150, 1000, 650] | 아군 남측 보급 접근 |
| S2 | 성운 | [2850, 3500, 850, 650] | 남측 우회·정찰 |
| S3 | 잔해 | [4150, 3100, 900, 650] | 적 남측 전선 분리 |
| R1 | 성운 | [5500, 2650, 650, 650] | 적 후방 철수·추격 판단 |

북·중앙 사이 y=1350~1500, 중앙·남 사이 y=2700~3050 부근은 횡단 연결의 중심선 후보로만 사용한다. 이 구간의 150~350 폭을 실제 가용 통로 폭으로 확정하지 않는다. 장애물 배치 후 통로의 유효 폭은 아래 장애물 상세안의 진형 외곽 기준을 만족해야 한다. 시작 배치·기함·탈출 지점은 지형 구역 위에 두지 않는다. 보급 거점은 아군 후방과 남측 측면에 분리하고, 적 기함은 적 후방에 둔다. 비대칭 배치를 허용하되 한쪽만 안전한 사격선을 독점하지 않는지 검증한다.

효과 구역은 실제로 함선을 물리적으로 가리지 않는다. '잔해 뒤는 완전 엄폐', '행성을 돌아서 이동'하는 규칙에는 충돌·가시선·경로 탐색의 별도 구현이 필요하다. 사용자 추가 요청에 따라 통과 불가 장애물 6개와 해당 구현·검증 조건을 [PC 지형·장애물 상세안](PC-TERRAIN-OBSTACLES-SPEC.md)에 포함한다. 효과 구역 10개와 장애물 6개는 별도 항목이며 모두 제안 상태다. 구역 중첩은 사거리 배율이 곱해지므로 과도한 중첩으로 양측 사격이 막히는 배치를 피한다.

## 10분 동안의 플레이 구성

| 실제 경과 목표 | 플레이어의 주요 판단 | 구현 방향 |
|---|---|---|
| 0~1분 | 정찰, 선봉 선택, 접근 항로 결정 | 30~60초에 첫 유효 교전, 기함은 후방 |
| 1~3분 | 중앙 견제 또는 북·남측 우회 | 전력을 2~3전선으로 분산, 전군이 한 표적을 동시에 때리지 않게 배치 |
| 3~6분 | 손실 전대 교대, 보급, 측면 기동 | 기존 180초 대기 전대의 조기 활성화·이동 시간을 측정하고, 재접적·거점 이동 유도 |
| 6~8분 | 후방 병력 대응, 주공 전환 | 기존 360초 대기 전대가 새 항로를 압박하도록 배치. 6분 교전 보장은 별도 활성화 규칙 구현 전에는 하지 않음 |
| 8~12분 | 기함 압박·철수·추격으로 결판 | 현재 승패 조건으로 마무리되는지 우선 측정 |

처음에는 위 항목을 배치·AI 목표로 구현하고, 점령·점수 같은 새 승리 시스템은 추가하지 않는다. 다만 사기 붕괴로 중반 구간에 도달하지 못하면 맵 확대만으로 목표를 달성했다고 판정하지 않는다.

### 사기와 교전 지속 시간

선체 내구도만 올리는 방안은 우선순위가 낮다. `MoraleCore.hit()`에는 명중당 최소 사기 감소가 있고 함선 이탈도 별도 감소를 일으키므로, 내구도만 올려도 사기 패배가 먼저 발생할 수 있다.

1. 명중 횟수·거리대·방향별 사기 손실, 함선 이탈 손실, 군 사기 사건 손실을 각각 계측한다.
2. 맵·배치·속도 조정만 적용한 상태에서 집중사격과 종료 시간을 비교한다.
3. 출격부터의 시간과 별개로 첫 유효 교전→위기→붕괴 시간을 측정한다. 교전 후 60초 이내 붕괴가 정상 지휘 표본의 20%를 넘으면 사기 조정을 검토한다. 명중·함선 이탈뿐 아니라 퇴각/항복 사건·역병·특수 사건을 구분해 원인을 조정한다. 명중당 최소 감소와 이탈 감소 0.5배·0.25배는 비교 실험값으로만 사용한다.
4. 보급·결집·후퇴 후 재진입의 효과를 측정한 뒤 재정비 회복 규칙 도입 여부를 정한다. 현재 일반 보급이 사기를 자동 회복시킨다고 가정하지 않는다.
5. 붕괴 임계치를 먼저 낮추거나 초반 무적 시간을 두지 않는다. 위기 예고 후 철수·결집 명령을 내릴 시간 자체를 확보한다.

최초 발사 시각은 전투 시작 기준으로 정해지고, 표적이 없으면 준비 상태가 유지된다. 따라서 30~60초 접적 지연이 첫 일제 집중을 만들 수 있다. 접적 후 1·5·10초의 범주별 발사 수·함선 이탈·전대/군 사기 손실을 A/B 비교하며, 최초 발사 분산 정책은 독립된 실험 변수로 둔다. 퇴각·항복의 군 사기 사건 누적은 전대 사기가 회복돼도 자동 취소되지 않는다. 명령 후퇴 취소, 강제 퇴각 중 결집, 탈출 완료 후 복귀 불가는 각각 구분해 측정한다.

## 구현 시 확인할 결합 지점

- `scripts/FleetBattle3D.gd`: 전장·속도 하드코딩을 PC 전용 프로필로 옮긴다. 기존 모의전과 다른 플랫폼의 기본값을 의도 없이 함께 변경하지 않는다.
- `core/battle/scenario_profile.gd`: `enlarge_field()`는 초기 좌표·지형 rect·기지·탈출 좌표만 비례 확대한다. 적 증원 시간, 도착 반경, 탐지·지휘·지원 반경, AI 판단 거리는 자동 조정되지 않는다. 항목별로 유지·변경을 명시한다. 특히 확대 후 기함과 호위·보급함 거리를 따로 점검한다.
- `core/battle/terrain.gd`, `core/battle/ai/commander_ai.gd`: 현재 효과 구역과 직선 목적지 위주 AI로는 우회로 선택을 보장하지 못한다. 항로별 경유점·정찰 목표·보급 복귀 지점을 추가하고, 탐지하지 못한 적 위치를 AI 목표로 사용하지 않는다.
- `view/camera_rig.gd`, 3D 배경, 레이더·미니맵: 배경판 상수는 3400×2300이고 확대 전장이 배경보다 커진다. 배경 범위, 카메라 far·줌 한계, 가장자리 입력과 미니맵 선택을 함께 검증한다.
- `hud/ui_kit/tactical_overlay.gd`: 현재 지형 종류 3종의 표시를 재사용할 수 있으나, 구역 증가에 따른 라벨 겹침·선택 가림을 점검한다.
- `hud/ui_kit/battle_pacing.gd`, `view/fleet_render/battle_source.gd`: 조용함 판정이 실제 사거리 외 고정 미사일·함재기 반경도 사용한다. PC 배속 정책과 접적 ETA를 새 속도에 맞춰 검토한다.
- `tools/scenario/make_combat_m3.py`, `data/scenarios/base/red-cliffs-terrain-rules.json`: 생성되는 `combat_m3.json`만 고치면 재생성 시 유실될 수 있다. 기존 정본 변경과 PC 프로필 덮어쓰기 중 후자를 우선한다.
- `tests/terrain_display.gd`, `tests/battle_flow.gd`: 구역 3개 가정과 프로필 재생 경로를 PC 프리셋에 맞춰 검증하되 기존 프로필 기준선은 별도로 유지한다.

## 검증 계획과 완료 기준

코어 비교 실험은 배속 ×1을 고정하고 A 현재값, A1 속도만 변경, A2 맵·배치만 변경, B 맵·배치·속도, C B+지형·항로/공격 위치 AI, D C+필요한 사기 조정으로 나눈다. 첫 발사 정책 변경은 별도 비교군으로 분리한다. 같은 시드·명령 정책에서 묶음 간 효과를 비교하며 C의 지형과 AI 각각의 기여를 확정하려면 추가 분리 실험이 필요하다. 실제 기본 설정 체감 실험은 이와 별도로 배속 사용 시간을 기록한다. 헤드리스·실제 게임·재생은 동일 PC 프로필과 변환 경로를 사용해야 한다.

- 난이도 표준, 고정 시드 20개 이상, 공격·측면 우회·방어/보급 정책 각각으로 시뮬레이션한다. 이 결과는 게임 시계 기준이며 실제 사람 플레이 시간을 대체하지 않는다.
- 기본 PC 설정으로 실제 플레이 10회 이상 측정한다. 실제 활성 경과 시간 중앙값 8~12분, 정상 지휘 표본의 70% 이상이 8~12분 범위에 드는 것을 잠정 수용 기준으로 한다. 분포와 종료 사유, 배속 사용 시간을 함께 보고한다. 수치는 최초 시제품 전에 고정하고 결과를 본 뒤 통과를 위해 바꾸지 않는다.
- 첫 유효 교전 30~60초. 60초 이상 아무 명령 판단 없이 이동만 기다리는 구간은 개선 대상으로 기록한다.
- 정상 지휘 플레이에서 첫 2분 내 사기 붕괴 또는 첫 교전 후 60초 내 붕괴가 각각 20%를 넘으면 실패. 위기 예고 후 실제 유효 대응 시간이 10초 이상인지 측정한다. 후방 대기 전대와의 교전 전에 결판나는 비율과 결집·후퇴 성공률을 확인한다. 의도적 기함 돌격의 조기 패배는 별도 분류한다.
- 북·중앙·남 중 최소 2개 항로가 유효하고, 우회·보급·재접적을 실제로 선택할 수 있어야 한다. AI가 지형을 모두 직선 통과하여 차이가 사라지면 실패다.
- 전투 결과·소요 시간·첫 접적·사기 원인별 손실·전선별 명중·정지 구간·보급 이용·입력 명령 수를 기록한다. 동일 프로필·시드·명령의 재생 지문이 일치해야 한다.
- 전체 전장 이동·줌·미니맵 선택·지형 라벨과 원본 함대 수에서의 렌더/시뮬레이션 성능을 점검한다. 면적 확대를 함선 수 16배 확대로 연결하지 않는다.

초기 검토 단계에서는 저장된 로그와 코드만 확인했다. 이후 사용자 요청으로 PC 실험 프리셋과 15판의 헤드리스 비교를 수행했으며, 결과는 [별도 보고서](PC-PACING-EXPERIMENT-RESULTS.md)에 기록했다. 실제 사람의 10분 플레이 검증과 장애물·병기 제한 구역의 구현/시험은 아직 수행하지 않았다.

## 상위 모델 리뷰 반영

GPT-6 Astra가 원안과 관련 코드를 독립 검토했다(2026-10-24). 권고는 '설계 수정 후 시제품 실험'이며 새 밸런스의 실행 검증은 아니다. 주요 지적 6건과 반영 내용:

1. **P1 최초 일제 집중:** 접적 지연 시 준비된 무기가 몰리는 위험과 1·5·10초 계측·발사 정책 비교군 추가.
2. **P1 지형 앞 AI 교착:** 목표 거리 240은 성운을 지난 260×0.85=221 사거리보다 멀 수 있음. 장애물 상세안에 유효 사거리·사격선·도달 가능성을 만족하는 공격 위치 탐색과 정체 진단 추가.
3. **P2 증원 표현 오류:** 180/360초를 초기부터 존재하는 대기 전대로 정정. 시각 보장 증원은 별도 시스템임을 명시.
4. **P2 탐지 차폐 누락:** 성운은 직접 가시 범위의 접촉 단절을 보장하지 않음. 장애물은 센서 점수뿐 아니라 `Detection.in_view()` 직접 가시 경로도 차단하도록 상세화.
5. **P2 사기 계측 시간축:** 출격 경과 외 교전→위기→붕괴와 퇴각/항복 사건 누적을 계측하고, 후퇴 유형을 구분.
6. **P2 비교·수용 기준:** 속도 단독·맵/배치 단독 비교, 배속 고정 코어 실험, 실제 플레이 분포·조기 붕괴 비율 기준 추가.

우선순위는 첫 일제·사기 계측 → 장애물/차폐 계약·공격 위치 AI → 대기 전대/퇴각 경로 → 비교 실험 → 맵·속도 튜닝이다. 6800×4600·배율 30 자체를 10분 보장값으로 취급하지 않는다.
