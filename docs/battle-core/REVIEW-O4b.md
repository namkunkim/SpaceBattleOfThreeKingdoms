## 항목별 판단
**#1 거부된 편성**: 시작·다시 시작은 `_org_rejected()`로 막힌다(`command_deck.gd:221,230`, 테스트가 둘 다 재현). 천하 지도 "자동 해결"은 편성 화면을 거치지 않고 `Organization.load_auto`를 직접 쓰므로(`battle_brief.gd:43`) 해당 없음. 막히지 못하는 진입은 F-1, 난이도 경로는 F-2.
- 의도 평가: 사용자 편성이 통째로 첫 상태로 덮이는 것은 의도와 어긋난다. 거부 사유는 보이나(`함대가 빠졌습니다`) 무엇이 바뀌었는지(어느 함대·장수 배정이 사라졌는지)는 알리지 않는다. 거부 코드가 `missing_fleet` 같은 함대 단위라면 유효한 함대 편성은 남기고 빠진 함대만 자동 편성으로 채우는 편이 낫다(F-3).

**#2 부분 갱신**: 코드 경로로 검증한 결과 불일치 없음. `_status()`를 먼저 불러 `errors`를 갱신한 뒤 카드·행·합계를 갱신하므로 카드 ⚠ 줄, 확정 버튼 잠금, 아래 문구가 같은 `errors`를 쓴다. 함종 행은 `_update_ships`로 −/+ 비활성(`cap_left`), 수, 비용, 비용·한도·경고 줄을 모두 갱신한다. 풀은 ±와 무관(장수 불변)이고 `_sum`이 풀 합계를 갱신한다. 장수 배정·출전·초기화·자동 편성은 `_refresh`(전체)를 그대로 쓴다. 함대 간 검증(세력 예산)이 없어 한 함대의 ±가 다른 카드에 영향 줄 일이 없다. 테스트가 제자리 갱신과 카드 비용 줄을 확인한다. 다만 F-5(회귀 가드 부재) 참고.

**#4 부호**: `effect_per_stage`의 move −5, hit −4는 `penalty()`가 `1 + penalty`로 곱하므로 선형이고 표시 `t × 값`이 맞다. `formation_change_pct` −8만 전환 "시간"에는 `s /= 1 + penalty`(`salvo.gd:137`)로 비선형이다. 즉 1단계 +8.7%, 2단계 +19%, 3단계 +32%, 4단계 +47%인데 화면은 +8·+16·+24·+32%다(F-4).

**#10 문턱**: 마우스 클릭(PC)은 누르고 놓는 거리가 0~수 px라 16px 문턱에 안 걸린다. 휠은 LEFT가 아니라 무시된다. `MOUSE_FILTER_PASS`로 카드 위에서 시작한 터치 끌기가 스크롤로 넘어간다(이전 STOP이면 카드 위에서 스크롤이 안 됐을 것). 거리를 전역 좌표로 재서 스크롤로 카드가 움직여도 올바르다. 남은 위험은 F-6(실기기).

**사양 보류 문구**: `docs/ui/FLEET-ORGANIZATION-SCREEN.md:17`에 있다. 확인.

## 사람이 태블릿에서 확인할 목록
1. 함대 카드 위에서 손가락으로 목록을 끌어 스크롤 → 스크롤 뒤 선택(금색 테두리)이 안 바뀐다. 가볍게 톡 치면 바뀐다.
2. 대기 풀(오른쪽) 장수 목록을 끌어 스크롤 → 장수가 집히지 않는다(F-6, 이번에 안 고친 부분).
3. 가운데 열 −/+를 빠르게 연타 → 끊김 없음, 카드의 비용·막대와 가운데 합계·하단 풀 합계가 같이 바뀐다. 한도 초과 시 "△ 지휘 한도 초과" 줄과 "진형 전환 시간 +"가 보인다.
4. 장수 맞바꿈, 출전/대기 토글, 자동 편성, 정사 편성 초기화 뒤 3열이 모두 새로 그려진다(빠진 곳 없음).
5. 16:10 화면(예: 2560×1600)에서 3열 레이아웃, 하단 문구가 잘리지 않는지.
6. (난이도 연결 뒤) 편성 → 난이도 변경 → 출격 시 전투가 아니라 편성 화면 + 사유가 나오는지.
