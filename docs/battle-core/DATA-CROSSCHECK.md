## 0. 요약

- 제안서가 "본편 `data/`에서 확인"으로 남긴 항목은 대부분 값이 있다. 요격함 계수, 함종 ID 순서, 방향 판정, 탄약, 탐지 공식, 지형 배치, AI 태세가 모두 확인됐다.
- **제안서의 전제와 크게 다른 것이 넷 있다.**
  1. 적벽 편성은 28척 전대가 여럿인 구성이 아니다. **연합 4개 전대 대 조조 1개 전대**이고, 전대당 함선 수는 7~31척이다.
  2. **고속정(`SHP-08`)이 적벽 편성의 핵심이다.** 연쇄 폭발 작전의 폭발정이 고속정이다. 첫 버전에서 고속정을 빼면(Q11) 연쇄 폭발 작전(Q15)을 쓸 수 없다.
  3. 본편의 방향 효과는 **명중률 보정**(정면 방어 +10%, 후면 −15%)이다. POC처럼 피해에 ×1.3/×1.6을 곱하지 않는다.
  4. 진형 수치가 **두 벌**이다. `formations.json`(국면 계수, `combat.md` 계열)과 `red-cliffs-formation-rules.json`(기동·탐지·화력·방어 %, 데모 계열)이다. 데모 파일은 스스로 "formations.json의 5단계 전투 계수를 뜻하지 않는다"고 적었다.
- 본편 좌표계(1600×900)와 함종별 이동 속도를 쓰면 **20분 전투 길이에 자연히 맞는다**. POC 좌표에 맞춘 축척(P2)보다 이쪽을 권한다(§3).

- 데모의 5단계 원장(`red-cliffs-phase-ledger-rules.json`)은 **사건 종류**로 국면을 나누는 표시·감사용 계약이다(이동·탐지 = 접적, 포격·연쇄 폭발 = 포화, 피해 = 교전). 거리로 국면을 정하는 세션 결정(Q4)과는 다르다. 실시간 코어에서 기록 재생의 장(章) 나누기에 이 원장을 쓸지 정한다.

## 4. 결정이 필요한 새 항목

**결정됨 (2026-10-03, `BATTLE_DECISIONS.md` Q32~Q35):** A는 전투 기능만 포함, B는 본편 명중률과 사기 가중, C는 데모 % 보정, D는 함종별 단계 카운터. E는 본편 좌표를 기본값으로 두었다.

- **A. 고속정.** Q11은 고속정을 첫 버전에서 뺐는데, 정본 적벽 편성에 고속정 30척이 있고 연쇄 폭발 작전의 폭발정이 고속정이다. 고속정을 넣을지, 연쇄 폭발 작전만 특수 처리할지 정해야 한다.
- **B. 방향 효과.** 본편의 명중률 보정(정면 +10 / 후면 −15)을 쓸지, POC의 피해 배율(측면 ×1.3 / 후면 ×1.6)을 쓸지.
- **C. 진형 수치.** `formations.json`의 국면 계수를 쓸지, 데모의 % 보정을 쓸지, 둘을 함께 쓸지. 함께 쓰면 진형 효과가 두 번 들어간다.
- **D. 손상 단계.** 데모의 전대 단위 손상 구간을 쓸지, 제안서의 함선별 4단계(`ship-specs.md` §3.7)를 쓸지.
- **E. 코어 좌표.** 본편 1600×900을 쓸지(권고), POC 좌표를 쓸지.
