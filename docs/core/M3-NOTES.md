# M3 사격과 피해: 구현 메모

2026-10-04, 구현 세션. 브랜치 `worktree-battle-core-m3`. 제안서 §4.3~§4.5, §4.8, §9 M3 행을 구현했다.

## 1. 구조

```
data/profiles/combat_m3.json     사격·피해 규칙 전체(생성기 tools/scenario/make_combat_m3.py, 본편 스냅숏 + 제안값)
core/battle/salvo.gd             SalvoCombat: 범주별 일제사격, 명중률, 피해, 손실 배분, 손상 단계, 자원
core/battle/rule_set.gd          rs.c = combat 사전
core/battle/scenario_profile.gd  프로필 정의의 combat_rules_path를 읽어 profile.combat에 넣는다
tests/salvo_rules.gd             M3 완료 기준 테스트
tests/salvo_compare.gd           피해 방식 3종 통계 도구
tests/lib/salvo_fixture.gd       소규모 전장 픽스처
```

- `profile.combat`이 있으면 `BattleSim.salvo`가 켜진다. 적벽 프로필(`red_cliffs_rt.json`)만 켠다. POC 프로필은 POC 규칙 그대로라 M1 기준선 동등성이 유지된다.
- 코드에 규칙 수치는 없다(`tests/data_rules.gd` 통과). 제안값은 JSON에서 `status: "proposed"`/`source`로 표시했다.
- 한 틱: 자원 회복 → 전대·범주별 계획(표적·플랫폼·자원) → 같은 틱 피해를 피해 전 스냅숏으로 계산 → 표적별 적용(선체 → 손실 척 수 → 방향 배분 → 손상 단계).
- `apply_dmg`를 `book_loss`로 나눴다(누계·표시 척 수·사건·격침). POC와 salvo가 같이 쓴다.

## 2. 구현한 것

| 항목 | 내용 |
|---|---|
| 사격 주기 | 범주(포격·전열·요격·뇌격)마다 60초. 시작 틱은 `rng(전대 ID)`로 엇갈린다. 표적이 사거리·사격각 안에 있을 때만 쏜다. 주기가 찼는데 표적이 없으면 표적이 생기는 즉시 쏜다 |
| 사거리·사격각 | 플랫폼별(포격함 260/90°, 전열함 180/120° …). 사거리·사격각 안의 플랫폼만 유효 수에 든다 |
| 거리대 | 강습 ≤80, 교전 = 전열 사거리 안, 포화 = 포격 사거리 안, 그 밖은 접적. 함종 계수는 사격 전대 기준 거리대에서 척 수 가중 평균 |
| 명중률 | `clamp(기본 + 화력% − 방어%)` bp, 방어 = 진형 방어 + 방향(정면 +10, 측면 0, 후면 −15). 정면 ≤60°, 후면 ≥120°(경계 포함). 지휘 범위 밖 −10%p. 판정은 일제사격당 한 번 |
| 피해 식 | 기본 피해 × 플랫폼 배율(`damage_mode`: fixed / sqrt / linear) × 거리대 계수 × 지휘관 × 사기 × 진형 × 지형, 돌격 ×1.35, 방어태세 ×0.7 |
| 선체·손실 | 선체 = Σ 척 수 × 비용 × 10(고속정 장비 제외). 손실 척 수 = floor(원래 × 누적 손실 / 최대 선체), 단조 |
| 방향 배분 | 어린진 노출표로 60% 노출 함종, 40% 나머지. 묶음 안에서는 척 수가 많은 함종부터. 노출 함종이 없으면 다른 묶음으로 |
| 손상 단계 | 함종 × 5단계 카운터. 이탈 중 대파·격침 비율은 거리대별(0.80/0.50/0.60/0.75), 선체 7500bp 아래 25%·4000bp 아래 50%가 중파 이상 |
| 자원 | 탄약(전대 풀), 에너지(80+12×척), 열(100+8×척), 함재기 출격. 연속 회복(에너지 20%, 열 30+2×척, 함재기 25% / 60초). 모자라면 `suppressed` 사건(탄약·에너지·과열·함재기 미복귀·특수) |
| 돌격 | CP 대신 열 40% + 사기 ≥6000. 10초간 강습 거리(80)까지 접근, 속도 ×1.4, 피해 ×1.35 |
| 이동 | 전대 속도 = 가장 느린 함종 속도/60 × (1 + 진형 기동%). 초기 방향은 가장 가까운 적을 향한다 |
| 투영 | `counts`(함종 × 단계), `hull`, `ammo`, `energy_milli`, `heat_milli`, `suppressed`, `next_fire_s` |
| 사건 | `salvo`(범주·명중·피해·거리대·방향), `suppressed` |

## 3. 완료 기준

- **포격함 전대가 멀리서 이기고 가까이서 진다**: 포격함 8척 대 전열함 8척, 거리 230에서 30/30 승(전열함은 한 발도 못 쏜다), 거리 100에서 포격 8/30 승(`tests/salvo_rules.gd`).
- **후면 피격 +25%p**: 정면 7000, 측면 +1000, 후면 +2500bp. 방원진 상대로도 +2500(상한에 걸리지 않는 조건).
- **빌드·테스트**: `SALVO_RULES_PASS`, `CORE_RULES_PASS`, `BOUNDARY_PASS`, `DATA_RULES_PASS`, UI 테스트 8종(`roster`, `ui_flow`, `smoke`, `decision_flow`, `order_undo`, `pacing`, `squadron_strip`, `rule_text`)과 `battle_flow` 통과. POC 동등성: `none` 200시드 통과, `charge30`은 200시드에서 D가 한계를 넘었으나(M1 §7이 말한 200시드 우연) 1000시드에서 통과(길이 D 0.128).
- **화면**: 호스트(`FleetBattle3D`)는 아직 POC 프로필이라 화면은 그대로다. 적벽 프로필 화면 연결은 M10.

## 4. 피해 방식 3종 통계 비교 (K1)

기본 규칙은 sqrt(Q45). 고정 / √ / 정비례를 같은 시드에서 비교했다(`tests/salvo_compare.gd`).

**조건 A: 통제된 소 대 대 교전** (같은 구성비, 12척 대 32척, 서로 추격, 200시드)

| 방식 | 소(12척) 승률 | 평균 길이(초) | 소의 손실 척 | 소가 낸 격침 척 |
|---|---|---|---|---|
| 고정 | 0% | 582 | 11.9 | 11.8 |
| √ | 0% | 413 | 12.0 | 7.4 |
| 정비례 | 0% | 334 | 12.0 | 7.9 |

**조건 B: 적벽 표준**, 플레이어 전대가 5초마다 가까운 적 공격, 60시드

| 방식 | 연합 승률 | 종료(섬멸/기함 상실) | 평균 길이(초) | 연합 손실 척 | 조조군 손실 척 |
|---|---|---|---|---|---|
| 고정 | 20.0% | 12 / 48 | 815 | 48.8 | 43.1 |
| √ | 28.3% | 17 / 43 | 738 | 49.6 | 42.6 |
| 정비례 | 13.3% | 8 / 52 | 620 | 51.7 | 38.8 |

읽는 법(결론이 아니라 관찰):
- 소 대 대 교전은 세 방식 모두 대가 이긴다. 고정은 소가 거의 전부(11.8척)를 격침시킬 만큼 규모 효과가 약하고 길이가 길다. √와 정비례는 규모가 큰 쪽이 빨리 이긴다.
- 적벽 표준에서 승률은 √(28%)가 가장 높고 고정(20%), 정비례(13%)는 낮다. 정비례일수록 조조(큰 전대)에 유리하고 전투가 짧다. 표본 60이라 ±12%p 안팎 오차가 있어 차이를 단정하지 않는다.
- **적벽 프로필의 AI는 POC 규칙 그대로(거리대 유지·진형·정보 없음)라 이 승률은 밸런스 근거가 아니다.** 방식 사이의 상대 비교만 본다. 기본은 √ 유지가 타당하다(Q45 근거와 어긋나지 않음). M4에서 새 기준선을 잡을 때 다시 본다.

## 5. M1 보류 항목(REVIEW-M1 #4): 5초 공격 길이 −1.4%

M1의 의심(아군 미사일·함재기 쪽)을 한 번 더 좁혔다. 같은 증상이 남아 있었다(평균 길이 104.0초 대 기준선 105.4초, 200시드).

- 피해를 1/1000척으로 반올림하는 것이 원인인지: **아니다.** 반올림 잔여를 표적에 누적하는 변형에서도 평균 길이 104.02초로 같다.
- 정책 명령을 틱 위상만 바꿔 내는 것은 `queue`(다음 `step` 첫머리)와 `issue`(직후)가 같은 시점이라 실험 의미가 없다.
- 원인을 찾지 못했다. 이 증상은 POC 미사일·함재기 규칙 안에 있고 M3 salvo 규칙은 이 경로를 쓰지 않는다. 승패·종료 경로에 영향이 없는 효과 크기 기준 안의 차이다. **종결 처리: POC 규칙은 적벽 프로필에서 쓰지 않으므로 더 추적하지 않는다.** POC 프로필은 M4에서 정리할 때 함께 정리한다.

## 6. 일부러 하지 않은 것 / 편차

- **진형별 노출표는 어린진 하나로 모든 진형을 처리한다**(M5). 진형 상성 ×1.2, 전환 ×0.8도 M5. 장사진 ×0.9만 넣었다.
- **지휘관 보정은 통솔만 쓴다.** 시나리오 데이터에 지력·무력이 없다(생성기에 능력치가 생기면 거리대별로 바꾼다). 폭 ±20%는 제안값.
- **레벨·경험치(레벨당 화력 +7%)는 salvo 규칙에서 쓰지 않는다**(§14). POC 경로에는 남아 있다.
- **지휘 한도 초과 페널티(기동·명중·진형 전환)는 아직 없다**(조조 전대 3단계). 필요하면 M5 전에 넣는다.
- **무기 배분 비율은 구현하지 않았다.** 범주 순서는 고정(포격·전열·요격·뇌격). "열이 모자라면 비율이 높은 범주부터"는 배분 UI가 생길 때.
- **`missile`·`fighter` 명령은 salvo에서 `volley`(일제사격 지금)로 같은 일을 한다.** CP 비용 없음. 무장 탭의 두 버튼 문구는 M10에서 정리.
- **적 AI는 POC 그대로**다. 추격 거리 = 최대 사거리 × 0.8, 거리대 유지(`realtime_rules.range_band_hold`)는 M6·M7. `PocEnemyAi`는 salvo일 때 미사일·함재기 명령을 내지 않는다.
- **안개는 없다**(M6). 모든 적이 확인 접촉이다. 지형 보정은 1.0(M6).
- **CP는 salvo 돌격에 쓰이지 않는다.** CP 자체의 제거는 M4.
- **진형 슬롯 기하(`formation_offsets`)와 `rule_overrides.ai_advance_speed`는 남아 있다.** 진형 7종 교체는 표시 계층과 같이 M5·M10에서 한다(REVIEW-M2 후속 C는 M5로 넘긴다).
- 화공 연쇄 폭발·강습 진입(기함 진입)은 M9. 돌격과 강습 접근은 거리대 접근까지다.

## 7. 컨셉 세션에 묻거나 알릴 것

1. 사거리 안에서 서로 멈춰 있어도 60초마다 쏜다(§4.3 의도). 주기가 찼는데 표적이 없었다면 사거리에 들어오는 즉시 쏜다. 이 "대기 중인 일제사격"이 의도인지 본다. 아니면 표적이 없을 때 주기를 흘려보내도록 바꾼다(한 줄 수정).
2. 방향 손실 배분: 이탈 한 척마다 "노출 묶음 몫 `loss_exposed < 6000bp × (이탈 누계+1)`이면 노출 묶음, 아니면 나머지 묶음"으로 정한다. 그래서 첫 척은 노출 묶음이고, 장기 비율은 60%로 수렴한다(리뷰 요청: 소수 잔여 이월·20척 이상 60±5% 테스트는 M5).
3. 10~15초 주기 대안(P12)은 `combat.period_s`만 바꾸면 비교할 수 있다. 이번에는 60초만 측정했다.
4. (판정: ①채택, ④수용, REVIEW-M3) 포격함 대 전열함 거리 시험 결과는 §3이다. 가까이서 포격함 전대가 지는 폭(승률 27%)이 의도에 맞는지 본다.

## 8. 리뷰 후속 (REVIEW-M3)

- `tests/salvo_compare.gd`에 `--period`(초)와 `--dmg-scale`(기본 피해 배율)을 열었다. M4에서 (a) 주기만 (b) 주기·피해 같은 비율 두 변형을 같은 시드로 잰다.
- M4: 거리대별 지휘관 능력치(접적·포화 지력, 교전 통솔, 강습 무력, 시나리오 JSON의 `might`·`intellect`). 지휘 한도 초과 페널티는 조조 전대에 초과가 있는 난이도·편성이 있을 때만.
- M5: 방향 배분 소수 잔여 이월과 장기 60±5% 테스트.
