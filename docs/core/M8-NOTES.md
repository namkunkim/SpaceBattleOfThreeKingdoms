# M8 보급과 수리: 구현 메모

2026-10-05, 구현 세션 "M8 보급 구현". 브랜치 `claude/m8-supply`. 제안서 §4.13·§9 M8 행, 세션 Q25·Q48(K4), P16·P18. 수치는 `data/profiles/combat_m3.json`의 `combat.supply`(생성기 `tools/scenario/make_combat_m3.py`, `status: "proposed"`).

## 1. 구조

## 2. 규칙 표

| 규칙 | 값 | 출처 |
|---|---|---|
| 보급함 영역 | 보급함(SHP-05)이 남은 전대 중심 반경 140, 보급함 1척당 동시 1개 전대 | 본편 `supply_contract.source_types.supply_ship` |
| 처리량 | 보급함 전대 선체 ≥ 7500bp 100%, ≥ 4000bp 50%, 그 아래 25% → **진행 속도**(60초 / 120초 / 240초) | 본편 `throughput_basis_points`, 표현은 제안값 |
| 기지 | 유비 (120,780), 손권 (300,440), 조조 (1460,180). 반경 180, 동시 4개. 재고 무한, 수리 물자 불필요 | 본편 `friendly_bases`, 재고 무한은 제안값 |
| 받는 쪽 | 같은 진영이고 같은 세력 또는 연합(유비·손권). 조조 보급함·기지는 조조군만 | 본편 `mutual_supply_alliances` |
| 정지 | 초당 이동 ≤ `still_eps_px_s` 0.5px(틱당 0.5/hz, F-4). 선회는 정지로 친다 | 제안값(본편 movement_epsilon 0.001/턴) |
| 주기 | 반경 안 정지 60초(`stationary_s`). 움직이거나 벗어나면 진행 0 | Q48, 본편 1턴 |
| 탄약 | 주기 끝에 전 범주 전량 보충. 상한 = 남은 플랫폼 수(무손상+경파+중파) × 플랫폼당 탄약. 보급함 전대 재고가 모자라면 시작하지 않는다(전량만, 원자적) | 본편 `refill_policy` |
| 재고 | 보급함 1척당 탄약 12단위·물자 4. 보충 1회 = 탄약 부족분 + 물자 1. 이탈 시 `floor(재고 × (N − d) / N)` | 본편 `per_supply_ship_maximum`, `destruction_policy` |
| 재적재 | 보급함 전대가 **같은 세력** 기지 반경에 60초 정지하면 재고를 남은 척 수 기준 상한으로 | 본편 `reload_policy` |
| 순서 | 진행 중인 손님 유지 → 빈자리는 남은 탄약 비율 ↑ → 정지 시작 틱 ↑ → 전대 ID ↑. 공급원은 가장 가까운 곳 | 본편 연료 순서를 탄약으로(§4.13) |
| 수리 | 주기마다 물자 1로 중파 1척 → 경파(가장 많은 함종, ID 순). 대파·격침은 고치지 않는다 | §4.13, P16 |
| 경파 회복 | 마지막 피격 뒤 120초면 경파 전부 → 무손상. 보급 영역 불필요 | §4.13, P16 |

## 3. 편차와 판단

1. **처리량 표현.** 본편은 턴마다 정수 슬롯 크레딧(나머지만 이월)으로 50%면 두 턴에 한 전대다. 실시간은 슬롯을 척 수로 두고 진행 속도를 처리량으로 줄였다. 평균 처리량은 같고 연속 시간에서 계단이 없다.
2. **보급과 함께 수리.** 한 주기(60초)에 탄약 보충(물자 1)과 중파 1척 수리(물자 1)를 함께 한다. 제안서는 둘을 따로 적었지만 같은 60초 정지 조건이라 합쳤다. 탄약이 가득하고 중파만 있으면 물자 1로 수리만 한다.
3. **수리는 단계만 바꾼다.** 선체 점수·척 수는 그대로다. 손상 단계는 피격 때 선체 비율로 다시 계산(`_wound`)되므로, 수리·회복한 함선은 **다음 피격에서 선체 비율 기준으로 다시 손상될 수 있다.** 즉 수리 효과는 "다음 피격까지 화력 단계 계수(경파 0.9, 중파 0.65)를 올리는 것"이다. 선체 회복은 결산·패주 추출과 얽혀 넣지 않았다.
4. **경파 회복은 영역과 무관.** P16의 "경파 → 무손상(120초 무피격)"을 보급 없이 어디서나 적용했다. 보급함 0척 전대도 쉬면 회복한다(§4.4 "보급함 0척: 수리 효과 없음"은 중파 수리에만 건다).
5. **realtime_rules에는 보급 키가 없다.** 보급은 시나리오가 아니라 본편 고속정 규칙에서 오므로 다른 전투 규칙처럼 `combat_m3.json`에 두었다(기지 좌표 포함). 시나리오 생성기는 건드리지 않았다.
6. **기지 진영.** 기지 세력과 같은 세력 또는 연합 세력의 전대가 있는 진영이 기지 진영이다(손권 기지 → 진영 0, 조조 기지 → 진영 1).

## 4. 측정 (AI 대 AI, 안개 켬, 플레이어 명령 0건, 표준 규모 0.9)

같은 40시드(0~39)를 M8 직전 코드(`56e3faf`, M7 후속 F-1·F-2 병합 전)와 M8 코드로 돌렸다. 도구는 M7과 같다(`TAG=_m8 tools/m7/baseline.sh 표준 40 8`, `python tools/m7/summarize.py 표준 _m8`). `tests/autoresolve.gd` 행에 `supply`(진영별 [보급 주기, 탄약 보충, 수리, 경파 회복 척 수])를 더했다. 8병렬 약 9분.

| | M8 전 | M8 |
|---|---|---|
| 연합 승률 | 67.5% ±7.4 | 67.5% ±7.4 |
| 길이 중앙 | 13.9분 | 13.9분 |
| 종료 경로 | 조조 군 사기 붕괴 67.5%, 유비 기함 상실 30%, 연합 비용 손실 2.5% | 같음 |
| 비용 손실 평균(연합/조조) | 4626 / 4943bp | 4630 / 4940bp |

**시드별 승패·길이가 40판 모두 같았다.** 보급이 결과를 바꾸지 않는다. 한 판당 사건:

| 진영 | 보급 주기 | 탄약 보충 | 수리 | 경파 회복 척 수 |
|---|---|---|---|---|
| 연합 | 0.25 (23%의 판) | 0.17 (17%) | 0.15 (12%) | 1.6 (78%) |
| 조조 | 0.05 (5%) | 0.03 (3%) | 0.03 (3%) | 0.57 (45%) |

- 탄약은 14분 판에서 거의 떨어지지 않는다(§4.8 "탄약은 떨어지지 않았고 열이 실제 제약"과 같은 결과). 보급 주기는 대부분 우연히 보급함 전대 옆에 60초 서 있던 전대다.
- 경파 회복은 자주 일어나지만 회복한 전대가 다시 맞으면 선체 비율로 되돌아가(§3 3번) 결과에 남지 않는다.
- 즉 지금 AI 대 AI 판에서 M8은 **밸런스 중립**이다. 보급이 의미를 가지려면 플레이어가 물러나 쉬거나 AI가 보급하러 가야 한다(§6 3번). M7 기준선(표준 0.9)은 그대로 쓸 수 있다.
- 1000시드 기준선은 M7과 같이 대기열(`CHECKLIST-OPEN.md` §5)이다. F-1·F-2 병합 뒤 코드로 다시 잰다.

## 6. 컨셉에 알릴 것

1. §3의 편차 1~6(처리량 표현, 보급·수리 한 주기, 수리는 단계만, 경파 회복 영역 무관, 데이터 위치, 기지 진영)을 제안서 §4.13에 반영할지.
2. 정지 판정 `still_eps` 0.05px/틱과 기지 재고 무한·기지 수리 물자 없음은 제안값이다.
3. **AI가 보급을 쓰지 않는다.** 탄약은 판 길이 안에서 거의 떨어지지 않아(§4) 지금은 보급 효과의 대부분이 수리·경파 회복이다. 보급하러 물러나는 AI 행동(탄약 비율·중파 비율 임계)은 M8 범위 밖으로 두었다. 필요하면 M7 방침표에 `resupply` 임계를 더하는 후속으로.
4. 보급 영역 표시·진행 막대·재고 표시(UI)는 M10 몫이다. 투영 키(`supply_sources`, 전대 `supply`)는 준비됐다.
