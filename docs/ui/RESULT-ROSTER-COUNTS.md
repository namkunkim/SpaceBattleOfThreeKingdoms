# 작전 결과의 실제 잔존 수 (2026-10-25)

적 접촉의 `FleetView.ships`는 실제 척 수가 아니라 전력 구간을 10 기준으로 정규화한 표시값이다. 결과 화면이 이 값을 사용해 조조·장합 등 여러 함대를 모두 `10척`으로 표시하고, 미탐지·격침 적 함대는 누락하는 문제가 있었다.

`BattleProjection.outcome.roster`는 `st.over` 이후에만 모든 출전 함대의 결산 사본을 공개한다. 잔존 수는 적벽 코어의 `SalvoCombat.present_ships`(무손상·경파·중파), 최초 수는 `total0`를 사용한다. 격침 함대는 0척, 항복·탈출 함대는 이탈 당시 잔존 수와 상태를 표시한다. POC 프로필은 기존 1/1000척 상태를 올림한다.

`BattleViewModel.result_fleets`는 전투 중 접촉 배열과 분리하며 재시작 시 비운다. 결과 화면의 양군 목록·잔존 막대·생존 함대 집계는 이 결산 배열을 사용한다. 이름·초상·숫자는 전투 코어에서 오며 UI가 코어 상태를 직접 읽지 않는다. 전투 중 탐지·안개 계약은 바꾸지 않는다.

검증:

- `tests/result_roster.gd`: 실제 씬에서 접촉용 10척 재현 → 68척 편성 중 7척 격침 → 결산 61척 확인. 항복·탈출·격침, 미탐지 적 포함, 결산 사본 독립성, 재시작 초기화 통과. 그래픽 실행의 화면 캡처도 확인했다.
- `tests/detection_rules.gd`: `DETECTION_RULES_PASS`, 종료 코드 0. 전투 중 적 정확한 수량 비공개 검증도 전용 테스트에 포함했다.
- `tools/audit-localization.py --check`: 누락 0, 오류 0. 항복·탈출 상태를 영어·중국어·일본어에 추가했다.
- `tests/ui_flow.gd`: `UI_FLOW_PASS`, 종료 코드 0이지만 기존 `user://` 설정 복원 파일의 쓰기 권한 오류가 발생했다. 완전한 무오류 통과로 간주하지 않는다. trace·셰이더 캐시 접근 및 종료 리소스 잔류 경고도 실행 환경의 기존 제한으로 남는다.

실행 중이던 구버전 프로세스에는 코드가 자동 적용되지 않으므로 재실행이 필요하다. 이전 판의 결과를 새 프로세스에 재구성하지는 않는다.
