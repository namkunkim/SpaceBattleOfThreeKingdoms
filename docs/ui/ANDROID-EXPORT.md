# 안드로이드 태블릿 내보내기와 실기기 확인

1차 목표 플랫폼은 안드로이드 태블릿 + 윈도우 PC(Q56). 이 문서는 코드로 해 둔 준비와, 이 PC에서 할 수 없어 사용자가 해야 하는 단계를 나눠 적는다.

## 이미 해 둔 것(코드·설정)

| 항목 | 내용 |
|---|---|
| 프리셋 | `export_presets.cfg`의 "Android 태블릿": arm64-v8a만, 몰입 모드, 진동 권한, 비밀 정보 없음(키스토어 미지정). 개발·시험 내보내기 한정(디버그 키스토어) |
| 화면 방향 | `display/window/handheld/orientation=4`(가로, 센서로 좌우 반전) |
| 텍스처 압축 | `rendering/textures/vram_compression/import_etc2_astc=true`. 내보낼 때 ETC2/ASTC로 압축된다. 렌더러는 Compatibility(GLES3) 그대로 |
| 내보내기 제외 | `out/`, `docs/`, `tests/`, `tools/`, `altair-corridor.html`, `assets/concepts/`(코드에서 쓰지 않는 개념 이미지 25MB) |
| 안전 영역 | `input/touch/safe_area.gd`. 노치·카메라 구멍·내비게이션 바 만큼 전투 HUD를 안쪽으로 민다. 배경·전장은 끝까지 그대로. 1초마다·창 크기 변경 때 다시 읽는다. 환경변수 `SBTK_SAFE_INSETS="왼,위,오른,아래"`(화면 픽셀)로 PC에서도 확인할 수 있다 |
| 첫 실행 표시 밀도 | 모바일은 "낮음"(정원의 35%), PC는 "보통". 실기기 측정 뒤 `GameSettings.default_density()`만 고친다 |
| 밀도 측정 | `tests/bench_density.gd` (아래) |

타이틀·브리핑·일시정지·설정·결과 화면의 컨트롤은 가장자리에서 56단위 이상 떨어져 있어 안전 영역 보정을 따로 하지 않았다. 실기기에서 가려지면 화면 쪽에도 같은 `SafeArea`를 붙인다.

## 사용자가 해야 할 것(이 PC에는 없다)

확인한 결과 이 PC에는 Godot 내보내기 템플릿(`%APPDATA%\Godot\export_templates`가 비어 있음), JDK, Android SDK가 없다. 그래서 APK는 만들지 못했고 내보내기는 한 번도 시도하지 않았다.

1. Godot 편집기 → 편집기 → 내보내기 템플릿 관리 → 4.7.2 설치
2. JDK 17과 Android SDK(명령줄 도구, 플랫폼 도구, 빌드 도구, 플랫폼) 설치 후 편집기 설정 → 내보내기 → Android에서 경로 지정
3. 태블릿에서 개발자 옵션과 USB 디버깅을 켜고 PC에 연결
4. 프로젝트 → 내보내기 → "Android 태블릿" → 원격 디버그로 실행(또는 APK 내보내기)

## 실기기에서 확인할 것

- 첫 실행 UI 크기가 100%인지(`TouchMetrics.default_ui_scale`), 명령 버튼이 손가락에 편한지
- 안전 영역: 카메라 구멍·내비게이션 바 쪽 HUD가 가려지지 않는지, 회전(좌우 반전) 때 다시 맞는지
- 터치 입력(`input/touch/`)이 실제 터치에서 마우스 흉내와 겹치지 않는지, 길게 누르기 0.45초
- 백그라운드로 보냈다 돌아올 때 자동 일시정지(Q53)와 진동
- 성능: `tests/bench_density.gd`의 방식으로 밀도별 FPS. 설정 화면에서 밀도를 바꿔 가며 봐도 된다

## 표시 밀도 측정(PC 기준선)

```
godot --path . --resolution 1920x1200 --script tests/bench_density.gd
```

수직동기를 끄고 밀도별로 6초씩 잰다(첫 라운드는 워밍업으로 버린다). 결과는 `out/bench-density.md`.

2026-10-04, Intel Arc 130V 내장 GPU, Compatibility, 창 1920×1061:

| 밀도 | 표시 함선 | FPS | 평균 ms |
|---|---|---|---|
| 낮음 | 약 470 | 110 | 9.05 |
| 보통 | 약 800 | 112 | 8.93 |
| 높음 | 약 1,135 | 110 | 9.07 |

읽는 법: 이 PC에서는 함선 수가 3배가 되어도 프레임 시간이 같다. 함선 표시(MultiMesh)가 병목이 아니고, 병목은 함선 수와 무관한 고정 비용(빛 번짐 후처리, HUD 다시 그리기, 스크립트)이다. 그래서 이 숫자로는 태블릿 기본 밀도를 정할 수 없다. 모바일 GPU는 채움률(2560×1600 후처리)과 드로우 비용이 달라 결과가 다를 수 있다. 모바일 기본값 "낮음"은 측정 전의 보수적 임시값이며, 근거는 "숫자가 없으니 여유를 둔다"일 뿐이다. 실기기 측정 뒤 바꾼다. 설정의 "빛 번짐"을 끄는 것도 같이 측정할 만하다.
