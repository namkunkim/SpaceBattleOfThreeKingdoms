# 진형 탭 설계 (본편 스펙 반영)

2026-10-05. 정본: 본편 `C:\WorkSpace\Seonghanji\docs\03-systems\ship-specs.md` §5, `docs\06-tech\screens.md` §3.2~§3.4·§5, `data\formations.json`, `app\views\formation_spec.gd`(도형 규격).
실시간 코어 규칙(`PROPOSAL-realtime-battle-core.md` §4.7, `docs/core/M5-NOTES.md`)이 본편 턴제 규칙과 다르면 코어가 이긴다.

## 1. 정정: 진형은 10종이 아니라 7종이다
- 본편 정본과 코어(Q10) 모두 7종: 어린 FRM-01, 학익 FRM-02, 방원 FRM-03, 안행 FRM-04, 봉시 FRM-05, 장사 FRM-06, 팔진 FRM-07.
- "10종"은 호스트 POC의 배치 이름(`FleetBattle3D.FORM_NAMES`)이다. 효과·상성이 없고 코어 `formation` 명령과 무관하다. 탭에 올리지 않는다.
- 이름·순서는 `formations.json` 순서를 따른다(어린→학익→방원→안행→봉시→장사→팔진). 코어에서는 `SalvoCombat.formation_ids()`(정렬된 키)와 같다.

## 3. 상성 힌트
- 순환: 학익 → 어린 → 방원 → 봉시 → 안행 → 학익 (화살표 왼쪽이 오른쪽에 우위, 교전 거리대 ×1.2).
- 장사진: 상성 밖, 피해 ×0.9(코어 값). 팔진: 상성 판정 무효(양쪽 모두).
- 적의 진형 ID는 투영이 공개하지 않는다(M9). 힌트는 "내 진형이 어떤 진형에 강/약한가"를 후보 칸마다 표시한다(예: 학익 칸 "어린에 강함 · 안행에 약함"). 적 진형을 아는 척하지 않는다.

## 4. 선택 불가 이유 (코어 사유 코드 → 문구)
| 코드 | 상태 | 문구 |
|---|---|---|
| `formation_terrain` | 칸 잠금 | 지형이 허용하지 않는 진형 (기저 항로: 학익·안행 불가, 중회랑: 방원·봉시·장사만, 대회랑: 장사진 고정, 이때 ② 포화 계수 0.6 병기: screens.md §3.3) |
| `formation_master` | 칸 잠금 | 팔진: 통솔 90 이상 + "신기묘산" 특성 필요 |
| `unknown_formation` | 표시하지 않음 | — |
| 현재 진형 지정 | 전환 취소 | "전환 취소" 버튼으로 표시 |
- 적벽은 개활이라 지형 잠금은 실제로는 나오지 않는다(M5-NOTES §5). 문구·잠금 표시는 `terrain_class`가 있을 때만 쓴다.
- 지휘 한도·전환 중 피해 ×0.8은 코어가 처리한다. UI는 명령을 보내고 투영을 읽는다.

## 5. 명령과 선택 대상
- 명령: `{kind:"formation", ids:[전대 ID...], args:{id:"FRM-0x"}}` (`BattleCommands.make`에 `args` 추가가 필요하다. 지금 `make`는 `args`를 못 싣는다).
- 선택 대상 → 전대 ID 배열 변환은 한 곳(`BattleCommands`)에 둔다. 그룹 진형(CHECKLIST §8)은 같은 함수에 그룹의 ID 배열을 넘기면 된다.
- 전환은 전대마다 가능 여부가 다르므로(통솔·특성) 칸의 상태는 선택 전체에서 계산한다: 전원 불가면 잠금, 일부만 불가면 "n개 전대 제외" 표기.

## 6. 호스트 범위 (미결정)
호스트(`FleetBattle3D`)는 POC 규칙(salvo=null)이라 코어가 `formation` 명령을 거부한다. 사용자 결정 전까지 탭·명령·테스트는 적벽 프로필 sim 기준으로만 만들고 호스트 연결은 하지 않는다. 선택지: (a) 호스트를 시나리오 프로필로 전환(M10 규모), (b) 위 범위만(추천), (c) POC 코어에 `formation` 허용(코어 변경).
