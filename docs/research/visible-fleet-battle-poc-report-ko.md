## 결론

**가능하다.** 성한지의 전술 코어를 실시간 게임으로 교체하지 않고도, 기존 자유 좌표·방향·진형 데이터를 사용해 여러 함대를 실제 함선 군집으로 표시할 수 있다.

v1.0에서는 2D 스프라이트 기반 화면과 별도로 Quaternius CC0 함선 7종을 실제 Godot `MeshInstance3D`로 배치하는 3D 전투 장면을 추가했다. 메인 실행 장면은 `FleetBattle3D.tscn`으로 전환했으며 원근 카메라, 조명, 금속 재질, 102척 편대, 엔진 발광, 일제사격 빔과 피격 플래시를 실시간 렌더링한다. 기존 2D 장면은 비교·회귀 검증용으로 유지한다.

v1.1에서는 영상 레퍼런스의 화면 문법에 맞춰 성운 전장 배경, 선택 함대 보호막 돔, 함대별 부유 상태 태그, 실시간 방어막·함체 게이지, 원형 전술 레이더, 지휘관 초상, 명령 버튼 패널, 강화된 광선 포화와 다층 폭발·충격파·파편 VFX를 추가했다. 양 진영 거리를 압축해 주력함과 실제 교전이 화면 중심에서 읽히도록 카메라와 편대를 재구성했다.

v1.2에서는 첨부 레퍼런스처럼 모든 함선을 크게 표시하지 않는다. 기함 추가 확대는 사용하지 않으며, 원본 모델마다 다른 실제 바운딩박스 길이를 기준으로 크기를 정규화한다. 특히 다른 후보보다 약 두 배 긴 Imperial 전열함은 별도 축소했다. 작은 함선의 존재감은 선체 확대가 아니라 촘촘한 편대, 엔진 발광점, 길게 이어지는 항적과 교차 화선으로 확보했으며, 함대 상태 태그도 축소해 전장 면적을 덜 가리도록 조정했다.

함대 편제는 대형함 중심으로 변경했다. 전열함·화력함·강습항모·공성함·전자전함·보급/수리함을 각 함대의 주 전열에 반복 배치하고, 요격함은 외곽 호위 스크린에만 둔다. 조사 번들에는 전용 항모가 없으므로 Challenger는 POC용 강습항모 대역이며 제품 반영 전 교체가 필요하다.

Quaternius 모델의 로컬 선수 방향은 `+Z`로 판정했다. POC의 함대 로컬 전방은 `-Z`이므로 모든 선체에 Y축 180도 보정을 적용했다. 아군은 화면 상단의 적을 향하고 적군은 화면 하단의 아군을 향한다. 엔진광과 항적은 선체 회전과 분리해 각 함선의 선미 쪽에 유지한다.

첨부 레퍼런스의 전장 대비 함선 비율에 맞추기 위해 모든 함선 시각 노드를 이전 크기의 정확히 1/3로 축소했다. 편대 좌표와 함대 간 거리는 유지하며 선체, 엔진광, 항적만 함께 축소한다.

함선 수는 함대당 17척에서 34척으로 두 배 늘려 총 204척으로 구성했다. 횡진은 8열, 방진은 6열, 종진은 3열, 쐐기진은 4개 항로 단위의 압축 배열을 사용해 함선 수 증가가 편대 면적의 단순한 두 배 확장으로 이어지지 않도록 했다.

이번 POC는 1600×900 한 화면에서 다음을 동시에 표현했다.

- 아군 2함대, 동맹 1함대, 적 2함대
- 함대당 22~30척의 가시 함선
- 횡진·쐐기진·방진의 실제 공간 배열
- 기함 강조, 함대명, 함선 수, 사기
- 이동 목적선과 도착 방향
- 함대 사이 일제 화선과 피격 지점
- 전술 레이더와 전장 경계
- 선택 함대의 지휘관·참모·전력 배분·명령 HUD
- 선택, 우클릭 이동, Q/E 제자리 선회, 1/2/3 진형 변경, 일제사격 표적 지정, 보호막 피해, 일시정지

## 성한지 반영 후보 — 승인 전

### POC 목표 가설

사용자 제공 영상처럼 **여러 함대가 실제 함선 군집과 진형으로 보이는 전술 화면**을 성한지에서도 구현할 수 있는지 독립 POC로 검증한다. 아래 내용은 아직 제품 사양이나 구현 지시가 아니며, 영상 수준 도달과 사용자 승인 전에는 성한지 기준선에 반영하지 않는다.

### 구현 원칙

1. `RedCliffsTurnBattle`의 상태와 viewer projection을 유일한 권위로 유지한다.
2. 현행 2D 전술 지도 위에 `VisibleFleetLayer` 성격의 표현 계층을 추가한다.
3. 각 전대/함대의 `position`, `facing`, `formation`, `ship_count`, `flagship`, `side`, 관측 신뢰도를 입력으로 사용한다.
4. 함선 배치 좌표는 진형 데이터에서 결정론적으로 파생한다. UI가 전투 수치를 다시 계산하지 않는다.
5. 이동 해결 뒤 함선 군집 전체가 이전 위치에서 새 위치로 보간되며 방향도 함께 회전한다.
6. 진형 변경은 단순 라벨 교체가 아니라 함선들이 새 슬롯으로 재배열되는 애니메이션으로 표현한다.
7. 승인된 사격 이벤트만 함선 군집 사이의 빔·레일건·미사일·폭발로 재생한다.
8. `unknown` 적은 그리지 않는다. `estimated/stale`은 실제 함선 수·정확한 진형을 노출하지 않는 흐린 추정 군집으로 그린다.
9. 가까운 배율에서는 대표 함선 모델, 중간 배율에서는 함선 실루엣 군집, 먼 배율에서는 진형형 군집으로 LOD를 전환한다.
10. 한 함대의 모든 실제 함선을 항상 Node로 만들지 않는다. `MultiMesh`, 배치 draw 또는 GPU instancing으로 수백~수천 척을 표현한다.

FleetVisualState

이는 신규 전투 권위가 아니라 기존 코어 결과를 그리기 위한 읽기 모델이다.

### 승인될 경우의 단계별 후보 순서

1. **G-VF-01 가시 함대 정적 투영**: 현재 위치·방향·진형·함선 수를 군집으로 표시
2. **G-VF-02 이동·선회 재생**: 턴 해결 결과를 보간하고 이동선/도착 방향과 일치 검증
3. **G-VF-03 진형 전환 재생**: 7종 진형 슬롯과 변경 성공/실패 표현
4. **G-VF-04 사격·피해 재생**: G8 권위 이벤트를 무기 화선·피격·폭발로 연결
5. **G-VF-05 LOD·성능**: 다수 함대와 대표 함선 수 확대, 1600×900 프레임 기준 고정
6. **G-VF-06 지휘관 HUD**: 선택 함대의 지휘관·참모·사기·명령·전력 상태 연결

### 첫 인수 기준

- 전장에 최소 5개 함대와 합계 100척 이상의 대표 함선이 동시에 보인다.
- 세 종류 이상의 진형이 실루엣만으로 구분된다.
- 선택 함대의 위치·방향·함선 수·진형이 코어 snapshot과 일치한다.
- 아군/동맹/적 색상 외에도 명패와 형상으로 식별할 수 있다.
- 적 관측 상태에 따른 정보 차단이 유지된다.
- 이동·선회·사격 애니메이션 중에도 명령 원장 결과는 바뀌지 않는다.
- Windows 1600×900에서 지도·함대·명령 패널·하단 HUD가 겹치거나 잘리지 않는다.

## 범위 경계

- 이 POC는 화면 방향과 기술 가능성 검증이며 성한지 코어를 복제한 것이 아니다.
- 현재 절차형 함선과 HUD는 임시 표현이며 상품화 수준이 아니다.
- 사용자 제공 영상과 비교해 함대 밀도, 선체 형태, 이동·선회, 진형 재배열, 포격 연출, HUD가 충분히 근접해야 POC 완료 후보가 된다.
- POC 완료 후보가 된 뒤에도 사용자의 명시적 승인을 받기 전에는 성한지 작업 채팅에 반영 지시를 보내지 않는다.
- 승인 후 실제 적용 단계에서는 독자 함선 실루엣/3D 자산으로 교체한다.
- 사용자 영상의 함선·인물·대사·아이콘·UI 미술은 복사하지 않는다.
- 현재 진행 중인 G8 전투 피해 작업과 파일을 섞지 않는다. G8 완료 후 별도 수직 슬라이스로 착수한다.
