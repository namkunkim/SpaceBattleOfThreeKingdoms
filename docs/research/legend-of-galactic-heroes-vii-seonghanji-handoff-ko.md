# 《은하영웅전설 VII》 이동·전투·UI 분석 및 성한지 적용성 보고

> 작성일: 2026-09-12  
> 용도: 성한지 개발 채팅 전달용 설계 검토  
> 범위: 코드 구현 없음. 《은하영웅전설 VII》의 실제 플레이 규칙을 확인하고 현재 성한지에 그대로 적용 가능한지 판정한다.  
> 기준 변경: 기존 III·IV 기준 검토는 참고 이력이며, 본 문서가 VII 기준의 최신 결론이다.

## 1. 핵심 결론

《은하영웅전설 VII》는 일반적인 싱글 플레이 함대 전략 게임이 아니라, 한 서버에서 양 진영 합계 최대 2,000명이 각자 한 인물·탑승함·직책을 맡고 협업하는 실시간 MMOSLG다. 플레이어는 은하제국 또는 자유행성동맹의 사관으로 시작하며 전투·보급·내정 역할을 분담하고, 적 수도 함락을 목표로 한다.[1]

성한지에 **VII의 이동·전투 플레이를 프로그램과 화면까지 문자 그대로 이식하는 것은 부적합**하다. VII는 격자 워프, 한 탑승함의 실시간 조종, 다수 인간 플레이어의 채팅과 직책 분업을 전제로 하지만, 성한지는 19성계·45권역·37항로의 함대 단위 캠페인과 턴제 적벽 전투를 전제로 하기 때문이다.

그러나 **플레이 의미를 보존한 규칙 이식은 가능하며 상당 부분 이미 구현되어 있다.** 가장 적합한 이식 대상은 다음이다.

1. 이동 지점과 도착 방향을 한 명령으로 지정한다.
2. 제자리 선회와 정면 유지 평행 이동을 별도 기동으로 둔다.
3. 정면·측면·후면의 방어 차이를 전투 핵심으로 삼는다.
4. 엔진·센서·무기·방어 사이에 제한 자원을 재배분한다.
5. 자동 교전 태세와 무기별 수동 사격을 구분한다.
6. 탐지 전에는 적 위치를 숨기고 레이더·추정 정보로 싸운다.
7. 전략 지도, 전술 지도, 통신·명령 패널의 책임을 분리한다.
8. 계급에 따라 권한 카드가 열리고 상관에게 제안, 부하에게 명령하는 조직 플레이를 제공한다.

현재 성한지 적벽 코어의 자유 좌표·1~5개 경유점·방향·진형 7종·무기 배분·탐지/전쟁 안개·지형·고속정·보급은 VII보다 이미 넓다. 따라서 VII를 기준으로 기존 기능을 갈아엎기보다, **누락된 VII식 조작인 제자리 선회, 평행 이동, 전력 배분, 자동 교전 태세, 자발적 전장 이탈을 추가 검토하는 방식**이 가장 안전하다.

## 2. VII가 어떤 게임인가

### 2.1 시나리오와 장기 구조

- 실시간 1시간이 게임 내 1일이며 서버 하나에 최대 2,000명이 참가한다.[1]
- 전쟁 개시부터 종전까지가 한 세션이다. 예상 세션 길이는 현실 시간 최소 1개월, 최대 4~6개월이며 수도 함락 또는 시간 만료로 끝난다.[1]
- 전과로 얻은 계급·능력·포인트는 다음 세션에 이어져 더 높은 직책으로 시작할 수 있다.[1][2]
- 자유행성동맹의 평의회 의장은 선거로 도전할 수 있고, 원작 인물은 포인트와 추첨을 통해 한 세션 동안만 사용할 수 있도록 설계됐다.[1]
- 아래 계급에는 명령을 내리고 위 계급에는 제안을 올린다. 진급할수록 인사·행동 권한과 함께 부하 제안을 심사할 행정 부담도 커진다.[1]
- 발표 당시에는 전략 화면의 인사·부대 편성과 전술 화면의 전투가 양대 축이었고, 내정 명령도 여러 플레이어가 협력해 실행하는 구상이었다.[2]

중요한 한계도 있다. 2004년 5월 플레이어 안내에는 전략·전술 계통만 구현돼 정치가 직업의 실제 할 일이 부족했다고 기록돼 있다.[3] 2005년 4월에는 권리 허락 계약 해지를 이유로 운영 중단이 발표됐다.[4] 그러므로 발표 단계의 요새전·쿠데타·정치 구상을 실제 완성 기능으로 취급하면 안 된다.

### 2.2 VII의 진짜 핵심

VII의 독창성은 함선 그래픽보다 다음 연결 구조에 있다.

`개인 캐릭터 → 직책/권한 카드 → 탑승함 → 현지 동료와 정보 공유 → 전투 또는 보급/내정 기여 → 전공과 승진 → 다음 장기 세션`

즉 플레이어가 모든 함대를 내려다보는 신이 아니라 조직 속 한 사람이라는 점이 핵심이다. 성한지에 VII를 적용하려면 화면 모양보다 이 권한·책임·정보 비대칭을 먼저 가져와야 한다.

## 3. 함대 이동 방식 분석

### 3.1 확인된 실제 조작

VII의 전략 이동에서 플레이어는 자신이 탑승한 함선을 움직인다.[3]

- 우주 공간은 100×50 격자로 나뉜 평면이며, 양 진영이 같은 칸에 존재하면 전투 모드가 시작된다.[1]
- 워프는 격자 단위로 실행한다. 한 칸은 100광년, 1회 최대 항속 거리는 1,000광년, 즉 최대 10칸이다.[5]
- `함장` 권한 카드에서 `워프 항행`을 선택하면 이동 가능 원과 칸이 강조되고, 목적 칸을 클릭하면 자동 이동한다.[5]
- 먼 곳은 여러 번 워프해야 한다. 워프는 군사 명령 포인트(MCP)를 소비하고 포인트는 5분 단위로 천천히 회복된다.[5]
- 전략 정찰도 명령 포인트를 소비한다. 정찰 결과는 칸별 아군·적군 함선 수와 전투 중인 칸을 보여 주지만 영구 정보가 아니다.[5]
- 정찰 비용을 아끼기 위해 현지 채팅으로 아군에게 좌표와 적 정보를 묻고 공유하는 것이 실제 플레이의 일부다.[5]

### 3.2 성한지에 그대로 적용 가능한가

| VII 요소 | 그대로 적용 | 판정과 이유 |
|---|---:|---|
| 목적지 클릭 후 자동 이동 | 조건부 가능 | 성한지에도 명령 후 자동 진행이 있으므로 의미가 같다. |
| 100×50 고정 격자 | 불가 | 성한지의 19성계·45권역·회랑·37항로와 연속 좌표 지형을 훼손한다. |
| 1회 최대 10칸 워프 | 변환 필요 | 칸 대신 이동 예산·항속 원·도달 예상 구간으로 표현해야 한다. |
| 이동 때마다 MCP 소비 | 변환 필요 | 이동 연료가 아니라 지휘 대역폭/명령 변경 비용으로 쓰는 편이 성한지의 명령 지연과 맞다. |
| 적과 같은 칸이면 즉시 전투 | 변환 필요 | 동일 격자가 아니라 접촉 반경, 권역/회랑 충돌, 탐지 상태로 조우를 판정해야 한다. |
| 유효 시간이 있는 전략 정찰 | 직접 적용 가능 | 현재 전쟁 안개의 `unknown/estimated/stale` 모델과 매우 잘 맞는다. |
| 채팅으로 정보 공유 | 그대로는 불가 | 싱글 플레이에서는 참모 보고, 동맹 AI의 정보 요청/회신, 통신 지연으로 치환한다. |

### 3.3 권고

성한지 전략 이동은 현재의 `출발→항로/회랑→도착`, 명령 발행/도달 시각, 연속 좌표 진행률을 유지한다. VII에서 가져올 것은 격자가 아니라 다음 세 가지다.

- 선택한 함대의 **이번 명령으로 도달 가능한 범위**를 지도에 즉시 표시한다.
- 정찰과 잦은 경로 수정이 **같은 지휘 자원**을 경쟁하게 한다.
- 아군의 관측 정보를 자동 합치지 않고 **보고의 출처·시각·신뢰도**를 표시한다.

## 4. 전투 플레이 분석

### 4.1 전장 진입과 시점

전투 중인 격자로 워프하면 데이터를 불러온 뒤 전략 화면에서 전술 화면으로 전환한다.[6] 전투는 실시간이고, 상대가 퇴각하거나 전멸하면 끝난다.[1] 전술 공간은 3D 함선으로 표현되지만 조작 평면에는 Z축 이동이 없어 본질적으로 2D다.[1][2]

VII의 기본 화면은 자함을 비스듬히 보여 주는 3D 시점이다. F4로 자함을 원형 표식으로 바꾼 탑다운 전술 시점으로 전환할 수 있고 마우스 휠로 확대·축소한다.[6]

### 4.2 전투 전 준비: 전력 배분

전술 화면에 들어가면 먼저 함선 성능 배분을 조정한다.[6]

- 적을 찾기 전에는 ENGINE과 SENSOR를 높여 탐색·기동을 우선한다.
- 적과 접촉하면 ENGINE/SENSOR를 낮추고 BEAM 또는 GUN과 방어막을 올린다.
- 함종에 따라 조절 가능한 폭이 다르고 전투 중 언제든 바꿀 수 있다.
- 방어는 정면이 가장 강하고 측면, 후면 순으로 약하다. 따라서 적에게 후면을 내주지 않는 기동이 중요하다.

이것은 단순 스탯 설정이 아니라 “먼저 발견할 것인가, 먼저 쏠 것인가, 맞고 버틸 것인가”를 같은 제한 자원 안에서 선택하게 하는 핵심 루프다.

### 4.3 이동과 방향

확인되는 명령은 다음과 같다.[6]

| 명령 | VII의 동작 | 성한지 대응 |
|---|---|---|
| 이동 | 목적점을 클릭한 뒤 그 지점에서의 방향을 다시 지정 | 이미 자유 좌표·경유점·도착 방향으로 구현됨 |
| 선회 | 이동하지 않고 제자리에서 방향만 변경 | 방향 초안은 있으나 독립 선회 비용/행동으로 분리할 가치가 있음 |
| 평행 이동 | 현재 방향을 유지한 채 이동, 정상 이동의 절반 속도 | 신규 이동 모드로 직접 적용 가능 |
| 정지 | 현재 행동을 취소하고 멈춤 | HOLD와 의미상 대응, 실행 중 명령 취소 규칙은 별도 확정 필요 |
| 퇴각 | 전장에서 이탈 | 현재 자발적 철수 정본이 없으므로 신규 정책 필요 |

평행 이동은 성한지에 특히 유용하다. 정면 화선을 적에게 유지한 채 측방으로 위치를 바꾸게 하므로, 이미 존재하는 정면·측면·후면 sector와 진형 방향을 실제 조작 선택으로 만든다.

### 4.4 공격과 사격

- 자동 공격은 가까워진 적을 계속 공격하는 태세다. `일제 공격`은 간격이 길고 1회 피해가 크며, `연속 공격`은 간격이 짧고 1회 피해가 작다. 공격 정지로 해제한다.[6]
- 수동 사격은 빔, 레일건, 미사일 중 하나를 골라 각 무기의 사거리·사격 가능 범위를 표시한 뒤 목표를 클릭한다. 단발 명령이라 반복 사격에는 입력을 반복한다.[6]
- 적은 처음부터 레이더에 나타나지 않고 아군 탐지 범위에 들어와야 표시된다.[6]
- 레이더는 자함 위치·방향, 아군, 탐지된 적, 좌표와 퇴각 가능 경계를 함께 표시한다. 다만 안내 작성자는 2004년 6월 당시 퇴각 경계 제한이 아직 구현되지 않았을 가능성을 명시했다.[6]

### 4.5 성한지에 그대로 적용 가능한가

| VII 전투 요소 | 적용성 | 권고 |
|---|---:|---|
| 2D 전술 평면 + 선택적 3D 관측 | 매우 높음 | 성한지의 2D 전술 지도와 3D 증거창 방향을 유지한다. |
| 목적점 + 도착 방향 | 이미 적용 | 현행 G4-02를 유지한다. VII처럼 단일 지점으로 축소하지 않는다. |
| 정면/측면/후면 | 이미 적용 | 현행 G4-04 sector를 피해·방어 해결과 연결한다. |
| 탐지된 적만 표시 | 이미 적용 | 현행 G5-01/02의 unknown·estimated·stale을 유지한다. |
| 무기별 사거리·사격각 | 대부분 적용 | 현행 무기 배분·사격선·목표 지정에 명확한 공격 가능 영역 표시를 보강한다. |
| 제자리 선회 | 높음 | 이동과 다른 비용을 가진 `TURN` 명령 후보. |
| 평행 이동 50% 속도 | 높음 | `STRAFE` 후보. 비율 50%는 VII 복제가 아니라 성한지 밸런스로 재검증한다. |
| 자동 일제/연속 공격 | 높음, 변환 필요 | 실시간 반복 대신 턴 태세 `SALVO / SUSTAIN / HOLD_FIRE`로 번역한다. |
| 전력 배분 | 높음, 신규 시스템 | `ENGINE / SENSOR / WEAPON / SHIELD`의 합계 고정 배분안으로 시험한다. |
| 퇴각 경계 | 중간 | VII 당시 구현 여부가 불확실하다. 성한지 고유의 탈출 지점·지휘 붕괴·추격 규칙으로 설계한다. |
| 한 척 직접 조종 | 낮음 | 성한지는 전대·함대 지휘 게임이므로 입력 단위는 선택 전대에 유지한다. |
| 완전 실시간 조작 | 낮음 | 현재 턴 원장·결정론·모바일 지원과 충돌하므로 채택하지 않는다. |

## 5. UI 구성 분석

당시 실제 캡처와 플레이 안내에서 확인한 레이아웃은 다음과 같다.[3][5][6]

### 전략 화면

- 상단 대부분: 성계와 격자를 표시하는 광역 우주 지도
- 좌측 하단: 상태 알림, 지역 채팅, 채팅 입력의 3단 통신창
- 하단 좌측: 인물 초상, 상태 수치, PMP/MCP
- 하단 중앙: 전체 은하 미니맵과 좌표 표시 전환
- 하단 우측: 현재 위치/시설과 직무 권한 카드·행동 버튼

### 전술 화면

- 중앙: 3D 함선 시점 또는 탑다운 전술 지도
- 좌측 상단: 시간·좌표·아군/적·이탈 경계를 보여 주는 레이더
- 좌측 하단: 전투 상태/채팅창
- 우측 상단: 엔진·센서·빔·포·방어막 배분 패널
- 우측 하단: 이동·선회·공격·사격·평행 이동·정지·퇴각 명령판

### 평가

VII의 UI는 기능 위치는 일관되지만 640×480 시대의 작은 고정 패널, 많은 아이콘, 카드 탭, 별도 채팅창으로 정보 밀도가 높다. 실제 플레이 안내도 초보자에게 조작이 복잡하다고 평가했다.[3] 따라서 픽셀 단위 복제는 금지한다.

성한지는 VII의 **책임 분할**만 가져온다.

- 중앙은 전장 판독에 사용한다.
- 좌측은 아군·적 접촉과 턴/보고 원장에 사용한다.
- 우측은 선택 전대의 전력 배분과 명령 초안에 사용한다.
- 하단 고정 CTA는 `초안 검토 → 명령 제출`의 원자 경계로 유지한다.
- VII의 채팅은 `참모 보고 / 동맹 통신 / 상관 명령 / 부하 제안` 탭으로 변환한다.

## 6. 성한지 현재 상태와의 구체 대조

현재 저장소 문서·코드 기준으로 성한지는 다음 기반을 이미 보유한다.

- 전략 지도: 19성계, 45권역, 15회랑, 37항로
- 전략 이동: 출발·도착·출항 tick·도착 tick과 진행률, 발행 시각/도달 시각을 가진 비차단 명령
- 적벽 전투: 최대 20턴, 자유 좌표, 전대별 HOLD/MOVE, 경유점 1~5개, 도착 방향
- 전투 체계: 진형 7종, 정면·측면·후면, 무기 배분, 요격·탐지·추정 사격, 지형, 연쇄 폭발
- 지원 체계: 고속정 임무·귀환·회수, 보급 영역·처리량·제한 재고·거점 재적재
- 표현: 2D 전술 지도가 주 화면이고 3D는 상세 관측/증거창으로 분리

이 대조에서 나오는 결론은 명확하다.

### 그대로 유지할 것

- 다중 경유점과 턴제 원자 제출
- 진형 7종과 전대 단위 지휘
- 전쟁 안개와 viewer-safe 정보 차단
- 항로·회랑 기반 전략 지리
- 2D 지휘 화면과 3D 관측 화면의 분리
- 결정론적 명령 원장과 저장/재생

### VII에서 추가 검토할 것

1. `TURN`: 이동 없는 방향 전환
2. `STRAFE`: 방향 고정 이동, 속도/연료/명령 비용 가중
3. `POWER_POSTURE`: 탐색·추격·교전·방어 프리셋과 수동 배분
4. `FIRE_POSTURE`: 일제·지속·사격 중지 태세
5. `WITHDRAW`: 탈출점, 이탈 준비 턴, 추격/차단, 강제 후퇴와 자발적 철수 구분
6. 공격 가능 범위·무기별 사격각의 지도 미리보기
7. 직책 권한 카드와 상향 제안/하향 명령 받은편지함

### 적용하지 않을 것

- 100×50 격자로 전략 지도 교체
- 한 탑승함만 조작하는 MMO 전투 단위
- 현실 시간 1~6개월 세션과 상시 접속 압력
- 2,000명 동시 접속을 전제로 한 역할 공백
- 640×480 패널과 아이콘의 외형 복제
- 은하영웅전설 명칭·인물·함선·UI 미술의 직접 사용

## 7. 권고 적용 사양

### 7.1 이동 입력

성한지의 현행 경유점 편집기에 이동 모드만 추가한다.

```text
MOVE    목적지까지 선회 후 전진, 도착 방향 지정

STRAFE  현재 방향을 유지한 채 측방/후방 이동
HOLD    위치·방향 유지
```

VII처럼 실시간으로 계속 클릭하지 않고, 한 턴의 모든 이동·방향·진형·전력·사격 태세를 하나의 명령 초안으로 제출한다.

### 7.2 전투 입력

```text
전력 프리셋  SEARCH / PURSUIT / ENGAGE / BRACE / CUSTOM
사격 태세    SALVO / SUSTAIN / HOLD_FIRE
표적          직접 지정 / 위협 우선 / 기함 우선 / 사거리 우선
```

전력 배분은 재미 가능성이 크지만 기존 G8 피해·사기·센서·지형 수치에 광범위하게 영향을 준다. G8-00 작업과 섞지 말고 별도 설계 게이트와 회귀 기준선을 가져야 한다.

### 7.3 조직 플레이

멀티플레이를 먼저 만들 필요는 없다. VII의 인간 직책을 AI 조직으로 번역한다.

- 플레이어보다 높은 직책: 목표와 제약을 명령하고 제안을 승인/거부한다.
- 동급 지휘관: 정보와 지원을 교환하고 공적을 경쟁한다.
- 부하 지휘관: 플레이어 명령을 실행하되 충성·성향·통신·상황에 따라 지연 또는 이견을 낸다.
- 플레이어 계급: 조작 가능한 전대 수, 볼 수 있는 정보, 발행 가능한 명령, 인사 권한을 결정한다.

이는 성한지의 기존 세력 전체 조작을 즉시 폐기하라는 뜻이 아니다. 적벽 데모를 완성한 뒤 `군주 모드`와 별도인 `장수 경력 모드`로 검증하는 편이 안전하다.

## 9. 내부 검토 메모 — 성한지 전달 금지

이 보고서는 **구현 지시가 아니라 다음 설계 결정의 입력**이다. 아래 항목도 내부 후보일 뿐이며, 가시 함대전 POC가 사용자 제공 영상 수준에 도달하고 사용자가 명시적으로 승인하기 전에는 성한지 작업 채팅에 전달하지 않는다.

1. 현재 승인된 적벽 작업과 G8 범위를 변경하지 않는다.
2. 이 문서 때문에 코드, 데이터, 트래커, HANDOVER를 즉시 수정하지 않는다.

6. UI는 VII의 정보 배치 원리를 참고하되 미술·아이콘·패널 형태를 복제하지 않는다.
7. 장수 경력/직책 시스템은 적벽 데모 이후 독립 수직 슬라이스로만 검토한다.

## 10. 최종 판정

- **이동 플레이 그대로 적용:** 45%. 목적점+방향, 선회, 평행 이동은 적용성이 높지만 격자 워프와 개인 탑승함 단위는 부적합하다.
- **전투 플레이 그대로 적용:** 70%. 2D 전술 평면, 방향 방어, 탐지, 무기별 사격, 전력 배분은 잘 맞는다. 다만 실시간 한 척 조작을 턴제 전대 명령으로 번역해야 한다.
- **UI 그대로 적용:** 30%. 화면 책임 배치는 유효하지만 고정 해상도·아이콘 밀도·채팅 중심 구조는 현대 성한지에 맞지 않는다.
- **조직/경력 구조 적용:** 80%. VII의 가장 가치 있는 부분이지만, MMO 인간 역할을 AI 동료·상관·부하로 치환해야 한다.
- **성한지 전체 확장성:** 높음. 기존 코어를 교체하지 않고 누락 조작을 얹는 증분 확장이 가능하다.

한 문장으로 정리하면, **성한지는 VII의 격자와 화면을 복제할 것이 아니라, `제한된 정보 속에서 방향·전력·사격 태세를 선택하고 조직의 권한 안에서 싸우는 경험`을 현재 턴제 함대 코어 위에 이식해야 한다.**

## 12. POC 검토 방향: 함대가 실제로 보이는 영상형 전투

2026-09-12 사용자는 사용자 제공 영상의 함대전 감각과 가시 함대를 독립 POC로 먼저 검증하도록 정했다. 현재 결과는 진행 중인 POC이며 상품화 수준, 성한지 정식 사양 또는 구현 승인 상태가 아니다. POC가 영상 수준에 충분히 근접한 뒤 사용자가 확인·승인해야만 성한지 작업 채팅에 반영 지시를 전달한다.

### 12.1 POC 검증 목표

- 전투 지도에 함대가 점이나 초상 마커만으로 존재해서는 안 된다.
- 선택 여부와 무관하게 아군 함대의 함선 군집과 진형 실루엣이 보여야 한다.
- 탐지된 적도 정보 신뢰도에 맞는 함선 군집 또는 추정 대형으로 보여야 한다.
- 함대 이동은 목적선만 바뀌는 것이 아니라 군집이 선회하고 전진하는 재생으로 보여야 한다.
- 진형 변경은 이름과 수치만 바뀌는 것이 아니라 함선들이 새 대형으로 재배열되는 과정이 보여야 한다.
- 빔·함포·유도탄·함재기/고속정은 보이는 함대에서 출발해 보이는 목표에 도달해야 한다.
- 포위, 측후방 노출, 화선 집중, 퇴각 방향이 지도를 보는 것만으로 판독되어야 한다.
- 선택 함대의 제독·참모·함대 상태와 전술 명령은 영상처럼 전장과 함께 읽혀야 한다.

### 12.2 권장 표현 계층

전 척을 언제나 고해상도 개별 객체로 그리는 방식은 전술 판독성과 성능을 모두 해칠 수 있다. `함대가 보인다`는 요구를 유지하면서 확대 단계에 따라 표현 밀도를 바꾼다.

| 확대 단계 | 화면 표현 | 반드시 유지할 정보 |
|---|---|---|
| 광역 | 진형 외곽, 함선 광점/실루엣 군집, 기함 표식 | 함대 규모, 진형, 방향, 이동 벡터 |
| 전술 | 대표 함선 다수와 전대별 소군집 | 전대 간격, 정면/측면/후면, 무기 사거리 |
| 근접 | 기함과 대표 함선의 실제 3D 모델 | 함급, 피격, 포격·폭발, 진형 재배열 |

함선 수는 실제 전력 수치와 분리하지 않는다. 화면에 모든 함선을 개별 렌더하지 않는 확대 단계에서도 군집 밀도·열 수·대형 폭이 실제 척수 비율을 반영해야 한다.

### 12.3 POC 승인 이후의 인수 조건 후보

1. 기본 전투 진입 화면에서 최소 아군 2개 함대와 탐지된 적 1개 함대가 함선 군집으로 식별된다.
2. 함대마다 기함, 진행 방향, 진형 외곽, 전대 구분이 시각적으로 구별된다.
3. MOVE/TURN/STRAFE 또는 현행 이동 명령의 결과가 함선 군집의 실제 위치·방향 변화로 재생된다.
4. 진형 변경 전후의 공간 배열 차이가 한눈에 보인다.
5. 사격선과 피격 효과가 추상 로그가 아니라 함대 군집 사이에서 발생한다.
6. 확대·축소해도 함대 선택과 전쟁 안개 정보 수준이 일관된다.
7. 1600×900 Windows 기준에서 HUD가 함대와 주요 교전 지점을 가리지 않는다.
8. 실제 코어 상태와 화면의 함대 수·진형·방향·피해 상태가 모순되지 않는다.

### 12.4 구현 경계

- 영상의 원작 함선 모델, 인물 초상, 음성, 대사, UI 아이콘과 패널 미술은 복제하지 않는다.
- 영상의 실시간 규칙을 그대로 넣기 위해 현재 턴 원장과 결정론을 제거하지 않는다.
- 기존 2D 전술 지도는 폐기 대상이 아니라 함대 군집을 올릴 지휘 평면이다.
- 현재 성한지 작업을 중단하거나 섞지 않는다.
- 영상 수준 도달 여부와 사용자 승인이 확정되기 전에는 성한지 작업 채팅, 기준 문서 또는 구현 브랜치에 지시를 전달하지 않는다.
- 승인 후에만 `가시 함대 전장 표현`을 별도 수직 슬라이스로 계획한다.
