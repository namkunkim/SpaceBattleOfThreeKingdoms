**적벽대전 시나리오 진입 흐름 신규 설계 리뷰**

작성일: 2026년 11월 11일  
범위: 게임 실행부터 적벽 지역 상세 맵 진입 또는 게임 종료까지  
설계 기준: 기존 구현의 유무와 구조에 의존하지 않고 새로 설계한다. 아래 권장안은 구현 완료를 뜻하지 않는다.

**검토 결론**

제안한 흐름은 적벽대전 하나에 집중하는 첫 플레이 구간에 적합하다. 배경 서사로 전쟁의 이유를 설명하고, 전략 맵으로 전장의 위치를 보여 준 다음, 플레이어의 선택으로 지역 상세 맵에 들어가게 하면 각 화면의 역할이 분명해진다.

제작의 핵심은 화면 개수보다 화면 사이의 연결 규칙이다. 특히 ① 적벽 이외 지역의 비활성화 범위, ② 전투 알림이 나타나는 시점, ③ 상세 맵 진입과 실제 전투 시작의 구분, ④ 아니오 선택에 따른 종료를 먼저 명세해야 한다. 최초 완성 목표는 이 흐름이 처음부터 끝까지 한 번 끊김 없이 동작하는 것으로 잡는다.

**요청 흐름과 권장 동작**

게임 실행 → 시나리오 선택 → 적벽대전 SF 배경 서사 → 전략 맵 → 적벽 위치 강조 및 그 외 지역 비활성화 → 전투 발생 알림과 진입 문의 → 예: 적벽 지역 상세 맵 / 아니오: 게임 종료

| 단계 | 플레이어가 보는 내용 | 진행 조건과 동작 |
|---|---|---|
| 게임 실행 | 로딩 표시 후 시나리오 목록 | 별도 타이틀 화면은 필수 범위에 넣지 않는다. |
| 시나리오 선택 | 적벽대전 카드, 짧은 소개, 시작 버튼 | 적벽대전을 선택하고 시작하면 서사로 이동한다. 다른 시나리오는 첫 버전에서 숨기거나 준비 중으로 표시한다. |
| 배경 서사 | SF 세계의 전쟁 배경, 양측 세력, 적벽의 중요성, 플레이어의 임무 | 다음 및 건너뛰기를 제공한다. 마지막 장의 전략 맵으로 버튼을 누르면 이동한다. |
| 전략 맵 | 전체 세계의 맥락과 적벽의 위치 | 적벽만 밝게 표시하고 나머지 지역은 잠금 상태로 보여 준다. 카메라가 적벽을 식별할 수 있는 구도로 정착한다. |
| 전투 알림 | 적벽에서 교전이 발생했다는 메시지와 진입 문의 | 지도 표시가 끝난 뒤 한 번만 자동으로 띄우는 방식을 권장한다. 팝업 뒤의 지도 입력은 차단한다. |
| 예 선택 | 적벽 지역으로 접근하는 연출과 필요시 로딩 표시 | 적벽의 상세 맵을 불러오고 초기 카메라와 HUD를 표시한다. |
| 아니오 선택 | 종료 처리 | 데스크톱 실행본의 프로그램 종료로 정의한다. 타이틀 복귀와 혼동하지 않는다. |

전략 맵의 첫 표시 시간은 약 2초를 초기 연출값으로 제안한다. 로딩 완료와 카메라 정착 후 시간을 세며, 실제 가독성을 보고 조정한다. 별도의 적벽 클릭을 필수로 요구하지 않으면 사용자가 요청한 순서를 가장 직접적으로 따른다. 클릭을 넣고 싶다면 적벽 표식 선택 → 동일한 전투 알림으로 연결하되, 자동 알림과 중복되지 않게 한다.

**필요한 제작 요소**

| 분야 | 최소 필요 산출물 | 완성 조건 |
|---|---|---|
| 화면 설계 | 시나리오 선택, 서사, 전략 맵, 전투 알림, 로딩, 상세 맵의 와이어프레임 | 각 화면의 진입 조건과 다음 행동을 한눈에 알 수 있다. |
| 서사 | 세계관 요약, SF 적벽 배경 원고, 플레이어 역할과 임무 | 왜 여기서 전투가 벌어지고 왜 내가 개입하는지 설명한다. |
| 전략 지도 | 전체 지도, 적벽 좌표, 활성·잠금 표식, 위치 강조 효과 | 적벽의 위치가 즉시 식별되고 다른 지역으로 이동할 수 없다. |
| 상세 지도 | 적벽의 국지 지형, 진입 시점의 카메라, 양측 표시, 기본 HUD | 전략 지도에서 선택한 장소와 같은 전장이라는 점을 이해할 수 있다. |
| 흐름 제어 | 화면 상태와 전환 규칙, 중복 입력 차단, 오류 처리 | 잘못된 순서나 반복 클릭으로 화면이 건너뛰어지지 않는다. |
| 시나리오 데이터 | 시나리오 ID, 원고, 지도 위치, 상세 맵 참조, 시작 설정 | 제목·위치·진입 대상이 일관되며 누락을 진입 전에 찾는다. |
| 음향과 연출 | 버튼 반응, 전투 경보, 화면 전환 효과 | 효과가 없어도 진행 가능하며 소리 없이도 알림을 이해한다. |
| 검증 | 정상 진행, 종료, 잠금, 중복 입력, 로딩 실패 체크리스트 | 실제 실행본에서 예와 아니오의 분기를 모두 확인한다. |

첫 제작에서는 임시 지도·텍스트·도형으로 흐름을 완성해도 충분하다. 고해상도 배경, 음성 내레이션, 영화식 영상, 정교한 확대 연출은 흐름이 검증된 뒤 적용한다. 상세 맵의 공간 구조와 초기 시점은 먼저 정해야 하지만, 함선의 최종 모델과 모든 전투 효과가 진입 흐름 검증의 선행 조건일 필요는 없다.

**SF 배경 서사 설계**

적벽을 우주 배경으로 옮길 때는 지명만 바꾸기보다 전투의 원인이 SF 환경에서도 성립하도록 만드는 것이 좋다. 다음은 신규 세계관을 위한 제안이며 확정 설정은 아니다.

| 서사 요소 | SF 해석 제안 | 화면에서 전달할 의미 |
|---|---|---|
| 장강 | 주요 성역을 연결하는 대규모 항로 | 이 항로를 장악하면 남부로 진출할 수 있다. |
| 적벽 | 항로가 좁아지는 성운 경계의 방어 구역 | 수적으로 열세인 함대도 진격을 저지할 수 있다. |
| 조조군의 남하 | 북부 통합 함대의 남부 항로 진출 | 연합이 지금 대응해야 하는 이유가 된다. |
| 손권과 유비의 연합 | 독립 세력들의 공동 방어 함대 | 이해관계가 달라도 함께 싸우는 이유를 설명한다. |
| 동남풍과 화공의 모티프 | 플라스마 흐름과 밀집 함대의 열·에너지 연쇄 피해 | 이후 전투 규칙에 반영할 경우 지형과 전술의 관계를 예고한다. |

성운의 흐름을 지상 바람처럼 묘사하기보다는 플라스마 이동·센서 간섭·열 확산 등 작품 내부의 규칙으로 설명한다. 화공에 해당하는 전술을 실제 게임에 넣지 않는다면 서사에서 플레이어가 반드시 사용할 수 있는 기능처럼 약속하지 않는다.

서사는 세 장, 총 45~60초 안팎의 읽기 분량을 초기 목표로 제안한다. 자동 넘김을 강제하지 않고 다음 버튼으로 진행한다.

- 첫째 장 — 위기: 북부를 통합한 조조의 함대가 장강 대항로를 따라 남하한다.
- 둘째 장 — 장소: 적벽은 남부 성역으로 이어지는 항로의 관문이며, 연합이 적의 진격을 저지할 마지막 방어선이다.
- 셋째 장 — 임무: 플레이어가 연합 전술 지휘관으로 적벽 방어 작전에 참가한다. 이는 첫 버전의 권장 역할이다.

서사 초안:

“북부 성역을 통합한 조조의 대함대가 장강 대항로를 따라 남하한다. 그 항로 끝에는 남부 성역으로 향하는 관문, 적벽이 있다.

손권과 유비는 서로의 경계를 잠시 거두고 연합 함대를 결성했다. 압도적인 적을 정면에서 막아 낼 수는 없다. 좁은 항로와 불안정한 성운이 이들에게 남은 기회다.

그때 적벽 전초기지에서 긴급 신호가 도착한다. 적 선봉과의 교전이 시작되었다. 연합 함대의 전술 지휘관인 당신에게 현장 지휘 요청이 내려온다.”

전략 맵에서는 서사를 반복하지 않고 “적벽 전초 구역에서 교전 발생. 현장 지휘가 필요합니다.”처럼 현재 상황만 전달한다.

**전략 맵의 활성화 규칙**

비활성화는 색을 어둡게 만드는 것만으로 끝나지 않는다. 시각 표현과 실제 입력 처리가 일치해야 한다.

- 적벽: 이름·위치·교전 표식을 밝게 표시하고, 색 이외에도 테두리나 아이콘으로 강조한다.
- 기타 지역: 흐리게 표시하고 잠금 아이콘 또는 이번 시나리오 범위 밖이라는 안내를 제공한다.
- 잠긴 지역의 클릭·터치·키보드 포커스·게임패드 선택으로 지역 정보창이나 상세 맵이 열리지 않게 한다. 자동 지도 이동도 발생하지 않아야 한다.
- 화면 버튼뿐 아니라 지역 진입 요청 자체에서 허용된 지역 ID인지 검사한다. 우회 경로에서도 다른 맵이 열리지 않게 한다.
- 최초 버전은 지도 카메라를 안내용으로 고정하는 방식을 권장한다. 자유 확대·이동은 선택 사항으로 두어 적벽을 놓치는 상황을 줄인다.
- 전투 알림이 열린 동안에는 적벽을 포함한 배경 지도의 모든 입력을 막는다.

전략 맵은 이번 범위에서 전쟁의 위치와 규모를 설명하는 화면이다. 도시 관리·외교·자원 배분까지 넣으면 별도의 전략 게임 루프가 필요하므로 후속 범위로 분리하는 편이 좋다.

**전투 진입 문의와 종료 규칙**

팝업 제목은 “적벽에서 전투 발생”, 본문은 “적벽 방어 구역에서 적 함대와 교전이 시작되었습니다. 해당 지역의 상세 맵으로 진입하시겠습니까? 아니오를 선택하면 게임이 종료됩니다.”로 제안한다.

버튼은 “예 · 상세 맵 진입”과 “아니오 · 게임 종료”로 표시한다. 사용자가 원하는 예·아니오 구조를 유지하면서 선택 결과를 분명히 알린다. 아니오를 눌렀을 때의 종료는 그대로 구현하되, 추가 종료 확인창을 넣어 흐름을 늘리지 않는다.

초기 키보드 포커스는 예에 두고, Esc나 팝업 바깥 클릭을 아니오로 처리하지 않는 것을 권장한다. 종료는 명시적으로 아니오를 선택할 때 발생하도록 한다. 예 또는 아니오가 선택되면 즉시 두 버튼을 잠가 연속 클릭과 중복 처리를 막는다.

**상세 맵 진입과 전투 시작의 구분**

요청의 마지막 단계는 해당 지역 상세 맵 진입이다. 따라서 예를 클릭했다는 이유로 전투 시간이 즉시 흐르기 시작한다고 가정하지 않는다.

권장 초기 상태는 상세 맵 로딩 완료 → 적벽 지형과 아군 위치 표시 → 카메라 정착 → 임무 요약 확인까지다. 첫 버전은 이 상태를 진입 흐름의 완료 지점으로 삼고, 실제 전투 시작은 별도 명령으로 확장한다. 이미 교전이 발생했다는 서사와의 연결은 정지된 전술 상황을 인계받는 것으로 설명할 수 있다.

상세 맵에는 최소한 적벽이라는 지역명, 아군 집결 위치, 적의 접근 방향, 주요 항로 또는 지형, 초기 작전 목표가 필요하다. 적의 위치와 규모는 설정한 정보 공개 수준 안에서만 보여 준다. 전략 맵과 상세 맵 사이에는 지명·방위·대표 지형·세력 색을 일치시켜 장소의 연속성을 만든다.

**구현 구조 제안**

진행 상태는 시나리오 선택, 서사, 전략 맵 소개, 전투 확인, 상세 맵 로딩, 상세 맵 준비, 종료 처리로 분리한다. 각 상태에서 가능한 입력과 다음 상태를 정하고, 공통 흐름 관리자가 전환을 담당하게 한다.

| 현재 상태 | 허용되는 전환 | 방지해야 할 동작 |
|---|---|---|
| 시나리오 선택 | 적벽 선택 후 서사 | 잠긴 시나리오의 시작 |
| 서사 | 다음 장 또는 전략 맵으로 건너뛰기 | 한 번의 입력이 여러 장을 건너뛰는 현상 |
| 전략 맵 소개 | 지도 준비 후 전투 확인 | 준비 전에 알림이 뜨거나 중복 생성되는 현상 |
| 전투 확인 | 예는 로딩, 아니오는 종료 | 배경 지도 입력, 이중 선택 |
| 상세 맵 로딩 | 성공 시 상세 맵 준비 | 로딩 중 두 번째 진입 요청 |
| 상세 맵 준비 | 후속 전투 흐름 | 이전 화면의 입력이 전투 명령으로 전달되는 현상 |
| 종료 처리 | 프로그램 종료 | 로딩이나 맵 생성의 재개 |

시나리오 설정에는 scenario_id, 표시 제목, 서사 내용 또는 참조, 전략 맵 참조, 적벽 위치, 진입 허용 지역 목록, 상세 맵 참조, 플레이어 진영, 초기 카메라와 임무를 둔다. 실제 전투에 영향을 주는 난이도·편성·시드는 전투 범위가 정해졌을 때 추가한다. 이번 진입 흐름에 필요 없는 선택지를 먼저 늘릴 필요는 없다.

알림 표시 여부와 전환 중 여부는 진행 세션 안에서 관리한다. 새로 게임을 시작하면 초기화하고, 재시도 때문에 알림이나 맵이 두 번 생성되지 않도록 한다. 첫 버전에는 저장 기능을 필수로 넣지 않는다. 추후 이어하기를 추가할 때 서사 재생 및 시작 위치 정책을 별도로 정의한다.

상세 맵을 불러오지 못하면 임의의 다른 맵으로 보내지 말고 실패를 알린다. 재시도와 게임 종료를 제공하고, 실패 시에는 전투 시작 상태로 넘어가지 않는다. 읽어야 할 지도나 서사 데이터가 없는 경우도 같은 방식으로 구분 가능한 오류 안내를 만든다.

**제작 순서와 단계별 완료 기준**

| 순서 | 작업 | 완료 기준 |
|---|---|---|
| 1 | 화면 흐름과 동작 명세 확정 | 자동 알림, 지역 잠금, 아니오 종료, 상세 맵 준비 상태의 의미가 문서로 정해진다. |
| 2 | 임시 UI와 상태 전환 제작 | 게임 실행부터 예·아니오 양쪽 결말까지 연결된다. |
| 3 | 적벽 시나리오 데이터와 SF 서사 작성 | 세 장의 서사와 플레이어 역할, 임무가 일관된다. |
| 4 | 전략 지도와 잠금 처리 | 적벽만 활성화되며 입력 방식에 관계없이 다른 지역 진입이 차단된다. |
| 5 | 상세 지도 연결 | 같은 적벽 위치로 진입하고 초기 카메라·HUD가 준비된다. |
| 6 | 오류 처리와 연출 적용 | 실패 시 재시도 가능하며 효과가 흐름을 방해하지 않는다. |
| 7 | 실행본 검증 | 정상 진입·종료·잠금·반복 입력·실패 복구를 모두 통과한다. |

2단계의 임시 흐름이 동작한 뒤 서사와 지도 아트를 병행 제작할 수 있다. 상세 맵의 목표 해상도와 2D 또는 3D 표현 방식이 정해지기 전에는 제작 기간을 확정하지 않는다. 단계별 산출물을 먼저 확인하고 일정과 인력을 산정하는 것이 적절하다.

**권장 기본값과 추가 결정 사항**

| 항목 | 첫 버전 권장값 | 달라질 경우 필요한 추가 작업 |
|---|---|---|
| 제공 시나리오 | 적벽대전 1개 | 시나리오별 서사·지도·진입 조건 추가 |
| 플레이어 역할 | 손권·유비 연합의 전술 지휘관 | 진영 선택, 진영별 서사와 목표 작성 |
| 알림 방식 | 전략 맵 정착 후 자동 표시 | 클릭 방식이면 표식 선택 안내와 대기 동작 추가 |
| 기타 지역 | 배경으로만 표시하고 상호작용 차단 | 정보 열람을 허용하려면 비활성화 정의 변경 |
| 지도 조작 | 초기에는 고정 카메라 | 확대·이동 허용 시 복귀 버튼과 이동 범위 설계 |
| 아니오 동작 | 데스크톱 프로그램 종료 | 다른 플랫폼에서는 종료 가능 방식 별도 확인 |
| 상세 맵 진입 | 준비 상태로 시작 | 즉시 전투라면 사전 로딩·입력 인계·준비 시간 설계 |
| 서사 재생 | 새 시작마다 재생, 건너뛰기 허용 | 최초 1회 정책이면 저장 플래그 필요 |
| 실제 전투와 종료 후 처리 | 후속 설계 범위 | 전투 규칙, 승패, 결산, 재도전·복귀 정책 추가 |

이 기본값으로 기획과 임시 흐름 제작을 시작할 수 있다. 실제 전투까지 한 번에 개발하려면 상세 맵에서 무엇을 조작하는지와 승패 조건을 먼저 추가로 명세해야 한다.

**인수 체크리스트**

아래 항목은 향후 구현 완료 판정 기준이며 아직 검증 완료된 항목이 아니다.

- [ ] 실행 시 시나리오 선택 화면이 표시된다.
- [ ] 적벽 선택 후 SF 배경 서사가 표시된다.
- [ ] 서사 완료와 건너뛰기가 모두 같은 전략 맵으로 이어진다.
- [ ] 적벽 위치만 활성화되며, 다른 지역은 모든 지원 입력 방식에서 진입할 수 없다.
- [ ] 지도 준비 후 적벽 전투 알림이 한 번만 표시된다.
- [ ] 알림에서 아니오가 게임 종료임을 선택 전에 알 수 있다.
- [ ] 예를 선택하면 적벽 상세 맵이 한 번만 열리고 카메라와 HUD가 준비된다.
- [ ] 아니오를 선택하면 실제 실행본이 정상 종료된다.
- [ ] Esc·바깥 클릭·연속 입력이 의도하지 않은 종료나 화면 전환을 만들지 않는다.
- [ ] 상세 맵 로딩 실패 시 재시도 또는 종료가 가능하다.
- [ ] 새로 실행하면 이전 실행의 알림·선택·로딩 상태가 남지 않는다.
- [ ] 지원 해상도에서 서사·알림·버튼이 잘리지 않고 읽을 수 있다.
- [ ] 소리 없이도 전투 발생과 버튼의 의미를 이해할 수 있다.

이 레포트의 완료 범위는 신규 진입 흐름에 대한 설계 리뷰다. 게임 코드 변경, 실제 실행 검증 및 전투 시스템 구현은 포함하지 않는다.
