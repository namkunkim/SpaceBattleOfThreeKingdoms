> 비교 기준: 《은하영웅전설 IV EX》 조사에서 도출한 핵심 가치 — **세력 자체가 아니라 한 인물의 제한된 권한으로 시작해, 제안과 성과로 영향력을 넓히는 전략 경험**  
> 성격: 읽기 전용 기술·게임 디자인 검토. 성한지 소스와 자산은 변경하지 않았다.

## 1. 핵심 결론

성한지는 이 핵심 루프로 확장할 수 있다. **기술적 실현 가능성은 높고(8/10), 현재 콘텐츠와의 주제 적합성도 매우 높다(9/10).** 그러나 지금 구현된 게임의 기본 주체는 여전히 `플레이어 세력`이며, 인물 생애·관직·공적·승진은 데이터와 코어에 없다. 따라서 단순 기능 추가가 아니라 **플레이어 권한 모델을 한 층 삽입하는 중형 구조 변경**이다.

권고안은 다음과 같다.

1. 현재 `군주 모드`와 적벽 전술전을 유지한다.
2. 같은 세계 시뮬레이션 위에 선택형 `인물 모드`를 추가한다.
3. 모든 플레이어 명령 앞에 `권한 판정`을 두고, 권한 밖 행동은 `제안`으로 변환한다.
4. 제안 결과와 전투·내정 성과를 `공적`으로 환산하고, 관직·담당 범위·병력 지휘 한도를 확장한다.
5. 처음부터 492명·6개 시나리오를 지원하지 않는다. 적벽의 1명, 10~20턴짜리 수직 슬라이스로 검증한다.

이 접근이라면 기존 월드·항로·경제·함대·전투·AI·저장 기반의 상당 부분을 재사용할 수 있다. 반면 현재 UI와 명령 경로는 “플레이어가 자기 세력 전체를 직접 통제한다”는 전제를 갖고 있어, **통제·권한·결재 계층은 새로 설계해야 한다.**

## 2. 현재 성한지의 실제 상태

### 2.1 제품 정체성

성한지는 삼국지의 정치·인물·지리를 우주 전략 게임으로 번역한 작품이다.

- 핵심 주제: `정통 vs 실력`, `통일 vs 분권`
- 세계: 한제국 말기, 성계 군웅할거, 인간 내부 정치만 존재
- 전략 자원: 천명, 국력, 실동원, 항로·회랑, 인재
- 전투: 함대·전대, 진형·방향, 탐지·전쟁 안개, 제한 자원, 사기, 계략
- 데이터 규모: 인물 492명, 배치 레코드 2,394개
- 구현 규모: GDScript 183개, 테스트 스크립트 85개, 데이터 JSON 39개

이 세계관은 은영전 IP를 복제하지 않으면서도 정치·군사·개인 경력의 결합을 자연스럽게 담을 수 있다. 따라서 이전 조사에서 권고한 **법적으로 독립된 정신적 계승작** 방향과 잘 맞는다.

### 2.2 현재 플레이어 주체

초기 정본은 명확한 군주제다.

- 플레이어는 군주가 되어 인재·영지·세력을 경영한다.
- `World.player_faction`이 인간이 통제할 세력을 가리킨다.
- 플레이어 세력은 내정·작전 AI에서 제외되고 사람이 직접 명령한다.
- 저장은 `origin="player"` 명령 로그를 권위 입력으로 삼는다.

즉, 현재의 `player authority`는 **인물의 제한된 권한**이 아니라 **플레이어 세력과 AI 세력의 통제 경계**다.

### 2.3 최신 적벽 데모의 중요한 전환

최신 목표는 기존 장기 캠페인과 다르게, 다음 전술 수직 슬라이스다.

`적벽 선택 → 전투 준비 → 유비군 직접 지휘 → 손권군 수동/AI 선택 → 조조 AI → 동시 판정 → 최대 20턴 → 결과`

현재 `RedCliffsTurnBattle`에는 이미 다음 상태 전이가 있다.

```text
liu_command
    ↓
sun_control_prompt
    ├─ manual → sun_command
    └─ ai ─────────────┐
                       ↓
                 cao_cao AI
                       ↓
                   resolution
                       ↓
                 victory_check
```

이 구조는 인물 모드의 씨앗이다. 특히 “유비의 행동 뒤 손권 측 결정을 묻는다”는 경계는 향후 `하급자 제안 → 상급자 결재`로 일반화할 수 있다. 다만 현재 선택은 플레이어가 손권군을 직접 조종할지 묻는 **통제권 토글**이다. 제안 내용 평가, 거절 사유, 공적, 관직 변화는 아직 없다.

### 2.4 구현 신뢰도와 완료 상태

현재 작업 트리에서 읽기 전용 시험을 실행한 결과:

| 시험 | 결과 |
|---|---:|
| 공용 코어 회귀 | 35/35 섹션, 701/701 단언 통과 |
| 손권 수동/자동 문의 계약 | 180/180 통과 |
| 고속정 표류·구조·나포 | 77/77 통과 |

Godot의 사용자 로그 경로 및 Windows 인증서 저장소 경고는 있었으나 시험 프로세스는 모두 종료 코드 0이었다.

다만 이를 제품 완성으로 해석하면 안 된다.

- 최신 적벽 체크리스트는 단순 집계상 완료 33, 미완료 43이다.
- 전대·함대 지휘, 승패·결과·저장, 2D UX, 음향, Windows 사람 검수와 배포 수용이 남아 있다.
- 작업 트리는 410개 상태 항목을 가진 대규모 미정리 상태이며, 추적 파일 40개에 605행 추가·96행 삭제와 대형 GLB 변경이 보인다.
- 최신 기능 시험의 통과는 현재 미커밋 후보에 대한 관측이며, 해시로 고정된 릴리스 수용 증거가 아니다.

따라서 인물 모드를 지금 즉시 본개발에 병합하면 적벽 데모 완료 범위와 충돌할 가능성이 높다. **설계 및 얇은 코어 실험은 가능하지만, 본격 UI 통합은 현 데모의 G8~G10 종료 뒤가 안전하다.**

## 4. 권장 아키텍처

### 4.1 기존 시뮬레이션 위에 권한 계층을 삽입한다

현재 시스템을 갈아엎지 말고 명령 입구 앞에 아래 계층을 둔다.

```text
플레이어 의도
   ↓
AuthorityPolicy.can_execute(actor, action, target, state)
   ├─ 허용 → 기존 World/전투 명령으로 발행
   ├─ 결재 필요 → Proposal 생성 → 상급자 AI 평가
   └─ 금지 → 이유 코드와 필요한 관직 표시
                          ↓
기존 결정론적 시뮬레이션 → 결과 귀속 → MeritLedger → 인사 평가
```

중요한 원칙은 UI에서 버튼만 숨기지 않는 것이다. UI, AI, 저장 재생이 모두 같은 `AuthorityPolicy`를 사용해야 한다. 성한지는 이미 이동·관측 판정을 UI에서 코어로 끌어올린 `Orders` 패턴을 가지고 있으므로, 그 패턴을 재사용할 수 있다.

### 4.2 새로 필요한 최소 도메인

| 도메인 | 역할 |
|---|---|
| `PlayerAgent` | 플레이 인물, 소속, 현재 상관, 계급, 보직 |
| `Office` | 전대장·제독·방면군 사령·내정 담당관 등 실제 보직 |
| `AuthorityPolicy` | 보직별 허용 행동·대상·예산·지휘 범위 판정 |
| `Proposal` | 제안자·결재자·행동·근거·비용·만료·상태 |
| `DecisionPolicy` | 상급자의 성격·관계·전황으로 승인·수정·보류·거절 |
| `MeritLedger` | 전투·내정·외교의 개인 기여와 책임 기록 |
| `CareerService` | 승진, 좌천, 보직 이동, 해임, 독립·귀순 |

계급과 보직은 반드시 분리한다. 높은 계급이어도 맡은 함대가 없을 수 있고, 임시 지휘권을 받아 계급보다 넓은 임무를 수행할 수도 있어야 한다.

### 4.3 기존 데이터 확장

현재 인물 스키마는 `id/name/tier/stats/disposition/traits/class/era/origin_faction` 중심이다. 원본 인물 정의는 가능한 한 정적으로 유지하고, 시나리오별 변동 상태는 별도 런타임 레코드로 두는 편이 안전하다.

```text
CharacterDefinition  — 기존 492명 정본
CharacterState       — faction, location, alive, loyalty, ambition, reputation
CareerState          — rank_id, office_id, superior_id, authority_scope
RelationshipEdge     — trust, affinity, rivalry, debt
MeritEntry           — source_event, contribution, success, responsibility, tick
```

인물 492개의 관계망을 처음부터 수작업하지 않는다. 역사적으로 중요한 관계만 명시하고, 나머지는 소속·성향·사건으로 유도한다.

### 4.4 제안과 승인

제안은 별도 미니게임이 아니라 **권한 밖 명령의 표준 경로**여야 한다.

승인 점수 예시:

```text
기대 군사/경제 가치
- 비용과 위험
+ 제안자 신뢰·최근 공적
+ 군주 성향과 정책 일치
+ 참모 지지
- 다른 전선·예산 기회비용
- 반복 제안 피로
```

결과는 네 가지면 충분하다.

- 승인: 요청한 권한과 자원을 부여
- 조건부 승인: 병력·예산·기한을 축소해 허용
- 보류: 정보나 시점이 부족, 재제안 가능
- 거절: 명시적 사유와 관계·평판 영향

무작위 거절처럼 보이지 않도록 AI는 항상 `reason_codes`를 반환해야 한다. 기존 AI가 효용 요인을 기록하는 방향과 잘 맞는다.

### 4.5 공적과 승진

공적은 단순 킬 수가 아니라 성한지의 기존 시스템을 넓게 써야 한다.

- 전투: 목표 달성, 손실 억제, 보급 유지, 정보 획득, 상관 명령 준수/창의적 초과 달성
- 내정: 개발·복구·징병·훈련의 효율과 안정도
- 외교: 동맹 성립, 배신 예방, 시간 확보
- 정치: 천명 보전, 반란 진압, 인재 확보

승진은 공적 게이지가 차면 자동 발생하는 방식보다 `공적 + 빈 보직 + 상급자 신뢰 + 정치적 위험`의 함수가 낫다. 그래야 능력은 높지만 경계받는 인물, 충성은 높지만 무능한 인물, 파벌의 지원을 받은 인물이 서로 다른 경력을 만든다.

## 5. 게임 디자인 측면의 효과

### 5.1 성한지의 기존 주제를 강화한다

현재 `정통 vs 실력`은 주로 세력의 천명과 엔딩 축이다. 인물 모드를 넣으면 이것이 플레이어 개인의 딜레마가 된다.

- 정통 절차를 지키며 늦게 승진할 것인가
- 전장에서 독단으로 이기고 정치적 책임을 질 것인가
- 무능한 상관에게 충성할 것인가
- 공적을 이용해 찬탈·독립할 것인가
- 분권을 받아들이고 지역 통치자로 남을 것인가

즉, 기존 거시 주제가 개인 플레이의 순간 선택으로 내려온다. 이는 새 시스템을 덧붙이는 것 이상의 가치다.

### 5.2 인재 배분이 숫자 퍼즐에서 인간관계로 바뀐다

현재도 함대 참모와 내정 담당관이 같은 인물 풀을 공유한다. 인물 모드에서는 여기에 개인의 이해관계가 붙는다.

- 유능한 참모를 빼오려면 상관에게 요청해야 한다.
- 공을 세운 부하가 승진해 다른 부대로 빠질 수 있다.
- 위임한 권역의 담당관이 야심을 키울 수 있다.
- 패전 책임을 전가하면 충성·관계가 손상된다.

기존의 “함대를 채우면 위임할 사람이 없고, 위임하면 함대가 빈다”는 설계 문장이 자연스럽게 인물 드라마가 된다.

### 5.3 적벽 데모와의 연결

첫 인물 모드 검증 인물로는 `황개`가 적합하다.

- 주유 또는 손권에게 연쇄 폭발/위장 투항 작전을 제안한다.
- 승인받으면 한정된 고속정·보급·강습 자원을 지휘한다.
- 손실을 줄이고 조건을 성립시키면 공적을 얻는다.
- 실패하면 신뢰 하락, 부상·포로·좌천의 위험을 진다.

현재 적벽 코어가 이미 연쇄 폭발, 고속정 임무, 보급, 비상 귀환, 구조·나포, 탐지·지형·제한 자원을 구현하고 있어 새 전투 규칙을 거의 만들지 않고도 핵심 루프를 시험할 수 있다.

다만 장기 승진 경험은 20턴 전투 하나로 검증할 수 없다. 적벽 슬라이스는 `제안 → 승인 → 임시 권한 → 공적 산정`까지만 검증하고, `정식 승진 → 새 권한`은 전투 전후의 짧은 에필로그나 두 번째 임무로 검증해야 한다.

## 6. 충돌과 주요 위험

### 6.1 군주 게임과 인물 게임의 충돌

군주 모드는 모든 전략 자원을 직접 배분하지만, 인물 모드는 제한된 정보·권한과 상급자 AI를 받아들여야 한다. 한 UI에서 둘을 섞으면 다음 문제가 생긴다.

- 권한이 없는 버튼이 많아져 답답해진다.
- 상급자 AI가 플레이어의 계획을 망친다고 느낄 수 있다.
- 군주용 경제·외교 화면이 인물에게 과도한 정보를 준다.
- 기존 저장의 `player_faction`만으로 플레이 주체를 복원할 수 없다.

따라서 새 게임 시작 시 `군주 모드`와 `인물 모드`를 명시적으로 구분하되, 시뮬레이션 코어는 공유해야 한다.

### 6.2 시간 모델의 문서 충돌

상위 기획서는 한 줄 정의에 턴제라고 쓰면서 지도 최신 요구는 실시간 이동을 말하고, 기존 결정 기록은 세션 내 연속 시뮬레이션을 확정했다. 최신 적벽 전투는 명시적 20턴제다.

이는 다음처럼 정리할 수 있다.

- 캠페인: 세션 내 연속 시간 또는 향후 별도 결정
- 전술 전투: 동시 판정 턴제
- 제안·결재: 캠페인에서는 통신 지연, 전술에서는 턴 경계

이 구분을 정본 문서에 명시하기 전에는 인물 모드의 제안 만료·결재 지연·근무 기간을 구현하지 않는 것이 좋다.

### 6.3 범위 폭발

가장 위험한 접근은 처음부터 492명 모두에게 관계·경력·충성·대사를 넣는 것이다. 인물 모드는 규칙보다 콘텐츠 비용이 더 크다.

수직 슬라이스 상한을 다음처럼 둔다.

- 플레이 인물 1명
- 상관 2명, 핵심 동료·경쟁자 4~6명
- 제안 유형 3개
- 관직 3단계
- 전투 1개, 후속 임무 1개
- 개인 이벤트 8~12개

### 6.4 현재 작업 트리 위험

현재 성한지에는 대규모 미커밋 변경과 대형 바이너리 자산이 공존한다. 이 상태에서 인물 모드 작업을 섞으면 회귀 원인과 소유 경계를 추적하기 어렵다. 먼저 적벽 데모 후보를 해시·커밋으로 고정하고, 별도 브랜치 또는 worktree에서 실험해야 한다.

## 7. 권장 구현 순서와 예상량

아래는 1인 개발 기준의 거친 공학 추정이며, 기존 적벽 데모 완료 작업은 제외한다.

### 단계 0 — 정본 정리 (2~3일)

- 캠페인과 전투의 시간 모델 구분
- 군주 모드 보존 여부 확정
- 제안·권한·공적의 최소 정의
- 기존 적벽 후보 해시 고정

**통과 조건:** 같은 행동이 군주 모드에서는 직접 명령, 인물 모드에서는 제안 또는 금지 중 무엇인지 표로 판정 가능.

### 단계 1 — 헤드리스 권한 코어 (1~2주)

- `PlayerAgent`, `Office`, `AuthorityPolicy`
- 전대장 → 제독 → 방면군 사령의 3단계 권한
- 기존 명령을 권한 경유로 발행
- 저장·재생·digest 시험

**통과 조건:** UI 없이 동일 시드와 동일 인물 명령 로그가 같은 결과를 재생하며, 권한 밖 명령은 코어에서 거절된다.

### 단계 2 — 제안·결재·공적 (2~3주)

- `Proposal`, 상급자 `DecisionPolicy`
- 승인·조건부 승인·보류·거절
- 전투 결과의 공적 귀속
- 임시 권한과 관직 이동

**통과 조건:** 황개의 작전 제안이 관계·전황·자원에 따라 설명 가능한 결과를 내고, 성공 후 실제 지휘 가능 범위가 넓어진다.

### 단계 3 — 적벽 인물 모드 UI (2~4주)

- 인물 대시보드, 제안 작성, 결재 사유, 공적 원장
- 권한 범위를 전술 지도에 표시
- 기존 유비/손권 통제 흐름과 병행

**통과 조건:** 최초 사용자가 “왜 이 명령을 못 하는지, 누구에게 무엇을 요청해야 하는지, 다음 권한을 어떻게 얻는지”를 도움 없이 설명할 수 있다.

### 단계 4 — 정치·관계·이탈 확장 (3~6주)

- 충성·야심·관계·파벌
- 좌천·해임·귀순·독립
- 인물 계층 때문에 대기 중인 기능 이벤트 연결

**통과 조건:** 전투 승리만 반복하는 것이 승진의 유일한 최적해가 아니며, 충성·정치·내정 경력도 유효하다.

**최소 수직 슬라이스:** 약 5~9주.  
**정치·관계까지 포함한 첫 완성형:** 약 8~15주.  
UI 아트·대사·밸런스와 현재 데모의 미완료 범위를 함께 처리하면 더 길어진다.

## 8. 재사용률 추정

이는 코드 줄 수가 아니라 설계·기능 단위 추정이다.

| 영역 | 예상 재사용 | 판단 |
|---|---:|---|
| 세계·지도·항로·지형 | 85~95% | 그대로 개인 임무의 공간이 됨 |
| 함대·전대·편성·보급 | 80~90% | 권한 필터만 추가 |
| 전술 전투 | 85~95% | 현재 적벽 수직 슬라이스를 직접 활용 |
| 경제·내정 | 70~85% | 개인이 담당하는 범위만 제한 |
| AI 기반 | 60~75% | 효용·성격은 재사용, 결재·관계는 신규 |
| 저장·결정론 | 65~80% | 원칙은 재사용, 새 상태와 로그 추가 |
| 인물 데이터 | 40~60% | 정적 능력치는 재사용, 경력·관계는 신규 |
| 전략·인물 UI | 20~40% | 화면 목적과 정보 권한이 크게 달라짐 |

전체적으로 **시뮬레이션 자산은 약 70~80% 활용 가능하지만, 플레이 경험을 결정하는 통제·인물·UI 층은 절반 이상 새 작업**으로 보는 것이 현실적이다.

## 9. 최종 판단

### Go / No-Go

- **성한지를 독립적인 인물 중심 우주 전략 게임으로 확장:** `GO`
- **현재 적벽 데모 개발 중 즉시 전면 통합:** `NO-GO`
- **적벽 코어를 이용한 별도 헤드리스 수직 슬라이스:** `GO`
- **군주 모드를 제거하고 전면 인물제로 교체:** 현 단계 `NO-GO`
- **492명 전체 경력·관계 콘텐츠 선제작:** `NO-GO`

### 한 문장 권고

**성한지의 강한 세계·전투 시뮬레이션을 유지하고, `플레이어 세력` 위에 `플레이 인물과 권한 정책`을 삽입해 황개의 적벽 작전으로 제안·승인·공적·임시 지휘권을 먼저 검증하라.**

이렇게 하면 은영전 IV EX의 핵심 재미를 복제하는 것이 아니라, 성한지 고유의 `천명·분권·인재 부족·사자 지연·함대 참모` 시스템으로 더 깊게 재해석할 수 있다.
