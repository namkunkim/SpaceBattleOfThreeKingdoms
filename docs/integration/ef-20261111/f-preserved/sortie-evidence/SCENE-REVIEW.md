# F: 독립 검토용 장면 회귀

판정: 출격과 Atlas의 기능 회귀는 통과했다. 기본 1600×900에서 새 제품 버튼 하단이 잘리는 배치 문제로 현재 패치의 반영은 보류한다.

- 대상은 F: 공유본이 아니라 기존 제품 준비기·호스트를 포함한 E 격리 후보를 F:로 복제한 사본이다. F: 공유 HEAD는 520f142fdbda8d245004076e3f9262b3ef723ad7이다. F: 공유 지도 파일 SHA는 검증 전후 f0972cffbc13b8f3123a2d07cb4c9bc1e1a86c97fc7480bec8bbaedc197fc0d6이었다.
- 지도 파일 기준 SHA는 e92e6a4daaad5a663a10e574cbf2496ff86f05fe8c06a91b8c1e9d00b63b55fc, 실행한 패치본은 c1b58c340c790ab3975a2e1c771b69cb60bb06beaeee880b01cf9d7621b431c7이다. Git 텍스트 패치 적용 결과의 줄바꿈이 달랐다. 정규화한 텍스트 일치를 확인한 뒤 매니페스트 SHA의 정확한 바이트를 넣고 실행했다. 검증 후 격리 지도 파일과 변조한 정의를 원래 바이트로 복원했다.
- Windows Godot 4.7.2에서 실제 지도·전장 씬을 사용하는 7회 실행, 90개 검사에 통과했다. 일반 버튼과 seed 208 기존 요청은 레거시 전장에 들어갔다. 자동 해결은 지도 resolver를 시작하고 취소했다. 개발 정면·우회는 개발 호스트에 들어갔다. 새 제품 버튼은 일반 카드의 표준·직접 지휘에서만 활성화되어 실제 호스트 C0에서 정면을 시작했다. 첫 명령은 1틱/100ms에 한 번만 적용됐다. 원천 SHA 불일치 시 시작을 거부했고 호스트에서 돌아오면 기존 지도 카드가 복원됐다.
- Atlas의 실제 적벽 교전도 탭을 열었다. 모든 실행에서 미리보기의 레거시 요청과 프로필 지문이 같았고, WorldLink를 통해 출격하지 않았다. Atlas 코드 3개, 영역 데이터와 WorldLink/Brief 바이트는 실행 전후 일치했다.
- 기준 일반 카드의 최소 높이는 834이고 실제 하단은 y=872다. 패치 후 최소 높이는 902, 실제 하단은 y=930, 제품 버튼의 하단은 y=908이다. 뷰포트 y=900 밖으로 버튼 8px와 카드 30px가 나간다. 개발 카드의 기존 y=998은 패치 전후 동일하다. 레거시 직접/자동 실행 종료 시 리소스 정리 진단도 기준과 후보에서 같은 수로 재현됐다.
- 재현은 이 폴더의 `recheck_scene.ps1`을 실행한다. 사용자의 실제 저장 경로를 쓰지 않으며 공유 소스, Atlas, K6 실행 상태를 변경하지 않는다. 스크린샷이나 GUI 검증은 수행하지 않았다.
