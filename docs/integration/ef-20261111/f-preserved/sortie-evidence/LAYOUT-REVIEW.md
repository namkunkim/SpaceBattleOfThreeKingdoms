# 적벽 v1 일반 출격 카드 배치 재검증

일반 카드에서만 두 출격 버튼을 간격 10의 한 행에 놓았다. 기존 출격 버튼의 높이 66과 스타일, 제품 버튼의 선택 조건과 신호, 개발 카드 분기를 유지했다. 변경은 지도 스크립트 한 파일이다.

| 1600×900 클라이언트 | x | y | 너비 | 높이 | 하단 |
|---|---:|---:|---:|---:|---:|
| 일반 카드 | 1104 | 28 | 468 | 844 | 872 |
| 기존 출격 버튼 | 1128 | 784 | 205 | 66 | 850 |
| 제품 출격 버튼 | 1343 | 784 | 205 | 66 | 850 |

기존 7회 기능 검사 90개를 다시 통과했다. 추가로 자동 결산 실행 2회, 클라이언트 및 카드 경계 검사 20개가 통과했다. 개발 카드, Atlas 미리보기 프로필, 기존 seed 208 직접 출격·자동 해결 취소, 제품 C0/첫 명령, 원천 변조 시 복귀를 비교했다. 입문·seed 11 자동 해결의 결과 DTO와 지도 결과 표시 지문도 같았다.

첫 장시간 자동 결산 시도에서 진행 막대를 그리는 `_draw_resolve` 경로가 Godot 배열 오류와 함께 한 차례 종료됐다. 이 경로와 자동 해결기 코드는 후보에 포함되지 않는다. 결산 대조 재실행은 프로브에서만 진행 막대를 숨겼으며 실제 자동 해결 및 결과 카드 처리는 그대로 실행했다. 진행 막대의 장시간 안정성은 이 검증 범위 밖이다.

기준과 실행 바이트는 `manifest-layout.json`에 있다. `world_map_screen.layout.gd`가 실행 검증에 사용한 정확한 페이로드다. `sortie-entry-layout.review.patch`는 E 격리 기준 대비 전체 진입 패치이며, `layout-only.review.patch`는 이전 후보에서 이번에 고친 배치만 보여 준다. 텍스트 패치의 줄바꿈 차이는 최종 `verified.json`에 기록했다. `recheck_scene_layout.ps1`로 재현할 수 있다. F 격리 사본만 사용했고, 공유 E/F 소스와 실제 GUI는 사용하지 않았다.
