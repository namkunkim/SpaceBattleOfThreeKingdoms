# P03 첫 조각 독립 계획 심사

2026-11-05. 판정: **반려 — 스펙 보완 후 재심사**. 구현에는 참여하지 않았다. 이 심사 담당은 spawn 요청 인수로 `gpt-6.1-terra`를 명시 배정받았다. 계획 조사 담당은 세션 상속 모델이며 실제 런타임 모델명과 계획 작성자와 심사자의 실제 모델 차이는 확인되지 않았다. 배정 문자열을 실제 내부 모델 확인으로 취급하지 않는다. 이 판정은 사람의 최종 판단을 대체하지 않는다.

## 근거와 필수 보완

1. **현재 소스 교차확인의 독립 oracle이 불충분하다.** `source-inventory-observed.json`은 top-level과 알려진 BattleState inner만 관측한 제한 스캔이다. PLAN의 13번은 294 총계와 일부 클래스 개수만 제시한다. 서로 다른 누락과 오분류가 총계에서 상쇄될 수 있고, 다른 파일의 inner class 누락은 기존 관측 자체에 없을 수 있다. 30개 파일 각각의 scope/member/순서/선언 텍스트를 독립 추출 또는 수동 검토한 identity 단위 목록과 차이·미분류 처리 규칙을 사전 지정해야 한다. 지원 범위를 현재 알려진 scope로 제한한다면 새 inner class 자체를 오류로 검출해야 한다.
2. **지원 밖 구문을 조용히 놓치지 않는 판정이 실행 가능하게 정의되지 않았다.** 09번은 예시 하나의 오류만 요구한다. 클래스 본문의 알 수 없는 구문, annotation과 선언의 분리, 여러 줄 문자열·중첩 구분자 및 미완결 입력, 속성 접근자/정적 선언, 새 중첩 scope가 실제 선언으로 오인 또는 누락되지 않도록 허용 문법과 fail-closed 범위 및 각 반례의 기대 exit를 명시해야 한다. 파서가 이해하지 못한 파일을 정상 재고로 승인해서는 안 된다.
3. **기준선과 검사 입력의 고정 절차가 모호하다.** 구현 후 생성한 baseline을 같은 구현으로 즉시 검사하면 양쪽 오류가 일치할 수 있다. baseline 생성 시점·승인 책임·독립 oracle 비교 후 고정·source 변경 시 중단 규칙, baseline/runner/Python/대상 파일의 SHA와 테스트 직전·직후 일치 확인을 명시해야 한다. 현재 소스 crosscheck가 294와 다를 때 원인만 보고해도 통과인지 불명확하다. 미해결 차이는 실패여야 한다.
4. **검사 계약에 실패 원자성 및 실제 입력 오류 사례가 부족하다.** 11번은 읽기 전용 SHA만 확인한다. 누락/읽기 불가 파일, 깨진 소스, 중복 identity, 불완전 baseline, 출력 파일이 이미 있는 경우에 exit2와 입력·기준선·기존 출력 불변을 각각 확인하고 부분 성공 JSON이 정상으로 오인되지 않도록 해야 한다. 대상 파일 목록과 실제 읽은 바이트 사이의 변경도 실패로 처리해야 한다.

## 범위와 남는 한계

계획의 `tmp/p03-state-checkpoint-20261105/` 전용 신규 산출물, 생산 코드와 P02 소유 경로 무수정, Godot 미실행은 작은 비충돌 조각으로 적절하다. P2c의 제한 fresh 복원 70/11553/45, 활성 restore 20/20099(명명 8/호출 9)는 기존 제한 수용이지 전체 저장·운영 Cn·global cursor 증거가 아니다. 기존 `tests/i01b_active_replace.gd`의 실제 전진 후 복원·suffix 시험은 이 도구의 새 증거가 아니다. 전체 I01/I01b/A04~06 NOT_READY 및 외부 save schema UNCLASSIFIED 유지가 적절하다.

실제 복원 후 비교는 Variant 정확한 타입과 값, Dictionary 키 타입·삽입순서, Array 순서, typed builtin/class/script identity를 보존해야 한다. 이는 선언 경보만으로 검증되지 않는다. host clock, 동적 Dictionary 키, 명령 수용/적용/사건 drain, 실패 후 활성 상태 보존 및 suffix 절단점도 후속 독립 계약의 분모로 남는다. Godot class map은 이 조각에서 미사용이므로 runtime guard 통과로 주장하면 안 된다. 기존 전체 `git diff --check`의 CRLF exit 2와 새 산출물 게이트를 분리하는 계획은 타당하다.

위 네 항목을 계획에 명시하고 다시 독립 심사를 받아야 구현에 착수할 수 있다.
