# 첫 PC 입력 증거 계획 독립 심사

판정: 명세 및 비제품 적합성 후보 설계 범위 수용. 실제 CUA 호출이나 제품 실행 승인 아님. 기존 PC0 2/2는 소진 상태이며 이름만 바꾼 동일 시험을 재개하지 않는다. 실제 캠페인 조각은 작전·목표/철수·권위 연결 구현 후 별도 목표와 근거를 심사한다. 기존 K6도 바꾸지 않는다.

계획은 710초 지연의 원인을 단정하지 않고 unified CUA의 첫 호출과 Sky API의 별도 계약을 구분한다. screenshot ID를 HWND로 추측하거나 표시된 이미지를 임의 추출하지 않는 것은 타당하다. 단일 5초 timeout과 30초 합계는 현재 후보 숫자일 뿐, 하위 호출 취소 보장이 아니므로 실제 경과 상한이나 시스템 전체 자원 정리 보장으로 승인할 수 없다. 차후 fixture 심사에서는 문서화된 첫 호출, 실제 노출된 인터페이스, 소유 fixture 식별, 호출 대기와 중단 방법 및 미완료 요청을 정직하게 기록하는 구체 절차를 먼저 동결해야 한다. 첫 응답 불능이면 더 호출하지 않고 실패로 남긴다. 시간 초과 후 계속 백그라운드에서 동작하지 않는다고 추정하지 않는다.

관찰 대상은 새로 만든 무해한 전용 창만으로 제한하고 주변 화면·개인정보를 수집하지 않는다. 지원된 창 단위 캡처와 보존 방법이 없거나 native HWND 연결을 독립적으로 검증할 수 없으면 해당 속성 미검증으로 남긴다. 비제품 조회는 자동 입력·게임 검증·실제 제품 동작을 증명하지 않는다. 인계의 모든 입력 부재 또는 도구 장애 위치도 독립 원문만으로 확정하지 않는다.

사람 직접 플레이는 가능한 장래 경로이나 사람의 참여, 전경 확인, 자료 보존이 보장된다고 가정하지 않는다. 사람의 관측은 trace와 구분한다. 현 단계에서 제품 실현에 유효한 병행 작업은 P05/P07/P03의 구현·권위 경로와 목표/철수 조건을 확인하고 결손을 직접 해결하는 것이다. 도구 분모만 반복해서 늘리는 것으로 PC0 또는 P02가 전진했다고 주장하지 않는다.
