# 첫 PC 직접 출전 계획 독립 심사

판정: **§0 우선순위에 맞는 유한한 legacy 기준선 조각으로 조건부 수용한다. 현재 문서만으로 실제 실행이나 P02 완료를 판정하지 않는다.** `PLAN.md` SHA `22156978880803e82e231690e4e0e5ba5aa05709485b24f3a2372d34a824ac0a`, `BASELINE.json` `6356963e67d1a08c630746476b228a93dc47d9e2ff1724b26f21a5e6732a83b8` 확인. 심사 모델 gpt-6.1-terra. 제품/Godot/GUI/Job 실행 없음.

§0은 실제 PC 작전 시작·진행·종료를 먼저 하고 추가 소비자·replay와 저장/재개를 후속으로 둔다. 현재 `project.godot`의 기본 씬은 FleetBattle3D이므로 WorldMap 경로는 실행 진입 씬을 명시해야 한다. WorldLink `go_battle`은 brief를 게시하고 전투 장면으로 전환하며, `back_to_world`는 결과를 넘기고 `take_outcome`은 한 번 비운다. FleetBattle3D는 종결 시 `BattleOutcome.from_sim`을 넘기고 진행 중 복귀에는 null을 넘긴다. 이것은 코드 경로이며 자연 종료·실제 입력·플레이 결과의 실측은 아니다. 과거 forced-end 기록을 자연 종료로 승격하지 않는 계획은 정확하다.

PC0 착수 전 별도 완결된 짧은 실행 명세로 실제 WorldMap 시작 argv·고정 seed/profile/배치와 명령 action·대상·기대 변화, 반환 결과/1회 소비 관측법, 고유 process/window·격리 user/cache/log와 상태·스크린샷 산출물을 정한다. 별도 사용자의 기존 세이브를 사용하거나 변경하지 않는다. 소유 프로세스만 한정 종료하고 사용자가 이미 조작 중인 창을 강제로 닫지 않는다. 하나의 실제 입력 요청과 전후 렌더·제품 수신/상태를 연결하되 제3자 입력 완전 부재는 주장하지 않는다. 실제 조작이 제공되는 표면에서 가능하지 않으면 GUI 미완료로 기록한다.

배치 중 정지, pause 중 정지와 재개 증가를 각 상태의 동일 시계/tick에서 대조한다. 명령 전후 대상 ID·명령 원문과 실제 움직임/사건·HUD를 기록하되 UI 갱신만으로 시뮬레이션 수용을 대체하지 않는다. 자연 승패는 `sim.st.over` 및 종결 시각/사유와 동일 `BattleOutcome` 및 WorldMap의 한 번 인수를 비교한다. forced end나 직접 outcome 주입은 별도 smoke이며 자연 완료 분자에 넣지 않는다. 자연 종료 시간은 미측정이므로 시작 전 유한 wall-clock deadline 및 20분 가설의 측정법을 정하고, 미종료 시 미완료·원문 보존 후 횟수 한도 안에서 실패 원인만 진단한다.

PC1은 initial 실패에서는 보존할 기존 sim이 없는 경우가 있으므로 초기 탈출/결과 없음과 active 실패의 기존 객체·clock·selection·HUD·미소비 사건 보존을 분리해야 한다. 실제 지원되는 오류 fixture와 정상 재시도 경로를 구체화한다. active 경로가 변경되지 않으면 기존 독립 증거를 재사용할 수 있으며, 새 변경이 경계를 건드리면 같은 frame 대조가 필요하다. 기존 BattleOutcome 승패를 목표 달성·명시 철수의 근거로 사용하지 않는다. PC2는 P05/P07/P03의 실제 권위 계약 이후 별도 판정이며 현재 이 계획이 실제 적벽 operation 지원·목표·철수를 구현했다는 뜻이 아니다.

현재 P03 private +9와 worker +2의 보호 범위를 확인했다. 공유 호스트를 실제로 고치기 전 active owner의 현재 상태·허용 hunk와 순서를 확인하고, drift를 복원하거나 stage하지 않는다. 기준선에서 새 제품 코드가 필요하다는 가정 없이 기존 경로를 먼저 관측한다. 여덟째 공통 초기화 후보의 K1~K5와 미실행 K6/21행은 별개로 보존하며, 같은 후보/제품 검증을 다른 이름으로 시작해 K6을 피하지 않는다. PC0의 별도 legacy 기준선이 이 후보를 적용하거나 여덟째 조각의 증거를 대체하지 않는다는 실행 입력을 사전에 명시한다.

따라서 다음은 독립 실행 명세의 fixture·기대·유한 timeout·프로세스/화면 소유와 비파괴 경계를 채우고 짧게 재심한 뒤 PC0을 한 번 관측하는 것이다. 이 심사는 구현·GUI 실행 허가 또는 첫 플레이 완료 판정이 아니다. P02/P03 전체와 외부 저장 schema는 NOT_READY/UNCLASSIFIED다.
