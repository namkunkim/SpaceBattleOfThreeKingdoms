# PC0 direct Godot 소유 launcher 설계 독립 검토

판정: **직접 GUI executable의 suspended→Job assign→resume 구조는 PC0 준비 대상으로 수용한다. 실제 실행 승인이나 기존 K3 실패의 소거가 아니다.** 심사 모델 gpt-6.1-terra. 이 검토는 exe의 PE header와 SHA를 읽었을 뿐 Godot·Job·GUI·제품을 실행하지 않았다.

고정 일반 exe SHA `ab1824f85bfd8e0e4128182c000c4003a3e042245b2967848d089b2a04b22424`의 PE subsystem은 2(Windows GUI), console wrapper SHA `c8f0a6bc45a19b33541501e57f6f7cd972ab18453743266339d495cbbe846643`는 3(Windows console)이다. [Microsoft 문서](https://learn.microsoft.com/en-us/windows/win32/procthread/process-creation-flags)는 `CREATE_NO_WINDOW`가 console application에 적용되며 GUI application에는 무시된다고 명시한다. 따라서 GUI exe에 이 flag를 주는 것만으로 게임 창을 숨긴다고 추정할 이유는 없지만, 이 빌드에서 headless 기동·GUI 렌더·입력 및 로그 출력이 동작한다는 실측은 아니다. `--headless`와 실제 GUI는 별도 실행/별도 Job으로 취급하고 GUI 실행의 실제 HWND·owner PID·렌더를 확인한다. GUI subsystem에서는 콘솔 stdout/stderr 존재를 가정하지 말고 명시적 inheritable file/pipe handles와 Godot log 파일 또는 각각의 부재·오류를 구체적으로 검증한다.

[AssignProcessToJobObject 문서](https://learn.microsoft.com/en-us/windows/win32/api/jobapi2/nf-jobapi2-assignprocesstojobobject)와 process flags에 따른 유한 계약은 다음이다. `CREATE_SUSPENDED`로 반환된 정확 process·primary-thread HANDLE을 유지하고, 전용 Job 설정·assign·`IsProcessInJob` 양성 이후에만 한 번 resume한다. 생성/할당/확인 실패에서는 resume하지 않고 정확한 생성 process를 종료·wait한 뒤 handle을 닫는다. 정상/timeout에서는 해당 Job만 종료·drain하고 active 0 및 보유 process HANDLE signalled를 각각 남긴다. 외부 watcher의 global 및 단계 deadline, output bound·file flush와 watchdog/launcher 예외를 포함해야 한다. 사용자 기존 프로세스의 이름 검색·종료는 금지한다. 이미 관리 sandbox Job에 속한 경우 nested Job assign이 허용되지 않을 수 있으며 실제 실패는 실패로 기록한다.

GUI exe direct spawn은 실패한 Python→console broker→Python payload 계층과 실제로 다른 PC0 실행 구조다. 단 이름만 바꿔 같은 Python ownership qualification을 재시도하거나 K3을 초기화하는 근거는 아니다. 세 비제품 실패와 case-level cleanup 미증명을 보존한다. 이 제안은 실제 대상 PC0의 새 launcher 설계이며 구현·독립 검토 및 최종 manifest 수용 전 실행하지 않는다. 별도 Python Job 성공이나 Windows 전체의 helper 부재로 집계하지 않는다. launcher를 신뢰할 수 있도록 syscall wrapper·flags·HANDLE 수명·nested 실패·stdout redirection 및 시간 제한의 정적 검토와 합성 오류 경로를 먼저 완료한다. `CREATE_NO_WINDOW`의 GUI exe 영향은 위 PE/문서에 근거해 제한 설명하고 실제 화면 노출은 런타임 근거로만 판정한다.

`--headless` import/preflight도 실제 게임 project를 읽고 cache를 생성할 수 있다. 여덟째 후보 K6 제품 검증을 다른 이름으로 사전 실행하지 않도록, 독립된 HEAD legacy PC0 복제·후보 미적용·실행 목적과 생산 output을 분명히 한다. 그 경우에도 product baseline과 cache 관측으로 기록하며 K6 증거에 합산하지 않는다. 별도 fresh user/cache/log, 보호 HEAD/index·P03 +9·worker +2, 정상 target HWND 및 다른 사용자 창 비침범을 manifest에 고정한다. 실행 전에 실제 환경·entry scene·예상 output·에러/cleanup을 독립 재심하고, GUI 화면/입력/자연 종료가 불가하면 PC0은 미완료다. 기존 21행·K6 한 회, P03 경계 및 전체 P02 NOT_READY는 유지한다.
