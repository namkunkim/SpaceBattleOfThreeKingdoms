# PC0 실행 명세 V2 · Windows legacy 직접 출전

사전 독립 심사용. 제품 코드 적용이나 실행은 없다. 11월 9일 §0의 첫 PC 우선과 계속 실행 승인을 적용한다. 이 실행은 기존 P02 여덟째 후보를 적용하지 않는 별도 legacy 기준선이다. K1~K5, 마지막 K6, 21행 및 이전 실패 자료는 그대로 남긴다. P03 active 파일을 편집하지 않는다.

## 실행 입력

- 위치는 원본 repo 내부 tmp/p02-first-pc-20261109/run-01의 신규 격리 복제다. 원본 Godot cache, user data, 프로세스를 사용하지 않는다. 현재 사용 가능한 실행 파일은 C:/Tools/Godot/Godot_v4.7.2-stable_win64_console.exe와 같은 디렉터리의 일반 exe다. console SHA-256 C8F0A6BC45A19B33541501E57F6F7CD972AB18453743266339D495CBBE846643 및 일반 exe SHA-256 AB1824F85BFD8E0E4128182C000C4003A3E042245B2967848D089B2A04B22424를 확인했다. 두 exe 및 파일별 입력 SHA를 준비 manifest에서 재검사하고 root의 현재 HEAD/index 및 보호 P03 파일을 전후 비교한다. 필요한 전체 게임 리소스와 BGM을 포함하고, 현재 작업 트리의 별도 UI·브랜딩/설정 변경은 제품 기준선 입력에서 제외해 HEAD blob과 별도 근거로 관리한다. 준비 closure에는 versioned game resources, 리소스가 참조하는 추가 파일과 검증된 cache만 포함한다. 소스·assets·실행기와 runner를 일치 확인하고 원본 cache에 쓰지 않는다.
- 절대 argv는 C:/Tools/Godot/Godot_v4.7.2-stable_win64_console.exe --path C:/WorkSpace/SpaceBattleOfThreeKingdoms/tmp/p02-first-pc-20261109/run-01/project --log-file C:/WorkSpace/SpaceBattleOfThreeKingdoms/tmp/p02-first-pc-20261109/run-01/godot.log res://scenes/WorldMap.tscn 이다. cwd는 복제 프로젝트. APPDATA/LOCALAPPDATA 둘 다 run-01 아래의 서로 분리된 신규 디렉터리다. editor import가 필요하면 같은 복제에서 console exe --headless --editor --import --path <project>를 독립 사전 준비로 실행하고 300초 제한·exit/log를 기록한다. 제품 시작 전 예상 user://를 자체 초기 로그에서 비교하고 초기 세이브가 비어 있음을 확인한다. 종료 로그, stdout/stderr 및 JSONL은 격리 경로로 남긴다.
- 2개 좁은 test-only overlay를 준비 diff로 심사받는다. view/world/world_map_screen.gd:542의 무지정 seed만 777로 고정해 기존 출격 버튼을 그대로 사용한다. 실제 _show_result의 매 호출에서 받은 outcome.to_dict()와 함수의 동기 렌더 상태 확정 뒤 state/표시 및 WorldLink.brief/outcome null 여부를 읽어 로그한다. 권역색은 기존 0.6초 지연 및 화면 전환이 끝난 뒤 screenshot으로 관측한다. scripts/world_link.gd:26의 back_to_world 입력과 :32의 take_outcome이 이미 읽은 o를 각각 읽어 로그한다. probe는 take_outcome을 추가 호출하거나 상태를 쓰지 않는다. 제품 명령, scene 신호, clock, 결산 함수를 probe가 호출하지 않는다. 전투의 실제 command_request/applied/rejected, tick/sim_ms, fleet movement 및 battle_end 관측은 현행 scripts/battle_trace.gd를 사용한다. terminal fingerprint가 기존 trace로 필요하면 결과 payload에서 확인하며, sim 전체를 재실행해 대조하지 않는다. 해당 patch와 fixture와 oracle/argv 및 종료 로직이 준비 manifest로 독립 수용되기 전에는 실행하지 않는다.

## 제품 조작과 관측

0. CUA가 사용자 승인 범위에서 수행하는 물리 Windows GUI action을 사용한다. 컨트롤 함수 직접 호출, emit_signal, viewport 주입, debug fast-forward 또는 결과/코어 종료 주입은 사용하지 않는다. GUI window의 새 PID·creation time·exe SHA·HWND 및 foreground를 확인하고 앱 창 screenshot/좌표/시간과 각 요청을 일대일 기록한다. 작업 중인 다른 창은 건드리지 않는다. 대상이 고유하지 않거나 foreground 손실/입력 대상이 모호하면 중지한다. 창 rect/DPI와 시각 위치를 확인해 screenshot의 client 상대 좌표를 고정 기록한다. 외부 입력의 암호학적 귀속은 주장하지 않는다.
1. 천하 지도 적벽 카드 열기 → 입문 난이도와 직접 지휘를 화면에서 선택 → 출격 → 출격 연출에서 건너뛰기 또는 정상 전환 기다리기 → clean-user 실제 서막이면 건너뛰기. 카드 선택과 trace의 seed=777, profile=res://data/profiles/red_cliffs_rt.json, 난이도 입문, hz=10을 대조한다. 선행 clean-user 실패와 달리 예상 브리핑으로 못 가면 증거와 실패를 남기고 내부 함수로 우회하지 않는다.
2. 브리핑의 직접 배치 CheckButton을 켜고 자동 편성으로 시작한다. 배치 HUD와 placing=true 상태에서 최소 2초 동안 clock/tick이 움직이지 않았음을 placing 시작과 배치 확정 직전/전환 trace로 비교한다. 첫 배치 trace는 ally 측 직접 유비군과 위임 손권군, 고유 함대 ID와 위치의 실제 자료를 남긴다. 배치 확정 버튼을 누르고 실제 전진을 확인한다.
3. 표시에서 유비 기함을 선택한다. 독립 대상 규칙은 첫 trace에서 side=0으로 표시되고 is_flag와 control=direct이며 유비로 식별되는 유일한 함대다. 모호하면 정지한다. 가시 전장의 빈 지점에 이동 클릭 1회. 대상 규칙은 유비 기함 화면 중심에서 적 방향으로 화면 폭 8~12% 앞, UI·다른 함대·경계와 겹치지 않은 지점이다. 입력 전 프레임에 선택 ID와 클릭 위치를 고정 기록하고, trace의 move 명령 단일 ID와 목표, applied 후 nonzero displacement와 target 방향 투영 양수, 동일 ID HUD/렌더 이동을 확인한다. 현재 화면 관측을 기준으로 빈 점을 결정하므로 픽셀 수치는 사전에 추측하지 않는다. 명령 직후 모드나 목표를 내부 호출로 보정하지 않는다.
4. 이동 관측 후 Space로 일시정지, 같은 화면에서 2초 관측 후 계속 버튼. 두 ui_state row의 tick/clock_ms 일치와 이후 증가를 대조한다. 이후 1배속을 유지하며 실제 결정 카드가 있으면 입문의 UI가 권한을 기다리는지 확인하고 표시된 추천 선택지만 실제 클릭해 입력/사유를 기록한다. 그 외 공격·이동을 더 주입하지 않는다. 직접 지휘 유지한 유비 측 1개 명령과 손권·적의 정상 위임 AI를 사용하는 최소 기준선이며 플레이어 전술 최적화가 아니다. 게임 진행은 실제 규칙과 AI, 또는 기존 제한 시간 규칙으로 자연 종결하도록 둔다.
5. 기존 승리 규칙의 time_limit_s=1200은 data/profiles/combat_m3.json:701, timeout 승패/우선순위는 core/battle/victory.gd:135~136을 기준으로 한다. 논리 1,200초 전 자연 교전 종결이면 이유는 실제 유효 승리 규칙과 비교한다. deadline 사유가 time_limit이면 종료 clock_ms가 1,200,000을 처음 충족한 고정 100ms 격자이고 win=false여야 한다. 터미널 이벤트와 sim 결과는 한 건, 이후 tick은 고정. 전투 결과 화면에서 천하로를 실제 클릭해 직전 terminal tick/time·win/reason·손실이 전달된 payload 및 표시와 일치하는지 확인한다. loss_pct 기대값은 원문 st.result.cost의 original/remaining에서 독립 계산한다. WorldLink publish/consume/show_result 각각 동일 payload 정확히 한 건, 천하 ready 후 queue null, brief null. 지도 결과 카드에서 실제 제공하는 종류·결말·시간·손실과 허용된 지역색을 screenshot으로 비교하고, 원시 reason은 payload/종결 trace로 비교한다. 이 baseline의 자연 timeout은 기존 경로 종료 성공이며 P07 목표 달성·철수 성공이나 캠페인 품질 인수가 아니다.

## 시간과 정리

- 실행당 제품 전체 wall 1,920초, WorldMap/브리핑 180초, 배치 및 첫 명령/정지 180초, 이후 전투 자연 종결 대기 최대 1,440초, 천하 결산 120초다. 어느 상한이든 초과하면 미완료로 닫고 강제 종료/종결을 정상으로 집계하지 않는다. logical start/end 및 monotonic wall start/end, pause·결정 카드 대기, 배속을 따로 기록한다. 20 게임분은 기존 제한시간과 사용자 플레이 비교 자료이며 20분 wall 보장은 아니다.
- 실제 Windows 제품 및 소유 창 사용 가능 여부는 사전 독립 승인 이후 확인한다. 별도 monitor/supervisor가 runner와 console 및 자손을 자신이 만든 Job에서만 소유한다. launch 전 잡 귀속 실패 또는 stale/공유 window 발견 시 제품 입력 전에 중단한다. 정상 종료는 소유 창 닫기, timeout은 소유 Job만 종료하고 자손 잔존을 확인한다. 에러 원문 보존을 위해 스크린샷/JSONL/stdout/stderr와 foreground 창 기록의 monotonic 기준을 맞춘다. 기존 P09 BGM 등 진단은 계수해서 관측과 분리하고 새 SCRIPT ERROR, 잘못된 profile fallback 또는 누락된 상태 행은 gate 실패다.
- PC0 한 회, 확인된 실패 원인 해결 이후 별도 독립 범위 수용을 받은 경우 최대 추가 한 회만 한다. 단순 승패를 바꾸려고 재시도하지 않는다. GUI 수행 표면이나 장시간 소유/입력이 가용하지 않으면 실제 Windows 자연 종료는 미완료다. 이미 있는 강제 종료 smoke와 대체하지 않는다.
- PC1 초기/active 실패는 PC0에 주입하지 않는다. 실패에서 아무 기존 sim도 없던 최초 경로는 기존 P02 지정 profile_patch malformed ally 증거의 안전 탈출/결과 없음, active는 P03 host-clock 동일 frame·무실패 대조군을 별도 재사용한다. 이후 접점 변경 시 신규 한정 반례를 독립 계약에 넣는다. P03 active 파일 및 원본 save·프로젝트·Git 보호, 새 커밋·push 금지. 최종 실행 입력 SHA/파일·전후 상태, 결과·편차는 별도 비Astra 5-b에 넘긴다.
