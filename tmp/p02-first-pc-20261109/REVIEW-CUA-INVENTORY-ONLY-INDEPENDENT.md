# CUA 인벤토리 전용 계획 독립 심사

판정: 정적 계획 수용, 현재 실제 조회는 하지 않는다. 도구 설명의 첫 호출 단일 API 규칙 및 전체 활성 표면 inventory에 대한 getState 용도와 일치한다. 반환되는 제목·URL 등은 사전 필터가 보장되지 않으며 이미지 노출 여부도 단정할 수 없다. 특정 제품 창을 다루는 작업 자체가 모든 표면 조회를 필요로 하지는 않는다. 전용 상태 확인이 불가한 지금 이 광범위 inventory는 별도의 제품 진행 선행조건으로 정당화되지 않는다.

후속 독립 시험을 계획한다면 격리된 실제 표면과 세션 범위가 관찰 가능해야 하고, 5초는 도구에 요청한 timeout이지 하위 요청의 확실한 취소나 벽시계 상한이 아니다. 최초 호출이 완료되지 않으면 연속 호출·reset하지 않는다. 정상적인 CUA 작업의 최종 결과를 관찰한 경우 completion_summary 단독 호출 규칙을 따른다. 단순 조회 성공은 창 식별·캡처·입력 검증이 아니다. 현재 다른 표면이 없다는 사실을 확인하기 위해 다시 전체 inventory를 호출하자는 순환 절차도 채택하지 않는다.

이 계획은 PC0 2/2 소진을 바꾸거나 기존 시도를 우회하지 않는다. 별도 K6은 미실행이다. 제품 구현을 위한 P05/P07/P03 권위 및 명령·표시·결산 연결은 이 도구 적합성 테스트와 독립적으로 계속할 수 있다. 실제 제품 테스트의 새 범위가 준비되면 그때 필요한 가장 좁은 접근 방식을 선택한다.
