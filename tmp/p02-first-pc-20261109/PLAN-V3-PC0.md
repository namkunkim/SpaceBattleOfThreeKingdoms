# PC0 Windows legacy 직접 출전 실행 명세 V3

2026-11-09. 이 문서는 PLAN-V2-PC0.md의 심사 후 개정이다. V2의 경로·실제 Windows 입력·32분 wall·종결 및 보존 조건을 유지하고 아래 내용으로 관측·종료·입력 동결 조건을 대체한다. 준비 계획만 작성했다. 독립 수용 전에 runner/overlay 구현과 제품 실행을 시작하지 않는다. 이후 준비물이 생겨도 그 실제 SHA와 동작 계획이 독립 재심을 받아야 실제 실행한다.

## 선택한 실행과 입력

현재 HEAD 0be09755b70378286105972f35ac5b7031715664의 제품 기본 동작을 대상으로 한다. root HEAD/index 및 P03 operation_private_state.gd 현재 bytes는 BASELINE.json과 실행 직전/직후 별도로 비교한다. root의 +9행 활성 변경은 복원·스테이징하지 않으며 HEAD 복제의 입력과 다름을 manifest에 명시한다. 여덟째 미수용 공통 초기화 patch, K1~K5, 미실행 K6 1회 및 21행 계약은 이 baseline과 분리한다.

console과 일반 exe의 V2 고정 SHA를 재확인하고, 실제 argv는 V2의 res://scenes/WorldMap.tscn 명시를 사용한다. product import 전에 신규 절대 project path와 격리 APPDATA/LOCALAPPDATA/cache/log/screens 경로를 확인한다. 격리 project.godot에서 기존 다른 사용자 디렉터리 이름, UID/cache 참조, save 경로를 정적으로 검사하고 runner의 사전 nonproduct 조회로 실제 user://가 지정 루트 아래인지 확인한다. 제품은 fresh-user lane이며 prior local user 파일을 복사하지 않는다. 동일 project 입력의 manifest는 HEAD game source/resources와 참조 closure, assets/BGM, import 입력과 생성 cache, scene argv, appdata 초기 빈 상태를 분리한다. import/editor 종료·오류 확인 후 cache 파일이 필요한 경우 해시를 동결하며 원본 cache를 링크하거나 사용하지 않는다. writable log 및 screenshot 경로는 source manifest와 별도다.

격리 파일에만 세 가지 좁은 overlay를 허용한다. 제품 권위 흐름을 바꾸는 유일한 fixture는 seed 결과의 동결이다. WorldMapScreen.make_brief 원래 식을 그대로 두어 무지정 경로에서 randi()를 정확히 한 번 호출한다. 그 직후 seed < 0인 경우의 b.seed만 777로 덮는다. 명시 seed 경로, global seed 함수, 추가 random draw, 다른 필드를 건드리지 않는다. 고정 seed가 battle RNG와 그 결과를 의도적으로 고정하므로 임의 시드나 모든 전역 RNG 후속 경로 동등성을 주장하지 않는다. scripts/world_link.gd에서 기존 전달 인자와 실제 반환 o를 로그한다. WorldMapScreen._show_result는 매 실제 호출과 동기 상태 확정 이후 표시 결과를 로그한다. 이 둘에서 결산 산출·take_outcome·drain·scene 변경을 추가 호출하지 않는다. 세 번째 파일 scripts/battle_trace.gd에는 아래 읽기 계측만 추가한다.

## 읽기 probe와 반례

- scripts/FleetBattle3D.gd::_process 첫 호출의 trace.sample()은 play와 pause·placing에서도 호출된다. scripts/battle_trace.gd::sample에 기존 상태변경 로그와 별개로 명시적인 V3 phase sampler를 둔다. phase는 placing=G.state play와 host.placing true, paused=G.state pause와 host.placing false, running=G.state play와 host.placing false, terminal=sim.st.over다. terminal을 우선 분류한다. placing/paused의 첫 표본과 같은 phase가 2,000 monotonic ms 이상 지속한 첫 프레임 표본을 한 번씩 append한다. phase 도중 이탈하면 그 epoch는 무효다. 표본은 probe-local epoch, 실제 engine monotonic ms, host와 sim ID, tick, clock_ms, G.state, placing, UI screen과 focus, speed, command_log size를 기록한다. UI에서 해당 화면을 2.5초 이상 유지하며 화면·창과 샘플 시간대를 비교한다. 두 점만으로 그 사이 임의 변조 부재를 주장하지 않으며 동일 epoch와 실제 phase 종료 순서를 함께 확인한다. phase당 최대 첫 표본/2초 후 표본을 쓰고 그 뒤 최초 advancing frame의 tick/clock 증가를 별도 한 번 기록한다. 배치 확정과 실제 pause 계속 버튼이 각각 대응한다. 정상 terminal도 결과 대기 중 2초 이상의 두 점으로 tick/clock 정지를 확인한다. 여러 시작 때문에 trace.session이 바뀔 수 있으므로 결과를 한 파일로 가정하지 않고 실제 최종 sim session ID를 먼저 식별한다.
- V2의 유일 유비 기함 식별은 기존 ally-only fleets trace에 없는 faction을 첫 배치 read-only 표본에 side=0의 id, name, faction, is_flag, control 값으로 추가해 한다. roster에서 side=0·liu_bei·is_flag·direct 1개를 요구하며 손권의 delegate는 동결 source 및 출력으로 대조한다. 플레이어의 입력 전 스크린샷과 selected ID가 일치해야 한다. 상대 가시 방향은 실제 렌더에서 확인되는 표시만 사용하며 raw 적 상태나 안개 속 적 증거를 수집하지 않는다. 하나의 move 목표 선택이 모호하거나 명령 전 기함이 이미 움직이거나 시야 밖이면 반례 우회 없이 실패로 기록한다.
- 기존 FleetBattle3D.issue는 command_request → sim.issue → command_applied → _pump 순서다. BattleSim.issue는 거부 전에도 command_log에 c를 append한다. read-only probe는 command_request/applied의 before/after log size와 마지막 원문 cmd를 기록한다. 기존 _pump의 rejected core_event를 그대로 읽고 같은 seq/tick/관련 ID와 수용 창에서 매칭하며 관련 rejection의 애매함도 실패 처리한다. read-only probe로 이벤트 큐를 추가 소비하지 않는다. 명령 합격은 single selected ID, request/serialized command log/after id·move kind·goal 일치, 한 건 증가, command_blocked와 해당 rejected 부재, 즉시 실제 has_move 및 move_to 상태 변화, 뒤따른 같은 ID 위치 변화가 모두 있어야 한다. vector(target - before_pos)와 vector(after_pos - before_pos)의 dot > 0 및 최소 1.0 world-unit 순이동을 실제 trace에서 계산하고 같은 전대 표시를 전후 screenshot으로 확인한다. 추적 구간은 move 이후 최대 10 논리초, 다음 의도적 입력 전이다. 같은 ID에 다른 명령이 끼거나 근거가 모호하면 실패한다. 화면 world 목표와 엔진 명령을 일대일로 붙이되 field clamp는 input/battle_commands.gd::_fit_to_field의 별도 기록과 사유 없이 허용하지 않는다.
- 종료 진실값은 battle_end event 및 실제 trace의 terminal win/reason/result/tick/time이다. Victory.check는 매 1초 주기(check_period_s=1, hz=10, period=10 tick)와 st.tick modulo를 사용하고 _step_slice의 first 조건에서 호출된다. 초기 상태 0/0, sim clock/tick 순서와 상위 종결 사유를 코드에서 검토하고 1200초 제한을 처음 만족하는 실제 eligible 판정 경계를 독립 oracle의 고정 예상으로 동결한다. 단순 100ms grid는 충분한 oracle이 아니다. 실제 이전 종료 사유는 Victory의 동시 패배→아군 패배→적군 패배→제한 성과→시간초과 순서를 적용한다. timeout이면 win=false와 제한 충족 및 더 이른 eligible time_limit 종료 기회의 부재를 확인한다. 자연 종결 event와 terminal summary는 각각 1개, 종료 tick은 정지다. 결과 손실은 st.result.cost로 독립 계산한다. WorldLink publish/consume과 지도 _show_result의 실제 전달 payload exact, 각 1회, routed brief null/queue null, 표시값과 단계별 screenshot을 확인한다. 지역색은 지도 전환 완료 후 관측한다.

## Windows 실행 소유와 실패 정리

준비할 runner는 기존 owned broker 방식을 하나만 선택한다. inert broker가 사전 Job 할당과 승인된 job identity 확인 전 console을 생성하지 않도록 handshake한다. kill-on-close의 전용 Job과 생성 시각·이미지·membership 확인을 사용한다. console parent와 실제 GUI 자손을 따로 기록하고 conhost를 이름만으로 허용하거나 다른 프로세스 종료 대상으로 승격하지 않는다. 입력 전 launch PID, actual HWND/owner PID·creation time·image SHA 및 membership, 유일한 전경·client rect·DPI를 확인한다. 별도 기존 사용자의 Godot 창은 대상에서 제외한다. 사전 할당/창 확인 실패 시 제품 조작을 하지 않으며 자신의 broker/자손만 정리한다.

Windows CUA의 실제 시각 액션만 써서 V2의 정해진 버튼·한 move·Space·계속을 입력한다. 각 액션 직전 대상 HWND/foreground와 실제 화면, click/keypress, 전후 screenshot, 대응 trace 상태/event를 기록한다. 관측자의 monotonic timestamp와 엔진 시간은 실행 초기/액션 marker로 연결하고 각 clock 원문을 보존한다. foreground 이탈이나 시간 연결 불능은 입력을 멈추고 해당 케이스를 실패로 남긴다. 외부 입력의 완전 배제를 추론하지 않는다. V2의 1,920초와 하위 상한은 독립 supervisor가 보장하고 runner CUA tool 세션의 종료가 감독 Job을 누락시키지 않도록 별도 제어한다. 정상 종료는 소유 UI로, 초과·실패에서는 그 Job만 정리하며 job active 0 및 process 잔존 여부를 확인한다. 프로세스 식별 실패 시 이름 검색 kill을 금지한다.

overlay 실제 diff·hash, read-only counter/log 감사, runner args·Job 종료 및 시간 상한, fixture 초기 roster·독립 deadline oracle, SHA 및 보존 경로를 하나의 review-only manifest로 확정한다. 해당 manifest 독립 수용 전에 product 실행하지 않는다. PC1의 최초 실패/active 실패는 V2처럼 기존 별도 독립 근거를 재사용한다. PC0의 성공은 legacy 기준선 한정이며 첫 캠페인/P07 목표·철수/P03 저장 및 전체 P02 인수는 별개다.
