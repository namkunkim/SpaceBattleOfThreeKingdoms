# P02 첫 PC 도구 적합성 및 사람 플레이 인수 설계

2026-11-09 · 설계 전용. PC0는 2/2회 소진했다. 아래 설계는 해당 실행의 새 회차·재개 승인이나 기존 증거의 대체가 아니다. 여덟째 후보의 K6은 미실행이고 첫 PC 캠페인/operation은 NOT_READY다.

## 관측과 문서 계약

- run02의 foreground 불일치와 최초 조회/캡처 구간의 약 710초 지연은 별도 관측이다. get_window·캡처·반환·렌더·세션 중 장애 지점과 비전경의 인과는 미확정이다. 기존 독립 심사와 OS 로그, 화면/액션 부재, 감독기 종료 후 조율자 중단 기록을 보존한다.
- 현재 노출된 unified CUA의 문서화된 첫 호출은 getApp 또는 getState 같은 단일 초기 API 호출이다. 이후에는 반환된 인터페이스 문서만 따른다. tool timeout_ms는 실행 timeout의 입력으로 노출되지만 하위 OS 요청의 실제 취소·완료 또는 지속 캡처 내보내기를 보증한다는 문서는 확인하지 못했다. runtime 초기 호출이나 창 조회를 하지 않았으므로 동적 반환 API의 native handle·취소·내보내기는 미검증이다.
- 별도 bundled Computer Use 26.1103.32239의 docs/api.md와 docs/guidance.md는 Sky list_windows 반환 객체로 단일 창을 선택하고 screenshot 또는 UIA를 별도로 조회한다. Window.id와 screenshot ID는 해당 인터페이스의 식별자다. native HWND나 CUA ID로 변환하지 않는다. activation은 Sky에서 별도 메서드가 있고 입력은 자동 활성화할 수 있으나 이를 unified CUA 계약으로 전용하지 않는다. Sky 캡처의 inline 표시 및 action에 대한 screenshot ID 사용과 지원된 evidence export는 별개다. 내보내기가 문서에 없으면 payload를 별도로 추출·저장하지 않는다.

## 가장 작은 다음 설계 산출

1. **자동화는 준비·감독·판정만 우선 재사용한다.** run02에서 검증된 격리 import와 소유 Job, 기존 JSONL과 결산 원문, 저장된 baseline manifest를 재사용 가능한 계약으로 정리한다. run01/02의 격리 데이터와 캐시는 역사적 증거로 보존한다. 제품 또는 CUA 호출은 없다. 기존 trace가 확인한 것과 사람이 관측해야 할 UI를 행별 분리한다.
2. **자동 입력 적합성은 별도 비제품 범위에서만 장래 검토한다.** 제품 재시도와 무관한 명시된 harmless fixture와 독립 승인 없이는 호출하지 않는다. 단일 반환 창 선택 → 독립 native 소유 확인이 가능한 지원된 매핑 → 캡처 없는 경량 조회 → 캡처 단일 호출 순서다. 활성화 및 입력은 이 읽기 전용 조각에서 제외한다. 각 호출별 host monotonic 시작/반환/오류, 증거 형태, 지원된 timeout·실제 완료 또는 취소 확인을 기록한다. 후보 예산은 호출당 5초, 최대 각 1회, 전체 30초이며 사전 독립 심사에서 확정한다. 첫 정체에서 다음 호출을 금지하고 fixture 감독기는 소유 프로세스만 정리한다. Promise.race나 도구 timeout 뒤 반환은 미완료 OS 요청의 취소 근거가 아니다. 승인 fixture가 없거나 identity·실제 취소/응답·지속 캡처 중 필수 조건이 충족되지 않으면 자동 GUI는 미수용이다.
3. **제품 인수의 실제 UX는 사람 입력을 우선 설계한다.** 장래의 실제 캠페인 조각이 P05 공간/P07 정책/P03 최소 상태 계약을 충족한 후, 별도 독립 인수 계약에서 사람이 일반 PC 실행 경로로 천하 지도 → 실제 작전 카드 → 직접 지휘 → 배치 → 이동/전투 → 목표 또는 명시 철수 → 지도 결산을 수행한다. 입력·전경 전환·화면 확인은 사람이 맡고 자동 감독기는 배정된 전용 프로세스/로그만 본다. 순서와 식별이 필요한 경우 시간 마커와 현행 trace를 대조하며 운영 중 하나의 앱 창과 격리된 사용자 프로필만 쓴다. 사람이 참여할 수 있다는 가정과 지원되는 캡처 저장 방식은 현재 미확정이다. 이 설계만으로 사용자에게 실행을 요청하거나 PC0를 다시 시작하지 않는다.

## 증거의 분모와 범위

- **자동 저장 가능 근거:** 현재 이미 존재하는 run02 process/import/clock_anchor 및 원본/보호 SHA는 역사적 증거다. 별도 미래 실행에서는 실행 계획에 근거한 승인된 파일 기반 stdout/stderr, Job root/active/retained signals, 명령/배치·pause clock·실제 displacement·terminal 및 WorldLink 1회 소비 trace를 기록할 수 있다. 이 증거는 앱 표시나 OS 입력 자체를 대신하지 않는다.
- **사람 관측 근거:** 실행자 체크 기록, monotonic과 매핑 가능한 단계별 시간, 실행자가 지원된 방식으로 전용 게임 창만 캡처한 파일이 후보 자료다. 캡처 없이 사람 증언만 있으면 관찰자 보고로 표기하고 화면 검증의 독립 재현을 주장하지 않는다. 외부 화면·다른 사용자 입력의 완전 배제도 주장하지 않는다. 대상 창이 유일하지 않거나 게임이 포커스를 잃은 구간은 별도 기록한다.
- **첫 PC 새 조각의 입구:** 기존 HEAD PC0와 동일 조건·동일 목적을 이름만 바꿔 재시도하는 방식은 제외한다. 새로운 제품 조각은 실제 채택 작전 프로필과 정책, 기존 UI의 동일 authority, 목표/철수의 판정까지 승인된 후 별도 범위로 심사한다. 실행 범위가 그 수준에 도달하지 않으면 남는 진전은 비제품 도구 적합성 명세와 P05/P07/P03 계약 확인뿐이다. 저장·재개는 승인된 2단계다. 이번에는 GUI·제품·도구 적합성 실행과 저장 파일 변경을 하지 않았다.
