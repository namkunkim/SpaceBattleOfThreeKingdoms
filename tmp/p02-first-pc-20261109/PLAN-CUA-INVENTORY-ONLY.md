# 통합 CUA 인벤토리 전용 적합성 계획

2026-11-09 · 정적 문서 확인만 수행했다. PC0 2/2, 여덟째 후보의 별도 K6 미실행과 P03 병행 작업을 유지한다. 아래 호출은 실행 예제가 아니라 독립 재심을 위한 고정 명세다.

## 고정 호출과 접근 한계

현재 mcp__cua_repl.js 도구 설명은 첫 호출이나 reset 후에 정확히 하나의 초기 API 호출만 허용한다. 모든 활성 표면의 앱·브라우저·탭 인벤토리와 API 문서가 목적일 때 초기 진입점은 await cua.getState()다. 제품이나 특정 사용자 앱을 선택하는 getApp, getTab, 브라우저 탭 생성 또는 후속 캡처·입력은 범위 밖이다. 이미 초기화된 세션을 이어받거나 공유 상태가 불명확하면 첫 호출을 시도하거나 reset하지 않는다.

독립 승인된 전용 테스트 세션에서만 아래 한 번을 호출하는 안이다. 타임아웃 요청은 5초다.

    mcp__cua_repl.js({
      "code": "await cua.getState();",
      "timeout_ms": 5000,
      "title": "전용 세션의 도구 인벤토리 확인"
    })

이 코드는 정확히 한 초기 API 호출이다. 추가 write, 이미지 emit, 스냅샷, 기다림 또는 앱 선택을 포함하지 않는다. 도구 설명은 getState가 모든 활성 표면의 인벤토리와 문서를 반환한다고 안내한다. 대상별 축소 필터, 이름/탭 URL 필드의 사전 가림, 이미지 없는 응답 또는 안전한 원문 내보내기를 약속하지 않는다. 따라서 현재의 공유 세션에서 사용자의 앱·창 제목·탭 URL 등 민감 메타데이터가 나타나지 않는다고 보장할 수 없다. 전체 화면 픽셀을 반환한다고 단정할 근거도 없다. 기존 사용자 지시는 PC 검증을 계속할 근거지만, 모든 사용자 표면을 조회할 필요성까지 만들지는 않는다. 통제된 전용 세션이 확보되지 않은 현재 상태에서는 호출하지 않는 것이 비례적이며 추가 사용자 질문도 필요 없다.

## 실행 전 조건, 기록과 중단

1. 전용 세션에 개인 앱·창·브라우저·탭이 없다는 운영 조건, 권한·도구 표면 및 run01/02와 분리된 비제품 적합성 범위를 먼저 독립 확인한다. 검증할 수 없다면 실행 없이 종료한다. 지원된 실제 session isolation 기능이 현재 문서에서 입증됐다고 가정하지 않는다.
2. 외부 monotonic 시작/반환 또는 오류, 요청 timeout, 호출 종류, 반환 문서에서 지원한 capability의 유무만 기록한다. 제목·URL·사용자 식별자·이미지·원문 인벤토리를 지속 파일로 저장하지 않는다. namespace가 다른 Sky의 list_windows/get_window_state는 현재 호출에 사용하지 않는다. 도구가 자동으로 결과를 표시한다는 점 때문에 결과를 받은 후 가리는 방식은 사전 격리 대체가 아니다.
3. 시간 초과·미응답·예상치 않은 표면 정보나 이미지를 반환하면 실패/중단으로 기록한다. OS 백엔드 취소를 문서가 보장하지 않으므로 후속 조회, reset, retry, 앱 입력을 하지 않는다. timeout은 요청값이지 실제 벽시계 경계나 미완료 OS 작업의 정리 확인이 아니다. 정상적으로 최종 인벤토리 결과를 관측한 경우 unified tool 지침대로 다음 호출을 completion_summary만 담은 1회로 제한한다. 결과 미확정·호출 미완료는 정상 완료로 표현하지 않는다.
4. 인벤토리 조회 성공은 surface metadata/API 반환만 입증한다. native HWND 결합, 창 단위 캡처, 지속 저장, foreground·입력 또는 제품 플레이는 각각 미검증이다. fixture 없는 현재 단계에서 기능이 없다고 판정하지 않는다.

## 제품 상태와 다음 독립 작업

현재 WorldMap→WorldLink→FleetBattle3D→BattleOutcome 경계는 legacy 제품이다. P05의 native 접근 결과는 별도 격리 확인이며 실제 제품의 첫 작전 데이터·배치·이동과 붙어야 한다. P07은 설계·인수 계획으로서 실제 가동 보급/시간 증원/목표·철수 결과가 제품에 연결됐다는 근거가 없다. 현재 P03 제한 owner는 증원 및 일부 모듈을 명시 거부하고 shared private-state 변경이 진행 중이다. 이 정적 관측에서 기존 호스트 파일은 편집하지 않았다. 실제 첫 PC 조각의 다음 기술 작업은 P05 공간 입력, P07 채택 정책, P03 최소 권위 상태/시계/종결의 현재 구현과 소유권을 맞춘 뒤 같은 실제 출전 경로의 명령·표시·결산을 연결하는 것이다. 인벤토리 결과나 전체 K6를 첫 플레이의 신규 선행조건으로 설정하지 않는다. 저장·재개는 승인된 2단계다.
