# P02 재개 추가 독립 판정 — 입력과 seed

판정: **계획 문구를 명시적으로 개정하고 재심할 조건으로 두 제안을 수용**한다. 이는 K6 실행 승인이나 기존 제품의 키보드 전용 접근성 인수가 아니다. 심사 turn metadata: gpt-6.1-terra / low.

원계획 PLAN.md 16·17행은 각각 실제 OS 마우스 출격/배치와 실제 OS 키보드 입력 및 재시작/천하 복귀를 요구한다. 문장 자체는 후자의 재시작과 복귀까지 키보드로만 하라고 명시하지 않는다. 그러나 후속 RESUME-PLAN 행 16은 “OS 키보드 재시작·천하 복귀”라고 구체화했으므로, 혼합 입력으로 실행하고 기존 문장을 충족했다고 조용히 집계하는 것은 허용하지 않는다. 실제 코드에서 battle_input.gd의 Space는 메뉴 토글이고 pause 상태에서는 명령 키 경로가 차단된다. PauseScreen 버튼은 ScreenKit.menu_button으로 만들어지며 FOCUS_NONE이다. 해당 코드에서 키보드 재시작·복귀 경로를 찾지 못했다. 이는 정적 조사이지 모든 가능한 플랫폼 입력을 동적으로 증명한 것은 아니다.

개정안은 별도의 실제 OS 키 입력(예: Space 메뉴 전환 또는 유효 전투 명령)의 결과·focus와 OS 마우스의 실제 재시작 및 routed 천하 복귀를 각 원문과 렌더로 기록하고, 버튼별 입력 출처를 분리한다. 이를 명시적으로 행 16의 혼합 입력 정의로 재동결하고 독립 재심을 받는다. 키보드 전용 재시작/복귀 미지원이라는 현재 정적 한계는 남기며 그 기능을 추가하거나 성공으로 주장하지 않는다. PID/HWND/foreground 등 기존 GUI 소유권 조건은 그대로 적용한다.

행 14: world_map_screen.gd make_brief는 음수를 임의 seed sentinel로 처리하므로 UI 출격에 -27182818을 전달해도 그 값이 보존되지 않는다. 제품 출격 버튼으로 생성한 유효 Brief에서 seed 필드만 고정값으로 바꾼 뒤 실제 skip 버튼→_finish_sortie→_start_resolve 경로를 검증하는 것은 고정 seed 결정 비교를 위한 계측 fixture로 수용 가능하다. 이때 변경 전/후 typed Brief 전체 비교로 seed만 달라졌음을 기록하고 B/A/I에서 동일 시점·값을 적용하며 mode 실패 주입과 구별한다. 사용자 UI가 해당 음수 seed를 선택할 수 있다는 근거로 보고하지 않는다. UI 무수정 자연 seed 경로를 별도 관찰한다면 고정 seed의 전후 동일성 증거와 혼합하지 않는다. 실패 칩, browse, 실제 재시도, join·결산 조건과 600초 만료 실패 판정은 바뀌지 않는다.

기존 v2의 signed seed 계약과 직접 positive 경계 사례는 유지한다. 이 변경은 행 14의 fixture 생성 방법과 행 16의 입력 해석을 명확히 하는 계획 변경이다. 최종 명령, SHA, 주입 지점, 관측 및 기대값을 동결하고 독립 재심한 뒤에만 K6을 시작한다. 기존 시도·실패를 보존하고 K 상한을 재설정하지 않는다. 제품 코드는 수정하지 않았고 테스트나 GUI 입력을 수행하지 않았다.
