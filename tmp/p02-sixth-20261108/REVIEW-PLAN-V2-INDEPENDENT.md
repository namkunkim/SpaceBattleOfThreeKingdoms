# P02 여섯째 조각 계획 v2 독립 재심

판정: **한정 수용**. `PLAN-v2.md` SHA-256 `493adbb5f88432d18628e45ee2ee78a774e9c9caafa8c0f7513e56a75a98085f` 확인. 이전 심사의 caller 반례를 staged 편성, 실제 deck/org 경로 guard와 사후 실패 사례로 다뤘다. 이 실행의 실제 모델 ID는 독립 메타데이터로 확인할 수 없다.

수용 범위는 지정된 bench patch 두 오류에 대한 후보 준비 거절과 명시된 제품 caller의 동기 실패 보존, 기존 legacy 정상 경로의 전후 대조다. operation 제품 연결, 적벽 operation 지원, 일반적인 잘못된 profile 검증, 전역 RNG rollback, 엔진/게시 예외, GUI·Android·성능은 인수하지 않는다. 특히 이 계획은 실패 시 HUD에 메시지를 표시하지 않으므로 사용자에게 오류가 보인다고 주장할 수 없다. 반환을 무시하는 버튼 callback에서 진단을 확인할 수 있게 엔진 출력 경로가 실제로 남는지 기록하고, 그 부재 또는 사용자 표시 요구가 생기면 범위를 재심해야 한다.

검증에서 다음 조건을 유지한다.

- `begin_battle`의 새 편성 선대입 및 `open_org` 복구 선대입을 제거하고, 실패 시 기존 org·org_errors뿐 아니라 `_load`가 바꾸던 scn/prof/skill_defs, 안내·선택·검색·화면·로그까지 같은 프레임에서 비교한다. 정상 조직 오류 경고와 legacy fallback은 오류가 아니라 기존 성공 결과로 대조한다. 기존 `confirm_org` 및 자동 시작 callback이 반환을 무시하더라도 실패 후 추가 변경이 없는지 확인한다.
- 초기 `_ready` 실패에서 프레임 진행이 실제 중지되고 presentation이 만들어지지 않으며 진단이 남아야 한다. `_restart`와 deck 3경로 각각의 부작용 부재를 실제 호출로 확인한다. initial controls는 실제 native 호스트의 양 진영 roster 기준으로 전후 대조한다.
- 사건은 실제 보이는 것과 안개로 감춰지는 것을 각각 생성해 비공백을 증명한다. 독립 native 기준의 seed/프로필/동틱 명령, 큐 순서, 필터 결과를 고정한다. trace는 실패 전후 파일 identity·바이트·seq, 성공 시 기존 close 및 새 start를 외부에서 관찰한다. trace 계수는 다른 모든 UI 게시 효과의 유일한 증거가 아니므로 FleetView·UI·시계 및 카메라 단언도 함께 필요하다.
- 독립 전후 프로젝트는 실제 `res://` 경로와 클래스, 엔진·캐시·fixture 해시, clean/returning 사용자 데이터, 각 프로세스 exit와 단언 분모를 고정한다. `organization_ui`를 양쪽에 추가한 점은 적절하다. 사전 오라클 및 관측값은 구현 전에 저장하고 사후 구현에서 생성한 기대값으로 대체하지 않는다. 기존 WorldLink clean 실패는 정확히 일치할 때만 별도 분류한다.
- 19,365개 기준선 수치는 이 재심에서 재계산하지 않았다. 실행 전후 및 마감 전 경로 목록·바이트·index 재관측과 허용 hunk 역대조를 수행하고, P03 915개 포함 미귀속 변화는 소유를 추정하지 않는다. 실행 입력이나 편집 hunk와 충돌하면 보류한다. 측정용 callback의 의도적 호스트 부작용은 계약 밖이며, 일반 사용자 경로의 준비 실패 지원으로 확대 해석하지 않는다.

구현 후 별도 비-Astra 독립 5-b에서 상기 실제 증거와 반례를 다시 판정해야 한다. 이 계획 수용은 구현이나 마감 수용이 아니다.
