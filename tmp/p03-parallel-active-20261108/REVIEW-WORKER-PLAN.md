# P03 작업 계획 독립 심사

2026-11-08. **승인: 명시된 제한 범위의 세 검사 및 5-a 실행.** 심사자는 구현에 참여하지 않았다. 기존 `PLAN.md`는 건드리지 않았다.

`WORKER-PLAN.md`, P03 인계·개정 체크리스트, 기존 활성 모듈 관측 결과와 독립 closeout을 대조했다. `scripts/FleetBattle3D.gd`의 자동 편성 로더와 정본 `BattleSim` 후보 생성·게시, `core/battle/operation_private_state.gd`의 활성 모듈 검사와 복원 교체 분기도 읽어 대조했다. 기존 관측은 강제 주입된 모듈이 capture에서 거부되고 same-context restore 후 새 sim에서 없어졌다는 것이다. 자연 제품 도달이나 정책 위반은 입증하지 않았다.

세 검사는 서로 다른 경계를 가진다. 첫 검사는 제품 호스트가 쓰는 기본 자동 편성 입력과 생성자를 재현하는 직접 생성 검사이며, 실제 호스트 준비·게시 실행이나 제한 owner에 대한 도달을 입증하지 않는다. 둘째는 지원되는 제한 owner의 정상 복원 대조군이고, 셋째는 그 입력에 scenario만 추가했을 때 생성 단계의 정확한 거부를 검사한다. 셋째는 활성 owner의 restore 동작을 새로 시험하지 않으며, 기존 강제 주입 관측을 대체하지 않는다. 전체 적벽 프로필의 최초 거부 이유로 일반화해서도 안 된다.

실행과 결과 판정 시 다음을 유지한다.

- 첫 검사에서 실제 호스트의 기본 profile 경로와 난이도 및 `Organization.load_auto` 인자를 확인하고, fallback이나 손으로 조립한 대체 profile이 아니라는 사실과 비어 있지 않은 카드, 정본 script identity 및 sim 역참조를 각각 단언한다. 직접 생성 성공을 호스트 UI 게시 성공으로 기록하지 않는다.
- 둘째의 capture 성공, tick 전진, 같은 context 복원 성공, 교체 후 tick 0·decisions null·busy 해제를 각각 검증한다. 셋째는 둘째와 다른 점이 scenario 추가뿐임을 확인하고, 정확한 오류·owner 부재·입력 deep equality를 단언한다.
- 각 실패와 실제 종료 코드, 원문 로그 및 동결 입력을 보존하고, canonical 경로·진단·누수 확인과 독립 5-b를 거친다. 성공 전 관측을 확정하지 않는다. 쓰기는 전용 디렉터리로 한정하고 공유·제품 파일은 읽기만 한다.

이 승인은 계획 및 관측 절차에 한정된다. 전체 P03/I01/I01b/A04~A06은 NOT_READY, O07은 OPEN, 외부 저장 스키마는 UNCLASSIFIED다. 제품 경로와 제한 owner의 연결, 운영 정책 및 host 원자성은 별도 미결이다.
