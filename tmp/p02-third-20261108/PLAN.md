## 계약

1. 새 JSON envelope는 정확히 format, input, commands 세 필드. format 값 p02/restricted-fresh-replay/1은 이번 CLI 입력 식별자다. input은 기존 p02/restricted-headless/1 그대로 공통 factory에 한 번 넘긴다. 명령이 유일한 외부 정책이며 input.policy=none만 허용, 다른 지원 정책은 unsupported_replay_policy / input.policy. factory의 error/path는 원 분류에 input. 접두사(원 경로 $는 input으로 치환). source definition, checkpoint, product/reinforcement/지원 밖 모듈, 잘못된 tick rate는 factory에서 그대로 실패한다. max_ticks 1~18000, commands 최대 18000, 입력 파일 최대 16 MiB. 초과는 replay_tick_limit / input.max_ticks, replay_command_limit / commands, replay_input_limit / input. input.initial_controls는 factory 기본값 [] 또는 유효한 명시 배열을 그대로 사용한다. 후속 control 명령·policy 생성·AI 변경은 없다.
2. commands는 입력 순서대로 적용하는 Array. 각 행에 정확히 tick, side, ids, kind, target_id, point, args. 숫자 정수 필드는 유한한 정수 JSON 숫자를 정규화하고 tick 0<=tick<max_ticks, side 0/1, ids 각 0..2147483647, target_id -1..2147483647. 빈/중복 ids는 실패한다. point는 유한한 JSON 숫자 두 개, Vector2 변환 결과도 유한해야 한다. 제한 재생은 move, stop, attack만 허용하고 args는 빈 Dictionary. tick은 비감소이며 동틱 입력 순서를 보존한다. 범위·형·미지원 kind·순서 거부는 각각 replay_command_tick / commands[i].tick, invalid_replay_command / 해당 필드 또는 행, unsupported_replay_command / commands[i].kind, replay_command_order / commands[i].tick. 명령 구조 전체를 틱 전 검증한다. 실제 코어 전술 거부(없는 ID, 반대 소유, 전술상 불허 등)는 native 사건으로 보존하며 CLI 입력형 거부와 분리한다. P03 명령 suffix, command/cursor serialization, trace file 재생을 사용하지 않는다.
3. main 단일 소유. fresh adapter owner는 생성 후 한 번 close한다. 요약을 읽고 현재 tick과 같은 명령을 source order로 queue한 다음 advance, drain, summary. 초기 사건은 기존 sync/worker와 같이 첫 틱 drain에 포함한다. 새 정책, UI clock, 시계 추산, 임의 정렬, issue 즉시 적용, 이벤트 재구성, side 가시성 변경은 없다. over 또는 max_ticks에 도달하면 중지하고 summary의 tick/clock/end 및 events의 순서·타입을 사용한다. 자연종료 후 미적용 행이 남으면 replay_unconsumed_command / commands[i].tick, 성공 DTO와 부분 파일 없음. 마지막 처리 틱의 명령 및 사건 포함. max_ticks 도달을 자연종료로 표시하지 않는다. 반환은 ok/summary/events/event_count/meta이며 meta는 factory meta와 executor=replay, replay_format, replay_file_sha256, commands_consumed. consumed는 queue되어 native step을 거친 행 수로, 전술적으로 채택됐다는 뜻이 아니다.
4. 실제 CLI dispatch는 replay 플래그 존재 시 명시 opt-in. --operation-input / --operation-worker와 혼용 시 conflicting_option / --operation-replay, legacy 옵션 및 missing/duplicate/unknown 판정은 기존 helper의 순서를 유지한다. 기존 두 옵션이 replay 없이 섞이면 기존 오류 그대로. 사전 출력 검사 후 파일을 한 번 읽어 파싱한 바이트 SHA를 결과에 담고, 검증·재생·close 성공 후 기존 출력 helper로 다시 경로 검사/쓰기/verify. 읽기·파싱·계약 실패 exit1, 출력 없음 또는 기존 대상 bytes 보존. exit0은 실제 성공 파일 검증 뒤. single-process no-clobber 범위. OS 동시 writer/디스크 쓰기 장애/엔진 예외·강제종료 복구는 이 조각의 게이트 밖이다.
5. 기존 허용 hunk는 tests/autoresolve.gd의 replay dispatch, 공통 parser에 replay 옵션 충돌 검사 추가, 신규 replay CLI 읽기/검증 dispatch. 기존 worker/sync/legacy 본문과 output helper 보존. 새 core/battle/operation_replay.gd 한 파일에 신규 계약과 실행을 둔다(preload, class_name 없음). 새 tests/p02_replay_adapter.gd와 tests/fixtures/p02/replay-*.json만 허용. 기존 core/adapter/private/service, BattleSim.replay, AutoResolver, FleetBattle3D, trace, WorldMap, UI/project, P03 자료는 공유 소유로 보호한다. 새 UID/import 파일은 승인된 경로에 없으므로 자동 수용하지 않는다. 마감은 별도 승인된 P02 문서 hunk와 전용 문서에 한정한다.
