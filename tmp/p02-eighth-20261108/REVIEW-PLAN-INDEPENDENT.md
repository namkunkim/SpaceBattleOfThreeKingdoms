# P02 여덟째 조각 독립 계획 심사

판정: **반려 — 스펙 보완 후 재심**. 대상 `PLAN.md` SHA-256 `d1da017b717d65ce5bb2f2ef215c3ea17cfd23f2c8d15c88c944ceaf5a3dc9b5`. 이 심사는 코드 변경이나 실행 검증이 아니다.

1. **공통 어댑터 거절의 실제 direct 경로가 입증되지 않는다.** 14행의 잘못된 roster patch는 기존 `FleetBattle3D._prepare_game`에서 patch 직후 이미 `invalid_candidate_profile`로 반환된다(현재 코드 297~305행). 따라서 이 행이 통과해도 새 어댑터를 호출하지 않으며 새 어댑터 거절 시 기존 세션 보존·최초 탈출을 증명하지 못한다. 어댑터가 수신한 유효 경계 입력을 실제 호출 지점에서 잘못된 ID/hz 등으로 바꿔 거절시키는 분리 주입 방법, 호출/생성 횟수와 원래 경로 보존을 계획에 지정하라. 주입이 제품 사용자 입력이 아님을 표시하고 기존 roster patch 검사는 별개로 둔다. auto도 같은 호출 증거가 필요하다.
2. **새 계약의 ID가 미정이다.** 변환·초기 지휘의 고정 ID의 허용 값, ID별 효과와 입력/출력 정확 구조, 오류 우선순위 및 경로, POC·fallback의 ID, seed 정수 범위와 사본/alias 경계가 정의돼 있지 않다. 특히 ID가 단순 출처 표식인지 실제 지휘 정책 선택인지 구분해 중복 적용·거짓 ID를 막아야 한다. I01의 source→effective ID 충족으로 주장하지 않는 범위도 명시하라. 구체 입력과 기대값은 K1 전 동결 예정이지만 현재는 독립적으로 채점할 스펙이 아니다.
3. **관측 가능한 입력과 독립 오라클을 구체화해야 한다.** 1~4행의 '원본 caller/독립 native'와 별도 계산의 필드·시점을 정하고, 어댑터 출력으로 기대값을 만들거나 normalize해서 차이를 지우지 않도록 타입·배열 순서·좌표·원문 사건·명령까지 비교하라. direct 변환 후 patch, auto의 아군만 `set_manual_all(false)`, 적 기본값 및 증원 생성 뒤 controls, seed와 clock을 각각 확인하라. 독립 기준선과 실제 두 제품 caller의 연결 확인을 분리하라.

계획의 범위 구분은 적절하다. 현재 제한 어댑터는 적벽 scenario/reinf/AI 및 주요 모듈을 거절하고 owner는 제품 배치 명령을 지원하지 않는다. native 준비 공유가 제품 operation 연결이나 I01 전체 인수는 아니다. 성공 후 게시 도중 엔진 예외의 롤백은 제외되어 있으며 실제 GUI OS 입력과 viewport 입력도 구분했다. 기존 fallback은 legacy 유지이며 공통 준비 거절 후 재시도는 금지한다.

공유 P03 경로는 시점별 해시 관측으로만 다루고 동시 변경 주체나 관측 사이 안정성을 추정하지 않는다는 조건을 유지하라. 계획 hash는 직접 재계산해 일치했다. 이 심사 세션의 실제 모델은 이 기록 자체로 증명할 수 없으므로 권위 있는 turn metadata 확보 전 모델명을 확정하지 않는다.

4. **deep copy의 기존 동작 동등성이 미증명이다.** `BattleSim._init`은 `_reinf_def = profile.get("reinf", [])`로 배열을 참조하고 combat 구성도 생성자에 넘긴다. direct의 `profile_patch` 콜백이 참조를 보유하거나 이후 변경하는 경우 무조건 사본화가 기존 동작을 바꿀 수 있다. 실제 콜백 생산자 및 사용 범위를 조사하고, 지원되는 콜백의 사후 변경·중첩 alias 영향을 전후 독립 oracle로 비교하라. 호환 계약을 의도적으로 바꾼다면 별도 명시와 영향 판정이 필요하다. 사본 소유를 스펙에 넣은 것만으로 호환이 성립하지 않는다.
