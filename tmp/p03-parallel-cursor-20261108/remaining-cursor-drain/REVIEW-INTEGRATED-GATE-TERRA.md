# 보존 종료·출처 통합 독립 재심사

판정: **합성 범위 조건부 수용, 실제 엔진 실행 승인 아님.** Godot 실행 없이 확인했다. 검토 대상 `launch_preserved.py` SHA-256 `2E90D94721DB2BB5207D3ADE3EB2BF05EC13F9F2A28A77838BB7E440228E0A1D`, `preservation_exit.py` SHA-256 `42E2933AAD446B7C730333D30EA476211ABD890CF287374C04A04F8F1C9707D7` (담당자 보고; 최종 실행 전 다시 확인).

실제 main 경로를 fake Job/Popen으로 호출한 v3 합성 결과는 정상, 보호 변경·삭제·예상 밖 신규, 비정상 exit, 예약 충돌, 자체 영역 기존 변경·신규 생성 및 예약 attempt 외 파일에서 기대 결과를 기록한다. v2의 오류 누락을 v3에서 누적 처리한 점과 자체 status 예외를 예약 attempt로 좁힌 점을 코드로 확인했다. 별도 출처 합성은 독립 PID 누락·자체 PID·시간·SHA 불일치 및 보호 루트 누락을 거부한다. 이 결과는 합성 데이터와 대체 프로세스 경로에 한정되며 실제 Godot/운영 P02의 출처를 증명하지 않는다.

실제 P02 process.json에는 독립 engine_pid가 없어 현재 새 trace를 신뢰성 있게 귀속할 수 없다. 예외 허용에는 해당 trace의 정확한 경로·해시, 실행 창 시간, P02 실행의 독립 engine PID 및 command 환경·로그가 연결된 원문이 필요하고 자체 Job PID/경로와 구별되어야 한다. 또한 이 증거 파일이 고정 보호 파일로서 창 중 생성·변경되면 자체가 hard stop이다. 필요한 독립 증거가 없다면 새 trace는 무조건 hard stop이며, P02가 새 trace를 만들지 않는 경우에도 그 부재는 사전에 보장되지 않는다.

상위의 별도 실행 지정과 최신 코드·계획 SHA 재확인, 전체 고정 입력 및 보호 루트 사전 열거·해시, 예약 및 격리, 종료 전후 원문 검증과 별도 5-b가 남아 있다. 실제 엔진 실행을 이 심사로 승인하지 않는다. 실행 창에서 허용 밖 변화나 출처 미확인이 있으면 즉시 hard stop하고 자동 반복하지 않는다. 이전 attempt들은 원문 보존, 5-a 미통과, 실제 Godot 3회/K=6 유지.
