# 새 trace 없는 실행 창 독립 선심사

판정: 기존 승인 baseline과 게이트를 바꾸지 않는 조건에서 **네 번째 실제 시도는 조건부 허용 가능**하다. 신규 trace 0은 사전에 추정하는 사실이 아니라 종료 시 보호 범위 실물 전후 비교로 판정하는 조건이다. 이것은 실행 성공이나 5-b 수용이 아니며 승인 계획이 요구하는 상위의 별도 1회 지정 및 직전 preflight가 선행돼야 한다. 이 선심사에서는 엔진을 실행하지 않았다.

기능 계획 SHA `8852B8C89A2217D1967BEF431FBA6913B66FC0D4BCEC10652C19F271D4A345AF`, 보존 개정안 SHA `0567C1306E14B142E82D3AD8F271A43C2530CA06BA200A7BE517DA991C3FDFD9`, 이전 합성 심사 대상 launcher `2E90D94721DB2BB5207D3ADE3EB2BF05EC13F9F2A28A77838BB7E440228E0A1D`, exit adapter `42E2933AAD446B7C730333D30EA476211ABD890CF287374C04A04F8F1C9707D7`를 재확인했다. 01–03은 실제 실행 3회, K=6이다. `attempt-04`는 긴 경로 경고로 preflight에서 중단되어 엔진 미시작이며 기존 폴더를 덮어쓰지 않는다. 네 번째 실제 실행은 다음 미사용 폴더에서 원자 예약한다.

두 허용 trace 부모에는 현재 각 기존 파일이 있고, 읽은 clean process.json은 user_after 해시를 포함하나 독립 engine_pid를 제공하지 않는다. 과거 파일명의 숫자를 PID로 인증하거나 신규 파일에 출처를 추정하지 않는다. 일회성 Get-Process 관찰에서는 Godot 프로세스가 표시되지 않았으나 미래 비실행을 입증하지 않는다. CIM 조회는 접근 거부돼 명령행 확인에 쓰지 못했다. P02와 그 출력을 수정하지 않았다.

종료 시 신규 trace 0, 사전 보호 파일 및 고정 입력/목록·HEAD 불변, 자체 출력 경계와 기타 status·재귀 인벤토리, Job·actual exit·32개 마커 및 진단이 모두 승인 게이트를 충족해야 한다. 새 trace가 하나라도 나타나면 기존 승인 규칙의 독립 경로·시간·PID·해시와 자체 출력 배제를 만족해야 하며, 입증 불가면 hard stop이다. 기존 파일 append나 다른 신규 산출물도 hard stop이고 자동 반복·기준선 재분류를 하지 않는다. 보호 범위 열거 실패나 경고는 실패다. 조건 충족 여부는 그 시도의 원문과 별도 5-b로 판정한다. 현재 관찰로 실행 창이 안전하다고 보장할 수 없다.
