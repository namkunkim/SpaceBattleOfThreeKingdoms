# P03 owner lifecycle의 가드 우선순위 읽기 조사 계획

Terra 계획 심사 대기. 실행과 검사 코드는 작성하지 않는다. 독립 조각은 operation_private_state.gd의 serial 가드 우선순위와 DTO 계약을 소스 기준으로 대조한다. 기존 active replacement 검사는 busy 상태의 restore와 active 보존, private state 검사는 몇 개의 busy 거부, viewer 검사는 raw/filtered 소비 순서를 실제로 검증했다. 이번 조각의 차별화는 11개 진입점 전체의 정적 교차 원장과 가드·DTO 차이 정리다. tests/p02_viewer_events.gd:232의 busy+invalid side 및 정확 {ok:false,error:busy,path:owner}, tests/p02_headless_adapter.gd:323의 읽기 busy DTO, tests/i01b_active_replace.gd:259의 restore busy는 겹치는 기존 runtime 근거로 표시한다. 같은 반례를 신규 실행이나 신규 검증 범위로 집계하지 않는다.

사전등록 분모는 공개 진입점 11개다. create와 prepare는 별도 신규 후보 생성이며 이 분모에서 제외한다. 대상은 issue, queue, advance, drain_events, drain_events_for, read_projection, summary, observe, capture_completed, restore_completed, close다. 각 행에서 guard 호출 여부, payload 검사 순서, busy/unprepared의 정확 키·값·path, 기존 상태 접근 및 쓰기 위치를 표시한다. close는 가드 없는 void 호출로 별도 표기하며 guard 실패 DTO를 기대하지 않는다. 세 반례는 busy+invalid side, busy+invalid command 또는 packet, closed+restore·read side의 교차다. 코드상 결과를 정적 결론으로 표시하고 재진입·스레드·실제 UI 및 외부 ACK에 일반화하지 않는다.

5-a는 11개 고유 행과 반례 3개, 코드 근거 위치, 실제 과거 runtime 근거와 추론 분리, 시작·종료 정본 및 기존 테스트 SHA 일치를 검증한다. 사전 고정 집합은 core/battle/operation_private_state.gd, tests/p02_viewer_events.gd, tests/p02_headless_adapter.gd, tests/i01b_active_replace.gd, tests/i01b_private_state.gd와 실제로 인용할 실행 증거의 정확 경로다. 각 원문 경로·SHA-256·크기를 시작에 확정하고 종료에 같은 집합을 확인한다. 실행 증거를 확인할 수 없는 사례는 정적 추론과 구분해 미확인으로 남긴다. 집합의 파일 누락·읽기 실패·해시/크기 차이, 근거 위치 불일치, 고유 행 11 또는 반례 3 부족, 불명확한 DTO는 원문과 이유를 보존하고 5-a 실패로 판정하며 5-b 수용 단계로 넘기지 않는다. 동시 P02 전체 무변이를 주장하지 않는다. 5-b는 별도 Terra가 순서, 오류 DTO, 기존 증거 범위를 독립 대조한다. 승인 후 전용 새 폴더에서만 조사 문서를 작성한다. 엔진 없이 읽기만 하므로 cursor/drain의 기존 3/6 및 미통과와 분리한다. P02 작업을 중단하지 않는다. 전체 P03/I01/I01b/A04–A06 NOT_READY, O07 OPEN, 외부 저장 schema UNCLASSIFIED.
