# P02 일곱째 조각 개정 계획 v2 — 전투 준비 실패 표시와 최초 진입 탈출

## 선택과 제품 계약

여섯째 조각의 독립 구현 5-b와 closeout-v2는 기존 전투 보존 및 두 가지 bench patch 거절을 한정 수용했다. 현재 init_game 실패가 엔진 로그에만 남는다. 기존 화면에서 실패 이유를 표시하고 초기 진입에서는 결과 없이 나갈 수 있어야 한다. 두 오류는 현 profile_patch 주입으로 재현한다. 일반 profile 오류나 실제 사용자의 자연 발생 빈도는 입증하지 않았다.

- 수정 허용 제품 경로는 scripts/FleetBattle3D.gd 하나. init_game의 기존 오류 반환과 로그를 유지하고 오류 UI를 동기 표시한다. 제품의 호출자별 별도 상태 관리보다 scene-owned 하나의 경고 컨트롤을 사용한다. _ready는 build_canvas 직후 presentation 생성 전에 실패할 수 있으며, 정상 CommandDeck CanvasLayer 5와 숨겨지는 legacy canvas 어느 쪽에도 의존하지 않는다. 전용 layer는 두 HUD보다 위, SafeArea 아래에 배치하고 기존 UI 테마/한국어를 사용한다.
- 기존 sim이 있으면 짧은 비모달 경고를 보여 준다. 예를 들어 “전투를 준비하지 못했습니다. 기존 전투는 유지됩니다. 다시 시도해 주세요.”와 고정된 이유 (“전투 프로필이 비어 있습니다” / “함대 편성 데이터가 올바르지 않습니다”). 반환 error/path는 진단용으로 유지하고 원시 경로를 플레이어 문구로 출력하지 않는다. 재차 실패하면 같은 컨트롤에서 갱신한다. 모든 경고 자손은 mouse ignore, focus 없음. 기존 화면·선택·일시정지·clock/event 흐름에는 별도 정책을 추가하지 않는다. 성공적 publish 후 즉시 숨기거나 제거하고 scene 종료가 모든 경고 객체를 소유 해제한다. 정상 첫 시작에 보이지 않는다. load_error 및 org_errors 기존 fallback 표시는 별도로 유지한다.
- sim 없는 _ready 실패는 전용 오류 화면을 표시한다. 기존 build_canvas가 만든 legacy “출격” 버튼이 sim 없이 동작할 수 있으므로 legacy canvas를 숨기거나 상호작용을 차단하고, 기존 host process/input 차단을 유지한다. routed일 때만 “천하로”를 WorldLink.back_to_world(null)에 연결한다. FleetBattle3D.back_to_world는 sim.st를 읽으므로 호출하지 않는다. WorldLink의 정본 계약은 null이 미결산 복귀이며 정상 route가 brief를 해제하고 map을 연다. 이때 last_difficulty/last_mode 유지, 전투 결산·trace·시계·명령 없음. 직접 실행 시 main_scene 자체가 FleetBattle3D이고 정상 타이틀은 성공한 presentation의 화면이므로 기존 legacy 메뉴와 같은 “종료”를 _quit에 연결한다. 최초 실패에서 빈 타이틀을 흉내 내거나 실패한 후보로 재진입하지 않는다. 버튼은 키보드와 포인터가 사용할 수 있게 하고 비활성 host process에서도 작동해야 한다. 실패 직후 사용 가능한 동작을 안내한다.
- FleetBattle3D의 제품 진입에 operation 선택이나 전환 경로가 없다. WorldMap의 레거시 resolver.start/poll/cancel과 WorldLink BattleBrief/Outcome이 현재 제품 경로이며 start_operation/poll_operation/cancel_operation은 제한된 별도 worker API다. Adapter.normalize는 operation 명시 형식/10Hz/none·attack5를 받으며 create의 owner는 증원과 morale·victory·command·stratagem·assault 설정 등 일부 모듈을 거절한다. 적벽은 시나리오 로더의 증원 및 combat 규칙을 사용한다. 모듈을 끄면 제품 규칙이 바뀌고 legacy fallback이면 operation이 요청한 동작을 실행했다는 잘못된 신호가 된다. 실제 제품 operation 지원은 지원 계약, 권한/clock/command/events와 결산 경계를 공동 검증할 별도 조각이다. 이번에는 replay/worker/공통 owner와 P03 작업 경로를 읽기 전용으로 유지한다.

## 5-a 검증 분모 및 오라클

1. 최초 baseline.json의 branch HEAD, 물리 index SHA, stage SHA, staged raw와 전체 경로 해시를 사용한다. 2,453 tracked, 20,831 nonignored untracked, 새 증거 폴더만 분모에서 제외. 목록/읽기 drift 0이며 순차 관측이다. 앞뒤 해시 일치는 그 사이의 변경 부재나 변경 주체를 증명하지 않는다. P03·기타 미귀속을 복원하거나 포함 편집하지 않는다. before 복제 전과 각 5-a 실행 전·후에 실제 의존 제품 경로 및 suite/fixture/runner, Godot 콘솔 wrapper와 실제 exe, .godot/global_script_class_cache.cfg를 전수 동결한다. wrapper C8F0A6BC…E846643, 실제 exe AB1824F8…B22424, cache 0EB214EB…AB1, 4.7.2.stable.official.ed1daf0bf. 프로젝트 복제본은 독립 user data, HEAD/index 비접촉, source cache 수정 금지. 최초 baseline과 비교해 입력·소유 파일에 drift가 있으면 관련 실행을 보류하고 별도 정본과 심사로 돌아간다. P03 실행과 무관한 차이는 path별 기록 후 겹치지 않는 근거를 남긴다.
2. 사전 실행은 제6조각 공통 8행/27단언 native oracle과 atomic 10행/546단언 경계를 현 바이트에서 재생한다. 사전 실패 UX 탐침은 같은 조작에서 경고 부재, 초기 구형 출격 가능 여부, 복귀 버튼 부재를 관측한다. 사후 기존 정상 common JSON 및 전체 trace 행(기존 wall_time/mono_ms만 제외)과 대조하고 이전 trace 접두 바이트·단일 start/close·복구 native roster를 확인한다. 정상 조직·브리핑·재시작·타이틀·legacy fallback을 이전 동작과 비교한다. 원본 사전 결과에서 동결한 오라클에 control/pos 변조 거절 self-check를 유지한다.
3. 실제 제품 씬 및 제품 연결 버튼으로 사전/사후 행을 다음 12개로 동결한다. (1) profile 비움 직접 init_game (2) roster 형식 직접 init_game (ally·foe 각 별도 입력, 중립 문구 동일) (3) 편성 확정·출격 (4) 브리핑 자동 편성 (5) 편성 복구를 일으키는 실제 열기/출격 (6) 제품 다시 시작 (7) unrouted 타이틀 (8) legacy 처음부터 (9) 반복 오류 및 정상 재시도 (10) 최초 직접 실행과 실제 종료 (11) 최초 routed 진입과 실제 천하로 (12) 정상 시작/기존 fallback과 경고 부재. 버튼 행은 scene/control의 이름, 표시, enabled, 실제 입력과 연결 함수 도달을 기록한다. 실제 GUI 입력으로 기본 버튼 callback을 탄 증거가 필요하다. emit_signal 또는 콜백 직접 실행은 구조 검사로만 별도 집계한다. 최초 두 탈출 모두 host process 비활성 상태에서 마우스 클릭과 별도 프로세스/시나리오의 키보드 포커스·활성화를 각각 입증한다. 실행 전에 12행 각각의 assertion ID를 작성하고 목록 SHA와 양쪽 분모를 동결한다. early-out, 누락, skip, 예상치 못한 엔진 오류는 실패로 판정한다.
4. 동기 실패 전후의 sim identity 및 fingerprint, roster, 선택·배치·카메라, 기존 deck/org cache 및 화면, clock/tick/alpha, trace 바이트·seq·경로·목록, 대기 명령과 viewer 사건 큐 및 각 소비 결과, WorldLink brief/outcome, 사용자 설정과 프로필 입력 동일성을 확인한다. 경고 전용 노드/문구만 허용한다. 초기 상태는 sim/presentation/trace 없음, legacy 버튼 무입력, scene fatal UI enabled. 종료 행은 실제 독립 프로세스 종료(타임아웃과 구분), routed 행은 실제 WorldMap scene 변경과 결과 없음·last 선택 보존. 검증용 subscene나 fake WorldLink를 실제 제품 라우팅 결과로 집계하지 않는다. 기존 WorldLink clean-user 서막 기대 실패와 returning 성공을 따로 보존하고 ObjectDB/resource 종료 진단은 원문과 전후 차이를 별도 보고한다. thread·operation 경로는 제품 호출 및 파일이 그대로임을 확인하되 새 operation thread 검증으로 계산하지 않는다.
5. 화면 경고인 만큼 독립 5-b에 격리 로컬 Godot 네이티브 GUI 근거가 필요하다. 실제 renderer에서 첫 실행 실패 화면, 기존 브리핑/편성 또는 메뉴 위 경고와 성공 후 제거를 최소 두 viewport(예 1600x900·1280x720 및 SafeArea 인셋 주입)에서 증거로 남긴다. 각 최초 탈출의 실제 입력과 결과를 입증한다. HTML/browser 금지. 독립 심사자가 구현의 테스트 헬퍼나 제품 표시 문자열을 오라클로 재사용하지 않고, 이 계획의 기대 문구·동작과 실제 스크린샷, 버튼 입력 기록, 종료 코드 및 WorldMap 활성 씬 기록을 직접 대조한다. 최초 버튼 화면 내 위치, 포커스 및 클릭·키보드 경로, 경고와 가려진 legacy 출격의 클릭 표적, 기존 UI의 입력 통과를 확인한다. GUI가 불가하거나 실제 입력·가독성 증거가 부족하면 자동 검사와 UI 트리까지만 보고하고 구현 5-b 및 완료 마감을 보류한다. Android 실기·성능은 별도다.

## 단계 및 보존

- 독립 계획 심사, 구현, 5-a, 구현과 다른 비Astra 모델 5-b, 결과/체크리스트/인계·ZIP 마감과 독립 마감 순. 이 계획·baseline은 제품 소유권이나 계획 수용을 선점하지 않는다. 계획 반려 시 스펙으로 회귀한다. 전체 5-a 시도 K=6, 중단/실행/프로세스 수를 별도로 기록한다. 사용량 제한 첫 발생 시 즉시 상태를 기록하고 반복하지 않는다.
- 각 단계 session/turn/actual model을 권위 있는 세션 turn metadata 원문에서 검증하고 메타의 파일 경로와 원문 행, 해당 인용 SHA를 남긴다. 요청 모델과 실제 모델을 같은 것으로 추정하지 않으며 예상 라벨과 실제 확인을 분리한다. 확인할 수 없는 모델은 unknown으로 남기며 구현↔5-b 모델 차이가 확인되지 않으면 독립 인수 보류. 원본 branch, checkout, worktree, commit, push 금지. 단계별 non-owned bytes/경로/index/engine/cache 및 기존 HTML/ZIP 차이는 별도 기록한다. 관련 제품 입력이나 소유권 충돌은 정지한다. 새 증거와 본 조각의 승인 소유 파일 외 직접 수정 금지.
