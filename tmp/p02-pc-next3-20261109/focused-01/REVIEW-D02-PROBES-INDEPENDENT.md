# D02 진단 및 정규화 probe 정적 심사

판정: 진단 overlay는 원본 두 roster 단언식을 그대로 유지하고 실제/기대 양쪽 행 값과 id·faction·wait·morale의 typeof를 부가 기록한다. 실행 결과 없이 원인 확정은 불가하다. 배열 전체와 타입을 기록하므로 관찰 대상과 순서가 원래 비교와 대응하며, 부가 계측이 무부작용임은 실제 실행에서 확인해야 한다.

정규화 overlay는 기대 사본의 wait_ticks 및 start_morale_bp만 int로 바꾸고 ID·진영·순서·숫자값 비교와 기존 실패 단언을 유지한다. 범위·정수성을 확인하고 비정상값이면 fixture.oracle_roster_integer 실패를 추가하여 조용한 PASS를 막는다. 다만 `value != int(value)`보다 앞서 float에 `is_finite(value)`를 검사하지 않아 NaN/무한대가 int 변환에 도달할 수 있다. JSON 문법 및 현재 고정 입력은 통상 이런 값을 만들지 않지만, 명세상 변환 유효성을 강제하려면 타입 검사 후 float 유한성, 범위, 정수성 순서로 검사하고 그 뒤에만 int 변환해야 한다. 실패 시 해당 테스트를 명시 중단하거나 완결 실패로 남기며 중복 ID를 삼키지 않는다. 숫자·길이·순서·ID를 변형하거나 허용 오차로 완화하지 않는다.

두 overlay의 파싱·타입 및 비교 결과는 실제 엔진에서 관측되지 않았다. D02 기존 exit 1을 통과로 바꾸지 않으며, 별도 최소 진단의 정확한 manifest·예산·격리와 별도 독립 승인 전에 실행하지 않는다. 정규화는 제품 변경이 아니다.
