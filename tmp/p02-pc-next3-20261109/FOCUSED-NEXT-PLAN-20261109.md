상태: 준비만 함. 실행·독립 심사·제품 적용 전. 2026-11-09 C: 읽기 관측 8,306,167,808 bytes. 가용 공간은 실행 직전 다시 확인한다. 이 문서는 기존 28개 검사 재실행 승인이나 K6 한도 변경이 아니다.

## 범위

실제 WorldMap에서 전달된 적벽 BattleBrief 난이도가 FleetBattle3D 시나리오 규칙·함대 편성에 사용되는지와 실패 시 기존 전투의 보존을 우선 검증한다. 현재 원본 FleetBattle3D SHA `029a11be7c08038f2ed4a482f0b2668bd924c842c33a2a671409cd486f0191c9`, 격리 제품 후보 SHA `0be6a03729a0906b6170169e607c0d26cb08ae046f9e31785c8862f372b10e81`. 실행 전 P03 등 병행 변경과 HEAD/index·입력 closure를 재동결하고 달라진 파일은 확인한다.

## 최소 검사 제안

1. 기존에 실행된 probe의 파서 오류를 고친 `probe-fix-v2/p02_difficulty_probe.gd` SHA `2a343973144c518dcb40e20b8031ca79aa9e331ff1b8c0b8ef07e962684e3107`는 441행의 명시 bool 한 줄만 다르다. 파싱 성공은 미확인이다. 새 격리 실행 기록에 실제 엔진 import·스크립트 로딩 결과를 남긴다. 오류가 나면 성공이나 예상 기준선 실패로 치지 않는다.
2. 기존 데이터 기반 오라클과 D01~D04의 네 난이도별 `route.difficulty`, `profile.host`, `profile.rules`, `roster.full`, `roster.wait`를 후보에서 확인하고 기존 원본과 비교한다. 명령 출처와 종료 코드·모든 검사 ID·원문 오류를 보존한다. 자동 signal 주입은 물리 입력이 아니다.
3. D08의 잘못된 후보 실패 후 기존 sim·seed·difficulty·시계 등 보존과 정상 재시도, D09 단독 실행 기본 동작을 확인한다. 실패·결측은 미완료다. 후보 적용 전 별도의 구현 독립 5-b가 필요하다.
4. Windows GUI 실제 선택·출격 확인은 별도로 기록한다. 기존 PC0 2/2를 재시도하거나 다른 이름으로 성공 처리하지 않는다. 물리 입력 귀속을 확보할 수 없으면 실제 사용자 입력 미검증으로 남긴다.

위는 테스트할 동작과 기존 probe를 재사용하는 제안이지 고정된 실행 manifest가 아니다. 실행 전 격리 경로·엔진과 입력 SHA, 각 사례 정확한 명령·예상 종료 및 ID, 제한 시간과 종료 정리, 공간 바닥, 실행 예산을 확정하고 독립 심사를 받는다. 기존 attempt-01 결과 및 로그와 P03 변경을 보존한다. 첫 PC 필수 경로 외의 replay·K6 전체는 이 계획의 전제에 넣지 않는다.
