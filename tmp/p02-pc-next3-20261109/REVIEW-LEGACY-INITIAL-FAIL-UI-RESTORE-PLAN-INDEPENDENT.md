# 최초 준비 실패 지도 복원 계획 독립 심사

판정: legacy UI의 관측된 복구 공백에 대한 유효한 후속 설계로 수용하나 첫 PC 정상 플레이의 선행 필수 구현으로 올리지 않는다. 최초 준비 실패시 기존에도 오류 화면과 지도 복귀가 가능하며, 이 계획은 이전 카드/결산 표시의 보존을 개선한다. 세 공유 파일과 소비 lifecycle을 새로 바꾸는 작업이 정상 제품 작전 연결보다 우선한다는 근거는 없다. 후보 작성·엔진 실행·원본 적용은 이 정적 심사에서 승인하지 않는다.

결과 화면의 outcome은 이미 WorldMap이 take_outcome으로 소비한 local 객체이므로 이를 WorldLink.outcome에 재큐하지 않는 방향은 타당하다. 복원 데이터의 nullable 결과와 유효성, 복사 깊이·동일 값, UI 색 snapshot 및 실제 지도 focus/level의 관계를 고정해야 한다. _show_result를 분리할 때 정상 경로의 라벨/소리/0.6초 색 연출이 한 번 유지되고 복구 경로에서는 효과를 다시 발행하지 않음을 각각 검증한다. L04는 사용자가 이전에 보지 못했을 수 있는 결과색을 정착된 색으로 보여주는 명시적 UI 정책이며 실제 전투 결과 지급이나 persistent state를 변경하지 않는다.

직접 scene 요청 거절, 최초 준비 실패 뒤 최초 복귀의 거절/재시도, 정상 복귀 및 계속/자동/standalone 경로에서 snapshot 공개·소비·폐기의 순서와 횟수를 명시해야 한다. 특히 즉시 복귀 실패 후 인계 유실·중복, 정상 성공 후 오래된 인계가 다음 지도에 섞이는 경우를 반증한다. 정상 map _ready에서 새로 발생한 실제 결산과 복원 snapshot이 동시에 존재할 때 우선순위를 조용히 정하지 말고 무효 또는 명시 처리해야 한다. 초기 준비 오류 전용 경로와 활성 재준비 실패가 실제로 구분되는지도 필요하다.

L01–L07은 방향성 제안으로 fixture·실제 scene 오류 주입·assertion ID/분모, 독립 효과 계측·원본/후보 closure, 명령/timeout/프로세스·디스크 예산이 아직 없다. 작업을 진행할 경우 후보와 이들을 동결해 별도 독립 심사를 받는다. P03/P05/P07 작업과 WorldLink/FleetBattle3D/WorldMap의 현재 소유·해시를 직전 재확인하며 일회성 UI snapshot을 작전 권위나 외부 저장 schema로 승격하지 않는다. PC0/K6/실제 물리 플레이는 별개다.
