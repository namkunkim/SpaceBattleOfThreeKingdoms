## 계약 및 작은 구현 조각

1. 실제 AutoResolver에 opt-in 공개 호출 start_operation(input) / poll_operation() / cancel_operation()을 추가한다. start는 기존 legacy thread가 아직 join되지 않았거나 새 worker가 active인 경우 busy를 반환하고 현재 작업/결과를 건드리지 않는다. legacy start/run_blocking의 신규 operation active guard만 허용한다. legacy cancel/poll/error/outcome/sim/brief/progress 경로는 유지한다. CLI는 AutoResolver.new(null)의 별도 작업 인스턴스를 명시적으로 쓰며 legacy 메서드를 호출하지 않는다.
2. Main에서 기존 Service._data로 object/cycle/nonfinite 등 plain-data 경계만 검사한 뒤 deep-copy로 caller와 분리한다. 실패는 invalid_worker_input / input. 새 thread의 Thread.start 반환값을 검사하고 실패 시 후보만 폐기하며 worker_start_failed / worker 및 실제 Godot 코드 반환. 한 번에 작업 하나. 기존 완료값이 있다면 새 start가 성공할 때만 새 작업으로 교체한다. poll은 running/idle/완료 응답을 구분하고 main에서 is_alive가 false일 때 wait_to_finish로 1회 join한 후 결과만 공개한다. 반복 poll은 복제한 동일 결과를 반환하고 caller가 수정해도 내부 결과가 변하지 않는다. cancel은 Mutex로 보호한 단일 취소 신호를 worker에 쓰고 main이 join한 뒤 결과를 폐기한다. 완료 직전/직후 cancel도 poll 전에 호출됐으면 결과를 게시하지 않는다. 이미 게시된 결과는 취소로 소급 변경하지 않는다. 호출 책임은 시작한 main 소유자가 반드시 poll/join 또는 cancel/join을 끝내는 것이다.
3. Worker가 기존 adapter.create(snapshot)를 정확히 한 번 호출한다. adapter normalization/profile 오류는 원 error/path. 이후 policy=none, initial_controls가 명시 nonempty 전원 delegate(Private가 길이 검증), max_ticks <= 18000만 허용한다. 순서 policy, controls, max_ticks. 각각 unsupported_worker_policy / policy, worker_requires_delegate / initial_controls, worker_tick_limit / max_ticks. 지원 밖 입력의 모듈/증원/controls/policy를 수정하거나 legacy로 내려가지 않는다. 지원 제약 위반으로 owner가 생성된 경우 같은 worker에서 즉시 close한다. 취소 신호는 최소 factory 전, 루프 매 틱 경계와 반환 전 확인하며 main은 동기 join에서 worker의 현 작업 경계까지 기다린다. 취소/반환형 오류/정상 종료 모두 worker에서 정확히 한 번 close(미생성 제외). owner, sim, projection, node/resource/BattleBrief 및 BattleOutcome은 스레드 경계를 넘지 않는다. Mutex 상태는 취소 비트만이며 대기·join 동안 lock을 보유하지 않는다.
4. 명령을 외부에서 주입하지 않는다. 명시 delegate의 기존 내부 AI만 동작한다. owner.summary의 실제 tick/clock_ms/end 필드를 사용하며 강제 추산이나 timeout을 자연종료로 승격하지 않는다. 초기 summary → advance → drain → summary 순서. 종료 틱 사건을 포함해 순서/타입을 보존한다. 결과 DTO는 기존 제한 CLI와 같은 summary/events/event_count/meta만, meta executor=worker를 추가한다. 취소/오류에는 부분 사건·결산·success DTO 없음. 진행 중 clock/progress 및 army_bp의 신규 공유 게시 없음. live worker 필드를 읽어서는 안 된다. WorldMap 결산을 만들어내지 않는다.
5. CLI 신규 옵션은 값 있는 --operation-worker이며 --out 필수. 양 경로 옵션 혼합은 명시 conflicting_option, 신규 누락/중복은 기존 방식으로 분류. 새 경로 input은 단일 파일 read로 얻은 실제 bytes를 파싱·SHA 기록하여 join 이후 파일 교체의 영향을 받지 않는다. 기존 sync 입력 및 오류 우선순위 보존. CLI는 process_frame 사이에 poll하여 busy-spin을 피하고, 결과/오류를 join 이후 기존 출력 검사와 쓰기/verify 루틴으로 넘긴다. 새 경로는 사전에 존재하는 파일/디렉터리 및 parent missing을 거부하고 쓰기 직전 재확인한다. 정상 반환 exit0, 반환형 거부 exit1, legacy fallback/조기 출력 없음. 기존 single-process no-clobber 범위 유지. disk fault injection, 부분 WRITE 복구, OS writer 경합, 프로세스 강제종료는 계약 밖.
6. 허용 production hunk는 scripts/world/auto_resolver.gd의 operation 전용 상수/상태/메서드, legacy start/run_blocking의 active guard 두 곳이다. tests/autoresolve.gd는 신규 옵션·dispatch, worker용 읽기·대기, 기존 operation output block을 공유하기 위한 이동(이동 전후의 기존 검사/오류 우선순위와 출력 바이트 보존)만. adapter/private/service/BattleSim/profile/world_map/FleetBattle3D/replay/project/cache 변경 없음. 새로운 worker 전용 tests/p02_worker_adapter.gd 및 tests/fixtures/p02/worker-*.json만 허용. 먼저 기존 3 fixture를 수정하지 않고 별도 worker fixture의 출처·변경을 기록한다. 마감 문서 수정은 별도 소유 hunk 승인 후 최소 P02 행과 새 전용 결과/체크리스트/인계로 제한하며 33행과 다른 작업 문구, HTML을 유지한다.
