# P02 다섯 번째 조각 수정 계획 v3

2026-11-08. 독립 재심 전 실행 및 구현 금지. PLAN.md SHA-256 8815a7de71980fe46b2ce1cbe744bb05ff8f7529731d3a1b645482333e7689da, PLAN-V2.md SHA-256 c13395a4229619f94335916f195660b8bafd039b4e074e16ccdec11863159383. v2의 구현 계약·보존·K6·독립 oracle을 승계하며 아래가 실행 입력·분모·합격 조건의 개정이다.

- before-attempt-01은 실패 기록으로 보존한다. common 99단언 2실패(exit 1), clean-user WorldLink WORLD_LINK_FAIL 1(exit 1), 두 adapter exit 0. 기존 A03은 brief 단언 실패 후 begin_battle 직접 호출로 서막을 우회했다. 이어진 결과·라벨·호출 증거를 A03 정본 비교에서 제외한다. 이전 WORLD_LINK_PASS의 사용자 설정은 미확인이다. returning-user 설정이 당시 성공 원인이었다는 해석은 추정에 그친다.
- A03은 초기 설정 파일 없는 격리 user://에서 시작한다. 실제 WorldMap 출격/skip→WorldLink→FleetBattle3D로 이동하여 deck.screen == prologue, GameSettings.prologue_seen == false, 실제 deck.screens["prologue"].skip Button 존재·visible·enabled를 검사한다. pressed를 통해 PrologueScreen.finish를 실행하고 brief 전환과 prologue_seen 및 격리 설정 파일 기록을 확인한다. 전환 실패 시 해당 행을 중단하고 begin_battle 또는 대체 진입점을 호출하지 않는다. 이어 실제 brief 화면의 자동 편성으로 시작 버튼(hud/ui_kit/deck_screens.gd:221–228)을 눌러 OrgScreen.start_auto → deck.begin_battle로 진행하며, 고정 tick 검증, native 종료 주입, 실제 결과 버튼, WorldLink의 1회 인계 및 WorldMap 카드 결과/라벨·권역 상태를 확인한다. 제품 입력 전환의 중간 단계와 고정 tick 증거가 빠지면 미통과다.
- A06은 같은 원본 적벽 profile 바이트/SHA 및 adapter 클래스 경로를 검증한다. 기대는 정확히 {ok:false,error:"unsupported_scenario",path:"profile"}다. 강화 지원이나 나머지 지원 밖 분기 전수 실행으로 해석하지 않는다. 같은 fixture/동일 common runner 및 사후 재생성 금지의 정본 baseline 결과를 편집 전 별도로 동결한다.
- WorldLink clean-user 검사는 계속 수행한다. 원본 tests/world_link.gd 무편집, 기존 1개 prologue/brief 실패 시드·위치·진단을 동등성 관측으로 보고하며 통과로 계수하지 않는다. returning-user WorldLink를 별개 프로세스로 추가한다. settings.cfg는 UTF-8 BOM 없이 정확히 [progress] LF prologue_seen=true LF 30바이트(SHA-256 c8b752aba9f5015889c00c5a45db9fef916af2a1e1be3e68d49b8121b2db721b), 다른 user 파일은 초기 상태에서 없음. fixture 실제 파일 bytes/SHA를 사전 동결하며 런처가 동일 파일을 격리 user:// 실제 해석 위치로 복사한다. APPDATA, LOCALAPPDATA, XDG_DATA_HOME, 실제 OS.get_user_data_dir 및 시작 파일 목록/해시를 각 실행에서 기록한다. 사전과 사후에 새 격리 경로와 같은 초기 바이트를 사용하며 실행 후 설정/로그는 분리 보존한다. clean-user도 각 프로세스의 새 경로 및 settings 부재를 증명한다.
- 분모는 개정 pre 5/post 6 프로세스다. common clean-user, WorldLink clean-user, WorldLink returning-user, worker adapter, headless adapter 및 post에만 boundary. common 18행과 boundary 7행은 유지하고 A03 추가 단언은 실측하여 별도 기록한다. before-attempt-01의 pre 4개를 이 분모로 소급하지 않는다. 변경된 runner/launcher/fixture 바이트와 SHA, 명령, 각 초기 user 상태, 실행 리소스·엔진·classcache 및 오라클을 새 사전 시도에서 기록한다. 이전 runner/계획/실패 로그는 수정하지 않고 v3 입력 사본과 새 attempt 디렉터리를 쓴다.
- 최소 제품 검증은 clean-user A03의 실제 서막부터 제품 결과 카드/1회 소비, A01의 실제 자동 시작·poll·결산 카드, A04/A05 실제 취소 버튼·씬 제거 및 join/미게시, 고정 원본 대비 두 성공 카드 전필드·라벨·결과를 포함한다. returning-user WorldLink 정상 통과 및 기존 adapter 통과, boundary 7행, 보존 감사가 필요하다. clean-user WorldLink는 오직 사전과 동일한 단일 실패를 별도 공개할 수 있다. 추가 실패/진단 악화·timeout·누락, 사후 유저 설정 또는 입력 오염, 실제 경로 우회는 no degradation 조건 위반이다. stderr/엔진 로그의 기존 이탈·리소스 종료 진단을 보존 비교한다. 원래 실패가 사라지는 등 예상 편차가 바뀌면 독립 심사를 거쳐 해석한다.
