# P02 다섯 번째 조각 독립 계획 심사

2026-11-08. 판정: **반려 — 스펙 보완 후 재심**. 대상 `PLAN.md` SHA-256 `8815a7de71980fe46b2ce1cbe744bb05ff8f7529731d3a1b645482333e7689da`. 독립 심사자 세션 `/root/p02_fifth_review`; 요청 모델 gpt-6.1-terra, 실제 실행 모델은 이 세션에서 독립적으로 확인할 수 없어 미확인. Astra를 사용했다고 주장하지 않는다. 제품 코드 수정·실행은 하지 않았다.

1. **실제 제품 직접 경로 증거가 불충분하다.** 계획 ③의 native `_end` 주입 및 결산은 `FleetBattle3D.back_to_world` 호출, `WorldLink` 결과 인계, WorldMap 결과 카드의 실제 경로를 거친다는 조건이 없다. 기존 WorldLink 테스트가 실제 두 씬과 결과 카드를 실행한다는 주장도 테스트 본문·명령으로 입증되지 않았다. 해당 테스트 범위를 확인하고, 실제 제품 메서드/씬 호출과 `BattleOutcome.to_dict`, 표시 텍스트·결과 1회 소비를 변경 전후 대조하라. 실행이 불가능하면 해당 흐름은 미검증으로 남기고 보존 근거에서 빼라. WorldMap 자동 경로도 실제 `_start_resolve`→`poll`→`_show_result` 호출과 취소/exit join을 명시하라.
2. **작업 스레드 경계의 실패 계약이 비어 있다.** 새 callable이 `_loop` 후 snapshot을 수행하므로 반환 누락/잘못된 값, snapshot 실패·예외와 `wait_to_finish` 결과 처리에서 기존 `poll`의 성공/결산 동작이 달라질 수 있다. `poll`이 null/오류 facts를 성공으로 발표하거나 크래시하지 않도록 허용 가능한 관측 결과와 기존 동작 차이를 먼저 정의하고, 주입 가능한 실패를 실측하라. 엔진 예외와 OS Thread.start 실패는 미주입 한계로 명확히 남겨라. `_cancel`/진행값은 기존 동기화 없는 공유 필드이므로 새로운 경합 안전성을 주장하지 말고, 취소가 join 전에 관측된 경우와 이미 poll로 게시된 경우를 구분하라. 이전 공개 sim 접근 가능성 때문에 worker snapshot과 외부 변경이 겹치는 경우도 기존 호출 계약의 미지원 또는 명시된 보호 범위를 정해야 한다.
3. **독립 오라클과 테스트 자료의 동일성을 고정해야 한다.** 사전 결과 보관만으로는 이후 새 코드가 원본 결과를 생성하거나 fixture가 달라지는 순환 비교를 막지 못한다. 편집 전 고정된 원본 코드·입력·전체 결과 및 SHA, 실행 명령과 엔진/클래스 경로를 기록하고, 사후에는 그 불변 결과와 비교하라. `result` 중첩 원가, 사기 경계(10/30/60), 장수 상태, limited, 패배 사유, null brief, 빈 result와 후일담 후보 조합을 독립 기대값으로 검증하라. 사본 오염은 양방향(추출 후 원본 변경, facts 변경 후 원본/결과 변경)과 중첩 데이터·반복 호출을 확인하라. 실제 1800초 상한은 미검증으로 유지한다.
4. **범위와 필연성의 서술을 제한해야 한다.** 현재 제한 owner는 victory와 result를 지원하지 않으며 `summary`로 제품 결산을 만들 수 없다. 이 변경은 기존 legacy 결산 경계 정리일 뿐 실제 operation 제품 경로, 공통 adapter 소비, P02 제품 결산 인수의 증거가 아니다. 새 facts API가 미래 owner와 호환된다고 단정하지 말고, worker에서 live sim을 소유한 채 자료를 추출하고 join 후 기존 brief를 읽는 기존 계약을 명시하라. FleetBattle3D 시계·명령·선택·카메라·사건/trace, WorldMap operation 진행/취소·결산, replay, P03 및 schema는 미완료로 유지한다.

계획의 장점은 실제 적벽 입력을 임의로 축소하지 않는 점, 기존 worker 요약을 결산 근거로 삼지 않는 점, baseline/P03 보호와 한계를 분리한 점이다. 위 항목 해결 후 변경 계획 및 오라클을 독립 재심해야 하며, 현재 판정은 구현 승인이나 최종 5-b가 아니다.
