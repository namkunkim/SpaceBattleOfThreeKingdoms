# Python no-window 마지막 진단 독립 심사

판정: **비제품 Python normal 한 사례의 세 번째이자 마지막 시도를 수용한다.** 이번 심사에서 child·Job·Godot·GUI·제품은 실행하지 않았다. 제품 K6 및 ABI 실행은 승인하지 않는다. 심사 모델 gpt-6.1-terra.

계획 SHA `cf3a95ceca2044cc2256544c1851ba93d41624e4e5ce2f3fe018f0d85a0234cd`, 목록 `a1eb22a917aa6074c61f383e0b2edb7be2173d052d704d7b33cf8cfdbbbd97be`, review-only manifest `466e28f1544738abcc12d89aaf7fb694061e1bb7f4957eea7cc05fda3372c0c3`을 확인했다. 새 broker diff는 subprocess.call에 `CREATE_NO_WINDOW` 한 플래그만 더하고 `stdin=DEVNULL`, 기존 stdout/stderr와 breakaway 부재를 유지한다. [Microsoft Process Creation Flags](https://learn.microsoft.com/en-us/windows/win32/procthread/process-creation-flags)는 이 플래그가 콘솔 응용 프로그램을 콘솔 창 없이 시작한다고 설명한다. 모든 console host의 부재나 과거 두 실패의 원인을 입증하지는 않는다. 설치된 Python subprocess.py의 Windows 경로에서 stdin=DEVNULL 시 stdout/stderr None은 GetStdHandle 및 상속 가능한 핸들을 사용하는 것을 정적 확인했다. 실제 pipe/EOF와 Job membership은 이 시험에서만 관측한다.

승인 파일은 review-only manifest의 status만 `INDEPENDENTLY_APPROVED_NONPRODUCT_PYTHON_NOWINDOW`으로 바꾼 `variant-abi-review/PYTHON-JOB-NOWINDOW-MANIFEST-APPROVED.json`, SHA-256 **`fc61b561d7e9f4740497c77d9dbacb1ea603dfd5d0cf584f0acd692655bc603f`**다. 현재 source 29개와 protected 6개 SHA가 일치하고 HEAD `0be09755b70378286105972f35ac5b7031715664` 및 symbolic ref가 일치하며 scratch·guard journal은 없다. 실제 실행 직전 승인 bytes/모든 SHA·HEAD/ref·scratch와 diagnostic 출력 부재를 재확인하고 drift 시 중단한다. 원본·P03 및 기존 두 실패 자료를 복구·삭제하지 않는다.

정확 argv는 manifest의 `outer_watchdog_argv_template`에 승인 manifest 절대경로와 위 digest를 치환한 `C:\Python314\python.exe -I -B C:\WorkSpace\SpaceBattleOfThreeKingdoms\tmp\p02-ninth-20261108\prep-ab-sol\variant-abi-review\python_job_nowindow_external_candidate.py <승인 manifest 절대경로> <위 SHA>`다. 기본 managed sandbox에서 한 번만 실행한다. 기존 Python-only allowlist를 확대하지 않고, unexpected 소유 image는 retained HANDLE·membership 및 raw 진단을 보관한 실패다. 대상 Job 외의 사용자 프로세스를 조회·종료하지 않는다. 별도 소유 sentinel은 case Job 바깥에서 확인한 후 자신의 Popen으로 종료한다.

기존 실패 #1·#2를 포함해 Python 비제품 K=3의 마지막 #3이며 중단/미관측도 시도에 포함한다. 25초 global, bootstrap/barrier 3초, inner 3초·case outer 10초, drain/journal 2초의 코드상 경계와 Job kill-on-close를 사용한다. OS/스레드 전체 정지까지 절대 제한을 보장한다고 주장하지 않으며 HANDLE 미관측·drain/EOF/원문 누락은 실패다. 원시 image 경로는 로컬 증거에만 보존한다. 정상이라도 이번 조건의 normal 1회 결과에 한정하고 timeout·ABI·GUI·제품을 대체하지 않는다. 실패 또는 성공 결과를 독립 심사하기 전 후속 제품 실행은 금지한다.
