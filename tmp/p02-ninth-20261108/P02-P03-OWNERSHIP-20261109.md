# P02 · P03 공유 호스트 조율

## 현재 확인한 범위

HEAD는 `0be09755b70378286105972f35ac5b7031715664`다. 경로별 Git 상태에서 FleetBattle3D, UI Sound, runtime adapter, auto resolver에 변경이 없었고 private owner, worker 테스트, P02 진행표에는 기존 작업 트리 변경이 있었다. 실제 FleetBattle3D의 `_prepare_game`은 여전히 `BattleSim.new`를 직접 호출한다. 격리 패치는 미적용이고 여덟째 조각의 K1~K5 기록과 마지막 K6 한 회를 유지한다. K6은 미실행이다. Q/C/B 시험의 독립 오라클과 증거를 준비 중이다. C side 1 v6은 정적 판정기 보강만 수용됐으며 실제 producer 결합과 실행 근거는 남아 있다.

현재 공유 제품 파일에 쓸 수 있는 P02 hunk와 실제 쓰기 창은 없다. K6 독립 실행계획 수용 전에는 준비를 격리 범위에 둔다. 독립 실행계획 수용은 격리 K6 실행 게이트이고, 제품 원본 반영 검토에는 K6 결과의 독립 5-b 수용도 필요하다. 현 후보의 변경 범위는 runtime adapter의 `create_product_native` 추가, FleetBattle3D `_prepare_game`의 raw sim 생성과 direct 제어 초기화 교체, auto resolver의 raw sim 생성과 auto 제어 초기화 교체 세 hunk다.

## 겹치는 경계와 책임

| 경계 | 확인한 접점 | 인수 책임과 미정 사항 |
|---|---|---|
| FleetBattle3D 진입·준비 | 공개 시작 흐름 177~183행과 `_prepare_game` 270행부터. P02 후보는 준비 내부 303행 문맥의 legacy 생성만 교체한다. P03의 제품 복원 후보 수신 위치는 미정이며 P03 계획의 정적 조사 범위에서는 제품 복원 호출을 찾지 못했다. | P02는 legacy profile, 초기 제어와 새 전투의 성공·실패 원자성을 인수한다. P03은 복원 지원 프로필, private owner 준비·검증 및 거부 계약을 인수한다. 공통 진입에서 신규 시작과 복원의 분기 위치와 반환 계약은 조율한다. |
| 게시·프레임 | `_publish_game` 316행, `_process` 478행, `update_sim` 선언 529행과 본문 530행. P02 현 후보는 이곳의 hunk가 없으나 향후 operation 호스트 인수와 P03 복원 게시가 모두 사용한다. | P02는 호스트 초기화, 게시 뒤 명령 대상, events 소비와 UI 바인딩 계약을 인수한다. P03은 복원된 논리 tick/clock, 사건 순서와 owner 연속성의 독립 기대값을 제공한다. 단일 후보 게시와 오류 시 기존 owner/sim, 두 누산기, speed/pause, 선택·카메라·투영, pending·미소비 사건 보존은 공동 인수한다. 첫 프레임의 phase 동등성 또는 새 주기 계약, 두 시계 갱신 및 사건 소비의 호출 책임은 미정이다. |
| UI Sound BGM | `hud/ui_kit/ui_sound.gd`의 재생·finished·stream 수명은 양쪽 호스트 실행과 종료 진단에 영향을 준다. P02 현 후보의 파일 범위 밖이다. P03 격리 진단은 Ogg 경로와 종료 진단의 상관을 보고했으며 원인과 수정 hunk는 미정이다. | P03은 BGM 포함 진단 재현과 원인 분리, 수정이 필요한 경우 최소 hunk와 회귀 근거를 맡는다. P02는 동일 baseline/candidate 입력과 기존 종료 진단 판정에 영향을 주는지 확인한다. 호스트 전환이나 오디오 수명 변경이 필요할 때 해당 호출부를 함께 조율한다. |

공통 인수에서 P03은 실제 제품 복원 진입과 지원 guard의 증거를, P02는 초기화·게시·명령·사건·UI 연결의 증거를 제공한다. 두 계획의 독립 수용에서 같은 복원 실행의 후보 identity, 명령 전달 대상, 첫 프레임 tick/clock 및 순서 있는 사건과 UI 상태를 대조한다. 실패 뒤 정상 후속 프레임도 비교한다. 격리 fixture나 직접 주입 결과는 해당 격리 시험에 귀속한다. 제품 lifecycle 저장·재개 연결, O07, 외부 저장 스키마는 별도 인수다.

공유 hunk 변경이나 상대 증거를 무효화할 실행이 구체화되면 먼저 최신 HEAD/index/status와 원본 bytes, 실행 입력 closure를 읽기 전용으로 재동결한다. 상대에게 파일·함수·hunk, before/after 입력, 예정 쓰기·실행 창, 회귀 및 증거 귀속을 전달해 충돌 구간의 순서를 조율한다. P03 현재 private owner를 K6 입력에 포함한다면 before/after 양쪽에 같은 동결본을 사용한다. 변경이 감지되면 차이를 기록하고 기준선을 재동결한다.
