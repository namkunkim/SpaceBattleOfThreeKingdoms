# P02 아홉째 선행계획 독립 심사

판정: **선행 준비에 한해 조건부 수용. K6 실행은 미승인·미실행이다.** `NEXT-PLAN.md` SHA-256 `a0efbbd1aa0fa3aab2fdc9d79aed36c705e7a0578b35676cbb3cf12059e3a0e9` 및 HEAD `0be09755b70378286105972f35ac5b7031715664`를 직접 확인했다. 이 리뷰는 모델의 실제 식별값을 도구에서 확인하지 못했으므로 모델명을 추정하지 않는다. 제품·GUI·사전 적합성 프로세스는 실행하지 않았다.

## 판단과 구체적 다음 단계

1. 원문 inventory는 일곱 suite 각각의 소스·fixture·호출 경로와 실제 도달 가능한 단언 및 exit를 표로 확정하는 **한 번의 유한 작업**으로 한다. HEAD와 수용 패키지 및 현재 worktree를 대조하고 차이를 명시한다. 루프·조건·조기 종료는 케이스 분기를 표현하며 단순 정적 개수로 확정하지 않는다. 누락 시 구체적 누락을 수정하고 독립 검토한다. inventory만 계속 반복하지 말고, 성공하면 바로 아래 사전 적합성 명세와 실행 manifest 완성으로 진행한다. 현재 worker 테스트에 2행의 작업 트리 변경이 있으므로 HEAD와 혼동하지 않는다.
2. 비제품 적합성은 제품 테스트나 K6 결과가 아니다. 실제 엔진과 같은 프로세스 생성 방식 및 Job 계층을 최소 프로젝트에서 확인할 필요가 있다. 제안의 suspended 생성 방식은 기존 V5의 inert broker 할당 후 자손 실행과 다르므로, 실제 채택 runner와 동일한 방식으로 시험하거나 차이를 명시하고 별도 검증해야 한다. assign 거부는 해당 환경에서 실제 관측될 때만 주장하고, 불가능하면 미검증으로 기록한다. 로그에는 생성·할당·해제·종료 순서와 자손 Job membership, 종료 후 잔존 여부 및 비소유 프로세스 비침범을 남긴다. 이 적합성 PASS는 실행 허가나 제품 통과가 아니다.
3. GUI의 nonce/PID/생성시각/SHA/HWND 및 연속 foreground와 Godot 수신의 연결은 필요하지만, low-level hook의 injected flag는 Sky 요청자의 신원 증명이 아니다. 요청과 OS 이벤트를 독립적으로 결합할 수 있는 근거 및 누락 감지 한계를 미리 제시하고 반례를 검사한다. 입증할 수 없으면 GUI 미완료로 둔다. 다른 검증 방식으로 대체하려면 실제 사용자 입력이라는 인수 조건과 신뢰 모델을 보존하는 구체적인 대안을 독립 검토해야 한다. viewport 주입이나 synthetic 이벤트를 OS 입력으로 재분류하지 않는다.
4. 21행은 기존 승인 계약의 기본 분모다. 이것이 제품 요구의 유일한 최소 집합이라는 증거는 아직 없으므로 축소는 요구사항별 추적·독립 심사 전 금지한다. V5 manifest를 직접 계산하면 58개 프로세스의 timeout 18,490초 + cleanup 580초 + reserve 1,200초 = 20,270초(5시간 37분 50초)다. 이는 시간 상한 합이며 실제 성공 시간이나 실행 타당성의 실측이 아니다. staging/import/검증 및 전체 deadline 초과 시 정리까지 포함되는지 확인한다. 프로세스 병합은 케이스별 독립 상태·원문·실패·timeout 격리와 21행 대응을 증명한 뒤에만 평가한다. 이전 실행의 성공을 K6 누락 분모에 합치지 않는다.
5. 원본 native 소비자와 독립 BattleSim 및 고정 fixture를 기준으로 사용하되, 공유 adapter 또는 동일 변환을 양쪽에서 반복해 맞다고 결론내리지 않는다. typed 원문·alias 변경 후 분리·증원·재변환 금지에 반례를 둔다. 실패 원자성은 초기/활성 실패에서 실제 제품 객체 identity, sim, clock, controls, 선택·카메라, trace·명령·사건 및 정상 재시작을 비교한다. 제품 버튼과 main-thread join 후 결산 확인을 대체 계측과 구분한다. 실제 코드·fixture와 독립 oracle 대응 및 각 기대값은 최종 manifest 심사 대상이며 이 계획만으로 충족되지 않았다.
6. 현재 `core/battle/operation_private_state.gd`의 P03 변경은 HEAD 대비 9행 추가다. 이 파일을 포함한 P03 현재 bytes와 병행 변경을 보호하고, 사전·사후 경로별 bytes/SHA 및 Git index/HEAD를 비교한다. 샘플 사이의 순간 변경까지 부재라고 주장하지 않는다. 원본 후보 적용 시 허용 세 파일의 정확한 hunk와 현재 bytes를 대조하며, drift 시 중단·재동결하고 타 작업을 복원하거나 stage하지 않는다. before/after에 적용할 P03 snapshot은 동일하게 고정하고 선택 근거를 남긴다.

K1~K5를 포함한 K=6과 K4의 175초 실패 및 K5 입력 귀속 미확인 기록은 유지한다. K6 한 회는 계획의 정의대로 최초 제품 검증 프로세스 시작 시 소진하며 실패·중단·부분 실행을 새 예산으로 리셋하지 않는다. 선행 명세 독립 검토 → 실제 비제품 적합성 결과 검토 → 완전한 행별 manifest·입력 SHA 및 oracle 독립 재심 → 단일 K6 → 독립 결과 5-b가 제품 적용으로 가는 경로다. 각 단계의 실패는 원문을 보존하고 실행을 중단한다. 이 심사는 적합성 명세나 실제 결과, 최종 manifest를 수용한 것이 아니다.
