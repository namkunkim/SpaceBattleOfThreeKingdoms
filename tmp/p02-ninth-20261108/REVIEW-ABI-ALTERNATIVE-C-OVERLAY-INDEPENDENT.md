# Managed ABI 대안 및 C producer overlay 독립 심사

판정: **위험 기반 ABI 방향과 C source-only 준비는 제한 수용한다. 두 실행 모두 미승인이다.** `NONPRODUCT-ABI-MANAGED-ALTERNATIVE.md` SHA `bdb581e563daff0b787f85e617a7c4332bfdac1dfe0e3a3a6a722ab2a0481b5a`, C overlay manifest `709e819832adf76d622df4c03ebe4330877efb0ab75f891c6a37b0c1b55162a8`, generator `f053026be2e4b25b035ba eefd36700d4fbfc0f1eda5df9327fb6ce792c996e08`의 실제 값은 공백 없이 `f053026be2e4b25b035baeefd36700d4fbfc0f1eda5df9327fb6ce792c996e08`로 확인했다. 심사 모델 gpt-6.1-terra. 제품/Godot/GUI/Job 실행 없음.

ABI 대안은 명시된 managed root read/workspace write 하에서 검토된 최소 source와 신뢰 엔진, 격리 scratch 및 전후 hash를 사용하는 제한 관측이라는 점을 솔직히 밝힌다. 이는 OS read-deny 또는 변경 후 복구가 없었다는 보증이 아니다. 이 낮은 위험의 literal ABI 목적에 전용 read-deny를 보편 필수로 삼지 않고, 실제 source/argv audit, cwd/user/cache/temp/log 격리, owned process cleanup 및 원본 보호를 검증하면 독립적으로 실행 가능성을 재심할 수 있다. 다만 현재 owner adapter·outer watchdog 및 실제 lifecycle 증거가 없고, exact global cap·출력/예외 정리·short-lived engine identity 관측도 미완성이다. 예상 외 쓰기를 실제 어느 범위에서 발견할 수 있는지와 파일 목록의 범위를 밝힌다. 이 대안은 제품 K6, GUI 귀속이나 강제 격리 증명이 아니다.

Overlay diff는 `Detection._eval`에서 side 1일 때 meta observer만 부르고 `_detection`에서만 observer 등록·해제한다. `_restore`의 primary/repeat와 wrong-position에 wrapper를 넣되 각 경로에서 실제 restore를 한 번 호출하고 반환값을 다시 사용하는 형태이므로 정적 호출 순서 보존 의도는 명확하다. 단 실제 GDScript parse·Callable.bind 시그니처·typed serialization·관측 성능/로그 용량은 미실측이다. 실제 `_all` 캡처와 출력이 평가·예외·lifetime·time budget에 미치는 영향과 예기치 않은 `get_meta` 충돌, 다른 suite 비활성 경로를 반례로 확인해야 한다. 예외·출력 누락·worker timeout을 성공으로 치환하지 않는다.

이 overlay는 **완성된 v4~v9 evidence producer가 아니다.** `_k6_record`는 `mono_usec`, `payload_hex`, scope-local event를 내며 v7의 `mono_ns`·launcher identity·packet/state SHA/request ID 및 v9의 pre/post schema와 다르다. `source-before`/`restore-request`/`restore-result`/`source-after` 원문을 독립 verifier에 일대일로 연결하고 raw bytes·run/lane/process·offset·single-writer ordinal·clock 단위를 명시해야 한다. 기존 원문의 `_check` identity/detach 결과와 alias mutation은 기록된 원문 상태만으로 자동 증명되지 않는다. 실제 element identity, 원본 packet mutation 전후·target/source 불변 및 events/command/fingerprint/suffix를 별도 판정해야 한다. Geometry 증인의 `stages`/config/terrain/skills/chain을 독립적으로 해석해 v4의 정확한 8,960 평가 및 초기·phase에 결합하고, observer 미호출이나 C 외 사례 혼입, 중복/순서/위조·동일 producer 자기참조를 거부해야 한다. candidate가 fixture pin을 만들지 않도록 독립 승인 source/context를 사용한다.

Source-only SHA와 diff는 승인 closure·실제 읽은 바이트·중간 불변을 보장하지 않는다. before/after에 동일 overlay를 적용하고 각 source/fixture/engine/cache의 정확한 hash 및 protected P03·worker/index 전후를 검증하며 동시 drift면 중단한다. HEAD lane은 P03 활성 변경과의 결합을 입증하지 않는다. GUI per-request provenance·Job·완성된 21행 manifest가 여전히 미해결이므로 K6을 시작하지 않는다. K1~K5와 최초 제품 import부터 소진되는 마지막 K6 한 회, 175/320과 기존 원문을 유지한다.
