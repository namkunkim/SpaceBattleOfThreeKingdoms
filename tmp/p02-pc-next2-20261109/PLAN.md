# P02 전장 → 천하 즉시 전환 거절 복구

독립 계획 심사 대기. 제품 편집·Godot 실행 0회.

## 1. 의도

세션 요구사항 §0의 첫 PC 출전·결산 우선순위 안에서, 적벽 legacy 전장의 기존 천하 복귀를 실패 후에도 다시 사용할 수 있게 한다. `deck_screens.gd:318,605`의 일시정지·결과 버튼은 `command_deck.gd:288`의 `to_title`을 거쳐 routed 전장에서 `FleetBattle3D.gd:432`를 호출한다. 끝난 전투에서는 `BattleOutcome.from_sim(sim, link.brief)`를 만들고, 끝나지 않은 전투 및 최초 준비 실패 카드(257행)에서는 null을 보낸다. `scripts/world_link.gd:36`은 outcome을 먼저 바꾸고 brief를 지운 뒤 `change_scene_to_file(WORLD_SCENE)`의 즉시 거절을 버린다. 로더가 거절하면 전장은 그대로인데 `routed()`가 false가 된다. 다음 클릭은 기존 천하 복귀 분기를 잃고, 같은 전투의 시드·난이도·지휘 방식도 결산에 다시 넣을 수 없다. 성공 경로와 일회 소비는 WORLD-MAP-LINK §3의 기존 계약이다.

직전 수용은 천하 → 전장 즉시 거절이다. 이번 조각은 반대 방향으로, 직전 두 소스 변경 중 `go_battle` 및 WorldMap의 출격 화면 복원 hunk를 보존한다. 여덟째 공통 native 초기화는 격리 후보이며 K6 미실행이다. PC0는 2/2 소진, 제품 적벽 operation·자연 종료·첫 PC 플레이는 미인수다. PC0의 실제 OS 입력 시도를 되풀이하거나 우회하지 않는다.

P03 제품 복원은 정적 범위 마감이며 adapter는 checkpoint를 거부한다. 새 시작/복원·시계·사건 게시 및 FleetBattle3D 공유 쓰기 창은 별도다. P05의 19/19는 전용 이동 가드 Windows 자동 실행 및 헤드리스 근거다. 실제 지도 제품 적용은 별도다. P07은 계획 수용 단계이며 보급·증원·목표·명시 철수의 작전 정책은 별도다. 현재 '결과 없는 천하 복귀'를 작전상 명시 철수로 해석하지 않는다. P04 저장·재개는 첫 PC 인수 뒤로 둔다. 읽기 전용 채팅 스냅샷에서 P03/P05/P07은 각각 idle이었으며 쓰기 잠금으로 사용하지 않는다.

## 2. 스펙

- 제품 변경 위치는 `scripts/world_link.gd`의 `back_to_world` 한 함수. 이전 Brief와 Outcome 참조를 보관하고 기존대로 전달 값을 배치한 후 로더를 한 번 호출한다. 즉시 Error 반환 시 두 참조를 정확히 복원하고 수치 Error를 포함한 한 건의 명시 경고를 낸다. 제안 경고의 안정 식별자는 `WORLD_RETURN_REJECTED`다. 호출부와 기존 void API를 보존해도 이 계약을 만족한다.
- 거절 시 기존 전장 scene, paused/result/최초 준비 실패 화면과 해당 복귀 버튼이 남는다. 기존 Brief를 되살려 같은 버튼을 통한 정상 재시도를 가능하게 한다. 완료 결산의 재시도는 새 Outcome 객체를 만들 수 있으며 같은 결과 값으로 판정한다. 과거 대기 Outcome 보존은 객체 동일성으로 판정한다. null 복귀도 거절 시 과거 대기 Outcome을 지우지 않는다. 난이도·모드 값은 바뀌지 않는다. scene 진행 후 로드/초기화 문제, 중복 성공 요청의 신규 제어 및 사용자용 신규 오류 안내는 별도 범위다.
- 성공 시 WorldMap의 기존 진입 및 `take_outcome` 일회 소비를 보존한다. 완료 후 결과 표시, 중도 또는 최초 준비 실패 후 결과 없는 복귀, 선택값과 seed/mode/difficulty 및 기존 결산 필드에 대한 일치가 판정 기준이다. 사용자 저장 위치와 원본 자산을 실행 입력으로 변경하지 않는다.

## 3. 분해 및 게이트

1. 독립 계획 검토가 한 조각, 입력/오라클, 보호 hunk, 진단의 현실성을 판정한다. 승인 전 제품 편집·엔진 실행 금지. 입력 기준은 baseline.json의 26개 경로, staged 비어 있음과 양끝 index SHA 일치다. WorldLink/WorldMap 원문 바이트 사본을 포함한다. 표본의 시점 차이와 비소유 변경은 따로 보고한다. 현재 전체 workspace 재스캔은 이 함수 계획에 불필요하다. 실행 전에는 검토된 기존 프로젝트 closure를 사용해 필요한 의존성만 동일 입력으로 다시 동결하며, 경로 변화가 후보/근거에 닿으면 중단하고 재검토한다.
2. 독립 수용 뒤 실행자가 승인 범위에 격리 후보와 소규모 검사를 만든다. 같은 격리 Godot 프로젝트/별도 사용자 데이터에서 baseline과 후보를 비교한다. 정상 WorldMap scene, 그리고 격리본에서 해당 고정 경로를 독립 불러오기/임포트 전부터 깨뜨린 입력을 사용한다. 로더의 실제 Error를 원문으로 확인하고, fixture가 init·활성 전장 구성을 막거나 cache 때문에 거절이 안 되면 해당 lane은 무효다. 정상 복구 재시도는 거절 fixture에서 리소스를 복원하고 로더의 반환·씬 교체까지 실제 확인할 수 있을 때만 같은 프로세스 증거로 쓴다. 격리 자산 복원 후 cache 때문에 이 증거를 못 얻으면 별도 프로세스 성공을 구분하고 동일 전장에서의 재시도는 미검증 처리한다. 기존 승인 runner의 제한/종료/귀속을 재사용한다. 신규 인프라, OS 입력, 사용자 PC0/K6 실행은 범위 밖이다.
3. 반례는 결과 화면의 완료 결과와 일시정지의 null 복귀다. 최초 준비 실패 카드의 null 호출은 기존 실제 준비 오류 fixture를 사용할 수 있을 때 동일 범위에 확인한다. 테스트 전용 `sim._end`를 사용하면 완료 UI 진입 fixture로만 귀속한다. 실패 전후 current_scene·brief/outcome identity, routed, sim 및 화면/버튼, seed/mode/difficulty를 대조한다. 정상은 실제 기존 버튼의 viewport/signal 동작과 WorldMap의 결과/무결산 화면 및 Autoload 큐의 1회 소진을 각각 확인한다. 정상 lane에는 새 경고가 없어야 하며 실패 lane에는 실제 로더 경로·거절 진단과 후보 경고가 각각 대응해야 한다. `SCRIPT ERROR`, 예기치 않은 진단, timeout 또는 exit 불일치는 PASS에서 제외한다. 시각 변경을 설계하지 않으므로 viewport의 해당 화면과 버튼 유지가 이 조각의 검사다. 실제 Windows 화면/입력/자연 종료 인수로 표시하지 않는다.
4. 기존 `tests/world_link.gd --quick`의 왕복 및 직전 직접 전환 거절에 해당하는 최소 회귀를 같은 입력으로 검증한다. clean-user 서막의 기존 단일 실패와 returning-user 통과를 구분하며, baseline 종료 진단은 기록하고 후보 신규 진단과 분리한다. K 상한 6은 이 조각에만 적용한다. 독립 5-b에서 전후 로더 오류·참조·호출·결과, 한 함수 diff 및 비소유 경로 보존을 대조한 뒤 원본에 최소 hunk만 적용한다. 진행표/증거 및 최종 독립 마감은 실제 성과만 기록한다.
